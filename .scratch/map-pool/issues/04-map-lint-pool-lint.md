# 04: map-lint 池级断言 —— 最近一圈归属、矿路红线、Jaccard 风格

**What to build:** `map-lint` 从「校验一张图」扩到「校验一个地图池」。三条跨图判据在这里落地，每一条都是单图判据**结构上判不了**的：

- **最近一圈资源点的归属**（`handoff` 定为规则不变量，由校验器对地图 JSON 断言）
- **矿路红线**（矿路不许被墙拉过 10 格，否则枯竭顶破 600 tick）
- **Jaccard 风格判据**（三图墙体集合两两相似度上限 0.15）

这三条都带一个「为什么是这个数」的实测依据，凭据是原型阶段的度量。**把数字连同依据一起落进票**，是为了让日后想改阈值的人先看见当初量到了什么。

**Blocked by:** 03（map-lint 单图断言）

**Status:** resolved

- [x] 入口接受**一个目录**（地图池）而不是单文件；目录读取是薄壳的活，断言本身仍是纯函数
- [x] **池内 `size` 一致**：不同尺寸的图进不了池
- [x] **地图数量满足下限**：池内至少 3 张（规则要求）
- [x] **最近一圈归属**：对每方主基地算全部资源点的 **Chebyshev 理论距离**，取 `d_min`；该方 `initialOwner` 指向的资源点集合**恰好**等于距离等于 `d_min` 的那组点
- [x] 那组点**构成一条完整的四重轨道**，且数量是 4 的倍数 —— **读法有偏差**：逐方读法在落库图上恒为假，改成「四方最近一圈的**并集**由完整轨道构成」，理由见 Answer「冲突一」
- [x] **并列即判失败**：两组资源轨道到某家的距离相等时报错，**不选一个**。理由是「最近一圈」不唯一时任何自动选择都会把一个设计歧义悄悄定死；报错才是这张图唯一有用的行为。必须有一条等距的反例锁死这一点
- [x] 距离用 **Chebyshev 理论距离，不用绕墙的路径距离**。理由有两条：度量自洽（规则已把 Chebyshev 定为移动度量）；以及避免把点位不变量耦合到地形设计上——用路径距离的话改一堵墙可能改掉某家的开局矿归属，于是地图迭代变成排雷
- [x] **矿路红线**：对每方算「家 → 最近自家资源点」的路径长度，**`d ≥ 11` 判失败**。**（本条原写 Chebyshev，已作废）**：阈值 10 的依据在原型里是以 BFS 路径代入 `2d+20` 估的，判据却一度量坐标差——账实不符。票 06 的换尺修订见本票 `## Answer` 的「修订（后续票）」一节，值 10 未动。依据是采集往返 `2d + 20` 的线性放大实测：`d=6` → 枯竭 479、`d=8` → 539、`d=10` → 599、**`d=11` → 629 顶破 600**（400–600 是规则给枯竭时点定的窗口）
- [x] 红线的判据是 **Chebyshev 距离**（与最近一圈同一把尺），不按路径距离——路径距离会让这条线随墙形漂移
- [x] 边界两侧各有用例：`d = 10` **必过**、`d = 11` **必被拒**
- [x] **Jaccard 风格判据**：池内任意两张图的墙格集合相似度 `|A∩B| / |A∪B|` **必须 ≤ 0.15**
- [x] 阈值 **0.15** 附实测依据：三张真图两两为 0.0000 / 0.0200 / 0.0247；而 0.2 会放过「只把外环挪 1 格」这个 **0.195** 的探针——那正是「作者复制一张图微调几格后交付」这种最像真实手误的情况
- [x] **负对照用例**：外环挪 1 格（0.195）必须被 0.15 挡住。这条是判据存在的理由，没有它阈值会被调回 0.2 —— 测试里的同类探针落在 **0.167**（同一道缝里、且比 0.195 更难挡住），**0.195 那个精确值要等票 05 的三张真图才能构造**，见 Answer「冲突三」
- [x] 另一条负对照：同风格只加密度（0.509）必须被挡住 —— 测试里的同类探针是 **0.500**（同一条轨道 + 一条轨道），见 Answer「冲突三」
- [x] **不引入 `style` 字段**：风格由地形判，不自报标签。加字段要改地图的七字段契约，而它表达的是「样式」而不是「差异」
- [x] 阈值作为**常量放在校验器这一侧**，不写进地图 JSON、不进规则集
- [x] 池级违规的诊断文案与单图违规**可区分**：「这张图画错了」vs「这组图凑不齐」
- [x] 目录不存在 / 为空 / 混进非地图文件时的行为有定义且有判失败用例
- [x] **本票不落三张图**：本票只用已有的一张（或构造的最小池）验证判据，真实三图池是下一票的事

## Answer

落在 `apps/cli/src/map-lint/`，与票 03 的单图层同形，只是多了一层**池级**：

- `pool.ts`（新）纯函数「一个地图池 → 一组带定位的违规」。不碰文件系统、不读时钟、不设退出码；连「目录里哪些文件名算地图」都是纯函数（`poolMapFileNames`）。判据 8 条。
- `rules.ts` 只加了三样：池层的 8 个类别名进 `MapLintRule`、把 `rotate` / `orbitOf` / `compareViolations` 导出给池层复用。单图判据一行没改——**旋转与排序各只有一份**，两层各抄一份的话，分叉的表象是一张对称的图被判成不对称。
- `render.ts` 加 `renderPoolViolations`：抬头是「地图池校验」，且每行前面标 `[单图]` / `[池级]`。合并规则（同类并成一行、穷尽 `Record` 标签表）原样沿用。
- `index.ts` 从「收一个文件」改成「收一个目录」（`commands.ts` 里登记的用法本来就是 `modelwar map-lint <maps/>`，是票 03 落的实现与登记表不一致，本票修平）。逐张跑单图判据、整组跑一次池判据，合并后渲染；**形状不过就不跑跨图规则**，形状诊断原样转发 `validateMap`。

**三条判据的阈值与实测依据**（依据原文在 `.scratch/map-pool/proto/metrics.txt` 第 2/4/5/6 节与 `findings.md` 第 3/4 节）：

| 阈值 | 常量 | 依据 |
|---|---|---|
| 池内 ≥ 3 张 | `POOL_MIN_MAP_COUNT` | gdd §4 的三种风格，下限 3；两张图只给出一个差值 |
| 矿路 ≤ 10 格 | `MAX_MINE_ROUTE_CHEBYSHEV` | 采集往返 `2d+20` 线性放大：d=6 → 479、d=8 → 539、**d=10 → 599**（窗口 400–600 内）、**d=11 → 629 顶破 600**。判 `d ≥ 11` 失败 |
| 墙格 Jaccard ≤ 0.15 | `MAX_WALL_JACCARD` | 三张真图两两 0.0000 / 0.0200 / 0.0247；负对照探针「同风格加密度」0.509、「只把外环挪 1 格」**0.195**、挪 2/3/4/6/8 格 0.200/0.205/0.211/0.222/0.308。0.2 落在 0.025 ↔ 0.195 那道缝的外侧，会放过最小结构共享；0.15 对真图留 6 倍余量 |

三个数都是**校验器这一侧的具名常量**，不写进地图 JSON、不进规则集、hld §7.2 的七字段契约不动；`pool-lint.test.ts` 里有一条断言盯着「自报 `style` 标签的地图在装载期就被拒」。

### 三处与票面/代码现状的冲突（按最保守的读法实现，没有自行放宽）

**冲突一：「那组点构成完整四重轨道且数量是 4 的倍数」逐方读法在落库图上恒为假。** 票面（与 spec、gdd §7 同一句）说的是**每方**最近一圈的数量是 4 的倍数。但落库的 `maps/open-clash.json` 里，四方各拿到内圈轨道上的**一个**点：座位 0 的家 (10,10) 到 #12 (6,16) 的 Chebyshev 是 6，次近 #16 (19,19) 是 9，`d_min = 6` 那组点只有 1 个。「每方那组点是完整轨道」会把这张图判失败，而它正是本仓唯一的合规图；照字面实现等于让票 05 落下来的三张图全部 lint 不过。

实现取的是唯一可判的读法：**逐方**判「归属集合恰好等于 `d_min` 那组点 + 无并列」，**跨四方**判「四方最近一圈的并集由完整四重轨道构成、数量是 4 的倍数」。后者的内容就是 FR-1 的四方对等——旋转把座位 0 的矿映成座位 1 的矿，所以归属集合必须在旋转下自洽，这也是「4 的倍数」这句话唯一能落成断言的形式。它不比字面读法松：字面读法在别的布局上（每方各拥有一整条轨道）也过，而它拒绝的是本仓自己的图。

**连带**：gdd §7 点位表那行「每方开局恰好拥有家附近最近的一圈（**数量为 4 的倍数**）」与落库布局矛盾，要么改成「全池归属点数量是 4 的倍数且成完整轨道」，要么去掉括号里的数。这属文档归位，留给票 07（gdd 是规则机制的家），本票没动。

**冲突二：矿路红线的距离该用哪把尺，票面与口头交办不一致。** 票面 checklist 明写「红线的判据是 Chebyshev 距离（与最近一圈同一把尺），不按路径距离——路径距离会让这条线随墙形漂移」；而 spec 的叙事（`家 → 最近自家矿` 被「墙拉过 10 格」、`采集往返 2d+20`）与主线程的口头交办都说的是**绕墙的路径距离**。本票按 checklist 实现（Chebyshev），理由是它给了理由且判据确定；代价与两者的分歧点写在 `pool.ts` 文件头：三张真图的矿路拉伸比是 **1.000**，两种读法在真图上结论完全一致（都是 d=6），分歧只出现在「刻意把矿路绕远」的图上。

补充一条给日后想改的人：路径距离这条读法目前**结构上判不了**——八向移动时「斜着穿不穿墙角」在本仓没有定义（gdd 只写了 Chebyshev 是移动度量），引擎那一侧的移动裁决细则归 hld《engine 概要设计》。要改成 BFS，得先等那条细则落地，否则两条实现会给出不同的红线结论。另外记一条本票发现的事实：在归属合规的图上，矿路距离**恒等于** `d_min`（两者都是「家到最近自家矿」），所以红线对合规图等价于「`d_min ≤ 10`」；它独立起作用的场合只有归属写错的图。

### 修订（后续票）：矿路红线的尺改成八向最短路，最近一圈归属不变

本票 checklist 那句「红线的判据是 Chebyshev 距离（与最近一圈同一把尺）」后来被推翻了：矿路红线的**距离函数**换成**八向 BFS 最短路（墙不可通行）**，常量随之改名 `MAX_MINE_ROUTE_CHEBYSHEV` → `MAX_MINE_ROUTE`；**值 10 一个没动**（值是当初量出来的，尺是当初就该量的那一把）。

**为什么两条判据从此用不同的尺，这是有意的，不是过渡状态。** 「最近一圈归属」量的**声明与「最近」是否一致**，它继续用 Chebyshev 理论距离：改一堵墙就可能改掉某家的开局矿归属，于是地图迭代变成「每加一堵墙重验四条归属」的排雷，而点位与墙本来是两个正交的设计维度。矿路红线量的**走过去要走多少格**，它必须量到墙：理论距离判的是「点位摆得远不远」，判不了「墙把路拉长了」——而后者才是这条红线存在的理由（采集往返 `2d+20`，墙只加长往返）。统一到任何一把都会坏掉一条判据，理由与代价写在 `pool.ts` 文件头那张两行表里，注释里明写「别顺手统一」。

**账实不符是当初就该发现的**：本票冲突二记的那个 10 的依据（枯竭 599 / 629），在原型里是以 **`d = 家到最近自家矿的 BFS 路径`** 代进 `2d+20` 估出来的（`proto/metrics.mjs` 头注、`metrics.txt` §4）——**依据量的是路长，判据却一度量的是坐标差**，两者只在真图上碰巧相等。票 06 的诊断量到三张真图家↔自家矿的八向距离全是 6、与理论距离相同（拉伸比 1.000），所以换尺当前零成本：`modelwar map-lint maps` 仍退出 0，三张真图四方各 6 格。

**一个仍未收口的前置条件（本票冲突二留的那个坑，这里选了边站）**：八向移动「斜着穿不穿墙角」在本仓始终没有定义（hld §4.7 只说「八向按固定方向表」）。这里**照抄原型度量那一次的约定**（斜向一步只判落点格，不额外判两个正交邻格），理由是枯竭估算表只有那一份、换个约定就得重估它；而不是就地发明一条规则。这条依赖写在 `routeDistance` 的头注里：引擎那一侧落地移动细则后若改了这条约定，红线表要跟着重估。

两条新反例（都在 `pool-lint.test.ts`，都先断言 `mapViolations(fixture)` 为空，保证反例只坏在那一条）：

- **漏放那条**：在 x=7 上砌一道从 y=6 到 y=20 的墙（连同旋转伙伴），家 (10,10) 与自家矿 #12 (6,16) 直线只隔 **6 格**（旧判据必然放行），绕过去要 **16 格** → 判失败，文案同时给出「要走 16 格」与「两点只隔 6 格」。
- **误伤那条**：把四方归属的四个矿整体挪到对角线轨道 (16,16)/(47,16)/(47,47)/(16,47)，每方路长 **6 格**，而按曼哈顿算是 **12**（已越过红线 10）→ 零违规。这条钉的是红线是**路长上限、不是两点间距离上限**。

另加一条走不到的反例（矿被墙围死，文案说「没有可走的路」而不是把它当成一条很长的路）：`route ≥ chebyshev` 恒成立，所以换尺**只会多拦不会少拦**，唯一例外就是压根走不通。

**冲突三：两个负对照探针的数值复现不出来，测试里换成了同类探针。** 「外环挪 1 格 = 0.195」依赖廊道分割图的墙形（原型产物），而那三张真图要到票 05 才落库。测试用的是同一道缝里的同类几何：`J = 4/24 ≈ 0.167`（共享一整条轨道、其余不同，与「挪 1 格」同性质，且**比 0.195 更接近阈值、更难挡住**），并断言它落在 `(0.15, 0.2]`——即 0.2 那条线会放过、0.15 挡住；密度那条是 `J = 0.500`（原型 0.509）。票 05 落库后可以把 0.195 那个精确探针补成一条真图回归。

**目录行为的三格**（票面要求「有定义且有判失败用例」）：目录不存在 / 不是一个目录 → stderr + 退出码 1，`cli.test.ts` 有一条 e2e 钉住；目录里混进非 `.json` 文件（`.gitkeep`、`README.md`）→ 跳过，不算地图；跳过之后一张都没有 → 池判据 `pool-empty` 判失败而不是静默通过；某个 `.json` 形状不过 → `validateMap` 拒绝（原有那条缝，入口原样转发）。
