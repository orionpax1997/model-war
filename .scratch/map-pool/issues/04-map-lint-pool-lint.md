# 04: map-lint 池级断言 —— 最近一圈归属、矿路红线、Jaccard 风格

**What to build:** `map-lint` 从「校验一张图」扩到「校验一个地图池」。三条跨图判据在这里落地，每一条都是单图判据**结构上判不了**的：

- **最近一圈资源点的归属**（`handoff` 定为规则不变量，由校验器对地图 JSON 断言）
- **矿路红线**（矿路不许被墙拉过 10 格，否则枯竭顶破 600 tick）
- **Jaccard 风格判据**（三图墙体集合两两相似度上限 0.15）

这三条都带一个「为什么是这个数」的实测依据，凭据是原型阶段的度量。**把数字连同依据一起落进票**，是为了让日后想改阈值的人先看见当初量到了什么。

**Blocked by:** 03（map-lint 单图断言）

**Status:** ready-for-agent

- [ ] 入口接受**一个目录**（地图池）而不是单文件；目录读取是薄壳的活，断言本身仍是纯函数
- [ ] **池内 `size` 一致**：不同尺寸的图进不了池
- [ ] **地图数量满足下限**：池内至少 3 张（规则要求）
- [ ] **最近一圈归属**：对每方主基地算全部资源点的 **Chebyshev 理论距离**，取 `d_min`；该方 `initialOwner` 指向的资源点集合**恰好**等于距离等于 `d_min` 的那组点
- [ ] 那组点**构成一条完整的四重轨道**，且数量是 4 的倍数
- [ ] **并列即判失败**：两组资源轨道到某家的距离相等时报错，**不选一个**。理由是「最近一圈」不唯一时任何自动选择都会把一个设计歧义悄悄定死；报错才是这张图唯一有用的行为。必须有一条等距的反例锁死这一点
- [ ] 距离用 **Chebyshev 理论距离，不用绕墙的路径距离**。理由有两条：度量自洽（规则已把 Chebyshev 定为移动度量）；以及避免把点位不变量耦合到地形设计上——用路径距离的话改一堵墙可能改掉某家的开局矿归属，于是地图迭代变成排雷
- [ ] **矿路红线**：对每方算「家 → 最近自家资源点」的 Chebyshev 距离，**`d ≥ 11` 判失败**。依据是采集往返 `2d + 20` 的线性放大实测：`d=6` → 枯竭 479、`d=8` → 539、`d=10` → 599、**`d=11` → 629 顶破 600**（400–600 是规则给枯竭时点定的窗口）
- [ ] 红线的判据是 **Chebyshev 距离**（与最近一圈同一把尺），不按路径距离——路径距离会让这条线随墙形漂移
- [ ] 边界两侧各有用例：`d = 10` **必过**、`d = 11` **必被拒**
- [ ] **Jaccard 风格判据**：池内任意两张图的墙格集合相似度 `|A∩B| / |A∪B|` **必须 ≤ 0.15**
- [ ] 阈值 **0.15** 附实测依据：三张真图两两为 0.0000 / 0.0200 / 0.0247；而 0.2 会放过「只把外环挪 1 格」这个 **0.195** 的探针——那正是「作者复制一张图微调几格后交付」这种最像真实手误的情况
- [ ] **负对照用例**：外环挪 1 格（0.195）必须被 0.15 挡住。这条是判据存在的理由，没有它阈值会被调回 0.2
- [ ] 另一条负对照：同风格只加密度（0.509）必须被挡住
- [ ] **不引入 `style` 字段**：风格由地形判，不自报标签。加字段要改地图的七字段契约，而它表达的是「样式」而不是「差异」
- [ ] 阈值作为**常量放在校验器这一侧**，不写进地图 JSON、不进规则集
- [ ] 池级违规的诊断文案与单图违规**可区分**：「这张图画错了」vs「这组图凑不齐」
- [ ] 目录不存在 / 为空 / 混进非地图文件时的行为有定义且有判失败用例
- [ ] **本票不落三张图**：本票只用已有的一张（或构造的最小池）验证判据，真实三图池是下一票的事
