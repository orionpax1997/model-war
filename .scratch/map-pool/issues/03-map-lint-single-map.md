# 03: map-lint 单图断言 —— 对称、点位、变体轨道

**What to build:** `modelwar map-lint <path>` 这个子命令第一次真正跑起来：给它一张地图，它读完、过形状校验、过跨字段校验、打印诊断、按退出码结束。**今天它是一个显式的「未实现」占位**——命令名已登记在册，但处理器还没落地，调用它会走「未实现」那条路径。

本票的判据全部是**单张地图自己跟自己比**的：terrain 与 sites 的四重旋转对称、点位不压不重不越界、变体槽位是不是真轨道。池级的三条（`size` 一致、最近一圈归属、矿路红线、Jaccard）是下一张票。

分界是刻意的：**单图能判的判在这里，跨图的判在池级**。理由是失效模式的形状不同——单图违规是「这张图画错了」，池级违规是「这组图凑不齐」，诊断文案与退出码的读法都该分开。

**Blocked by:** 01（变体槽位形状定稿）、02（第一张地图落库）

**Status:** ready-for-agent

- [ ] `map-lint` 子命令的处理器落地并**接上登记表**：命令不再走「未实现」那条路径。登记表里它已登记为本应用自己的模块（不挂在真源包上），本票兑现那一格
- [ ] 断言是**纯函数**：「一份地图数据 → 一组带定位的违规」，不读文件系统、不读时钟、不设退出码。读目录与设退出码是入口那层薄壳的活——沿用仓库既有的「纯规则 / 目录薄壳 / 退出码」三层形状
- [ ] **terrain 四重旋转对称**：绕中心 90° 旋转后与自身逐格相同。terrain 与 sites 是**两条独立断言**（不同代码路径，各配一条能被弄红的反例）
- [ ] **sites 四重旋转对称**：点位集合绕中心 90° 旋转后与自身相同
- [ ] **点位不重叠**：任意两个点位不共格
- [ ] **点位不在墙上**：点位的每一格都是平原
- [ ] **点位不越界**：坐标落在 `size` 范围内
- [ ] **terrain 自洽**：行数等于 `size`、每行长度等于 `size`、只含 `.` 与 `#`（形状层管字符集，跨字段管行长与行数——JSON Schema 表达不了后者）
- [ ] **变体槽位是完整轨道**：每条槽位恰好 4 个坐标对，且这 4 格恰是其中某格的旋转轨道。长度不足 4 的、非轨道的各有反例
- [ ] **变体槽位不压点位及其八邻域**（这是槽位那层独有的卫生规则：墙格压住点位或起始单位会改变点位可达性与初始条件对称性）
- [ ] **不压起始单位**：变体槽位不覆盖 `spawnUnits` 落到的那几格
- [ ] 违规**带定位**：每条带出是哪个字段、哪一格或哪一行。不定位的违规等于让人回去肉眼数 4096 格
- [ ] 违规**分两层**：机器层是结构化数组、面向模型层是渲染文本，且面向模型层**对同类错误合并成一行**（沿用已落的读入端诊断纪律）
- [ ] 退出码 0/1，**标准输出是全部对外契约**；参数缺失按退出码 1 + 用法处理，不悄悄取默认值
- [ ] **本票不引入任何池级判据**：`size` 一致、最近一圈归属、矿路红线、Jaccard 一律不在范围
- [ ] **每条断言都有一个能被弄红的反例**，且反例在测试里
- [ ] **不测子命令的退出码**：断言落在纯函数上（沿用仓库既有先例——薄壳不单独测）
- [ ] **同源断言**：改真源包里的变体槽位类型与 schema，校验器行为随之改变——证明它一个形状都不自己存
- [ ] 合规地图零违规：原型那张开阔对攻图过本票全部单图判据
