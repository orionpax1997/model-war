# 02: 第一张地图落库（开阔对攻图）+ 原型分支合流

**What to build:** `maps/` 目录里出现第一张真实地图——**开阔对攻图**，64×64、28 个点位、四重旋转对称——它能通过读入端的形状校验而**还不要求任何跨字段校验**（那是下一张票的事）。本票同时把原型分支的产物合进 `main`，因为后面三张图的墙形与度量都在那条分支上，不合流它们就只有一个分支能读到。

开阔对攻图是三张里最该先落的一张：它的墙最少（132 格 / 3.2%）且最分散，抄错了一眼能看出来；而且它的定位是**无地形偏置的基线图**（原型实测点位对路径拉伸 mean 1.00、最绕的一对 1.14），三图池里需要一张这样的对照。

## Answer

原型分支 `prototype/map-pool-terrain` 以 merge commit `176cc66` 并入本 feature 分支（票面写的是「并入 main」，实际走的是「先进 feature 分支、经 PR 合入 main」——本仓的规矩，PR 是主干的唯一入口）。合流前工作树干净，自动合并无冲突：`spec.md` 取主干那一份（原型分支上的是切票前的旧稿）。

三张图里的第一张。选它是因为墙最少（132 格 / 3.2%）且最分散，抄错了一眼能看出来；而且它的定位是**无地形偏置的基线图**（原型实测点位对路径拉伸 mean 1.00）。

- terrain 是**抄**自 `.scratch/map-pool/proto/terrain-open.txt`（剥掉 3 行注释头），不是重新生成或手写。落库后从那份纯文本**独立读回复核**：四重旋转违例 0 格、墙 132 格。
- 28 个点位（4 主 + 8 中立 + 16 资源）沿用标定环夹具 `center-fortress@64` 的展开值。开局归属用 `initialOwner`，中立写 `null`（不引入桩里的 `-1`）。
- 「家附近最近一圈」按 Chebyshev 理论距离判，**实测**而非照抄：四家 `d_min = 6`、次近 9、第三 16，**无并列**。
- `variantSlots` 是**静态候选轨道清单**（8 条 / 32 格 / 全图 0.781%），不是某个种子上实际填上的那几条。实测 0 格压点位八邻域、0 格压在墙上。
- `spawnUnits` 每方 2 个 `worker`，偏移 `(1,0)` / `(0,1)`（票面口径）。
- 落库后由**机器**确认通过（`validateMap` 的 ajv 层 + 版本下界那层），不是人眼。

**一条票面自身的问题，留给后续票解决**：本票最后一条要求「每方 `d_min` 那组点构成一条完整四重轨道」。落库布局是**每方各拿内圈轨道上的一个点**（四方并起来才是完整轨道），所以按字面逐方读这条恒为假。票 04 已按「逐方严格判归属 == `d_min` 组 + 无并列，轨道那条判在跨四方那层」实现，并在它的 `## Answer` 里记了这个偏差——它的内容是 FR-1 的**四方对等**，而那才是可判的一句。
