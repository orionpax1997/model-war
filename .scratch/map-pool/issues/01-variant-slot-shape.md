# 01: 变体槽位形状定稿（真源类型 + JSON Schema + 校验骨架）

**What to build:** 地图 JSON 的第七个字段 `variantSlots` 从「任意 JSON 值」收成一个**可判的形状**：一条完整四重旋转轨道的 4 个坐标对。今天它是 `packages/schema` 里唯一硬写着「待回填」的东西，类型侧取 `JsonValue`、schema 侧是一个不带任何约束的 `items: {}`，两处的说明都写着「等地图图定稿后回填」。这个 feature 的图已定稿，触发条件成熟，本票就是那次回填。

本票是**纯机械活**：三处一次改完，不碰任何地图内容，不写任何校验逻辑。收窄形状的理由是把「四重对称」这条不变量从运行时断言挪进类型层——写成 4 元组之后，校验器要判的退化成「长度是不是 4、这四个是不是某个点的轨道」，而后者在类型层面就几乎已经保证了。

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] 变体槽位的类型是一个 4 元组，每元是坐标对；`variantSlots` 本身仍是数组。**不是**代表元坐标（那会把旋转塞回引擎，多一层间接且校验器仍要重算轨道），**不是**带语义字段的对象（现在没有语义可填）
- [x] 类型上表达「一个槽位就是一条完整轨道」：要么用定长元组，要么用带自说明的类型别名——**取哪个要有理由**，理由写进该类型的头注
- [x] JSON Schema 侧同步收紧：槽位元素的 `items` 从空 schema 变成带 `minItems: 4` / `maxItems: 4` 与坐标对形状的 schema
- [x] 两处 schema 的 `description` 里**「待回填」「待 A 节点」「尚未定稿」「过渡形状」四类措辞全部退役**，换成新形状的一句话说明
- [x] 类型头注里那段「写窄一点就是替地图图做决定，所以现在取 `JsonValue`」的推理**保留为历史注记并标明已回填**——删掉它，后来者会重新论证一遍同一个问题
- [x] 「形状与类型由同一次书写产生」这条纪律不破：类型与 schema 仍同文件，两处贴在一起
- [x] **同源断言**：schema 的必填键集合等于类型的键联合（沿用真源包已落的那条类型级断言）；收紧后它继续成立
- [x] **双过 fixture**：同一组地图 fixture 既过 TypeScript 类型又过 ajv；收紧后旧 fixture 全部通过、新形状的反例被拒
- [x] 地图的七字段契约**不动**：不新增字段、不放宽 `additionalProperties: false`、`size` 仍是必填的整数
- [x] 类型层面**不含**「槽位不得压点位及其八邻域」这条判据——那要跨字段，留给后续的校验票
- [x] 真源包的导出面不变：不对外多暴露一个名字

## Answer

`MapVariantSlot` 从 `JsonValue` 收成**定长 4 元组**，每元是坐标对；`variantSlots` 本身仍是数组。JSON Schema 同步收成 `minItems: 4 / maxItems: 4` + 坐标对形状（非负整数）。

**取定长元组而不是另外两条路**，理由写在该类型的头注里：代表元坐标会把旋转塞回引擎、多一层间接，而校验器仍要重算轨道；带语义字段的对象则要求现在还没有的语义。另外两条被否掉的取法也各带了一句理由，留在头注里免得后来人重新论证一遍。

「一个槽位就是一条完整轨道」这条不变量因此**从运行时断言挪进了类型层**——构造不出来的数据构造不出来。

- 类型与 schema 仍同文件、贴在一起，「形状与类型由同一次书写产生」没破。
- **同源断言加了一条新的**：类型元组长度 ≡ schema 的 `minItems` ≡ `maxItems`。这一条对定长形状尤其要紧——「加一个键」有既有断言兜着，**「改一个数字」没有**。做过 mutation check：把 `minItems` 改成 3，`tsc -b` 确实变红。
- 七字段契约不动，`additionalProperties: false` 不动，导出面不加新名字（坐标对别名是模块内的）。
- 类型层面**不含**「槽位不得压点位及其八邻域」——那要跨字段，归票 03/04。
- 「写窄一点就是替地图图做决定，所以现在取 `JsonValue`」那段推理**保留为历史注记并标明已回填**。

四类退役措辞（`待回填` / `待 A 节点` / `尚未定稿` / `过渡形状`）在两处 `description` 里已零残留（grep 验过）。
