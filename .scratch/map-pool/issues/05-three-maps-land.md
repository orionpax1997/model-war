# 05: 三张地图落库 —— 开阔对攻图 / 廊道分割图 / 中心要塞图

**What to build:** `maps/` 从一张图变成**三张风格迥异的地图**，规则要求的三种风格全部到位，池级校验全绿。这是整个 feature 的交付面：三张图 + 一套把它们守住的东西，构成后续对局内核的初始条件来源。

三张图的墙形已经在原型阶段画完、量过、目视过。本票是**把它们落库**并让池级判据逐条过关——不是重新设计地图。原型实测的终稿数据是：三图墙格 132 / 200 / 72（密度 3.2% / 4.9% / 1.8%），四重对称违例 0 格，全部点位与起始位在全图连通。

**Blocked by:** 04（map-lint 池级断言）

**Status:** ready-for-agent

- [ ] `maps/` 下共三张地图，除 `.gitkeep` 外不多不少：**开阔对攻图**、**廊道分割图**、**中心要塞图**
- [ ] 三张图**共用同一套点位布局**：4 主 + 8 中立（边路 4 + 中心 2×2 共 4）+ 16 资源（四条轨道）。风格差异 **100% 由墙承载**，地图池在「开局布局」这个维度上零多样性——这是保住标定环那 1336 场证据的代价与收益，换来的是 `resourcePerSite=200` 的标定依据（「全图 16 点 = 3200」）不动
- [ ] 三图的 `size` 都是 64；`terrain` 各 64 行 × 64 字符
- [ ] 每张图的四重对称**从落库的纯文本独立读回复核**，违例 0 格
- [ ] 三张图的墙形**抄自原型产物**（原型分支已在本 feature 的前一张票合进主干），不重新生成、不手绘
- [ ] **开阔对攻图**：墙少、分散、不成线（象限里 12 撮散墙 + 2 撮站在矿→中心对角线上的小墙），132 格 / 3.2%
- [ ] **廊道分割图**：两层同心方环把战场切成「外缘带 / 中间带 / 中心盒」三条同心带；外环开口 3 格、内环开口 5 格，均偏心风车式排布。200 格 / 4.9%
- [ ] **中心要塞图**：中心紧环盒（4 个 2 格宽正门）+ 四角 L 碉堡线 + 每家角落两小撮幕墙。72 格 / 1.8%
- [ ] **三张图的中心都不放墙**（开阔图尤其）。这是原型阶段的实际观感结论：开阔图的 2×2 中心中立基地块读作「地图正中的争夺目标」而不是「主堡」，因为要塞语义完全由墙给出
- [ ] 池级校验**全绿**：池内 `size` 一致、地图数达下限、最近一圈归属成立（每方 `d_min` = 6、无并列）、矿路 `d` 不超过 10、三图两两 Jaccard ≤ 0.15
- [ ] 每张图内**全部点位与起始位在全图连通**（原型实测可达格 3964 / 3896 / 4024）
- [ ] 三张图的 `variantSlots` 都是**静态候选轨道清单**，形状是 01 定稿的那个；候选不压点位及其八邻域
- [ ] 地形 wall 格与 `variantSlots` 候选**不重叠**：候选是「种子可以填的地方」，已经画了墙的格子不能同时是候选
- [ ] **矿路红线在每张图上都成立**：家门到自家矿那一小片留空，矿路 `d = 6`
- [ ] 本票**不跑桩**、不裁决变体是否参与策略——那是下一票的事
- [ ] 三张图各自可被读入端独立装载（不依赖另外两张在场）
