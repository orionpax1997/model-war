# 跨边界调用形态对比:runtime bundle vs 逐函数注入(prototype)

Type: prototype
Status: resolved
Blocked by: 02

## Question

hld §12 #4:runtime bundle(每 tick 两次跨宿主边界)是否真比逐函数注入(每次 API 调用跨边界)显著省时?基于票「沙箱行为实测 harness」的环境与单次开销数据,做一个粗糙对比原型:不同快照粒度 × 不同 API 调用密度(查询为主 / action 为主 / 寻路轰炸)两形态的耗时曲线。

给出可反应的数字与建议:**保留 hld §4.5 的 bundle 设计,还是回退逐函数注入**(回退路径见 §2.2.2)。原型是 throwaway,链接为资产;结论只回答"哪个形态进 v0",bundle 的打包方式细节留给实现期。

## Answer

原型:**[prototype-bundle-vs-injection.html](../prototype-bundle-vs-injection.html)**(单文件,双击即开;分支假设与口径见页首)。形态取 prototype skill 的 LOGIC 分支——页内一个可整体搬出的纯函数成本模型 + 自由调节 + 四个引导走查格(查询为主 / action 为主 / 寻路轰炸 / 边缘开局);模型标定自票「沙箱行为实测 harness」FINDINGS §6 实测单价,全部展示数字已与模型逐格核对(线性外推,非重新实测)。

**定案(已裁决):保留 hld §4.5 的 runtime bundle 设计,不回退逐函数注入**(§2.2.2 回退路径照旧留档)。

数字(每 tick 跨边界耗时;交叉点 = 注入追平 bundle 所需调用数/tick):

| 负载格 | 快照 | 调用/tick | bundle | 注入 | 对比 / 交叉点 |
|---|---|---|---|---|---|
| 边缘:开局小图侦察 | 2KB | 23 | 20.5µs | 20.3µs | 打平 / ≈24 |
| 查询为主:遍历 200 对象 | 16KB | 405 | 56µs | 345µs | bundle 省 6× / ≈66 |
| 同上,大地图 | 64KB | 405 | 179µs | 345µs | bundle 省 2× / ≈210 |
| action 为主:满编 50 单位 | 32KB | 150 | 103µs | 128µs | bundle 省 1.25×(全图最贴近)/ ≈120 |
| 寻路轰炸 2000 次 | 8KB | 2040 | 37µs | 1735µs | bundle 省 47× / ≈43 |
| 寻路轰炸 1 万次(实测口径) | 8KB | 10040 | 37µs | 8535µs | bundle 省 233×(M6 实测 1 万次 = 10.7ms,同量级)|

判定要点:

1. 交叉点 ≈24–210 次/tick 随快照粒度上移;现实脚本密度(遍历对象/逐单位调度 = 数百次/tick)普遍越线,bundle 省 1.25–6×;滥用区 47–233×。
2. **优劣不对称是关键论据**:注入只在交叉点以下的稀疏区小赢,差额 ≲0.25ms/四方 tick(对 NFR-3 无感);稠密/滥用区大输且上不封顶(注入成本 = 0.85µs × 调用数,随玩家野心线性涨)。bundle 边界成本固定,性能面与 §5.3 API 计数判罚面解耦。
3. 实测 0.85µs/次是「数字返回」的最便宜注入口径,对象/数组返回更贵 → 注入实际曲线只会更差。

盲区(不在对比口径,标定 NFR-3 时须补,详见页尾):host 侧快照序列化/深拷贝成本未计(bundle 形态每 tick 每方一次);bundle 形态的查询/`findPath` 在 VM 内跑(QuickJS 慢于 V8),寻路轰炸的成本从边界转移到 VM 计算,由 §4.7/§5.3 既定预算裁决承接,不属形态对比;模型为 9+2 个实测点的线性外推(µs 级噪声 ±3–4%)。

已裁决:进 v0 形态 = runtime bundle。同步落点:map「Decisions so far」一行 gist;hld §4.5 记形态定案、§12 #4 关闭(打包方式留实现期)、§2.2.2 指针改写。
