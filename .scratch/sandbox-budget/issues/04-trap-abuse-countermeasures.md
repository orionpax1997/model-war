# WASM trap 滥用的约束设计(grilling)

Type: grilling
Status: resolved
Blocked by: 02

## Question

hld §12 #8:反复触发深递归 WASM trap 会重建该方 VM、清零模块级记忆,而只付 `exceptionTicks` 计数——这会不会变成**可用战术**(故意用 trap 换一次免费重置,或借重建规避某些后果)?基于票「沙箱行为实测 harness」的失控/重建数据做滥用分析:

1. 收益面到底是什么:清记忆换什么?规避什么?在 gdd 规则下真有可利用面吗?
2. `exceptionTickLimit` 是否足以约束这种滥用(量级上够不够)?
3. 若不足,给 VM 重建加什么代价:候选有"重建加权计异常 tick"、"重建即判负出局"、"记忆冻结保留(重建不清零)"、"重建次数独立限额"——或接受现状并在规则文档披露。

结论落进裁决表的修改建议(动不动 hld §5.2),供票「定案:沙箱选型与预算裁决形态」汇总裁决。

## Answer

**滥用不成立,无需加代价机制;hld §5.2 裁决表改写(动)。** 依据票「沙箱行为实测 harness」的实测:深递归栈溢出是 host `RangeError`、VM 可续用无需重建(spike [FINDINGS §3](../spike/FINDINGS.md#3-失控行为死循环深递归重建))——"trap→重建→记忆清零"的前提已瓦解。

**滥用分析结论(收益面 = 无)**:模块级记忆是选手自己的计算状态,脚本**随时可以合法自行清空/重置(自抹)**,零代价;trap 换重建不提供任何自抹做不到的能力,且 `exceptionTicks` 由 JSONL 续算、intent 一律作废,后果一个逃不掉。自抹唯一做不到的是归还 heap 空间(清碎片/降 `memoryUsage`),但那只有在**强制**重建语义下才是可滥用面——强制重建已随前提瓦解取消。因此"trap 换免费重置/借重建规避后果"无独立收益面;加权计异常/判负/记忆冻结/重建次数限额四个候选**全部作废**。

**`exceptionTickLimit` 足**(结构性):滥用面不存在后它只需兜住惯性失控/故障的脚本(深递归滥用已归普通异常轨)。§5.2 不加新机制;标定注脚(供预算参数标定图):"标定目标是'偶发异常的脚本不出局、惯性失控的脚本出局',防滥用不靠它。"

### hld 裁决表修改建议(供票 05 汇总裁决,文档改动在 05 定案后执行)

**A. §5.2 裁决表改写**:

| 情形 | 处理 | 确定性 |
|---|---|---|
| `loop()` 抛异常(host 侧异常同此行:含内存超限转成的 JS 异常、深递归栈溢出的 host `RangeError`) | 本 tick 该方 intents 置空(单位原地待命);`exceptionTicks++`;达 ruleset 的 exceptionTickLimit → 判负出局(点位回归中立)。**VM 续用、记忆保留** | ✅ 计数可复现 |
| 中断超限(`interruptHandler` 返回 true) | 同上;VM 中断后仍可用,无需重建 | ✅ |
| WASM trap(引擎故障级;**脚本栈溢出不属此类**,实测为 host `RangeError`) | 视同该 tick 异常计一次(同第一行)+ **防御性重建**该方 VM(重载脚本,模块级记忆清零);trap 事件写入回放 events 流与报告,夜间扫描复核——同一回放不复现则事后按 §8.4 `engine-crash` 同轨处理 | ✅ 判罚可复现;复核在扫描层 |
| 内存超限(`memoryLimit`) | 按第一行处理(可捕获,VM 继续可用);触发情况在报告中披露——guest 可吞该异常,host 检测兜底另票(「OOM 异常被 guest 吞掉的 host 检测兜底」) | ✅ |
| 越权调用(未定义 action / 访问已删除的宿主桥 / 访问未暴露字段) | 视同 `loop()` 抛异常 | ✅ |

表下注脚改为:**"异常/超预算不清记忆、不重建 VM;仅 WASM trap 的防御性重建会清记忆。`exceptionTicks` 随 JSONL 持久化,VM 中断或重建后由持久化值续算,不清零。"**

**B. §5.0 两处措辞修正**:
- "崩溃语义"条:"死循环/深递归表现为中断异常或 WASM trap" → **"死循环由中断计数截停;深递归栈溢出表现为 host 侧 `RangeError`(VM 可续用);WASM trap 仅剩引擎故障级可能"**;
- "代价"条:"深递归默认不设栈上限……表现为 WASM trap 而非可捕获异常" → **"quickjs-wasi 有 `maxStackSize` 选项,v0 不启用——启用会把溢出变成 guest 可捕获异常、可被脚本吞掉;不启用则溢出为 host `RangeError`,host 必见"**。

**C. gdd《异常与出局》补两行**:
- 首条扩一句:"……不影响其他三方与引擎" → 补 **";VM 与跨 tick 记忆保留"**;
- 新增一条:**"仅引擎级故障(WASM trap)会重建该方 VM,重建后模块级记忆清零;异常计数由持久化值续算,不受重建影响。"**

**D. 确认项(供票 05)**:`exceptionTickLimit` **足**,§5.2 不加新机制(标定注脚见上)。WASI 冻结三件套、`exceptionTicks` 续算机制维持现状(hld §5.1/§5.2 原文,实测支持)。
