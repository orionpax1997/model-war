===== Section 4: gcThreshold semantics =====
  4a. gcThreshold-get on fresh VM (no setter): 262144  (256KB)
  4b. set Infinity → get: 0 (is Infinity? false)  — note: WASM truncates Infinity to 0
  4c. set 0 → get: 0  (docs say 0 disables auto-GC)
  4d. set 1<<30 (1GB) → get: 1073741824
  4e. threshold progression on a fresh 8MB-limit VM:
      fresh:                       gcThreshold=262144 (256KB)
      after ~2MB alloc:            gcThreshold=3128088 (3055KB), memoryUsedSize=2078289
      after manual runGC():        gcThreshold=3128088 (3055KB), memoryUsedSize=2078289
      → threshold advanced during alloc (auto-GC fired). After manual runGC, threshold unchanged.
      → manually setting gcThreshold does not 'stick' across auto-GC cycles; the runtime
        rewrites it to (typically) 1.5× of post-GC mallocSize. To truly disable auto-GC,
        set gcThreshold = 0 (per docs) — set Infinity truncates to 0 anyway (4b).
  4f. under gcThreshold=Infinity, drop two large refs (plain, no cycles):
      before: mallocSize=75128, memoryUsedSize=64098
      after:  mallocSize=75200, memoryUsedSize=64154
      Δ      : mallocSize=72, memoryUsedSize=56
      → refcount-based free fires regardless of threshold; ~4.8MB freed,
        leaving only the script overhead (~5KB).
  4g. under gcThreshold=Infinity, allocate 500 * 8KB = 4MB anchored arrays:
      baseline:       mallocSize=75128, memoryUsedSize=64098
      after alloc:    mallocSize=4387084, memoryUsedSize=4092288
      Δ (raw allocs): mallocSize=4311956, memoryUsedSize=4028190
      → no auto-GC fired (would have shown as mallocSize dip mid-loop);
        malloc_size grew monotonically by exactly the alloc cost.
