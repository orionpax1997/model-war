# 04: 生成物漂移检查

**What to build:** 改了真源不重跑生成 → 全量门禁变红;重跑 → 变绿;生成物被删、或新增生成物没进版本库 → 同样变红。检查挂在全量门禁末尾,不进快门禁。实现是两刀而不是一道裸的 `git diff`:一道按生成物路径限定,一道按生成物路径查状态。

**Blocked by:** 03 生成器与允许名单退役

**Status:** ready-for-agent

- [ ] 漂移检查挂在全量门禁末尾;**不进快门禁**(它需要一次构建,而带类型感知那道门禁里已经有)
- [ ] 第一刀:按**生成物路径限定**的差异检查,非零退出。捕捉「改了没提交」
- [ ] 第二刀:按生成物路径的状态检查,**未跟踪的生成物算失败**。捕捉「新增生成物没进版本库」——裸的差异检查看不见未跟踪文件,而本 feature 的第一件生成物正是新增的
- [ ] 误报防护:工作树里有**与生成物无关**的未提交内容时,检查不报它(有验证用例)
- [ ] 反例四条,各验一次后还原:①改真源不重跑;②生成物被删;③生成物内容被手改;④新增一件生成物但未提交
- [ ] 检查自测进门禁自测工程,**不混进全量门禁**(否则 `check → 自测 → check` 无限套娃)
- [ ] 路径清单来自生成物注册表本身,不另存一份——注册表加一件生成物时检查自动跟着覆盖
