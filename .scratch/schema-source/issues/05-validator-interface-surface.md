# 05: D 的接口面:桥前缀、禁列、沙箱 API 名表

**What to build:** 宿主桥前缀、禁列全局名、沙箱注入的 API 符号表(空位)等**名单类**数据经 03 立好的同一分发机制交付。静态校验器一侧只留读取点、不实现任何规则——下一个碰它的人(D)接手时,一个名字都不用自己存。顺带补上 hld §3.2 自述的那个依赖门禁缺口:「声明即依赖」在工具包里目前只靠自觉。

**Blocked by:** 03 生成器与允许名单退役

**Status:** ready-for-agent

- [ ] 宿主桥前缀(`__`)作为真源包的名单类数据交付,不散落在别处
- [ ] 禁列全局名(`Date` / `Math.random` / `performance` / `queueMicrotask`)作为名单类数据交付
- [ ] 沙箱注入的 API 符号表在真源包里**位置留着且显式标「待沙箱执行器(G)回填」**,当前为空;它与 01 的变体槽位是同一条纪律
- [ ] 三者与 03 的内置全局白名单走**同一套分发机制**,不多开一条通道
- [ ] 静态校验器侧只留读取点,**不实现任何规则**(禁 `export`/`import`、禁 `__*` 前缀、禁列、脚本体积上限都属于 D)
- [ ] 脚本体积上限**不进名单**:它是数值,取值在规则集文件里
- [ ] 补上工具包的依赖门禁缺口:「声明即依赖」在工具包里有机器保证,不再只靠自觉(自举检查,或把它纳入一条会产出 JS 的编译路径,取其一)
- [ ] 该缺口有一个**能被弄红的反例**:在工具包里 import 一个未声明的依赖,检查必须非零退出
- [ ] 工具包刻意留在依赖门禁巡航范围之外这件事(它以源码形态执行)写进代码头注,不留成看起来像疏漏的样子
