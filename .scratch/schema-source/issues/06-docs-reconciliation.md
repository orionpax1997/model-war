### 与 spec 票面的一处出入(不在本票的账上,已按实际落地写)

- **真源包实际是 21 个键(13 定稿 + 8 预算),不是票面与 spec 写的 22。** spec 把「内存软阈」当预算键数了一遍,
  而 spec 自己的规则说它是 `0.8 × memoryTickCeiling` 的纯推导展示项、**不入键清单**(handoff §2.1 表的 9 行里,
  那一行自己标着「推导项,入表不入 schema」)。**本票按 21 写**(hld §7.1),并**没有单方面改 spec 与 DAG 节点表**——
  `spec.md` 的「22 键 / 9 个预算键」与 `docs/diagrams/v0-milestone-dag.md` 的 E / K 两行都还写着旧数,那是主 agent 的账。
  真源包侧(`ruleset-keys.ts` 头注、`ruleset.test.ts`)已把 21 的来历记清。

### 报告给主 agent 的三处新发现(本票未改代码)

1. **`hld §2.2.5` 原文把「读入端强制校验」挂在 FR-10 AC2 名下,而 srs FR-10 AC2 实际写的是「文档带版本号、错配时 runner 拒跑」。**
   spec 与 ADR-0003 也沿用了这个错挂。需求条目的家是 srs,本票按「修矛盾的一方」只改了 hld 的引用(漂移检查那一条改指 AC1,
   并在正文写明「版本错配与读入端强制校验**都按尚未兑现记**」)。**要不要给 srs 补一条独立的 AC,是需求侧的账**。
2. **`packages/tools/package.json` 的 `description` 里写着「由 `check:tools-deps` 兜住」,而根脚本的真名是 `check:declared-deps`**(05 票落地后留下的旧名)。属代码/清单漂移,本票不改代码。
3. **票面说「`hld.md` 在 oxfmt 的检查范围内」,实测不在**:根 `fmt` 脚本的路径清单是 `apps` + `packages` + 9 个根配置文件
(oxfmt 报「77 files」,而 `git ls-files apps packages` 恰是 68),`docs/` 一个文件都不在。所以本票改完 `hld.md` 后
`pnpm run fmt` 仍报「All matched files use the correct format」,那**不能**当作 hld 已排版过的证据。
4. **`packages/schema/src/ruleset.ts` 的头注仍写「9 个预算键在 M1 阶段取 `0`」**,与同包 `ruleset-keys.ts` 的 8 个不一致。属代码注释漂移,本票不改代码。
