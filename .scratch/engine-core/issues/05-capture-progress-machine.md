# 05: 占领——进度机

**What to build:** 占领进度机在真引擎上跑起来:单位站到可占领点位格上即驱动占领,累积到阈值后所有权易主、进度清零。四条并列的规则一并落地——**全兵种占领速度一致**（农民不加速）、**转轨重计无侵蚀**、**无人站立进度保留不动不衰减**、**同阵营驻守保留不动**。

**堵点战术是这一机制的战术面**:己方单位站在自家点位上可直接物理阻止敌方踩点,对方需要先消灭那个单位（单位可被攻击,基地不可）。这条让「经济死亡 ≠ 出局」在引擎里成为事实——占领不需要资源,所以没有农民的玩家仍可用残兵抢点、阻断、拿下胜利。

**两点写在这里是因为实现时最容易搞反**:一是**全兵种一致**这条与「农民是最便宜的兵种」相抵,农民因此也是最便宜的占领/堵点单位,那是 gdd 明写的设计张力,必须靠基准脚本验,不是靠本票的判据;二是「**无人站立不衰减**」是一条**保留**规则而不是**清零**规则,两者的差别在长时间僵持下极大。

决策依据：`.scratch/engine-core/spec.md`《结算管线》事件落位表,`docs/gdd.md` §3.2 占领机制。

**Blocked by:** 04（移动——轮转优先与占位基准）

**Status:** ready-for-agent

- [ ] 点位持有属主、进度属主与进度三样;属主与进度属主可为中立
- [ ] 点位是**单格**,同一时刻**最多一个驱动者**（站在点位格上的单位所属方）。单格单单位这条要有用例——两方同 tick 站进同一格时,占位基准（移动那张票）先判掉一个
- [ ] 驱动者与属主同阵营:占领进度**保留不动**
- [ ] 驱动者与属主不同:进度属主不同则**转轨重计**（进度属主换成新驱动者、进度置一,无侵蚀）；进度属主相同则进度加一
- [ ] 无人站立:进度**保留不动,不衰减**。用例钉住「一整局无人站立的点位进度一动不动」
- [ ] 累积达阈值后所有权易主、**进度清零**
- [ ] **全兵种占领速度一致**:农民不加速。这条要有一条用例钉住（四个兵种同样的驻留 tick 数产出同样的进度），否则后来者会「顺手」给农民加速
- [ ] 堵点成立:己方单位站自家点位上，敌方同 tick 站上去不推进度（它被占位基准判掉,或推进到零）；要弄清它必须先消灭那个单位
- [ ] 事件 `site-captured` 进**第四步**的槽位,按对象数值 id 升序定序
- [ ] 阈值从规则集装载,**不在代码里**
- [ ] 每条判据各有一个能被弄红的反例：把「无人站立」改成清零 → 衰减用例红;把「转轨重计」改成沿用进度 → 侵蚀用例红;给农民加一个加速系数 → 全兵种一致用例红
- [ ] 注释里写明**这一格是占领进度机的家**,而面向模型的契约面那一节尚未落库——下一轮补那节散文时以规则侧那一节为准,不在契约面另立一套
