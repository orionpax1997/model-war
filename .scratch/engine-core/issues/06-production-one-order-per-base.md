# 06: 生产——每基地一条队列

**What to build:** `spawnUnit` 这条**玩家级**意图在真引擎上落地:下单即占住那条产线,出兵格空出来才续出那一步。四条并列的规则一并落地——**一条产线一次只有一个订单**、**产线有订单时重复下单静默丢弃**、**出兵格被任意单位占据则挂起等待**、**基地易主时那条队列取消并全额退款给原主**。

**两处最容易写错的地方写在这里**:

**一、没有「产线忙」这个错误码。** 重复下单是**静默丢弃**:不扣款、不计异常、队列不变。错误码表里本来就没有那一码,也不要新加——脚本的正确写法是先读点位上的产线订单、为空才下单,不必自己记队列,也不必靠重复下单去试探队列状态。

**二、产线订单在状态模型里只有一份数据源,在点位上。** 脚本读到的就是它,不是一张独立队列表。这条解掉了架构文档与契约面之间那处真冲突(契约面已经宣告「字段名在这段声明期间不改」),而投影回来那件事会一直等下去。

**下单的校验顺序是资金先、扣款后。** 资金不足则这一单**无效**,不占产线队列、**不扣款**,资金一个不少地留着。

决策依据：`.scratch/engine-core/spec.md`《状态模型》《结算管线》事件落位表,`docs/gdd.md` §5 经济与生产。

**Blocked by:** 05（占领——进度机）——基地易主那条路径要靠易主才能观察到

**Status:** ready-for-agent

- [ ] `spawnUnit` 是**玩家级**意图,不参与单位级分组（其余五条意图都带单位 id,这一条不带）——用例钉住它不被「每单位只留最后一个」那条规则处理
- [ ] 下单**先校验资金、校验过才扣款**。资金不足 → 无效,不占队列、不扣款
- [ ] 下单即占住那条产线,一直占到出兵格空出来续出那一步;一条产线**一次只有一个订单**
- [ ] 产线已有订单时重复下单:**静默丢弃**——不扣款、不计异常、队列不变、**不抛错误码**。用例钉住「错误码表里没有产线忙这一码」这一事实（换个断言方式：新错误码一出现就红）
- [ ] 每 tick 生产推进：剩余 tick 减一,归零出兵
- [ ] **出兵格被任意单位占据（含己方单位）则该队列挂起等待**,不跳过、不换格
- [ ] **基地易主时**该基地队列取消并**全额退款给原主**;**原主已淘汰时不退款**
- [ ] 退款与花费**全整数运算**,走玩家资源池
- [ ] 产线订单在状态模型里**只有一份数据源,在点位上**;脚本读到的那一栏与它逐字段一致（同一条形状,不是投影）
- [ ] 契约面「先读产线、为空才下单」那段在本票之后**仍然是散文承诺**——形状与投影那一节的改写归文档对账那张票,本票只保证代码这一侧的形状对
- [ ] 每条判据各有一个能被弄红的反例：把校验与扣款调换 → 资金不足用例红;把「被占则挂起」改成「换格出兵」→ 挂起用例红;把易主退款改成不退 → 退款用例红
