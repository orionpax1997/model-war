# 03: 探针骨架与两个量测探针

**What to build:** 一条显式命令在真引擎上跑完探针、把读数落成文件(带**真的**沙箱运行时哈希);两个量测探针各补一个数——**封装顶**与**装 runtime bundle 之后的存活堆基线**。

**骨架从一次性 prototype 长出来,不另起一份:** 它已经解过「逐 tick 镜像执行器的每 tick 次序、不改任何判定、直接当座位执行器塞进四人对局」这道题,并且记下两个必须继承的坑:①计数器回调只在构造 VM 时装上,所以探针要拿事件读数就必须显式给事件上限一个极大值;②wasm 侧的计数器跨调用不清零、有相位残留,所以读数必须按「格数」记,不能按事件数记。

**这两个数为什么值得单独跑:** 判罚线的夹逼**上界**写的是「分配上限 − 最大单次分配」,而后者没有可代入的定值——实测封顶依分配形态从存活堆读数的约 96% 到「上限 − 请求量」都有;**下界**要的「装 bundle 之后的存活堆基线」从未被记录过(空 VM 基线 75,128 B 有实测并已冻成常量)。

**不许伪造哈希:** 读数里的沙箱运行时哈希必须是本仓真值,否则 `verify` 会**拒绝复算**——那批读数就不构成证据。

判据见 spec 的 Implementation Decisions 第 3、6 条与 Testing Decisions 第 1 项。

**Blocked by:** 01(两个量测探针都要真引擎的存活堆读数,读数在泄漏修复前不成立)

- [ ] 探针逐条镜像执行器的每 tick 次序,不改任何判定;既有执行器行为断言全绿
