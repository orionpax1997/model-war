# 01: 快照 handle 泄漏修复与存活堆稳态回归

**What to build:** 执行器给一个座位建沙箱、每 tick 灌一份快照时,不再把那份快照连同它引用的 guest 对象留在 VM 里;并有一条断言钉住「tick 末存活堆不随 tick 增长」,使这类泄漏不能再被引入。

**为什么必须先修:** 内存判罚线标的就是「tick 末存活堆读数」。实测空脚本 **+360 B / +5 个对象每 tick**、真实快照 600 tick 涨 18 MB、单局墙钟 27812 ms → 2737 ms(约 10×)。不修,内存两个键标的是一份会自己涨的读数——这是顺序约束,不是并列项。

**回归测试断斜率、不断绝对值:** 沿用既有「跑两 tick、断言两次读数相同」的形态(该文件现有先例断的是计数逐 tick 重置,存活堆没有同类用例,这正是缺口)。判据用「窗口极差 ≈ 0」或「拟合斜率为 0」,**不用绝对字节数**——绝对值随快照结构变化。

**一次性 prototype 整份入库:** 它记着本票唯一的量化证据(泄漏量级与墙钟代价),而泄漏一旦修好,那批数字**再也复现不出来**。读数部分要在顶部加失效声明:取自打过补丁的构建与伪造的沙箱运行时哈希,只能作量级参考。

判据见 spec 的 Implementation Decisions 第 6 条(读数落点与资产继承)与 Testing Decisions 第 1 项。
