# 04: 三类预算探针与标定读数

**What to build:** 死循环探针、API 轰炸探针、三轨异常探针各自在真引擎上跑出读数,并落成八键取值的**输入**。

**三类不是一类,每类各自对应一条轨:** 死循环探针只烧控制流事件(零 API),API 轰炸探针只烧 API 调用——两者互为盲区,这正是两条计数轨都必须存在的原因。三轨异常探针产的是**异常计数**,它替代了已被证伪的「故意写崩」形态:`loop()` 抛异常在当前实现里被原样重抛成整场崩溃,不产生任何异常计数。

**命题①在这一票成立:** `exceptionTickLimit` 的下限由三轨异常探针给出,不再挂在「1168 场桩」上——那批桩不模拟运行时,那个命题永远是零证据。

**读数按格数记:** 事件计数的有效分辨率是一整格,诚实局读数 p95 已满一格,所以事件轨的论证只能按格数、不能按事件数。

**余量分轨:** 计数两轨贴边(诚实与对抗差 ≳1000× 事件 / ≳10⁴× API),物理量轨留宽。统一系数是错的。

**诚实侧面必须包含基准脚本:** 三份基准脚本在真引擎上跑出存活堆峰值、单 tick 与单局墙钟、API 峰值——它们是所有「余量」的基准,也是 NFR-3 的输入(取值归节点 L)。

判据见 spec 的 Implementation Decisions 第 1、2、5 条与 Testing Decisions。
