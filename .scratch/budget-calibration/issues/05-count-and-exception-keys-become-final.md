# 05: 计数与异常三键落 final

**What to build:** `eventTickLimit`、`apiCallTickLimit`、`exceptionTickLimit` 写入规则集、标定状态转为定稿;双向失配断言第一次真正跑起来;静态门禁 `check:budget` 首版落地。

**失配断言必须双向:** 同一组终值下,三类探针**必被截停**,三份基准脚本**必不被截停**。单向断言在任何阈值下都能满足(把阈值设成 1 当然抓得住),它是空断言。

**「被抓住」必须指定是哪条轨:** 硬超时会作废整场却看起来像「抓住了」。不指定轨名与截停时的读数,命题②会被硬超时假满足——这是本票最容易埋雷的地方。

**事件轨的取值必须是中断粒度的整数倍:** 它的有效分辨率是一整格(判定只在中断点上发生,小于一格的取值彼此等价)。诚实局 p95 已满一格,所以取 5,000 会**误杀正常脚本**;贴边可取的最小安全值是第二格。

**异常键拒绝取 1:** 「tick 内瞬时借满即还」是已接受的残余,取 1 会把这个已接受的边界变成出局条件。

**静态门禁与动态断言的边界:** `check:budget` 只承担结构性断言(整数倍、硬下界、中断粒度常量与它在文档里的三处副本一致),零构建、只依赖真源包与文件系统;重活(真引擎失配)留在默认测试里。门禁必须遵守既有的**防假绿**惯例:读到零个文件/零个键按**失败**处理。

判据见 spec 的 Implementation Decisions 第 1、2、5、7、8 条与 Testing Decisions。
