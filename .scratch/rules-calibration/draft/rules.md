# rules-v1 规则（契约草案 prototype）

> throwaway 草案：正式版由 `schema` 包 + `rulesets/v1.json` 生成。此处数值只贴 03/04/05 定案值，其余 `TODO(归属)`。

## 1. 对局与时间

- 四方 1v1v1v1（玩家 index 0..3），tick 为唯一时间单位，无头运行。
- `tickLimit=600`。设计时间轴按比例验收（边界前后 20% tick 浮动，非硬编码路线）：0–40 开矿出兵；40–160 首次扩张接触；160–400 中后期争夺；400–600 终局压力。
- 地图：Chebyshev 距离（八向等价）；地形只有平原（可通行）与墙（不可通行）。点位为单格，单格单单位。
- 点位不变量：每方恰好 1 个主基地（四象限对称）；中立基地数量为 4 的倍数；资源点数量为 4 的倍数（内圈高危高收益 + 外圈家门口安全矿）。具体数量与坐标 `TODO(→地图票)`。
- 种子变体：装饰性微扰（成组四重对称墙体填充），不改变点位数量、不增加风格。槽位设计 `TODO(→地图票)`。
- 初始条件：四重旋转对称，四方初始单位与资源对等；起始资金 `initialResources=16（=2×melee.cost）` + 起始农民（编队由地图声明，`TODO(→地图票)`）。

## 2. tick 结算管线（顺序即规范，不可改写）

每 tick 严格按此顺序（顺序即规范，不可改写）：

```
0. dispatch   构建四方只读快照 → 按 playerIndex 0..3 串行执行各方脚本的 loop()（各方脚本跑在独立容器里）
              并收集 intents（预算与异常裁决在此层）
1. validate   intent 先按单位分组、每单位只留最后一个（静默丢弃，不计异常），
              分组后按 playerIndex 0..3 再按 unitId 升序逐条校验；无效者丢弃
2. movement   移动结算（基准与冲突裁决见 §3）
3. combat     同 tick 全部 attack 同时结算：
                a) 先计算全部伤害（攻击者本 tick 死亡不影响其攻击生效）
                b) 统一扣血，归零者死亡移除（不参与后续阶段）
4. objectTick 按对象数值 id 升序：
                a) 占领：单轨累积 / 转轨重计 / 冻结保留（见 §5）
                b) 采集：按 §4 结算，满携带上限即停
                c) 交付：carrying 清零入玩家池
                d) 生产：各队列 ticksLeft--，归零出兵；出兵格被任意单位占据则挂起等待；
                   基地易主时按 §4 退款规则处理队列（退款走玩家池，全整数运算）
5. evaluate   胜负判定（顺序即规范，见 §6）：
                a) 淘汰：满足淘汰条件者出局，点位回归中立
                b) 全部点位归属单一玩家 → 胜
                c) 仅剩一方尚存 → 捷径条款即胜（兜底）
                d) 淘汰方 loop() 不再执行（容器暂停调用，状态保留以便重放取证）
6. emit       记录本 tick 完整状态（可渲染画面 + 事件 + 状态 hash）；tick++
7. loop guard tick 达 ruleset 的 tickLimit → 超时，按 §6 领土分规则定名次
```

## 3. 移动与碰撞

- 一轮移动结算只以该轮开始时的占位为准：单位离开本轮所在格，不使该格对后来者可进入；同一格至多一个单位成功进入。
- 同格竞争：多方目标格相同 → 按轮转优先值 `(tick + playerIndex) mod 4` 排序取胜（方向假设：值大者胜；TODO(→终稿：来源只写“取胜者”，方向待确认）），其余原地不动（不尝试次优目标）。
- 交换/穿行（A→B 同时 B→A）与链式移动（A→B 同时 B→C）：按基准，B 格本轮被占，故 A 失败；B 是否成功只看 C。二者互不牵连，无链式裁决，无环形追逐。
- 己方单位之间同样按此裁决（无友军穿越）。
- `moveTo`：引擎每 tick 沿寻路结果走一步，等价于本 tick 的 `move`，参与同一套裁决；路径不跨 tick 缓存，每 tick 重算。
- 骑兵二次移动：重复整轮结算一次——第一轮结算后的占位即第二轮基准，轮转优先中的 `tick` 值不变。
- 先后手：座位在赛季内轮换以摊平偏置。脚本侧结论：座位会轮换，不要赌先手（偏置事实：下标差 d 的两人，低下标在 `(4-d)/4` 的 tick 中先手）。

示例（3×3 坐标系，无地图假设）：
- 同格竞争：A(0,0)→(1,1)、B(2,2)→(1,1)，(1,1) 空 → 按 `(tick+index) mod 4` 值大者胜（方向为草案假设，待终稿确认），一方进入、一方原地。
- 交换穿行：A(0,0)→(1,0)、B(1,0)→(0,0) → 两者都失败（目标格本轮被占），均原地。
- 链式移动：A(0,0)→(1,0)、B(1,0)→(2,0)，(2,0) 空 → A 失败（(1,0) 本轮被占），B 能否进入 (2,0) 只看竞争，与 A 无关。

## 4. 经济与生产

```
农民在己方资源点采集：+harvestRate(=1) 资源/tick（射程 1，站在矿相邻格）
携带上限：carryLimit(=20)，一次满载需 20 个有效采集 tick，满即停
交付：移动到己方控制基地相邻格，transfer（射程 1，一次交全部携带量）
  同时相邻多个己方基地时，交付给 id 最小的那个
资源归属：玩家全局共享池，无上限，不按基地分池
资源点：必须先占领才有开采权；有限储量 resourcePerSite=125，采空后点位仍计入胜利条件
```

- 无被动收入（刻意无死锁保护）。经济死亡（不可逆但非即时出局）：无任何农民且 `resources` < 农民造价时经济不可逆（占领资源点也不给农民）；但仍可用残兵抢点、阻断、军事胜利——"翻盘"指整局可翻盘，不指经济复活。
- 全图储量参考剖面：N=16 资源点、W=8 有效农民、利用率 0.5 时总量 2000，约 tick 500（5/6×上限）耗尽。地图可改 N，但须保持等效经济比例（W/N≈0.5、η≈0.5）；具体 N `TODO(→地图票)`。
- 生产：任何己方基地都是一条独立产线（一次一个）；基地不可摧毁、无攻击、无维修；基地格可通行、单格单单位。
- 下单即扣款；资金不足下单无效（`ERR_NOT_ENOUGH_RESOURCES`），不占队列不扣款。
- 出兵格被任意单位占据 → 队列挂起等待，格空后自动续出。
- 基地易主 → 该基地队列取消并全额退款给原主；原主已淘汰（基地回归中立）时不退款。

## 5. 占领

每个可占领点位（基地、资源点）持有 `owner`（可为中立）、`progressOwner`、`progress`。

- 单位站在点位格上即驱动占领；累积达 `captureTicks=10`（基地/资源点统一单值）后易主，进度清零。
- 全兵种占领速度一致。
- D 与 `owner` 同阵营：进度冻结保留。
- D 与 `owner` 不同：若 `progressOwner ≠ D`，则 `progressOwner=D、progress=1`（转轨重计，无侵蚀）；否则 `progress+1`。1-tick 触碰即把对手进度打回 1。
- 无人站立：进度冻结保留，不衰减。
- 堵点：己方单位站自家点位可物理阻止敌方踩点；对方须先消灭该单位（单位可被攻击，基地不可）。
- 占领不需要资源，因此经济死亡 ≠ 出局。

## 6. 战斗

- 同 tick 所有攻击同时结算（批处理，无先手秒杀）；攻击者本 tick 死亡不影响其攻击生效。
- 伤害单一血池扣减，归零死亡；无护甲、无技能、无冷却。
- 目标不可为基地；`attack` 目标须为敌方单位，任意兵种均可被攻击（含农民）；无攻击能力单位的 `attack` 无效（丢弃，不计异常）。

## 7. 胜利、淘汰与超时名次（判定顺序即规范，逐字搬）

- 主胜利：单一玩家控制地图上全部点位（含敌方主基地）的瞬间获胜，无需持续。
- 捷径条款：其余三方全部被淘汰时，仅剩玩家立即获胜。
- 淘汰条件：玩家同时无任何单位且无任何基地。被淘汰者名下残余点位全部回归中立。
- 结算顺序（判定即规范）：每 tick 先判淘汰 → 被淘汰者点位回归中立 → 再判全点位归属 → 最后判捷径条款（兜底）。回归中立可能破坏"全点位"条件时，由捷径条款接住。
- 超时（tick 达 `tickLimit`）与淘汰并存时的名次排序：
```
1) 获胜者（胜利或捷径条款）为第 1 名
2) 其余按存活状态分层：存活者排在已淘汰者之前
3) 层内：存活者按领土分降序；已淘汰者按淘汰时间倒序（后出局者更前）
4) 仍完全相同 → 并列同名次
```
```
领土分 = baseScore(4) × 控制基地数 + resourceScore(1) × 控制资源点数
       + ⌊Σ存活单位造价 / unitCostDivisor(6)⌋
```
单位分计入所有存活单位的造价总和（称"存活单位总造价分"，不限军事单位）。超时看分只看此式。

## 8. 异常与出局（规则面事实，完整披露）

- 脚本单 tick 抛异常（含超预算、越权调用）：该 tick 指令集为空（单位原地待命），不影响其他三方与引擎；你的脚本容器与跨 tick 记忆保留。
- 累计异常达 `exceptionTickLimit`：该方判负出局（按淘汰规则处理，点位回归中立；判定顺序见 §7）。取值 `TODO(→预算与性能终值图)`。
- 累计计数随对局状态持久化，容器中断或重建后续算不清零（否则反复失控可逃逸淘汰）。
- 仅引擎级故障（极罕见、非脚本可触发）会重建该方容器，重建后模块级记忆清零；异常计数由持久化值续算，不受重建影响。
- 内存判据：每 tick 末按该方存活堆占用判定，达 `memoryTickCeiling` 视同该 tick 异常（tick 内瞬时触顶后自行释放的分配不判罚；分配上限 `memoryLimit` 本身不可突破）。阈值 `TODO(→预算与性能终值图)`。
- 墙钟只用于观测，不参与判罚。
- 寻路调用量计入脚本 API 调用预算（别用寻路做算力攻击）。预算阈值 `TODO(→预算与性能终值图)`。

## 9. 确定性约束（FR-10 AC3：禁止 / 保证对照）

| # | 禁止 / 保证 | 你的行为指导 |
|---|---|---|
| 1 | 禁浮点：引擎禁浮点字面量与浮点 `Math` | 只用整数运算；别指望小数精度 |
| 2 | 玩家按 index 0..3、多对象按数值 id 升序 | 不要依赖对象遍历顺序，只认数值 id |
| 3 | 对局内无随机数（种子只在开局前做地图变体） | 别赌任何“随机先手”；`Math.random()` 在沙箱内是固定序列，不可当随机源（且静态校验禁 `Math.random`） |
| 4 | 引擎每 tick 排空异步任务，Promise 回调不得跨 tick 残留 | 别写跨 tick 的异步回调；`loop()` 当纯同步函数写 |
| 5 | 不存在 Set/Map 迭代参与结算 | 同 2：顺序只认 id |
| 6 | 寻路查询与实际移动是同一实现，结果一致 | `findPath` 算出的路就是 `moveTo` 会走的路，可信 |
| 7 | 每 tick 给你的世界是只读副本，对象身份不跨 tick | 跨 tick 只存数值 id 和自己的状态，别缓存对象引用（见 api.md） |
| 8 | 预算裁决可复现（控制流事件 + API 计数），墙钟只观测；硬超时使该场无效而非判罚 | 别用墙钟做策略分支；死循环会被截停记异常 |
| 9 | `Date`/`performance`/`queueMicrotask` 等非确定源禁用（静态校验直接拒绝） | 别读时间；别用定时器 |
| 10 | 脚本可见全局 = runtime API + 常量表；`__*` 桥函数已删除且进黑名单；`export/import/require/eval` 禁止 | 只调本文档的 API；别碰下划线开头的全局 |

### 附录：标定假设（非脚本硬约束，别照此写死策略）

- C1–C3 操作化定义：等成本配平取造价最小公倍数；全体存活集火当前最低 HP；同 tick 结算；接敌起点 Chebyshev 6、无遮挡，按射程/速度折远程先手；C3"优势明显"=近战胜后保留 ≥25% 初始总 HP。改任一假设须重跑工作台。
- 时间轴按比例窗口验收，事件允许边界前后 20% tick 浮动。
- 单基地满产烧钱率 2/tick；C7 硬约束恒成立（单基地消耗 > 单农收入）；D=4/8 落 2–4× 舒适带，D=12 只保硬约束。
- 本组取值已过 C1~C7（C1~C6 为等成本站桩对拼约束，C7 为单基地满产消耗严格大于单农收入；完整定义以终稿为准），脚本无需、也不应照约束反推策略（如“只爆近战”）。
