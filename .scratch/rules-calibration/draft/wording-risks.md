### 2. P0 待裁项：多模型是否分裂

**P0-1 index 自认——分裂，且无舱能闭环。**

- 候选 A：cell-a、cell-b、cell-d = **3 舱**；候选 B：cell-c = **1 舱**（3:1）。
- 三舱的“候选 A”实现各不相同：cell-a 靠 `move()` 返回值探测兜底、cell-b 直接 `MY_INDEX=0` 写死、cell-d v1 写死→回喂后改 `getObjectById` 回读。即**同一纸面候选落到三个不同机制**。
- cell-d 独立写出证据：`Snapshot` 无 `selfIndex/you/isSelf` 任何自标记字段、`loop()` 无参数、无 `getMyIndex()` 查询、读未暴露字段按 §2/§8 判越权 → **候选 A 与候选 B 在当前 schema 下都无可行解**。cell-a/c 的 FIXES 独立复现同结论。
- 结论：**终稿必须补显式机制**（快照标记位或独立查询函数），否则脚本只能发明行为探测（代价 + 歧义 + 单点风险）。此条从“待 07 验证”升级为**已证实 P0**。

**P0-2 轮转方向——不分裂，且未构成行为分歧。**

- 4 舱全部按“值大者胜”记录，**无一舱质疑方向**；`rules.md §3` 的“（方向为草案假设，待终稿确认）”标注已足够让模型继续。
- cell-d 额外自证“全脚本不依赖 `(tick+playerIndex) mod 4` 分支，方向翻转不改变行为”；cell-a/c 记录了假设但未依赖；cell-b 明说“脚本侧目前不直接利用”。
- 结论：**降级**——不是“会写错脚本”的卡点（模型未被误导），而是**记录口径**项。仅当终稿翻转方向且未来脚本开始赌先手时才回升 P0。

### 4. 新增 P0（盲写实证暴露，原清单未列；编号 P0-N1..N4）

- **P0-N1 脚本源是 JS 还是 TS 未定义**（`: void` 记法 4 舱 3:1 分裂）：硬约束字面写 `function loop(): void`、交付名却是 `.js`；cell-a/b/c 照抄 TS 记法，**cell-d v1 落 `function loop() {}`** 并自列为待回喂风险，回喂后才改。终稿必须定死“校验器是否接受/转译 TS 注解”。
- **P0-N2 `ErrResult` 未展开**：`spawnUnit` 返回 `ErrResult` 无判别式，三舱三种写法——cell-a `isError()`、cell-c `typeof r !== 'string'`、cell-d `!r` 真值；cell-d 还依赖 `ERR_NOT_OWNER` 做自愈，终稿改名即静默失效。
- **P0-N3 快照字段有、API 面缺**：`players`/`productions`/`tick` 声明在快照里，但 `getObjectsByType` 只支持 `'unit'|'site'` → `resources`/`exceptionTicks`/`alive`/自身 `index` 全读不到；4 舱被迫自记资源与生产队列。
- **P0-N4 `api.md §5` 候选 B 定义与 `PROMPT.base.md` 冲突**：api.md 说候选 B = `players` 项带 `you/isSelf`（并自认“来源状态模型里没有这个字段”），PROMPT 说候选 B = “自标记”——cell-c 按 PROMPT 实现。终稿须二选一。
