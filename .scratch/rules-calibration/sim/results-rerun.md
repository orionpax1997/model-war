# 票 09 复跑判读：`resourcePerSite=200` 下的定向复核

**性质**:票 08 的**复跑**（不是第二次标定）。08 的 `data/` 与 `results.md` 原样保留为证据源，
本轮数据在 [`data-rerun-200/`](./data-rerun-200/)，参数覆盖记录在同目录 `manifest.json`
（`setOverrides: {"resourcePerSite":200}`）。裁决归票 09 与 gdd §8，本文件只放**数字**与判读。

**为什么必须复跑**:08 用的 `resourcePerSite=125` 下"枯竭"是极端经济才碰得到的天花板事件（1168 场只 40 场采空），
而票 09 把终值改成 200。改了全局储量就等于改了所有对局的经济，所以 §1（时间轴）、§6（枯竭）、§8（形态）
三处的数字必须在新值下重出——**形态数字不是参数无关的**（这是 09 发现并纠正的疏漏）。

**复现**（先过自测，桩的结算语义自测是全部数字的回归网）：

```bash
cd .scratch/rules-calibration/sim
node --disable-warning=ExperimentalWarning selftest.mjs                      # 33 条
node --disable-warning=ExperimentalWarning run-all.mjs --set resourcePerSite=200 --out=data-rerun-200
node --disable-warning=ExperimentalWarning run-all.mjs --tables-only --out=data-rerun-200
```

**规模**:1336 场 = 08 的 1168 场 + M6 同策略对称局 72 场 + M7 骑兵开关实验 96 场(2v2 × 4 轮转 × 3 变体 × 8 种子)。

**顺带修掉的桩缺陷（影响可复现性，不影响 08 的结论）**:`map.mjs` 的单矿储量写死 `125`，
与 `ruleset.resourcePerSite` 的一致只是巧合——用 `--set` 覆盖时 harness 按 3200 算百分比、地图仍按 125 生成站点，
枯竭时点全线失真（本轮第一次复跑就是这样作废的）。现改为读 `RULESET.resourcePerSite`；**无覆盖时行为与 08 完全一致**。

## 1. 枯竭：终值 200 成立（对应 gdd §8 #7）

- **拉满经济剖面**（M5 四方农民自战，每家 6–8 个专职农）：`center-fortress@64` 全图采空中位 **479**，
  `open-four@64` **550**；6 农与 8 农同值（农民数不再是瓶颈），2 圈/3 圈开局矿为 470/543——与 08 一样，
  "给更多矿"不单调地给更多经济（农民要跑更远）。**全部落在 400–600 内**，即 gdd §2 决战段内。
- **全矩阵**：1336 场里 32 场采空，中位 **511**；25% 储量被采完中位 177、50% 中位 246、75% 中位 407.5。
  枯竭事件在典型对局里仍然不发生（结束时平均剩 80.1%）——这正是记录 #7 的"有意决定"所依赖的形态。
- 与 03 票目标的偏差：03 说"tick 500 采空"，实测极端经济 470–550、中位 511。**在窗口内**，
  偏差来自线性外推（08 的 315 是夹具上限吞吐下的实测外推，不是实测）。

## 2. 形态：新值下无新增失衡（对应 gdd §8 #9）

- 脚本局（M0–M4，1120 场）：**56.1% 以"其余三方全淘汰"收场**、11.4% 全点位、32.5% 超时。
  垃圾时间的结构没变：首淘汰中位 157，**首淘汰 → 结局中位 296 tick**——问题仍然是"有人被淘汰后剩下几家谁也打不死谁"，
  且集中在 M5/M7 这类对称残局（超时率 100%、尾段空转 479–522 tick）。
- M1（四方混战，一个明显更强的脚本）66.7% 在 400 前结束、M4（爆兵 vs 农民海）63.9% 在 400 前结束，
  M2（2v2 势均力敌）34.7% 在 400 前结束 + 44.4% 超时：双峰结构不变，**成因是脚本强弱差不是规则**。
- `unitCostDivisor` 派生的"单位造价分"在混战里的实际权重：本轮无新证据，仍是 03 票的算术口径 + 上面的超时率；
  **票 09 的裁决不变——不调分权重**（调它会把"垃圾时间"换成"终局屯兵等超时"）。
  新指标恰好给这个裁决加了一条反向证据：终局前 100 tick 的单位净增中位 0、p75 0，
  "一次性弃掉 ≥8 个单位"只占 16/5344 席位 → **"卖兵换分"与"屯兵等超时"都没成为策略**，所以调分权重的动机更弱。

## 3. 骑兵：机制层因果支持记录 #10

- 设计用 2v2 而不是四方自战：夹具的装饰墙打破四重对称，四方自战里"哪个座位吃到地形红利"的方差
  大于"造不造骑兵"（实测：四方自战 8 场里有 1 席独得 4 倍兵力）。2v2 + 4 轮转让两臂在**同一场地图**上对打。
- 结果：造骑兵臂平均终局名次 **2.97**、第 1 名 12.5%；不造骑兵臂 **1.91**、37.5%；两臂 100% 以超时收场
  （对称 2v2 打不完），所以差异全部体现在**领土分**上：20 vs 24。
- 读法（**不要过度解读**）：探针的打法是"守点 + 抢中立点"，骑兵臂把 1/4 兵力送去切敌后农民，
  于是**放弃守点**——损失大于战果。这证明的是"**在守点优先的打法下造骑兵是劣势**"，
  不是"骑兵是劣势兵种"（C1~C3 与 R3 消融已经证过它值 100% 来自速度，08 也测到 raider 探针 20% 拿第 1）。
  "真实模型会不会自造骑兵、造了会不会变差"仍然**不可归因**（`cell-d` 与 `cell-a` 之间差着模型、严谨度、静态不符三个变量），
  保持记录 #10 的缺口定性。
- 全场骑兵伤害份额 42.7%（两臂混合；结算按全场归因、不按席位，所以不能拆到臂）。
