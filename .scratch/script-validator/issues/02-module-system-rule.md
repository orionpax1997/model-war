# 02: 模块系统规则

**What to build:** 脚本产物里出现任何模块语法都在编译期被拒:静态 `export` / `import`、动态 `import()`、`require`、动态 `eval`。这四种在沙箱载入期取 `SyntaxError`(hld §2.2.2 的实测结论),是编译期即可判定的事实,不该留到运行时装载失败才发现。

**Blocked by:** 01 禁列规则端到端 + 校验器入口

**Status:** ready-for-agent

- [ ] 模块系统规则是一个纯函数,形状与禁列规则同形(源码 → 带行列的违规)
- [ ] 四种形态各有**一个能被弄红的反例**:静态 `export`、静态 `import`、动态 `import()`、`require`、动态 `eval`
- [ ] 每种反例都验一遍:退出码非零、诊断里点名那个形态
- [ ] 判定链里模块系统排在禁列与桥前缀之后,顺序不变
- [ ] 违规进入聚合后**全序稳定**这条性质继续成立(新增规则不得破坏排序)
- [ ] 动态 `eval` 与静态 `eval` 的区别:若实现只拦动态形式,须在规则文档与诊断里写明静态形式为何不拦;不得留成一条读不出来的规则
- [ ] 规则的边界在代码头注里写明:解析器在 script 源形态下同样会为模块语法生成节点,所以「单文件自包含」是这条规则判的,不是源形态保证的
