# 03: 宿主桥前缀规则 + 注入面一致性断言

**What to build:** 任何标识符链的根带宿主桥前缀即违规。桥函数在初始化后即被删除(hld §5.0 的实测结论 #5),脚本引用它只会得到一个可以自己吞掉的 `ReferenceError`,所以静态拒掉是纵深防御的最后一层。同时把 C 留下的一条不变量落成机器断言:沙箱注入符号表里不得出现带桥前缀的名字。

**Blocked by:** 01 禁列规则端到端 + 校验器入口

**Status:** ready-for-agent

- [ ] 桥前缀规则是一个纯函数,形状与禁列规则同形
- [ ] 判据是**任何**标识符链的根以桥前缀开头——读与写都拒,不需要作用域信息(不查它是不是全局的)
- [ ] 正例与反例各一:脚本自己声明一个带前缀的名字**也**判违规,并在诊断里说明这是命名约定而非「不得声明」
- [ ] **注入面与桥前缀不得矛盾**这条不变量落成一条机器断言(当前恒真,但沙箱执行器回填注入面前它必须在场)
- [ ] 该断言的落点写在真源包那侧(两张表是它的事实),不在校验器里
- [ ] 桥前缀与禁列的**重叠情形**有裁决与用例:一个既带桥前缀又在禁列表里的构造,判为哪一类(按判定链顺序即禁列)
- [ ] 规则的边界在代码头注里写明:注入的脚本 API 面走的是另一张表,两者在本 feature 之前没有任何机器保证它们不打架,现在有了
