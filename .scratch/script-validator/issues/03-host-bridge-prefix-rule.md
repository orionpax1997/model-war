# 03: 宿主桥前缀规则 + 注入面一致性断言

**What to build:** 任何标识符链的根带宿主桥前缀即违规。桥函数在初始化后即被删除(hld §5.0 的实测结论 #5),脚本引用它只会得到一个可以自己吞掉的 `ReferenceError`,所以静态拒掉是纵深防御的最后一层。同时把 C 留下的一条不变量落成机器断言:沙箱注入符号表里不得出现带桥前缀的名字。

**Blocked by:** 01 禁列规则端到端 + 校验器入口

**Status:** resolved

- [ ] 桥前缀规则是一个纯函数,形状与禁列规则同形
- [ ] 判据是**任何**标识符链的根以桥前缀开头——读与写都拒,不需要作用域信息(不查它是不是全局的)
- [ ] 正例与反例各一:脚本自己声明一个带前缀的名字**也**判违规,并在诊断里说明这是命名约定而非「不得声明」
- [ ] **注入面与桥前缀不得矛盾**这条不变量落成一条机器断言(当前恒真,但沙箱执行器回填注入面前它必须在场)
- [ ] 该断言的落点写在真源包那侧(两张表是它的事实),不在校验器里
- [ ] 桥前缀与禁列的**重叠情形**有裁决与用例:一个既带桥前缀又在禁列表里的构造,判为哪一类(按判定链顺序即禁列)
- [ ] 规则的边界在代码头注里写明:注入的脚本 API 面走的是另一张表,两者在本 feature 之前没有任何机器保证它们不打架,现在有了


## Answer

### 关键结论

1. **判据是任何标识符链的「根」以桥前缀开头——读与写都拒,且不需要作用域信息。** `__foo`、`__foo.bar()`、`__foo.x = 1`、`function __foo() {}`、`const __foo = 1`、`class __Bridge {}`、参数名 `function loop(__n)` 一律违规;不查它是不是全局的,与禁列规则同一条纪律。唯一的等价写法处理是 `globalThis`:它是全局对象本身而不是某个对象的属性,比较前先剥掉,且违规位置落在**真正要改的那个名字**上(`globalThis.__setSnapshot(1)` → `1:22` 而不是 `globalThis` 那一列)。
2. **脚本自己声明一个带前缀的名字也判违规,理由是命名约定而不是「这个名字危险」。** 判违规的依据不是危险(脚本自己声明的同名变量并不危险),而是**脚本里任何带这个前缀的名字都在冒充宿主注入的桥**,而模型没有理由知道哪个是真桥。判掉它省掉的是「模型以为自己在用宿主桥、而运行时拿到能自己吞掉的 ReferenceError」这条整轮作废的路径。诊断里给的动作是**改名**,不是「不许声明」——用例直接断言了消息里有「改名」与「命名约定」这两个词。
3. **前缀是命名约定而不是一张桥名清单**,理由与真源那侧一致:桥函数在初始化后即被删除(hld §5.0 实测结论 #5),参赛脚本能看见的桥永远是运行时才有的那一个,静态层能判的只有约定本身。所以消费的是 `isHostBridgeSymbol`(前缀查询)而不是一张桥名数组——同源断言那条用例改真源里的 `HOST_BRIDGE_PREFIX`、重跑 `pnpm run generate`,规则行为随之改变。

### 三条边界放行:逐条确认,全部维持放行

4. **键位上的名字(`obj.__foo`、`{ __foo: 1 }`、`class A { __foo() {} }`):放行,成立。** 那是一次取值,链的根是 `obj` / 对象字面量 / 类,不是 `__foo`。与禁列规则的 `x.Date` / `class A { Date() {} }` 同一份判据、同一个理由(误伤在五轮迭代预算里不对称地致命)。补上它会把「读一个恰好叫 `__foo` 的属性」全拒掉,而那在合规脚本里是很常见的写法。
5. **解构简写(`const { __a } = g`):放行,成立,而且这一处的漏报比上面两条更无害。** 理由值得单列:放行的只是**声明处**那一个节点,此后这个名字的每一次裸引用(`return __a`、`__a + 1`)仍然逐个判违规。于是脚本即便写得出 `const { __a } = g`,也**用不了**这个局部量——能通过校验的只有「声明了但从不读」的写法,那不构成一条可利用的路径。要把声明处也判掉,得给公共遍历加一条「解构简写算引用」的分支,而那会让禁列规则反过来开始误报 `const { Date } = g`(同一份遍历判据,方向相反)。已把这段理由写进 `rules/host-bridge.ts` 的头注,原先只写了「漏报只是回到现状」,没说清它为什么无害。
6. **字符串里的名字(`obj["__foo"]`、`"__foo"`):放行,成立。** 那不是标识符,链的根仍是 `obj`。严格说 `obj["__foo"]` 与 `obj.__foo` 语义相同、放行它们是对的——真要收,收的是**键位的豁免**本身,那是另一条更大口径的裁决,不在本票范围。

### 重叠裁决的口径:确认

7. **禁列与桥前缀的重叠造不出来源样本**——真源的 `FORBIDDEN_GLOBAL_NAMES` 四条(`Date` / `Math.random` / `performance` / `queueMicrotask`)没有一条带前缀。裁决因此落在**两个可观察的断言**上,而不是落在一条假想样本上:**① 同一位置时按类别名兜底,`forbidden-global` < `host-bridge`,禁列那条排在前面**(直接断言 `compareViolations` 的输出次序);**② 每条禁列名各自只报一条违规**,类别靠 `rule` 区分、不靠位置(逐条遍历 `FORBIDDEN_GLOBAL_NAMES` 跑一遍判定链)。这两条加起来就是裁决的全部内容:重叠时**两条都会报**,而模型先看到禁列那条。口径确认成立——它把裁决落在排序与归类这两处真正可观察的性质上,任何一次改动判定链顺序或类别名都会让它们红。

### 一处注释与实现不符,已改(不影响行为)

验收清单与实现本来是一致的,但实现里有一句注释**说错了**:`rules/host-bridge.test.ts` 与 `rules/host-bridge.ts` 的头注都写着「真源那侧有一条断言钉住禁列与前缀的交集为空」。真源那侧 `packages/schema/src/script-surface.test.ts` 的三条断言是「注入面里没有带前缀的名字」「注入面与禁列不相交」「注入面表内无重复」——**没有**任何一条钉禁列∩前缀。这是**故意不钉**的:交集将来出现或消失都合法,两种状态下都有裁决 7 兜着,钉住反而会把一条合法状态判成违规。已把两处注释改为如实记录,并说清为什么不钉。

### 遍历层抽公共件:接受,判定链之外的最大一处交叉

8. **票 03 把遍历层从禁列规则里抽成 `rules/identifier-chain.ts`,裁决为接受。** 依据写在两份规则的头注里:禁列与桥前缀的判据都作用在标识符链上(前者比整条、后者比根),而「哪些位置上的标识符是一次按名字找符号、哪些只是一次取值」是最容易写错的一处——写宽了会把 `obj.Date`、`{ Date: 1 }`、`obj.__foo` 全误伤。两份遍历各写一次这个判据,迟早有一份放宽了,而那时没有任何东西会红。抽取是纯搬迁:禁列规则的 27 条用例搬迁后全绿,判据逐字未变(唯一差别是 `hit[0]?.start ?? startOf(node)` 成了 `?? 0`,而 `forbiddenChainOf` 在空链时必返 undefined,所以那个兜底分支本来就是死的)。
9. **公共件不替调用方合并一次出现的多段链**:`__host.x = 1` 这一次出现给出两条(`__host` 与整条 `__host.x`),合并的形态属于各自的规则。但**判据只看根的那一条必须按根的偏移去重**,否则同一次出现会报成「2 处」而模型只看得见一个名字——这条约束写在公共件头注里,宿主桥规则按它实现。
10. **模块系统那一票没有消费这份公共件,原注释的预测已改为事实。** `identifier-chain.ts` 原头注写着「模块系统多半不需要本文件;但只要它要判一个裸标识符(`require` 这类),就该来这里取链」。落地事实是它**不**消费,而原因不是「多半不需要」:模块系统的判据是**「这是什么语法形态」**,它要看 `CallExpression` 的被调用者与实参形状,而一份链不带这两样——一份链说不了「这是不是一个调用」。两条规则共用的是「哪些位置上的标识符是一次按名字找符号」这一个**遍历层判据**,不共用「怎么从链上判违规」。头注已改为记这条事实,并把「下一张要动这里的人」改成「若将来还有第三条『只判某个名字、不关心形态』的规则,那时本文件就是它该来的地方」。

### 注入面一致性断言

11. **断言落在真源包那侧**(`packages/schema/src/script-surface.test.ts`),三条:注入面里没有带桥前缀的名字、注入面与禁列不相交、注入面表内无重复。理由是验收项第 5 条写明的——两张表都是真源的事实,在校验器里断言只能断言「空集合没有前缀名」这种恒真的废话。每条断言都写了**反例手法**(往真源里填一个 `__setSnapshot` / `Date` / 重复名字,对应那条立刻红)。
12. **当前恒真是它此刻该有的样子**:注入面刻意为空(真源头注写明「待沙箱执行器 G 回填」),断言在回填之前就位,回填那天它才开始干活。回填触发条件与「一张预填的名字只会是一份没人负责的答案」的理由在真源头注里,两处同源。
