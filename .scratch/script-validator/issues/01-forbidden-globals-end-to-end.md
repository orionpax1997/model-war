# 01: 禁列规则端到端 + 校验器入口

**What to build:** 一份脚本产物能走完整条通路:读入 → 规则 → 两层违规输出 → 退出码。这条通路的第一条规则是**禁列全局名**——标识符链命中禁列表即违规。它带着整条通路上最难锁死的一条用例:禁列表里的成员路径挂在白名单内的全局名下时,必须判为禁列违规。入口是子进程可执行的那一支,退出码与标准输出是它对外的全部契约。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 禁列规则是一个纯函数:一段源码 → 一组带行列的违规,不碰文件系统、不读时钟
- [ ] 禁列的判据是**标识符链**而非裸全局名(成员路径也在内)——这是真源包交付的接口形状,不是自选
- [ ] **判定链顺序固定**:语法失败 → 禁列 → 桥前缀 → 模块系统 → 体积。禁列必须先判
- [ ] **顺序漏洞的锁死用例**:一个既命中禁列、其根又挂在白名单内的构造(禁列表里的成员路径挂在白名单全局名下)必须判为禁列违规。这条用例锁死「按白名单先判就会放行」那个漏洞
- [ ] 违规序列**全序稳定**:按源码位置排序、同一位置按规则类别名兜底;同一份源码两次校验得到逐项相同的序列
- [ ] 解析失败**独占结果**:只产出一条解析失败、零条规则违规(残树上的结论不可复现)
- [ ] 违规分两层:机器层是结构化数组(规则类别 / 行列 / 文本);面向模型层是渲染文本
- [ ] 面向模型层对**同类错误合并**:多个同类错误并成一行,并有用例锁死(否则会被后来者改成逐行输出)
- [ ] **同源断言**:改真源包里的禁列表,校验器行为随之改变——证明校验器一个名字都没自己存
- [ ] 入口由 Node 直接执行,**退出码是 0/1**,标准输出是全部契约
- [ ] 入口的自测里有**能被弄红的反例**;它不混进全量门禁(本工具不进 `check`)
