# 05: 内置全局白名单的收录判据与表回填

**What to build:** 真源包里那张现在为空的**内置全局白名单**拿到一条可判的收录判据,并据此回填。判据是「无副作用、不读这个 VM 之外的任何状态」——它一句话对所有内置全局一视同仁,且与禁列构成一对方向相反的判据:禁列是「一律禁」(不可复算),白名单是「一律收」(不越界)。这张表不再被静态校验器的任何规则消费(白名单反转已由编译器执行),它喂的是面向模型的规则文档里的内置全局表。

**Blocked by:** None (can start immediately)

**Status:** resolved

- [ ] 收录判据**写成一条可判的陈述**,不是「纯函数子集」这种方向性描述;判据进 hld 的规则表
- [ ] 判据的**两个方向**都验过:一张现有的内建全局被收(`JSON` / `Object` / `Array` / `Map` / `Set` / `Number` / `String` / `Math`),一张被拒(`Date` / `performance` / `Math.random`——后两者与禁列同向,判据要给出与禁列一致的理由)
- [ ] 表按判据回填;**不写「分叉容忍条款」**——判据一旦确立就没有分叉,因而没有条款
- [ ] 回填的每个名字在头注里带一句**为什么收**(判据的实例),让人能一眼看出加名字的门槛
- [ ] 与禁列的一致性:任何出现在禁列表里的名字**不得**出现在这张表里,落成一条机器断言(两表相交的失败模式正是「白名单放行了禁列」)
- [ ] 显式记下:这张表**不参与**白名单反转的判定(那一侧是编译器的名字解析),它的消费者是规则文档的生成;两者不得互相引用为「依据」

## Answer

一张原本刻意为空的名单拿到了它的一句话判据,并按判据回填成 42 个名字。真源侧头注是这张表唯一的家:判据、逐个「为什么收」、逐条「为什么不收」、与禁列不相交的纪律、以及「这张表不参与白名单反转判定」四件事全写在同一个文件里,生成物只带表和一句不越界的指路。

### 判据

**收:拿它算出的值完全由脚本自己已经给定的输入决定。** 拆成两个方向——既不改变这个 VM 之外的可观察状态(宿主、文件系统、时钟、调度队列、共享内存),也不读这个 VM 之外的任何状态;任何一边沾了就是不收。它与 `FORBIDDEN_GLOBAL_NAMES` 的「一律禁」构成一对方向相反的判据,且判据没有第三种形态、也没有例外口子。

「内建」这一格的定义域也在判据里:宿主提供的东西(`console` / `setTimeout` / `fetch` / `process` / `crypto`)属于注入面而非内建,宿主桥(`__` 前缀)是禁列而不是白名单。这张表只装 JS 语言自己定义在全局上的名字。

### 关键结论

1. **回填 42 个名字**,头注逐个写明为什么收;反过来,`eval` / `Function` / `AsyncFunction` / `Proxy` / `globalThis` / `Intl` / `Atomics` / `SharedArrayBuffer` / `WeakRef` / `FinalizationRegistry` / `escape` / `unescape` 各有逐条不收的理由,理由本身也是判据的实例。其中 `globalThis` 的理由值得单记:收它等于把判据要证明的事(不读 VM 之外的状态)交给被校验者去证明,判据在这个名字上不可判。
2. **与禁列同向的三个名字**(`Date` / `performance` / `Math.random`)在判据这一侧得到与禁列逐条一致的理由,所以它们只出现在禁列里。`Math.random` 是成员路径,连「能不能进这张表」都不问——这张表只装全局名。
3. **两表不相交落成机器断言**。判定链把禁列排在白名单之前判只是为了在相交状态下也不放行,次序只是兜底;真正的护栏是那条相交断言(把 `Date` 写进两张表它先红)。
4. **不写分叉容忍条款**:判据一旦确立就没有分叉,因而没有条款。加进一个名字需要一个与判据同等具体的理由,删掉一个同样需要。
5. **这张表不参与白名单反转的判定**,消费者是规则文档的生成;两侧不得互相引用为「依据」,否则其中一侧被改动时会悄悄分叉成「文档说能用、编译器说不能用」。
