# 06: 四份盲写脚本的「不误伤」验收

**What to build:** 规则标定环的四舱盲写留下了四份独立盲写的合规脚本,其中两份在当时的契约下有已知静态不符。拿它们过一遍**全部**规则的最终形态,把「误伤合规脚本」这件事变成一次有记录的验收,而不是一句承诺。结果记在票里。

**Blocked by:** 01 禁列规则端到端 + 校验器入口, 02 模块系统规则, 03 宿主桥前缀规则 + 注入面一致性断言, 04 脚本体积规则

**Status:** ready-for-agent

- [ ] 四份脚本全部过完整条通路,**违规数逐份列出**(预期为零;若非零,逐条判读是规则过严还是脚本确实有静态不符)
- [ ] 两份已知有静态不符的脚本:判读其不符**是否落在本 feature 的规则范围内**;落在范围内的按规则修,不落在范围内的记录并说明归属
- [ ] 体积规则对这四份的结果:逐份的字节数(供预算终值标定那张图取实测值,命题④要的就是这个数)
- [ ] 结果作为**证据**记在票里,并在票的 `## Answer` 段留一行 gist + 链接
- [ ] **四份脚本不落仓库测试**:理由与「对第三方库行为的断言不落仓库测试」同源——一次性证据会被后来者误读成「合规性已验过」
- [ ] 明确写下「不进仓库」不等于「不验」:它们正是该验的那四份,而仓库里的常驻用例是现造的最小样本
- [ ] 盲写舱的隔离方案**不抢**:它是规则落库那张票复跑时要复用的
