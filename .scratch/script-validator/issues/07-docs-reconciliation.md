# 07: hld 文档收口

**Blocked by:** 01 禁列规则端到端 + 校验器入口, 02 模块系统规则, 03 宿主桥前缀规则 + 注入面一致性断言, 04 脚本体积规则, 05 内置全局白名单的收录判据与表回填

### 三条裁决(合并后由复核方裁决,均已落)

1. **gdd §8 开放项 #11(`docs/gdd.md:214`)——改一句,不在 gdd 里裁决这个开放项。** 原句「静态校验器对参赛脚本的白名单只到**全局名级**(`Math` 在名单 → 放行)」描述的那一层已不存在:承载权转移后校验器根本没有白名单判定。改为「参赛脚本侧**不做成员级白名单**……白名单反转那一层是编译器的名字解析(hld §6.2),它判这个名字存不存在、不判它的成员」。**理由**:失效的表述由本 feature 造成,根 `AGENTS.md` 的纪律是发现冲突就修矛盾的一方;但「参赛脚本要不要受整数闭包约束」仍是规则侧判断(会改变 §6.1 兵种设计约束),gdd §8 保留为开放项,#11 依然挂着。**现象本身不变**:`Math.sqrt` 仍无规则拦,这条要交给 gdd 图。

2. **hld §3.1 职责矩阵 `gen:pipeline / validator / archiver` 行(`docs/hld.md:316`)——改。** 原写「API 误用静态检查(白名单由 `schema` 生成)」把裁判权留给了本行。改为「API 误用静态检查挂真源包的类型面而非符号表(名单由 `schema` 生成,§6.2),白名单反转在编译步骤而不在本包」。**理由**:与 §6.2 现行两层承载直接打架,属本票授权范围(hld 收口),且票里「修掉任何『静态校验器是唯一裁判』的残留表述」这一条点名它。**未与并行票冲突**:票 06 的范围是四份盲写脚本的验收证据,不碰 hld;已核。

3. **收录判据进 hld §6.2(`docs/hld.md:580`)——接受现状,逐字核对过没有抄名字。** 该行只引判据一句原文(「收:拿它算出的值完全由脚本自己已经给定的输入决定」)+ 括号里两个方向的展开 + 指向 `packages/schema/src/builtin-globals.ts` 头注的指针;42 个名字一个都没进文档,逐个「为什么收/不收」也在真源包头注。**理由**:票 05 的验收项白纸黑字写的是「判据进 hld 的规则表」(`.scratch/script-validator/issues/05-…:9`),hld 这一格写的是「结论与理由 + 指针」而非机制副本,与 gdd 拥有「规则机制与参数意图」的分工不冲突——**真源仍是 `builtin-globals.ts` 头注,hld 只留结论**。该行还顺手写清了「这张表的消费者是面向模型的规则文档,不参与白名单反转的判定;两侧不得互相引用为依据」,避免 hld 反过来成为判据依据。

### 注入符号表那两句注释的核实

**删得对。** `script-surface.ts` 原先那两句(「查注入符号是否存在」+「两侧同源于是该洞结构上不存在」)在承载权转移后都不成立了:校验器没有这条规则,而「同源」保证的只是两侧读同一张表,给不出「这个名字存不存在」——后者要的是类型面。**全仓检索后,「该洞结构上不存在」这个断言已无残留**(只剩 `packages/*/dist/` 里的旧 `.d.ts`,是 gitignore 的构建产物,重建即消失)。

**但检出同族的第二处残留,已一并修掉**:`packages/schema/src/script-surface.test.ts:24` 与 `:41` 的两段头注仍把注入面描述成「校验器放行、runtime 铺上」的那一张,并写着「于是『校验器放行但运行时报未定义』……两头都坏」。同一个失效前提(假设校验器会放行注入面里的名字),同一个「该洞结构上不存在」的弱版本,留在真源包的断言注释里会让后来者以为校验器仍消费这张表。已改为如实记录:注入面这一侧今天没有任何规则消费它、放行它的是编译器的名字解析,并把失败模式改写成它现在真实的样子(执行器铺上、校验器又拒掉)。三条机器断言本身与判读未动。行号见上表末行的真源包各条。

### 探针实测结论的 gist

- **解析结果没有符号面**:`ParseResult` 的自有属性只有 `program` / `module` / `comments` / `errors`,`module` 只有 `hasModuleSyntax` / `staticImports` / `staticExports` / `dynamicImports` / `importMetas`;包的导出(含 `raw-transfer/*`)里没有 symbol/scope 入口。**复核方在本机独立复跑了一遍(oxc-parser 0.152.0),与票中所记一致。**
- **标识符不区分引用位与声明位**:同一段源码里 `function f(b){return b}` 的声明位 `params[0]` 与引用位 `body.body[0].argument` 反序列化后是同一个 `type:"Identifier"`、字段集相同(逐字段深比较只差 `start`/`end`)。**复核方独立复跑,与票中所记一致。**
- 两条都只对所记版本组合成立,换 `oxc-parser` 版本即需重测(已写进 hld 表头)。
