# 05: 错误码全定与 API / 常量表区块

**What to build:** 终稿 API 面里最容易漂的那一类被钉死：**每个错误码都有名字和一句触发条件**，并且错误码集合与「丢弃 vs 异常」对照表逐条对齐。

草案里只有「资源不足」那一码在来源文档被点名过，其余是按界检查职能反推的候选码。终稿要么全定、要么全删——**半截的码表比没有码表更坏**，因为模型会当真。所以本票的产物是：一张完整的码表 + 与它逐条对齐的对照表 + 出成区块的 API 表与常量表。

同时把草案常量表标题下的三种东西拆开：**类型名**（归类型面，不进这张生成表）、**错误码字符串**（进）、**数值**（归规则集文件那条链，不进）。

**Blocked by:** 02（符号表判据与回填）、03（区块形态）

**Status:** resolved

- [x] 错误码**全定**：每个码有名字 + 一句触发条件；码的集合与符号表里那一份**由同一次书写产生**，不是两处对齐
- [x] 每个错误码**标明它落在「丢弃」还是「异常」**——这两类的后果不同（一个丢单条、一个丢整 tick 且计一次），模型据此决定要不要兜
- [x] 「丢弃 vs 异常」对照表**重写一遍**：它原本按旧的错误返回形态写，现在错误码形态变了，表不动就是错的
- [x] **「资金不足无效」与「`loop()` 抛异常」两行必须能在表里被区分**，这是那轮措辞裁决明确点名要保住的一组对照
- [x] API 表与常量表出成区块：API 表一栏签名、一栏一句语义；常量表分**类型名**（不进生成表）与**错误码**（进）
- [x] 收进生成表的每个 API 名字都在符号表里——落成机器断言（文档多写一个名字即红）。这是「同源」的可执行证据
- [x] 符号表里有、文档里没有的名字也要报——它是「文档漏披露了一个符号」，模型会当它不存在

## Answer

**七码全定，一个不删**（集合与符号表里那一份同源，见下）：

| 错误码 | 一句触发条件 | 落在哪类 |
|---|---|---|
| `ERR_NOT_ENOUGH_RESOURCES` | 下单资金不足（唯一在来源文档被点名过的码） | 丢弃 |
| `ERR_INVALID_UNIT` | 动作函数点名的单位 id 不存在 | 丢弃 |
| `ERR_NOT_OWNER` | 点名的单位/基地不归本方（沙箱内即时返回，**不**用于自认座位） | 丢弃 |
| `ERR_OUT_OF_RANGE` | 射程外 | 丢弃 |
| `ERR_INVALID_TARGET` | 目标非法（如把基地当攻击目标） | 丢弃 |
| `ERR_INVALID_SITE` | 点位类型或归属不对（如把基地当资源点采集） | 丢弃 |
| `ERR_BAD_ARGS` | 参数越界（如 `move` 的 `dx`/`dy` 不是 -1/0/1） | 丢弃 |

**七个码全落在「丢弃」，这不是偷懒而是这张表的形状**：错误码是**单次调用**的返回值，而七种触发条件
全是这一次调用自己的界检查没过——丢的范围就是那一条意图。「异常」那一类全部**没有码**：它们是
整 tick 的判罚（`loop()` 抛异常／tick 末存活堆超 `memoryTickCeiling`／引擎级故障），压根不返回
任何值，模型在那一刻拿不到 `ErrResult` 可判。所以两类的区别在表里不是「哪些码」，而是「哪些情形」，
错误码表的「落在哪类」一栏由那张情形表按名字投影而来，两者不可能各说一套。

**「码的集合与符号表同源」怎么兑现的**：真源是一次书写，分三处落点，没有第二次抄写——
- 名字、类别、**签名**、**一句触发条件**都在 `packages/schema/src/script-surface.ts` 的注入面符号表
  一行上（`InjectedApiFunctionEntry` 带 `signature`，`InjectedErrorCodeEntry` 按类型就**没有**签名；
  「忘了给」与「这一档本来就没有」在类型上不可分）。
- **「落在哪类」不在那个文件里写**：`packages/schema/src/script-outcome.ts` 的后果行按**名字**引用
  错误码（`codes: readonly string[]`），并投影出 `SCRIPT_OUTCOME_BY_CODE`；错误码表与对照表都从
  这个投影取。后果行独立成文件是因为它回答的是另一个问题（「这次没生效丢什么」而不是「运行时有哪些
  名字」），合成一张表会让那张表的判据从一句变成两句。
- 反向的错位由 `script-outcome.test.ts` 兜：每个码**恰好**落在一行上、每行引用的名字都真的是错误码；
  少一个码、落两行、引用一个不存在的码，三种错位都当场红且报告里带码名。

**对照表按新形态重写**：草案那张表 6 行里只有 3 行返回码，另外 3 行（同单位多意图、`loop()` 抛异常、
内存判罚、引擎级故障）是**不返回任何值**的判罚。终稿把它们放进同一张表但用「落在哪类」一列分开，
并把「丢的是什么」「累计在哪儿」两句话提到类上（`SCRIPT_OUTCOME_CLASSES`）而不是抄进每一行——同一类
七行逐字重复同一句话，而分叉的形状正是「有的行说不扣款、有的行说丢整 tick」。
**「资金不足无效」与「`loop()` 抛异常」是两条不同的行、不同的类**，且前一行必须挂着
`ERR_NOT_ENOUGH_RESOURCES`、后一行**不许**挂任何码（有单独一条断言钉着，`script-outcome.test.ts` 末条）。

**四张表出成两个区块**（`packages/tools/src/generate/api-surface.ts`，注册表加两行，骨架未动）：
- `api-v1-api-surface` → API 表（四组：查询 6 / 动作 6 / 座位自认 1 / helper 2，各一栏签名、一栏一句语义）
  + 错误码表（码 / 一句触发条件 / 落在哪类）+ 常量表。**常量表只出错误码这一半**：`type ErrCode` 联合；
  类型名（`UnitType` / `IntentKind` / `ErrResult` / `Snapshot` / `Intent`）在表前一句话里点名归类型面、
  不进表；数值归第 5 节那张已存在的数值表。判别方式那段带一个可运行示例，示例里的每个名字都过一道
  **存在性 + 类别**校验（`exampleNames`），改了真源里的名字而忘了改示例，生成器非零退出并点名。
- `api-v1-outcome-table` → 两类后果（丢的是什么 / 累计在哪儿）+ 六行情形对照表（情形 / 落在哪类 /
  这一行的后果 / 例子 / 相关错误码）。
分成两件而不是一整块：两个真源两句判据，合一块的话漂移报告分不出是哪半边漂了。

**两条双向机器断言**落在 `packages/tools/src/api-doc.test.ts`（unit project 拾取），断言对象是
**工作树里那份 `docs/rules-v1/api.md`** 而不是生产函数的输出（对着输出断言等于什么都不查）：
- 文档 ⊆ 符号表：区块里表头列的每个名字都在 `SANDBOX_INJECTED_API_SYMBOLS` 里——多写一个即红。
  实测反例：往 API 表塞一行 `getResources` → 红。
- 符号表 ⊆ 文档：22 个名字一个不缺——少一个即红（那是漏披露，模型会当它不存在）。实测反例：删掉
  `getMyIndex` 那一行 → 红。
另两条同文件：错误码集合在文档与符号表之间逐字相同且每码有一句非空触发条件；对照表点名的错误码与
符号表一致。「抽不出区块」按红报（否则两条断言会在空串上绿）。

**门禁自测**在 `packages/tools/src/gates.test.ts` 加一条「API 表区块——改真源不重跑 → 变红，
手改区块正文 → 变红，还原 → 变绿」；票 04 那两条覆盖的是数值表（真源是数据文件），本票的真源是
`.ts`，多一道「改了得先 `tsc -b` 才看得见」的前提，所以这条不是重复。为此把 `withPatchedTruth`
泛化成「真源 + 会被重写的落点」（`TruthTarget`），白名单那一对是它的默认档；还原仍走字节而不走生成器。
未新增 project，未给区块抽取器加单元测试。

### 逐条对着验收条款

| 条款 | 落点 | 怎么验的 |
|---|---|---|
| 错误码全定，名字 + 一句触发条件 | 符号表 `error-code` 七行各带 `reason`，渲染成错误码表第二列 | `script-outcome.test.ts` 断言码集合逐字相等；`api-doc.test.ts` 断言每码第二列非空 |
| 码的集合与符号表同源，不是两处对齐 | 码只出现在符号表一处；文档侧全为投影；后果行按名字引用 | 加码 / 落两行 / 引用不存在的码，三种错位都红 |
| 每个码标明落在丢弃还是异常 | `SCRIPT_OUTCOME_BY_CODE` 投影 → 错误码表「落在哪类」一列 | 取不到落点时生成器非零退出（不留空格）；`api-doc.test.ts` 断言该列只允许那两个字 |
| 对照表按新的错误码形态重写 | `api-v1-outcome-table` 区块六行，四行无码且渲染成 `—` | 文档实拍：三类「异常」行都返回不了码，与错误码表形状一致 |

| API 表一栏签名一栏语义；常量表分类型名与错误码 | API 表四组表；常量表只出 `type ErrCode` 联合，类型名在表前一句里点名归类型面 | 文档实拍：15 行函数表 + 7 码联合；`script-surface.test.ts` 断言函数档都有签名、错误码档没有 |

### 票面之外的判断

1. **「同源」落在符号表的行上，而不是新开一张「API 面真源」表**。新开一张就得让符号表与它对齐，那
   是两处书写；把签名与触发条件挂到既有的行上，则是一次书写、两处渲染。代价是注入面这张表不再
   是纯名单——它本来也已经不是（`reason` 早就写给模型看了），且票 02 的注释已改口径。
2. **签名这一栏的归属写成「现在住这里，回填触发条件是类型面」**：签名本质是类型面事实，而类型面
   尚未落库（hld §6.2）。文档现在必须写出签名，所以由符号表这一处书写；类型面回填那天改为投影，
   与 `SANDBOX_INJECTED_API_SYMBOLS` 同一条纪律。**这是本票留的一个开放回填点**，不是已收口的事实。
3. **七码全落在「丢弃」，且「异常」那一类刻意不给码**。若将来沙箱执行器要让某些情形在 tick 内以返回值
   报出「整 tick 被判罚」，那要改的是后果行（新增一行 + 挂码），不是给现有码改类——这类改动的触发
   条件是引擎实现本身，不是文档需求。
4. **判别示例放在生成区块内**，而散文（脚本形态、`loop()` 骨架、快照面、异常披露）一律留 `TODO(→…)`
   占位并指明去处（票 07 / 08 / 10），不代笔。示例之所以例外：它引用的每个名字都要与符号表对上，
   放进区块才能让「改了真源忘了改示例」在生成器上非零退出。
5. **`ERR_NOT_ENOUGH_RESOURCES` 的 `reason` 里那句「唯一在来源文档里被点名过」留在表里**：它是给读者
   的来源标注，不是触发条件的一部分；删它要改真源（票 02 的交付物），本票只在散文里不再复述。
   同时把 `getMyIndex` / `isError` 两条 `reason` 里对交接单编号的引用换成了面向模型的措辞。
6. **表格单元的竖线转义提到 `emit.ts` 的 `tableCell`**：签名里的联合类型必然带竖线，而每件生产函数
   各写一份 `replaceAll` 就是排版零件的第二份（`rules-value-table.ts` 改为引用它）。
