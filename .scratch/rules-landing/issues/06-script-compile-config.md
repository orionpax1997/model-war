# 06: 参赛脚本的编译配置落库

**What to build:** 参赛脚本在什么类型环境里编译，这件事从「文档里的一句话」变成**一份能被 tsc 直接吃掉的配置**。全仓库白名单反转的承载就靠它：脚本在一个不含 DOM、不含任何类型包、只额外引入脚本 API 类型声明的环境里编译，「找不到这个名字」就是精确的白名单反转。配置不存在，这条防线就不存在。

这份配置**定在规则落库这一格**（它离契约面比离管线面更近），**由生成管线实现**（照它编译）。落定之后，静态校验器那条「解析层源形态比入口契约宽」的待办票解锁。

**实测约束（TypeScript 7.0.2，2026-10-04）**：本仓库的 TypeScript 7 **已移除 `outFile`**，且 `--module` 的合法取值里**没有 `none`**。单文件 script-mode 产物要走「输出目录 + 单文件输入」。探针实测 `preserve` / `esnext` / `commonjs` 三种模块取值对无 `import` / `export` 的源文件产出**逐字相同**的裸脚本，因此模块取值只需选一个不自引入模块语义的。

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] 配置落在仓库根、与根编译基座同一层；**不落进包目录**（包里那份是包配置，不是脚本配置）、**不做成真源包的生成物**（它的身份是编译器输入，没有任何仓库代码 import 它）、**不落进文档目录**
- [x] **刻意不继承仓库的编译基座**。脚本跑在沙箱里，要的是最小 ECMAScript + 脚本 API 类型声明；继承了就等于把 Node 类型带进沙箱，白名单反转当场漏。这条要有用例钉住：一份引用 Node 专有名字的脚本**编译期就红**
- [x] 入口签名的类型约束在配置里生效：顶层声明入口函数、返回类型可省略、单文件自包含
- [x] 类型环境里**只额外引入脚本 API 类型声明**，而那份声明的字段**不预填**——形状家已定在真源包，内容由对局内核与沙箱执行器回填。本票只保证配置指向那个家
- [x] 用一份真脚本跑一遍配置：产物是**裸脚本形态**（无 `import` / `export` / `require`），`loop` 是函数且调得动。这条把「产物里不会有模块语法」从运行时实测发现提前成配置层的可判定事实
- [x] 文档侧归属修正：架构文档 §6.2 编译那一行现写「参赛脚本的编译配置归生成管线的编译步骤」，与本票、以及静态校验器那张待办票的触发条件**对不齐**——改成「配置由规则落库这一格定、生成管线按它实现」
- [x] 收尾时写明解锁条件：静态校验器那条待办票（解析层源形态比入口契约宽）现在可以动了，**但不由本票实施**

## Answer

### 落点

- `tsconfig.scripts.json`（根层，与 `tsconfig.base.json` 同一层）——配置本体
- `packages/tools/src/script-compile-config.test.ts`——配置的五条用例，全部落在外部可观察面（tsc 退出码、诊断文本、产物内容、裸上下文里的执行结果）
- `packages/tools/src/version-control-boundary.test.ts`——产物目录能入库的那条断言（`git check-ignore`）
- `packages/tools/src/gates.test.ts`——「这份配置在格式门禁的覆盖范围内」那条红 → 还原 → 绿
- `package.json`（`fmt` 路径列表多一个文件名）、`docs/hld.md`（§6.2 编译那一行 + §2.2.2 共享编译基座那一行）

### 票面之外的几条判断

1. **配置是编译选项的基座，不是可直接跑的项目**（`files: []`）。`tsc -p` 不能与源文件同命令行出现（**TS5042**，本轮实测），而脚本路径每次编译都不同（`archive/<model>/<runId>/`、`benchmarks/<name>/`），所以生成管线将来按它派生一份只覆盖 `files` 与 `outDir` 的运行配置。`files` 置空还有第二层作用：留空则默认 `include` 是 `**/*`，这份配置会把整个仓库吞进一个 program；置空之后直接 `tsc -p` 它报 **TS18002**，即它自己拒绝被直接跑（有用例钉住）。
2. **`outDir` 取 `script-products/`，不叫 `dist`**。`.gitignore:5` 的 `dist/` 是无锚点规则、命中任意层级，而 hld §7.4 要求编译产物入库——同名即入库不了。`version-control-boundary.test.ts` 里正反两条一起断言。
3. **脚本 API 的类型面只留指针，不落空壳文件**。配置里 `types: []` 并写明家已定在真源包 `@model-war/schema`、字段由对局内核与沙箱执行器回填。没在真源包里替他们落一个空的 `.d.ts`：空壳文件会把「字段落在哪个文件里」这件事提前钉死，而那正是回填那一格的决定（先例是 `SANDBOX_INJECTED_API_SYMBOLS = []`——空值留在它自己的家里，不搬到用它的配置旁边）。指针腐烂的风险由行为兜住：`types` 一旦长出第二项（尤其 `"node"`），Node 名字那条用例立刻变红。
4. **`module` 取 `esnext`**，本轮复跑过探针：`preserve` / `esnext` / `commonjs` 对无 `import` / `export` 的单文件源产出逐字相同的裸脚本（`"use strict";` + 原样函数体）。另配 `moduleResolution` 刻意不设：脚本不从任何地方取模块，于是脚本里写下的任何 `import` 都在编译期红（「单文件自包含」的编译期那一半，有用例钉住）。
5. **「顶层声明入口函数」这一半不由配置判定**。配置的作用是清空类型环境，它无从要求某个名字出现（`noUnusedLocals` 那条路是反的：它会把每个合规脚本的 `loop` 报成未使用）。它在生成管线的编译步骤里查产物（`typeof loop === "function"`），配置这一侧只保证不逼人写错形状——返回类型可省略，这一点在 hld §6.2 同一行一并对齐了。
6. **`docs/hld.md` §2.2.2「共享编译基座」那一行补了一个指针**（参赛脚本那份刻意不继承它，理由见 §6.2）。不补的话，§6.2 那条「不继承」在一个只读 §2.2.2 的人眼里是无源的。

### 解锁条件（不由本票实施）

**静态校验器那条待办票现在可以动了**：`.scratch/script-validator/issues/08-parser-source-form-too-wide.md`（解析层源形态比入口契约宽，`parseToAst` 对 script 形态按 `lang: "ts"` 解析）。它的触发条件原文是「参赛脚本的编译配置（脚本 tsconfig，归 E）落地」，本票落地的 `tsconfig.scripts.json` 就是那个条件，所以那张票从「现在做会判死一个还没交出来的东西」变成「可以动手」。**本票不改 `parse-source.ts`、不动那张票的任何一行**——收紧的形态与落点（解析层改 `lang`，还是在入口处显式声明源形态）是那张票自己的裁决项，判据写在 hld §6.2。

顺带交给 15 号票的两件事（本票刻意没碰）：DAG 里 D-08 那两行状态，以及静态校验器节点规格里「接线归 E」那条指针——都属文档对账那一格。
