# 06: 参赛脚本的编译配置落库

**What to build:** 参赛脚本在什么类型环境里编译，这件事从「文档里的一句话」变成**一份能被 tsc 直接吃掉的配置**。全仓库白名单反转的承载就靠它：脚本在一个不含 DOM、不含任何类型包、只额外引入脚本 API 类型声明的环境里编译，「找不到这个名字」就是精确的白名单反转。配置不存在，这条防线就不存在。

这份配置**定在规则落库这一格**（它离契约面比离管线面更近），**由生成管线实现**（照它编译）。落定之后，静态校验器那条「解析层源形态比入口契约宽」的待办票解锁。

**实测约束（TypeScript 7.0.2，2026-10-04）**：本仓库的 TypeScript 7 **已移除 `outFile`**，且 `--module` 的合法取值里**没有 `none`**。单文件 script-mode 产物要走「输出目录 + 单文件输入」。探针实测 `preserve` / `esnext` / `commonjs` 三种模块取值对无 `import` / `export` 的源文件产出**逐字相同**的裸脚本，因此模块取值只需选一个不自引入模块语义的。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 配置落在仓库根、与根编译基座同一层；**不落进包目录**（包里那份是包配置，不是脚本配置）、**不做成真源包的生成物**（它的身份是编译器输入，没有任何仓库代码 import 它）、**不落进文档目录**
- [ ] **刻意不继承仓库的编译基座**。脚本跑在沙箱里，要的是最小 ECMAScript + 脚本 API 类型声明；继承了就等于把 Node 类型带进沙箱，白名单反转当场漏。这条要有用例钉住：一份引用 Node 专有名字的脚本**编译期就红**
- [ ] 入口签名的类型约束在配置里生效：顶层声明入口函数、返回类型可省略、单文件自包含
- [ ] 类型环境里**只额外引入脚本 API 类型声明**，而那份声明的字段**不预填**——形状家已定在真源包，内容由对局内核与沙箱执行器回填。本票只保证配置指向那个家
- [ ] 用一份真脚本跑一遍配置：产物是**裸脚本形态**（无 `import` / `export` / `require`），`loop` 是函数且调得动。这条把「产物里不会有模块语法」从运行时实测发现提前成配置层的可判定事实
- [ ] 文档侧归属修正：架构文档 §6.2 编译那一行现写「参赛脚本的编译配置归生成管线的编译步骤」，与本票、以及静态校验器那张待办票的触发条件**对不齐**——改成「配置由规则落库这一格定、生成管线按它实现」
- [ ] 收尾时写明解锁条件：静态校验器那条待办票（解析层源形态比入口契约宽）现在可以动了，**但不由本票实施**
