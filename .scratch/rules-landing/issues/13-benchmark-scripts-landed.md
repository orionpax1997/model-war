# 13: 基准脚本落库

**What to build:** 三份基准脚本进基准目录，连同**编译产物**与一份说明表。里程碑对基准脚本的验收口径是「双脚本对打一个对局、断言正常终局」，所以库里必须有产物：收紧源形态之后校验器判的就是产物，门禁跑的就是产物，库里没有产物就等于每次跑门禁多一道构建——而门禁的第一印象必须是「clone 完直接能跑」。

**不落存档元数据**：它的形状家已定在真源包、字段由生成管线那一格回填，现在写就是「半截字段比没有更坏」——真源包里对这类东西有一条明令，本票不能破。

**Blocked by:** 06（脚本编译配置）、12（三舱盲写）

**Status:** ready-for-agent

- [ ] 每份脚本落**源码 + 编译产物**两份；产物是配置真跑出来的，不是手写的
- [ ] 一份说明表：策略标签（**行为描述，不是能力评级**）、模型标识、生成参数、静态校验结果、契约版本
- [ ] **不落存档元数据**；说明表里**不写半截字段**，位置留着并注明由哪一格回填
- [ ] 按既有先例排除：标定环的采集探针**不进**（它不是参赛脚本）、某模型的零产出存档**不进**（失败记录不是基准）
- [ ] 「占点不采集」那舱的标签按旧一轮的修正写（**不是**农民海），且说明表里给出这个标签的行为依据——这正是它比另外两舱有信息量的地方
- [ ] 三份脚本的**体积分列记录**，因为脚本体积上限的取值要以它们的最大值为下限
- [ ] 脚本里的每个 API 名字都在符号表里、契约文档里——落成机器断言（沿用已有那条，不另立）
- [ ] 编译产物里的入口函数可被调用（用脚本执行器那一层的既有实测手段断言，不用第三方库行为落仓库测试）
- [ ] 契约版本写进说明表：**换契约版本时基线脚本的重跑规则写清**（是重跑还是保留，见说明表里那一行说明）
