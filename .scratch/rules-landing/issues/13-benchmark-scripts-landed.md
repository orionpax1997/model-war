# 13: 基准脚本落库

**What to build:** 三份基准脚本进基准目录，连同**编译产物**与一份说明表。里程碑对基准脚本的验收口径是「双脚本对打一个对局、断言正常终局」，所以库里必须有产物：收紧源形态之后校验器判的就是产物，门禁跑的就是产物，库里没有产物就等于每次跑门禁多一道构建——而门禁的第一印象必须是「clone 完直接能跑」。

**不落存档元数据**：它的形状家已定在真源包、字段由生成管线那一格回填，现在写就是「半截字段比没有更坏」——真源包里对这类东西有一条明令，本票不能破。

**Blocked by:** 06（脚本编译配置）、12（三舱盲写）

**Status:** resolved

- [x] 每份脚本落**源码 + 编译产物**两份；产物是配置真跑出来的，不是手写的
- [x] 一份说明表：策略标签（**行为描述，不是能力评级**）、模型标识、生成参数、静态校验结果、契约版本
- [x] **不落存档元数据**；说明表里**不写半截字段**，位置留着并注明由哪一格回填
- [x] 按既有先例排除：标定环的采集探针**不进**（它不是参赛脚本）、某模型的零产出存档**不进**（失败记录不是基准）
- [x] 「占点不采集」那舱的标签按旧一轮的修正写（**不是**农民海），且说明表里给出这个标签的行为依据——这正是它比另外两舱有信息量的地方
- [x] 三份脚本的**体积分列记录**，因为脚本体积上限的取值要以它们的最大值为下限
- [x] 脚本里的每个 API 名字都在符号表里、契约文档里——落成机器断言（沿用已有那条，不另立）

- [x] 契约版本写进说明表：**换契约版本时基线脚本的重跑规则写清**（是重跑还是保留，见说明表里那一行说明）

## Answer

### 类型面未回填时，编译产物怎么办（本票最需要交代的一件）

**做法：照常编译、照常落盘，产物入库；“编译是否通过”这件事改判“诊断属于哪一类”。**
不替后续那一格填类型面，也不在仓库里偷偷写一份 `.d.ts`。

理由与机制：

1. `tsconfig.scripts.json` 刻意不设 `noEmitOnError`（票 06 的配置里没有这一项，本次一个字没改），
   所以 `tsc` 在“类型面未声明”的情形下**照常 emit**。那份产物就是门禁与生成管线将来真正加载的东西。
2. 于是「产物是真跑出来的」这句话的机器形态不是“人记得跑过 tsc”，而是**逐字节可复现**：
   `packages/tools/src/benchmarks/run-benchmarks-gate.ts`（根脚本 `check:bench`，挂在 `check` 末尾）
   拿入库的源码重跑同一条命令，与入库产物逐字节比对，不同即红。反例是“只改产物的最后一个字节、
   不动源码”——那正是“手改过”与“编译出来的”的分界。
3. 编译非零退出的诊断被分成**三类**，三类之外任何一条都判红：
   - **名字未声明**（TS2304 / TS2552，40 / 25 / 17 条）——**类型面未回填的账**。名字逐个都在
     `SANDBOX_INJECTED_API_SYMBOLS` 里（由 `benchmarks.test.ts` 断言），回填那天这一类必须归零，
     那是回填那一格的验收信号；
   - **形参隐式 `any`**（TS7006，0 / 0 / 11 条）——cell-c 自己辅助函数的形参没标注，与类型面无关；
   - **可能为 `undefined`**（TS18048，0 / 4 / 0 条）——cell-b 自己按下标取值，与类型面无关。
   把后两类混进第一类等于替回填那一格把账赖掉，所以门禁与测试都分开报数，报告里看得见。
4. 落库的是**编译产物**，不是手抄的产物，也不是“等类型面回来再落”——后者会让基准目录在类型面回填
   之前一直是空的，而里程碑的验收口径正是拿产物对打。

**派生运行配置只覆盖 `files` 与 `outDir`**（票 06 定的用法），编译在系统临时目录里做，
与 `script-compile-config.test.ts` / `api-example-compile.test.ts` 同一形态：
临时目录在仓库之外，模块解析一路向上够不到本仓库的 `node_modules`，“模块解析面被清空”在这里是真的。

### 票面之外的判断

1. **`benchmarks/` 不进 `oxfmt --check` 的路径列表**（探索笔记把它列为一个待裁决的选择点）。
   理由是三条脚本是**证据**：格式化器改它们一个字节，产物就与源码分叉，盲写那一轮的原件也就没了。
   代价是这三份没有格式保证——它们是冻结产物，不需要。
2. **登记册用字面清单**（`BENCHMARK_NAMES`），不是“读目录再数”：数目对了不等于集合对了，
   与真源包那几条键数断言同一纪律。目录里多出任何文件即红（含探针、零产出存档、半截 `meta.json`）。
3. **注入面空值桩一个 API 名字都不写**：桩的返回值由 `SANDBOX_INJECTED_API_SYMBOL_CATALOG`
   每一条的 `signature` 推导（`number` → 0、字面量联合 → 第一个候选、`…[]` → `[]`、`void | ErrResult` → `null`…）。
   桩不是对局模拟器，只回答“产物能不能被加载、入口能不能被调”；用的是 `node:vm` 的裸上下文
   （与 `script-compile-config.test.ts` 同一手段），**没有把第三方库的沙箱行为落进仓库测试**。
4. **“裸脚本形态”按语句开头匹配，不按子串找**：cell-a 的头注逐字写着 “No imports/exports”，
   按子串找会在一份完全合规的产物上报红，而这种假红很容易被“改个正则糊过去”处理掉。
5. **`gates.test.ts` 里既有的那条「漂移检查挂在全量门禁末尾」断言改了写法**：原来判的是
   `check` 以 `pnpm run check:drift` **结尾**，本票加了第二道末尾门禁后那条就红了。
   改成判“末尾两步里含它”——纪律（末尾那几道是提交内容复核）不变，而“谁排最后”不再被当成纪律。
6. **产物与源码并列放在同一个目录**（`script.ts` + `script.js`），沿用 `archive/<model>/<runId>/` 的先例；
   目录名不叫 `dist/`，所以过得了 `.gitignore` 那条无锚点规则（已实测 `git check-ignore` 不命中）。
7. 舱内交付名是 `script.v1.ts`、终稿契约的交付名是 `script.ts`，入库用后者；生成参数一栏里记了舱内那个名字。
