# 11: 终稿盲写 prompt 基座

**What to build:** 盲写用的 prompt 基座按终稿契约重写。基座是模型看到的**唯一**任务说明（隔离舱里它读不到别的东西），所以基座里每一句过时的话都会直接变成一份不合规的脚本。

旧基座里有两处与终稿直接冲突的句子：「从快照认出自己（二选一：候选 A 容器顺序 / 候选 B 自标记）」——终稿只有一个正式入口；「轮转方向为假设（待终稿确认）」——终稿已定死。这两处不改，重跑出来的脚本必然踩已清零的坑。

**Blocked by:** 07、08、09、10（两份契约文档的散文定稿）

**Status:** ready-for-agent

- [ ] 「二选一自认候选」整段删除，换成**单一入口的调用方式**；基座**不留「记下你选了哪种候选」这类回答要求**
- [ ] 「轮转方向为假设」的措辞删除，改成终稿结论；**回答要求里那条「记下你对轮转方向的假设」一并删掉**（不改会让模型把一个已定的事当悬案写进注释）
- [ ] 硬约束列表与终稿逐条对齐：单文件自包含 + 入口签名 + 返回类型可省略、无模块语法、禁确定性污染源与宿主桥前缀、全整数运算、只调文档里的 API、跨 tick 只存数值 id 与模块级变量
- [ ] 错误判别 helper 的用法进基座硬约束（用两个 helper 显式判别，不用类型判断或真值猜）
- [ ] 「每 tick 只读快照、不另行告知你的 index」改为「入口函数就是取 index 的唯一入口」
- [ ] 三支策略取向**等长、同详细度**，只换一行方向性要求；沿用旧基座那条纪律：方向性要求不得违背文档硬约束、不得照抄文档里的验收口径反推编排
- [ ] 基座**留在本 feature 的工作目录**，不进生成管线的提示词数据文件目录（那是后续那一格的交付物）
- [ ] 基座**随附的契约正文就是落库后的那两份文档**，不是草案的副本——重跑跑的是终稿，这是这一整轮的全部意义
- [ ] 基座自身零过时表述：逐句过一遍，凡指向草案内容（候选形态、假设方向、待终稿确认、待某图定值）的句子**删或改**，不留「见上文」这类悬空指针
