# 14: 契约自证与等效命题 ② 的复验

**What to build:** 一条命令回答四个外部可问的问题：

1. 三份基准脚本**零静态违规**（契约没有把合规脚本判死）；
2. 三份都**打出正常终局**，不被判负出局；
3. 三份的**消耗中位数都落在总储量的四分之一以内**——这一条就是规则侧挂账的那笔账，等效命题 ② 的复验；
4. 三份的**取策略互不相同**（区分度的可观测代理：若三份脚本的行为指标收敛到同一形态，规则集就还没被证明有区分度）。

复验跑在**标定环那个已经跑过 1336 场的桩**上，桩**不搬不修**——搬桩等于改一个已经产出记录的证据源，动了那些记录就不可复现。本票的产品写在自己的工作目录里，只引用桩的代码。

**Blocked by:** 13（基准脚本落库）

**Status:** resolved

- [x] 一条命令跑完上面四问；断言对象是**外部可观察行为**，不是生成器排版、不是区块抽取实现、不是规则表每一行
- [x] 复验结论**引用两条口径**：(一)「整局约四百四十」那个数是单矿储量 125 时代、全矩阵平均，**不是「四份基准脚本」的数**（基准脚本口径实测三百五十一）——这条命题的松紧度是被储量那一刀改掉的，不是被地图改掉的；(二) 种子维度对消耗指标**零方差**，每臂的有效独立样本只有 4 个座位轮转，**不得写成「128 场独立样本」**
- [x] 复验的矩阵与标定环那一轮**同夹具、同臂数**，否则数字不可比；跑正表前先过夹具闸门
- [x] 每问**各有一个能被弄红的反例**：把配额改小 → ③ 变红；把一份脚本换成违规脚本 → ① 变红；三份换成同一份 → ④ 变红
- [x] 换一份契约版本 → 这条缝仍绿，但**四问的取值会变**；这一点在说明里写清，避免后来者把取值当回归基线
- [x] 复验结论**不覆盖 ① 号命题**（枯竭窗口落在 400–600）：它的返工方向是重推窗口、触发条件是「出现一个移动层不同的探针」，属规则侧后续工作。本票在文档里**只留指针**
- [x] 结论落成规则侧记录的更新：**只更新已过的那一条**，另一条的状态与触发条件一字不改
- [x] 桩的取数口径若与三份脚本的实际情况不符（口径是旧四舱的），**记下来而不是悄悄换口径**——换口径的代价是新旧结论不可比

## Answer

### 一条命令

```bash
pnpm run check:selfproof                    # 门禁：四问的退出码 + 报告文本（挂在 check 末尾最后一道）
pnpm run check:selfproof --out=.scratch/rules-landing/selfproof   # 同一次跑批，另落证据三件
```

产品落在 `packages/tools/src/selfproof/`：`contract-compat.ts`（兼容层）、`questions.ts`（四问判据，纯函数）、
`run-selfproof-gate.ts`（夹具闸门 → 矩阵 → 汇总 → 报告 → 退出码，同一文件兼 `--worker` 分片进程）。
报告与证据：`.scratch/rules-landing/selfproof/{report.md,summary.json,matches.json}`；
指针写进 `benchmarks/README.md` §7 与 `docs/hld.md` §2.2.7 门禁表。

**跑在标定环那个跑过 1336 场的桩上，桩一行未改。** 终稿契约比草案代多的四个 API 名字
（`getMyIndex` / `isError` / `errCode` / 7 个 `ERR_*`）与两个查询面变化（`site.producing`、
`getObjectsByType('player')`）由**宿主侧兼容层**补齐，走的是桩自己的扩展点
（`SCRIPTS[].inject`，标定环自己的探针就这么用），加载路径、结算管线、指标口径都没动。
补法与残余偏差逐条记在 `contract-compat.ts`，不静默换口径。

### 矩阵与臂数（与标定环那一轮同夹具、同臂数）

4 臂 × 4 个座位轮转 × 4 颗种子（`SEEDS_PROBE` = 11/23/41/71）= **64 场**：
三张真图 `open-clash` / `corridor-split` / `fortress-core` + 一张无墙夹具对照
（`center-fortress@64`，点位布局与三张真图逐格相同），`resourcePerSite=200`、`tickLimit=600`、
开局矿一圈。四席三份、重复席位给 B，四轮转之后每个座位各当一次 A/B/C。
**跑正表前先过夹具闸门**：`farmer6` 四方自战 `p100=479/479/479/479`、`delivered=3080/3080/3080/3080`，
与 map-pool、标定环两轮冻结的锚点逐字一致（0% 漂移），漂了就不跑正表。
`mirror` 取 `false`：终稿有 `getMyIndex()`，M1 那套镜像补丁在这里是空操作。

### 四问的实际取值

| 问 | 判据 | 实际取值 |
| --- | --- | --- |
| ① 零静态违规 | 静态校验器入口（子进程 + 退出码，`--phase freeze`）逐份判产物 | **三份退出码全 0**；`--max-bytes 8831` |
| ② 正常终局 | 每席 `exceptionTicks` 为 0 且终局原因属正常三种 | **64 场 / 256 席，异常 tick 合计 0**；终局 `shortcut×28 / victory×24 / timeout×12` |
| ③ 消耗 ≤ 总储量 1/4 | 每份脚本**每席位**消耗的中位与最坏单席都 ≤ 800 | **A 中位 220（6.9%）／B 96（3.0%）／C 0（0.0%）**；最坏单席 A 380（11.9%）／B 200（6.3%）／C 0；全批最坏单场 616（19.3%）；`0/64` 超配额 |
| ④ 取策略互不相同 | 每一对在 9 项行为指标上至少 3 项相对差 ≥ 25% | **A-B 分开 8/9、A-C 8/9、B-C 6/9** |

③ 的口径：消耗 = 全图储量 − 终局剩余，逐场校验**恒等于全场采获之和**（自洽校验逐场相等），
而采获逐席位可归因，所以「某份脚本消耗多少」取该脚本名下席位的采获；分母是总储量
3200（16 矿 × 200），配额 1/4 = 800。逐臂整场（与 gdd §8 记录 #13 那一轮可比的口径）：
无墙对照 12.9% / `open-clash` 14.0% / `fortress-core` 16.0% / `corridor-split` 16.1%，
离配额还有 **1.30 倍**余量（按最坏单场算）。

④ 的判据与读数：9 项 = 采获、交付、农民峰值、单位峰值、终局近战数、农民占比、占点次数、
终局名次、淘汰率，逐份取每席位中位（两个占比在读数阶段就乘 100 成了百分点），成对相对差取
`|x−y| / max`。三份指纹——A 采获 220 / 农民峰值 2 / 终局近战 8 / 占点 23 / 名次 1；
B 96 / 6 / 0 / 0 / 3；C 0 / 2 / 0 / 0 / 2——确实是三种打法，不是同一形态换名字。

### 三个反例（都真跑过，红 → 还原 → 绿）

| 反例 | 怎么弄红的 | 实际结果 |
| --- | --- | --- |
| ③ | `--quota-percent=6`（配额改小到低于 A 的实际消耗中位 6.9%） | 退出码 1，报告 `③ … **不过**`；`契约自证门禁:红（① 过 ② 过 ③ 不过 ④ 过）`；A 中位与最坏单席双双不过 |
| ① | `--script-a=<违规脚本>`：一份带 `Math.random` / `Date` / `performance` / `__` 宿主桥 / 浮点的产物 | 退出码 1，报告 `① 零静态违规：**不过**`，并带上静态校验器自己的原文（禁列全局名 3 处 + 宿主桥前缀 1 处）；② 顺带也红（该脚本整 tick 抛异常） |
| ④ | `--same-script`（三份换成同一份） | 退出码 1，报告 `④ 取策略互不相同：**不过**`，`A vs B：分开 0/9 项`（三对全 0）；③ 也顺带红（三份都爆兵时整场消耗更高） |

三条都落在 `packages/tools/src/gates.test.ts` 的 `gates` project 里，成对跑「红 → 同参数还原 → 绿」。
**矩阵规模两条路线**（这是后一条 commit `f801bcb` 改的，本节原先写的是「三条都跑整张矩阵」，
与实现相反，已按实现更正）：

- **③ 与 ① 跑缩矩阵**（`--probe`：1 臂组 × 1 座位轮转 × 1 种子 = 4 场，夹具闸门照跑，判据一字不改）。
  它们要证明的是「改这一项，门禁会红」，而红不红在小矩阵上照样判得红；判不出红时
  `gates.test.ts` 里那条 `toBe(1)` 会当场红，不会静默放过。
- **④（`--same-script`）跑全矩阵**，连同它的还原。它要证的是「三对都掉到 **0/9** 项」——一个关于
  **指标**的论断：小矩阵只有 4 场，采样噪声会混进来（淘汰率那一项就是这么混进来的），拿它判不出
  「三对全 0」这个事实。

基线绿那一条（四问全绿）始终跑全矩阵：四问的**读数**只能来自全矩阵，缩矩阵上的读数不是读数。
这一节改动把 `test:gates` 的墙钟从 894s 降到约 517s。

### 两条必须随引用一起带的口径（报告抬头也逐字带着）

1. 「整局 ≈440」是**单矿储量 125 时代、全矩阵平均**的数，**不是「四份基准脚本」的数**；
   基准脚本口径实测 **351**。这条命题的松紧度是被储量那一刀改掉的，不是被地图改掉的。
   本轮数字另起一代（终稿契约 + 终稿基准脚本），与 440 / 351 都不可互比。
2. **种子维度对消耗指标零方差**，每臂的有效独立样本只有 **4 个座位轮转**；本轮每臂 16 场
   = 4 轮转 × 4 种子，**不得写成「16 场独立样本」，更不是「128 场独立样本」**。

### 换契约版本

判据不变、**门禁仍绿是正常的**，而**四问的取值会全部变**：报告末尾与 `benchmarks/README.md` §7
都写明了这一点，避免后来者把本轮数字当回归基线。③ 的配额是判据不是读数——总储量变了配额跟着变，
跨版本比绝对量同样是错的。

### ① 号命题只留指针

**本票不覆盖 ①**（枯竭窗口 400–600）：它的返工方向仍是重推窗口、触发条件仍是
「出现一个移动层不是无墙感知贪心的探针」，`docs/gdd.md` 记录 #13 里 ① 的状态与触发条件**一字未改**。

### 票面之外的发现

1. **桩缺 `getObjectsByType('player')` 这一档，不补就会造出一条假读数**：三份脚本**都**用它读自己的
   `resources`；桩只认 `'unit'` 与 `'site'`，于是 `players[me]` 是一个点位对象、`.resources` 是
   `undefined`，`myRes >= 4` 恒假——**cell-b 一辈子不下单**，它的行为读数会纯粹由桩的缺口造成。
   补法是宿主账本（初始资金 + 下单扣款 + 交付入账），与引擎真值只可能分叉两处，报告逐批给出规模：
   本轮**产线忙被拒 328 次、基地易主退款 4 次**（64 场合计）。这属票面明令「记下来而不是悄悄换口径」。
2. **桩的快照没有终稿的 `site.producing`**：不补的话 `base.producing !== null` 恒真，三份脚本一条单都不下。
   补法是脚本自己的订单簿 + `getTick()` 过期，与标定环老脚本的做法同形（cell-a 当年就是这么记账的），
   所以不引入新口径；残余偏差两处（出兵格被占时的挂起、基地易主时的退款）同样逐批报数。
3. **`scriptSizeLimit` 仍是占位 0**，所以①的 `--max-bytes` 取的是三份入库产物的最大值 8831（地板值），
   报告里写明是哪一种；预算键回填之后这一栏会自动改走规则值。
4. **C 舱 94% 的席位是被战斗淘汰的**（经济死亡且不可逆是它自己的设计），这不是判负：② 判的是
   异常 tick 与终局原因，淘汰条款不在其列。报告把淘汰率单列成 ④ 的一项指标，正是为了让这件事可见。
5. **本轮逐臂消耗中位（12.9%–16.1%）高于 #13 那一轮的 10.4%–12.0%**：两代脚本不可互比，
   方向上说明终稿三份脚本（尤其 B 的扩张采集）比草案四份采得更凶。② 的余量从 1.74 倍收到 1.30 倍，
   仍然过，但**这条余量比 #13 记的那一版薄**。
6. **全量门禁因此离开秒级**：同机单次实测 `check` 墙钟 95s（契约自证自己 84s，6 路并行），
   `check:quick` 一项未受影响。数字与理由写进 `docs/hld.md` §2.2.7，明确标注是观测项不是承诺。
7. **并行与串行逐字一致**：同一份矩阵串行跑 227.4s、6 路并行 82.7s，两次的消耗与拒单读数逐字相同
   （328 / 4），所以分片没有引入不确定性。
