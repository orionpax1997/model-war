# 02: 沙箱注入 API 符号表——收录判据与回填

**What to build:** 真源包里那张**刻意留空**的沙箱注入 API 符号表拿到一条可判的收录判据，并按判据回填成终稿 API 面。这一票是本 feature 的技术核心：面向模型的那份契约文档要**直接进 prompt**，而静态校验器已经立了纪律说「参赛脚本能用什么，一个名字都不许自己存」——那张表空着，这条纪律就只剩注释。

收录判据一句话：**收脚本能在运行时当值用到的名字。**

- **收**：查询函数、动作函数、座位自认入口、两个错误判别 helper、错误码字符串。
- **不收类型名**（单位类型、意图种类这类）：它们不占全局，是类型面上的名字，而「API 误用」那条判据本来就是读类型面。两张脸各管一件事。
- **不收数值**：预算类与兵种类数值归规则集文件那条生成链，已经是另一张表。收在这里等于同一份事实两个家。

**收尾时顺带改掉真源侧的注释**：它现在写着「刻意为空，回填触发条件是沙箱执行器产出注入面」。那已经是历史陈述，留着会让后来者把它当成待办而跳过。

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] 收录判据写成**一句可判的陈述**并落在真源侧的同一个文件里，与逐个「为什么收」的理由放在一起；判据没有第三种形态、没有例外口子
- [x] 表按判据回填；**逐个名字带一句为什么收**（判据的实例），让人能一眼看出加名字的门槛
- [x] **类型名入表即红**——落成一条机器断言，不靠注释约束。这条是本票的核心护栏：类型名一旦被当成符号塞进来，类型面与符号面就分叉成了两个家
- [x] 错误码字符串在表里，与函数同表；`ERR_*` 的命名在这一票定死
- [x] 与内置全局白名单、与禁列的**不相交**各落成机器断言（宿主桥前缀的名字一条都不许进这张表）
- [x] **这张表不被静态校验器的任何规则消费**——显式记下：校验器判「这个名字存不存在」是编译器名字解析的职责，那一侧读的是类型面；两侧不得互相引用为依据
- [x] 沙箱执行器那一格回来填的是「怎么注入」，**不是「注入哪些名字」**——那条交接话术在本票的产物里改掉
## Answer

判据（真源侧逐字）：**收:脚本在运行时能把它当值用到的名字。** 表由
`SANDBOX_INJECTED_API_SYMBOL_CATALOG`（名字 + 类别 + 一句「为什么收」）唯一持有，
`SANDBOX_INJECTED_API_SYMBOLS` 是它的投影（名字只有一处可改）。

**22 个名字**：查询 6（`getTick` / `getObjectById` / `getObjectsByType` / `getRange` /
`getTerrainAt` / `findPath`）、动作 6（`move` / `moveTo` / `attack` / `harvest` /
`transfer` / `spawnUnit`）、座位自认 1（`getMyIndex`）、错误判别 helper 2（`isError` /
`errCode`）、错误码 7（`ERR_NOT_ENOUGH_RESOURCES` / `ERR_INVALID_UNIT` / `ERR_NOT_OWNER` /
`ERR_OUT_OF_RANGE` / `ERR_INVALID_TARGET` / `ERR_INVALID_SITE` / `ERR_BAD_ARGS`）。

`ERR_*` 命名规则：`ERR_` 前缀 + 失效原因的全大写名词短语，一条原因一个码，按动作函数做界检查
时能查出的那一件事命名，不按返回值形状命名。`ERR_BASE_BUSY` **不收**（重复下单是静默丢弃，
那一格由快照的 `producing` 字段供给，交接单「`ERR_BASE_BUSY` 可查询化」裁决）。

核心护栏落两半，都验过有牙：编译期是 `InjectedSymbolKindsExcludeType`（类别联合里加一档
`"type"` → `tsc -b` 非零退出），运行期是逐字类型名清单断言（加一条 `{ symbol: "UnitType", … }`
→ 两条用例同时红）。

交给沙箱执行器(G)的那一格：**填「怎么注入」，不是「注入哪些名字」**；G 若要改名，是改本表
并重跑 `pnpm run generate`。
