## Answer

**票据之外接进来的三处**（前三票的发现，本轮一并对上）：

1. **入口签名的第二个家**。`docs/hld.md` 有两处抄了参赛脚本入口的签名形态（§2.2.2 与 §6.2），而签名形态的家是面向模型的 `docs/rules-v1/api.md` §1.1（返回类型可省略）。两处都改成指针：hld 只留它对工程侧有约束的那一面（单文件、无模块语法、入口名固定），形状不再抄第二份。**钉了**一道窄门禁 `packages/tools/src/doc-homes.test.ts`：禁那一个签名形态的字面量（`function loop`），不禁 `loop()` 这个名字——那四份文档里「四方 `loop()` 串行执行」是正常工程叙述。门禁带一条正向对照断言（家那份确实写着签名且写着「返回类型可省略」），不是「没人写签名」的空断言。
2. **`test:gates` 的耗时没有家**。`docs/hld.md` §2.2.7 只记了 `check` 离开秒级（契约自证自己 84s），`test:gates` 一处未记，而票 14 的反例缩矩阵把它从 894s 降到约 517s——一条没人记的门禁耗时改动，下次有人改回去也没人知道代价是多少。补进 §2.2.7，并把 84s 更到 82s。两条都是观测项，不是承诺。
3. **交接单在代码注释里还被当依据引**。`packages/schema/src/ruleset-keys.ts` 有七处 `handoff §1 / §2.1`。那些记的是「这个键当初被谁裁定」的来历，不是当前事实的引用，所以在该文件头注加一段：交接单已作废，这里的引用一律是历史出处，取值真源只有 `rulesets/vN.json`。没有逐处改写——改写会毁掉来历信息。

**`docs/rules-v1/rules.md` §5「占领」这处唯一真卡点的处置**：**该节正文归 gdd《占领机制》（§3.2），已在**；缺的是面向模型那一节的散文，而终稿是生成物、手改要走重跑生成器那一路，归下一轮。规则侧**不缺机制**，缺的是契约面那一节——盲写三舱猜出两种互斥机制（「单位站上点位格」与「停在相邻格即累积」）是因为那一节写着「本节未排期」，而 API 表里确实没有占领动作函数，所以占领只能靠位置被动触发、「什么位置」正好落在空着的那节里。**正确的机制是 §3.2 那一版**（单格单驱动者、单位站在点位格上即驱动、累积达 `captureTicks` 易主并清零、转轨重计无侵蚀、无人站立不衰减），模型当时无从知道——这是排期缺口，不是规则歧义。这条读数落在 gdd §8 记录 #14（含影响面与回流条件：§5 落库后要把三舱脚本按真机制复跑一遍），srs 的 FR-10 AC1 加一句缺口指针，DAG 的 E 节点与 §6 缺口表各指一次。**没有凭空造新文档**，`docs/rules-v1/rules.md` 一个字没动。

**机器缝**：一道（`doc-homes.test.ts`，上面第 1 条）。另外把已有的收窄门禁 `rules-doc-prose.ts` 的扫描集合从「只有 `rules.md` 一份」扩到两份契约文档 + 四份设计文档 + `CONTEXT.md`，并加一条断言「别把最要紧的那两份从名单里改没了」。**gdd 不进这个集合**：它里面那些数字是标定环那一轮的证据口径（「这一批 1336 场跑在 `resourcePerSite=200` 上」），删掉会毁掉记录的可比性纪律，理由写在该模块头注里。其余几处对账结论钉不住也没必要钉，写进文档指针即可。

**参数取值一个数字都没往文档里放**——只对账了「有没有哪份文档抄了一份会漂的取值」，答案由那道收窄门禁给出：六份文档的生成区块之外都没有「键名绑数字」的赋值形态。
### 复核：这两道新门禁越不越界（复审提的判断题，结论是**不越界**，两道都留）

复审说 `doc-homes.test.ts` 与 `rules-doc-prose.ts`「是对散文内容做断言、且每次 `check` 都跑」，
而 spec《Testing Decisions》写了「**散文段的内容不测**」与漂移判定「**复用既有门禁，不加新门禁**」。
核了一遍，结论是两道都**不属于**那两条，写清理由：

**一、它们断言的是「形状有没有第二份」，不是「这段散文写得对不对」。**
逐条看这两道缝的判据：

| 断言 | 判据形态 | 它在问什么 |
| --- | --- | --- |
| `doc-homes.test.ts` 禁 `function loop` 字面量 | 正则 `function\s+loop`（摘掉反引号后逐篇匹配） | **这一个签名形态**在五份文档里出现了没有 |
| `doc-homes.test.ts` 家那份的对照断言 | 同一个正则 + 一句字面量 `返回类型可省略` | 家确实写着签名（防「没人写签名」的空断言） |
| `rules-doc-prose.ts` 禁键名绑数字 | 键名清单（从 `RULESET_KEY_CATALOG` 推）× 一条固定的连接件正则 | 「键名 + 数字」这个**赋值形态**在生成区块之外出现了没有 |
| `rules-doc-prose.ts` 放行清单 | 同一套正则的负例（时间段、格点坐标、倍数关系） | 那些不是手抄取值 |

没有一条在说「这句散文质量不够」「这里应该换个说法」「这段解释读者会看不懂」——
那才是 spec 排除的「散文段的内容」。它们问的全是**同一个事实有没有第二个家**，
而那正是本 spec 的第一条纪律（`AGENTS.md` 的「每个事实只有一个家」）。
spec 排除散文内容测试，原因是散文的质量证据是三舱盲写（模型读不懂就写不对）；
而这两道缝判的是「有没有人把一个契约事实抄了第二份」——盲写抓不到那个，
盲写只会让模型照着一张过期的第二份写脚本，**且过程里没有任何一步会红**。

**二、「复用既有门禁，不加新门禁」那一条管的不是它们。**
spec 那句话在《缝》的第 2 条里，上下文是**漂移检查的区块判定**：真源改了不重跑生成要判红。
漂移检查逐字节比的是**生成区块**，而它按设计**不比区块外的散文**
（理由写在 `generate/artifact.ts` 头注：逐字节锁死整份文档等于让人不敢改文档）。
这两道缝填的正是漂移检查**声明不覆盖**的那块地：散文里的第二份。
所以它们不是漂移检查的重复实现，是它边界之外的那一半。
若把它们算成「漂移检查的新门禁」，那就得让漂移检查去比散文——那才是与 spec 冲突的方向。

**三、`check` 每次都跑这件事本身不是问题。**
两道都在 `unit` project（`vitest.config.ts` 的 `include`），即 `check` 会跑——
但它们不做构建、不 spawn 子进程、**不跑门禁**（那在 `gates` project），
实测 3 条 + 7 条用例共约 1.1s，其中大部分是 vitest 自身的 transform。
`check` 里比它们贵得多的是 `tsc -b` 与依赖巡航。一道会让人不敢改文档的门禁，
贵的那部分不是「跑得慢」，是「红一次就得有人回来改」——而这两道的误报面已经被各自的放行清单压住了。

**四、唯一一处可以再讨论的地方，如实记下来。**
`doc-homes.test.ts` 那条正向对照断言里有一句字面量 `返回类型可省略`。
它是「家那份确实是家」的根据（形状本身谁都写得出，这句才是它作为家的理由），
但它确实把**家那份散文里的一句话措辞**钉住了：改写 §1.1 那句话而意思不变，门禁会红一次。
这一处是**有意保留**的：它是那道正向对照的全部价值所在，去掉它，
剩下的就只是「五份文档没有签名」——而那正是它要防的「恒绿」失败模式。
留着它的代价是改写家那份那一句要连测试一起改，这个代价换来的是那道断言不可能空转。

**结论**：两道都留，理由如上。判据的边界仍然窄：它们只禁**那一个字面量形态**与**那一种赋值形态**，
不判断任何一句散文的对错。
