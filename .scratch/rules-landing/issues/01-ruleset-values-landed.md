# 01: 规则集取值落库

**What to build:** `rulesets/v1.json` 第一次有了内容——21 个键，13 个定稿键取标定环的终值，8 个预算键取未定值占位。它必须能被真源包现有的 ajv 校验通路收下，版本断言与派生量断言全过，于是「规则集有取值」这件事第一次变成机器可读的事实，而不是散落在一张一次性 markdown 表里的抄本。

这一步做完之后，标定环那张交接单里「取值真源是 `rulesets/v1.json`」这句话才第一次指向一个真实存在的文件。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 21 个键一个不少，键名与真源包的键清单逐字一致；键数不对时**校验器拒收**而不是接受一份缺键的规则集
- [ ] 13 个定稿键取交接单 §1 的终值；派生规则（生产耗时 = 造价 × 0.5 上取整、满产烧钱率）**不作为独立键出现**，它们是公式
- [ ] 8 个预算键取未定值占位，且**「未定」由键自己身上的状态标记**，不由「值是不是 0」推断
- [ ] 内存软阈（硬判罚线的 0.8 倍）**不出现在文件里**，它是由另一个键推导出来的展示项
- [ ] 开局资源点归属**不作为键**——它是地图侧的不变量，由地图声明与地图校验器断言
- [ ] 读入端校验这条通路能跑通并给出带定位的诊断：**刻意不接进任何子命令的装载路径**（那个调用点随对局执行器落地），也不新增子命令
- [ ] 用一条可执行的断言证明「这份文件里的键集 == 真源包的键清单」，两个方向都查（缺键、多键）
- [ ] 记录事实并收口：`FR-10 AC2` 的「错配拒跑」与「读入端强制校验」**仍按尚未兑现记**，机制已定死、差的是接线，不是设计
