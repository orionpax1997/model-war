# 04: 规则文档的数值表区块

**What to build:** 规则文档里那张数值表第一次**由规则集文件生成**。规则侧定案的 21 个键、以及派生出来的兵种表，在这里对模型呈现成一张可读的表；而 8 个预算类键**渲染成「未定」而不是 0**。

这一票是「取值真源只有一个家」这句话的兑现点：文档里的数字不再是人抄的，改真源即改文档，不改真源而改文档会被漂移检查判红。

**Blocked by:** 01（规则集取值落库）、03（区块形态）

**Status:** ready-for-agent

- [ ] 数值表成成区块挂进规则文档；**同一份内容生成两次**（规则文档里的数值表与 API 文档里的数值常量表引同一处真源），不是两处各自维护
- [ ] 13 个定稿键渲染成**数字**；8 个预算键渲染成「未定」
- [ ] 「未定」的判据是键身上的**状态标记**，不是「值是不是 0」——`0` 在别的键上完全可能是真取值，判据写成 `value === 0` 就会把两者混成一件
- [ ] 兵种表（造价 / 生命 / 伤害 / 射程 / 速度 / 生产耗时）由四兵种键生成，**生产耗时那一列是按公式算的**，不是抄进去的第二份
- [ ] 内存软阈**出现在文档的表里**（它是推导展示项，模型该看到它），但**不出现在规则集文件里**——两者的分工在文档上一句话说清
- [ ] 漂移检查覆盖这个区块：改规则集文件里的值而不重跑生成器 → 判红；手改区块正文 → 判红
- [ ] 文档里凡是引用某个键的地方，改键名即改文档——**不留下手抄的第二份**
