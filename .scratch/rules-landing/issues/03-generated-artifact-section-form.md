# 03: 生成物的区块形态与按区块比对的漂移检查

**What to build:** 生成器从「一整份文件都是生成物」扩到「一份文件里的某一段是生成物」。真源产出一段带标记的正文，漂移检查按标记把工作树文件里对应的区块抽出来逐字节比，区块外的散文不比。

这一步是为了让规则文档能挂生成表格。`rules.md` 与 `api.md` 都是散文占七成篇幅的混合文件，逐字节比不了；而 hld 已经明写这两份文档的**表格部分**由真源包与规则集文件生成——现有机制只支持整文件，承诺兑现不了。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 一件生成物能以区块形态产出：真源返回标记 + 正文，标记是**稳定的串**，不随内容变化（漂移检查按它做 git 路径与状态判定，报告按标识指认）
- [ ] 漂移检查新增一段判定：按标记抽区块、与真源产出**逐字节比**，不一致判红
- [ ] **标记被手改 → 判红**；**整段被删 → 判红**；**整段被删后检查无事可做 → 判红**。这三条是同一件事的三个面：绕过检查的路只有「让检查没东西可查」这一条
- [ ] 现有两件整文件生成物的判定**行为一字不变**——这票是加一种形态，不是改一种形态
- [ ] 生成头注释沿用既有的「勿手改 + 真源在哪 + 为什么规则层读的是生成物」三件套，**不复述收录判据**（判据随真源走）
- [ ] 门禁自测落在既有的那一层（每道门禁的退出码与反向用例，单独一个 project，不混进全量门禁）
- [ ] 区块正文过格式化门禁：要么生成器复刻打印宽度的判断，要么生成物本身就是格式化器会产出的形态——**形态分叉会让 `pnpm run fmt` 当场变红**，那是提示改生成器，不是提示手改生成物
