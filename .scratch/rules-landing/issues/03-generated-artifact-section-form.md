# 03: 生成物的区块形态与按区块比对的漂移检查

**What to build:** 生成器从「一整份文件都是生成物」扩到「一份文件里的某一段是生成物」。真源产出一段带标记的正文，漂移检查按标记把工作树文件里对应的区块抽出来逐字节比，区块外的散文不比。

这一步是为了让规则文档能挂生成表格。`rules.md` 与 `api.md` 都是散文占七成篇幅的混合文件，逐字节比不了；而 hld 已经明写这两份文档的**表格部分**由真源包与规则集文件生成——现有机制只支持整文件，承诺兑现不了。

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] 一件生成物能以区块形态产出：真源返回标记 + 正文，标记是**稳定的串**，不随内容变化（漂移检查按它做 git 路径与状态判定，报告按标识指认）
- [x] 漂移检查新增一段判定：按标记抽区块、与真源产出**逐字节比**，不一致判红
- [x] **标记被手改 → 判红**；**整段被删 → 判红**；**整段被删后检查无事可做 → 判红**。这三条是同一件事的三个面：绕过检查的路只有「让检查没东西可查」这一条
- [x] 现有两件整文件生成物的判定**行为一字不变**——这票是加一种形态，不是改一种形态
- [x] 生成头注释沿用既有的「勿手改 + 真源在哪 + 为什么规则层读的是生成物」三件套，**不复述收录判据**（判据随真源走）
- [x] 门禁自测落在既有的那一层（每道门禁的退出码与反向用例，单独一个 project，不混进全量门禁）
- [x] 区块正文过格式化门禁：要么生成器复刻打印宽度的判断，要么生成物本身就是格式化器会产出的形态——**形态分叉会让 `pnpm run fmt` 当场变红**，那是提示改生成器，不是提示手改生成物

## Answer

**形态写在类型上**：`GeneratedArtifact = WholeFileArtifact | SectionArtifact`，判别字段 `form`。
两种形态的身份与落点（`id` / `path`）一字不差，差别只在 `produce()` 返回什么——整文件返回全文，
区块返回 `{ marker, content }`。加第三种形态时消费点在编译期就断（`artifact.produce()` 的返回
类型不再落到任何一支），而不断在运行期「安静地按错的形态处理」。

**机械只有一份**（`generate/section.ts`）：`readSection` 抽、`writeSection` 填，共用同一条正则。
分成两份的后果不是多一处要改，是「生成器写的」与「检查比的」不再是同一段东西，而漂移检查会一直
绿着，因为它压根没在检查那块地方。

**三条绕过面全落在「抽不出区块」这一支**，`readSection` 三态（`found` / `unmarked` /
`unterminated`）里**没有一态是「没事可做」**：标记被手改、整段被删、只删一端，各自按漂移报红，
报告里带 id、路径与那一行标记。

### 逐条对着验收条款

| 条款 | 落点 | 怎么验的 |
|---|---|---|
| 区块形态产出 + 稳定标记 | `artifact.ts` 的 `Section` / `SectionMarker`、`section.ts` 的 `sectionMarker(id)` | 门禁自测的探针**取自 `sectionMarker(id)`** 而不是另抄字面量——默认形状因此不是没人走过的死代码 |
| 按标记抽区块逐字节比 | `run-drift-gate.ts` 的 `consistencyFindings` | 改正文 → 判红，报告含「区块与真源不一致」+ 那一行标记 |
| 标记被手改 / 整段被删 / 无事可做 | 同上 + `readSection` 三态 | 四条反例各判一次红：改标记、删整段、删末行标记、删落点文件 |
| 整文件形态行为一字不变 | `form: "whole-file"` 只是给两件既有生成物补上判别字段 | `gates.test.ts` 里那六条既有漂移用例原封不动、票 02 重跑过生成器的新状态下仍全绿 |
| 三件套 + 不复述判据 | `artifact.ts` 的 `SectionArtifact` 头注把三条纪律挂在生产函数上 | 本票不新增生产函数（那是票 04），纪律写在下一个实现者必读的那一处 |
| 门禁自测落在既有那一层 | `packages/tools/src/gates.test.ts`（`--project gates`），新增两条用例 | 断言只有退出码与报告文本片段；探针按字节还原，红 → 还原 → 绿闭环 |
| 区块正文过格式化门禁 | 排版零件仍只有 `emit.ts` 一份（`PRINT_WIDTH = 100`），`section.ts` 明写不重排版 | 本票没往区块路径上加任何宽度判断，`pnpm run fmt` 全绿 |

### 票面之外的几条判断

1. **`section.ts` 不单独测**（spec《Testing Decisions》明写「区块抽取器不单独测」）。它上面就是门禁自测那几条缝。改用**反向证据**证明缝有牙：把 `unmarked` 折算成 `found`、把 `unterminated` 折算成 `found`、把区块比较换成整份比较，三处各跑一次 `test:gates` 都变红。
2. **「落点不存在」与「落点上没有标记」分开报**。两者处方不同（先建文件 / 把标记写回去），合成一句会把人指向一个他改不动的结论。生成器两条都非零退出，报告说得出是哪一种。
3. **生成器不猜落点**：目标文件里没有完整标记就抛错非零退出，不硬填。猜出来的正文会让工作树看着像跑过生成器，那比不跑更坏。
4. **标记重复出现不在检查面里**。抽取取第一个命中，所以一份文档里若把同一区块复制了第二份，第一份仍被逐字节比、第二份自由漂移。它不构成「让检查没东西可查」，票面的三条面都堵住了；但它是这条机制的一个已知边界，写在 `section.ts` 的标记纪律里（独占一行、只出现一次）。
5. **② ③ 两刀对两种形态一视同仁**：它们只看 `path`。所以一份挂了区块的文档，改了散文没提交也会被 ② 报红——这是「未提交」而不是「散文漂移」，与「区块外的散文不比」是两件事，hld 里一并写清了。
6. **`docs/hld.md` 三处对齐**（票 06 的先例）：§2.2.5 的三段判定补一段「两种形态、两种口径 + 标记即新的绕过面」，§2.2.5「文档生成」那一行点明散文/表格是同一份文件里的两种所有权所以取区块形态，§3.1 的 `tools:generate` 行把注册表那件的字段从三个改成四个。不补的话「每件 = id、产出路径、生产函数」在一个只读那一行的人眼里是过时的。
