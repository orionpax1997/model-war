# 07: API 契约（一）——脚本形态、座位自认与跨 tick 记忆

**What to build:** API 文档的散文部分改写第一批。看完这一票，模型能写出一份**在形态上完全合规**的脚本：单一入口函数、一种写法、一个正式的座位自认入口、以及关于「什么能跨 tick 记」的明确禁令。

这一批裁掉的是那轮措辞裁决里**最会让模型卡住的几条**：座位自认从「在快照里二选一猜」改成单一正式入口（实测四方跑同款位置法脚本会互相误判）、源码形态与交付名的记法自洽（只留一种写法并写明返回类型可省略，不留候选）、对象身份不跨 tick、同一单位一 tick 只留最后一个意图。

**Blocked by:** 05（错误码全定与 API / 常量表区块）

**Status:** ready-for-agent

- [ ] 座位自认只留**一个正式入口函数**，语义钉进错误码表（对非己方单位返回、沙箱内即时返回），但**不**把它写成「可以用它自认座位」
- [ ] 附录明确写上**「不要靠单位位置反推座位」**并给出理由（位置法在四方对称局里互相误判）
- [ ] **候选二选一的措辞删除干净**——不留「二选一」「任选其一」「见上文」这类指向已不存在内容的句子
- [ ] 脚本形态只留**一种写法**并写明「返回类型可省略」；**不留候选形态、不留「另一种写法」**
- [ ] 交付名与源码形态自洽（源码是单文件 TS，交付名与入口字面不打架）
- [ ] 跨 tick 记忆的禁令写成正面可执行的说法：**只存数值 id 与自己的模块级变量，不缓存对象引用、不缓存查询结果**
- [ ] 「同一单位一 tick 提交多个单位级意图 → 只留最后一个，静默丢弃，不计异常」写进形态约束
- [ ] **文档里每一个可运行示例都真能编译过**（用 06 落下的那份配置）。这是本票唯一的机器缝，但它把散文从「读起来对」变成「跑起来对」
- [ ] 例子里的每个 API 名字都在符号表里——沿用 05 那条断言，不在本票另立一份
