## Answer

**散文落在 §7 与 §8 两节**，§10 一个字没动（它是生成区块，`check:drift` 逐字节比它）。§7 拆成 `7.1 终局形态` / `7.2 胜利与淘汰` / `7.3 超时与名次`，§8 拆成 `8.1 必知` / `8.2 建议知` / `8.3 不披露`——**小节标题就是三层本身**，读者不用从措辞里推断哪句属于哪一层。

### 三层披露各写了什么

- **必知（§8.1，两句 + 一条对照）**
  1. 某一 tick 抛异常（含调用了契约里不存在的 API）**或**超出本 tick 计算预算 → 该 tick 在 `loop()` 里提交的全部意图**丢弃**（单位原地待命）+ 给该方**记一次异常**；只影响你一方，累计值快照可读。
  2. 累计达 `exceptionTickLimit` → **判负出局**，按 §7.2 淘汰规则处理、点位回归中立、判定顺序照 §7.2 那一串。
  3. 对照句（不是第三条判罚，是消歧）：意图被判无效而**丢弃**的（重复下单、无效攻击，见 §4.4 / §6.2）**不计异常**——不写这句，模型会把 §4.4 的静默丢弃当成判罚。
- **建议知（§8.2）**：异常与超预算**不清模块级记忆、不重建脚本环境**，下一 tick 从原处继续；**只有引擎级故障**（极罕见、脚本不可触发）才重建，那时模块级记忆清零；异常计数随对局状态持久化，重建/中断后**续算不清零**（否则反复失控可绕开淘汰）；耗时只作观测不参与判罚，卡死则整场作废重跑/剔除、**不判负**。
- **不披露（§8.3）**：只有「**每 tick 有计算预算上限，超限视同异常**」（后果同 §8.1 第一条）+ 取值引 §10；第二句点明「计数的粒度、内存读数的口径**不在本契约披露**」，并把它转成一条用法提醒：别拿任何实现细节当可依赖的边界来设计脚本。**这一层零个数**——没有「每 N 次事件一格」、没有内存读数字段名、没有墙钟毫秒口径。

### 两条警告句的最终形态（都在 §7.1「读法」下，与终局形态同处）

- **近战最强，不等于只爆近战**：近战是等成本对拼的性价比标杆，这是设计定位（回指 §6.1），不是「唯一解」判据。实测方向：四份盲写脚本里两份收敛到爆兵压制；唯一会造骑兵的那份成绩更差，但差距与模型档位/严谨度完全混淆、**归因不成立**；机制层受控对照显示「守点 + 抢中立点」打法下造骑兵是劣势（兵力送去切农、放弃守点）。所以能得出的只有一句「会玩速度才造它」，并明写**这不等于近战爆兵已被证实是全场景唯一解**（该缺口仍开着）。
- **超时名次不要照着反推策略**：实测方向上临近终局时各方单位数没有净增长、也没有一次性丢掉大批单位的情况——**「屯兵 / 卖兵等超时」这个动机实际并不存在**。
- 两条之后统一给指针：gdd §8 规则侧记录 #7 / #9 / #10，并声明「那批数字出自标定环的一次跑批，是**证据不是契约**」。

### 票面之外的判断

1. **两条桩证据按「不带数字」写，是把两个条款的冲突按后者裁的**：票面 checkbox 写「终局前 100 tick 单位净增中位 0、一次性弃掉八个以上单位的席位占比极低」，同一张票的收尾条款写「桩证据要么省掉、要么以『实测方向』的形式出现而**不带数字**，数字留在规则侧记录里」。后者是硬约束（且被门禁方向一致地支持），所以文档写「没有出现净增长 / 没有一次性丢掉大批单位」+ 指针，数字留在 gdd §8 记录 #9。「证据补上」按**方向 + 可追指针**兑现，不是按把数字抄进文档兑现。
2. **两条警告句都放 §7.1，没拆散**：草案里它们同属附录「别照约束反推策略」那一条，终局形态段也在同一处；它们的共同点正是「拿标定证据反推策略」。近战那条内部回指 §6.1 的设计定位，读者从兵种节过去能找到落点。拆到 §6.1 会让 §6.1 变成「设计约束 + 一条策略读法」的混装节，而那一节票 09 刚定过「约束是给调参者的判据，不是脚本要遵守的东西」。
3. **墙钟放「建议知」而不是「不披露」**：判罚侧的事实（不参与判罚、卡死整场作废而不判负）对脚本作者是可执行的，「口径」我按阈值与测量方法理解，所以前者不带数写进 §8.2。票面把「墙钟只观测」列在不披露那一侧，若判为串层，删掉 §8.2 最后一条即可，§8.1 与 §8.3 不依赖它。
4. **发现一处上游张力，未动**：§10 生成表里 `eventTickLimit` 的说明已经写着「以循环回边 / 函数调用 / 函数返回为一格累计」、`memoryTickCeiling` 写着「每 tick 末 `runGC()` 后的存活堆读数」——这两句正是「不披露」层要压掉的计量口径，但它们是**生成物**（真源是 `packages/schema/src/ruleset-keys.ts` 的键清单，归票 04 建立的生成面与票 15 的对账），本票不碰生成源。本票能保证的是散文侧不重复、不加强它。
5. **`check:drift` 的第二刀会拦未提交的散文改动**：它按生成物路径跑 `git diff --quiet HEAD`，散文改动在提交前必然报红。所以本票的顺序是「写散文 → 提交 → 跑 `pnpm run check`」，`pnpm run check` 在干净树上绿。§10 区块内容本身自始至终与真源一致（漂移报告里没有「区块与真源不一致」那一条，只报了未提交差异）。
6. **交叉引用补了三处**（§4.1 储量、§4.3 经济死亡、§6.1 兵种定位、§4.4/§6.2 丢弃不计异常），都是正文里已写定的事实，指向不改它们；票 09 的「存活单位总造价分」称谓在 §7.3 按同一口径下了定义并注明不分兵种，窄称「军事单位」零残留。
