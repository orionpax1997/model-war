# 08: API 契约（二）——快照面与错误面

**What to build:** API 文档的散文部分改写第二批，也是「快照里有、API 面里没有」这条缺口的收口。

草案的快照形状里写着玩家的资源、存活、异常计数，产线的当前订单，以及「自身下标」——但 API 面没有供给它们，于是模型被迫**在脚本里自己记一份队列**。实测那条路的代价是 69% 的下单被静默拒掉。这批改写把三样东西都变成读得到的：玩家侧三项、产线当前订单、以及那个正式的座位自认入口。

错误面同批收口：给两个必须显式判别的 helper 加可运行示例，返回什么形态由真源包定，**文档禁止让模型用类型判断或真值去猜**。

**Blocked by:** 05（错误码全定与 API / 常量表区块）、07（脚本形态与座位自认）

**Status:** resolved（一条验收条款按未兑现记，见下方 Answer）

- [x] 快照字段补进 API 面：玩家侧三项（资源、存活、异常计数）与产线的当前订单都能读到
- [x] 产线订单的供给方式写在文档里：**开局就有、在快照里**，模型不必自记队列
- [x] 「重复下单被静默丢弃、不扣款、不计异常」与「该产线一次一个订单」两句话都在，且**与产线订单字段同时出现**——只写前半句会让模型以为是自己没跟上
- [x] 两个错误判别 helper 有**可运行示例**，示例里的形态与真源包定的形态逐字一致
- [x] 文档里**明写禁止**用类型判断或真值去猜一个返回值是不是错误，并给一句为什么（那两类判断在两种返回形态下都可能给错答案）
- [x] 「丢弃 vs 异常」对照表已按新的错误码形态重写（05 产出的码表与这张表逐条对齐）
- [ ] 快照形状的字段名与真源包定的字段名**逐字一致**——草案那行「字段名以终稿为准」的免责句在终稿里删掉（**条款未兑现**，另一半已兑现，理由见下方 Answer）
- [x] 文档里每一个可运行示例都真能编译过（沿用 06 的配置）
- [x] 快照面不得出现「你自己是几号」这类**要求模型反推**的表述——入口函数是唯一入口

## Answer

### 快照形状落在**散文里的类型声明块**，不做生成区块

**落法**：`docs/rules-v1/api.md` §2.1 一段手写的 ```ts 围栏（`UnitType` / `Player` / `Unit` /
`Site` 四个 `type`），全仓**只有这一处**列字段。

**理由**（三条，按分量排）：

1. **生成区块的前提是「真源已经存在」，而这一格的真源恰好还不存在。** §3 那几张表能生成，是因为
   符号表（`packages/schema/src/script-surface.ts`）**已经是**一个可枚举的数据目录。快照形状没有
   这样一个已存在的真源：要么在真源包里新开一份——那是**替「类型面回填」那一格写类型声明**
   （票面明令 Out of Scope，且 hld §6.2 已把「API 误用」那条判据判给类型面）；要么写进生成器——
   那是把「形状」这个事实的家从真源包搬到渲染器，与 §3 的纪律正相反。两条路都在类型面回填之前
   抢先落一份将来必被替换的声明。
2. **回填那天的动作是「改投影」，不是「加一份」。** 触发条件是类型面里那些声明存在的那天；到那时
   本段与 §3 的签名一并改为从那份声明投影（那时它才有资格做成生成区块）。今天先做成生成块，等于
   在中间态里养一份「注定被整体替换的生成物」，而漂移检查会在那段时间里把「两份清单不一致」的
   报错误导到渲染器上。
3. **硬要求只有一条：模型必须能从这份文档读出字段名与语义。** 手写块是唯一无条件满足它的形态——
   它进 prompt、它自带每一行的注释、不依赖任何生成步骤。

**回填时的去处**：`packages/schema` 里那份脚本 API 类型声明（hld §6.2 已定家，内容由对局内核与沙箱
执行器回填）。回填后 §2.1 这一段与 §3 的签名一起改为从它投影，届时再把它做成生成区块也不迟。
在那之前**字段名不改**——本段写死一句承诺：改字段名要走一次有意的变更，像改一个错误码名那样。

### 票面之外的判断

1. **改了真源的两处签名，因为不然就没有「读得到」这回事。** 验收条款要「都能读到」，而 22 个名字
   定稿时 `getObjectsByType` 只支持 `'unit' | 'site'`——玩家侧三项在**任何**入口下都拿不到（P0-N3
   的原文就是「快照字段有、API 面缺」）。两条路：新增一个 `getPlayers()`，或给
   `getObjectsByType` 收第三档 `kind`。**选后者**：注入面维持 22 个名字（票 02 的逐字清单与其
   「加名字要走一次有意的变更」护栏一个字都不用动），而这个函数本来的定位就是「同一个快照值的批量
   入口」，多一档类型是它的本职而不是新职责。三个 filter（`owner` / `type` / `kind`）对 `'player'`
   不适用——玩家没有 owner、没有兵种——§2.2 因此给的是「读回四行再按 `index` 挑自己那行」。
2. **`getObjectById` 的返回类型去掉了 `Production`。** 产线状态按 P0-N3 折进 `site.producing` 之后，
   快照里不再有独立的 `Production` 对象；留着它会让模型去找一个取不到的东西。同一处顺带说明
   `producing` 是**快照侧的投影**（引擎内部仍按 `productions` 队列维护，hld §4.1）。
3. **`remaining?: number` 收进快照**（仅资源点）。这是笔记 05 点名的「快照与 `GameState` 的差集」之一：
   草案与 hld §4.1 都有，`packages/engine` 的空壳 `Site` 漏了。**裁成收**——模型要不要扩张取决于矿
   还剩多少，缺这一栏等于让它只能按拍脑袋估。**对账点**：`packages/engine/src/index.ts` 的 `Site`
   补上这一栏（那是内核那一格的事，本票只落文档侧并写明字段来源）。
4. **`producing` 定成必填的 `… | null`，不是可选字段。** 可选意味着模型还要分「键不存在」与
   「键在但是空」两种写法，而它要的判据只有「空 / 不空」一种；`null` 让判据是一行 `=== null`。
5. **`ErrResult` 的承载形态在文档里刻意不展开。** 它是类型面事实、尚未回填；不展开反而是那条禁令的
   **根据**——形态都没披露，猜形状必然是错的。§2.3 把这一点写成了理由，而不是免责声明。
6. **顺带核了 §3 与 §4 两块生成区块的一致性**：错误码七行、两类后果、六行情形与我写的散文逐条对齐，
   唯一需要动的是 §3 两行签名（走生成器）。§5 数值表零改动。

### 未兑现的那一条：「快照形状的字段名与真源包定的字段名逐字一致」

**勾选改为未勾选。** 这一条写的是「与真源包逐字一致」，而真源包那边**压根没有这个形状**：
- `packages/schema/src/script-surface.ts`（注入面符号表）只有名字、签名与一句触发条件，**没有快照形状**；
- `packages/engine/src/index.ts` 是内核那一格的空壳，它的 `Site` 里**没有 `producing`**、**没有 `remaining`**，
  产线还是一个独立的 `Production` 类型——与 §2.1 那段声明逐字对不上；
- 脚本 API 的类型声明面（hld §6.2 已定家）**尚未回填**。

所以「逐字一致」今天无处可比。本票原先的记法（"`Player`/`Unit`/`Site` 与 `packages/engine/src/index.ts`
逐字一致"）是**不成立的**，已改掉。

**另一半仍然兑现**：草案那行「字段名以终稿 schema 生成为准」的免责句**没有被抄进终稿**——模型读到的是
一份逐字段列全、每行自带语义的声明，不是「以别处为准」的指针。

**回填那天的动作**：类型面回填（对局内核与沙箱执行器那一格）之后，本条连同 §2.1 那段一起改为从那份
声明投影，届时逐字一致才有可比的对象。**这一格不去 `packages/engine` 补这个形状**——那是内核那一格
的活，本格硬补会让「回填那天改成投影」变成「回填那天才发现有两份」。

**§2.1 的散文同步改了**：原文那句「这份类型块与真源包逐字一致」是一句假话（引擎侧对不上，见上），
现改成实话——这段类型块目前是**契约侧的声明**，投影尚未建立；并写明回填那天它才改成投影。
