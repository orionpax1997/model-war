# 08: API 契约（二）——快照面与错误面

**What to build:** API 文档的散文部分改写第二批，也是「快照里有、API 面里没有」这条缺口的收口。

草案的快照形状里写着玩家的资源、存活、异常计数，产线的当前订单，以及「自身下标」——但 API 面没有供给它们，于是模型被迫**在脚本里自己记一份队列**。实测那条路的代价是 69% 的下单被静默拒掉。这批改写把三样东西都变成读得到的：玩家侧三项、产线当前订单、以及那个正式的座位自认入口。

错误面同批收口：给两个必须显式判别的 helper 加可运行示例，返回什么形态由真源包定，**文档禁止让模型用类型判断或真值去猜**。

**Blocked by:** 05（错误码全定与 API / 常量表区块）、07（脚本形态与座位自认）

**Status:** ready-for-agent

- [ ] 快照字段补进 API 面：玩家侧三项（资源、存活、异常计数）与产线的当前订单都能读到
- [ ] 产线订单的供给方式写在文档里：**开局就有、在快照里**，模型不必自记队列
- [ ] 「重复下单被静默丢弃、不扣款、不计异常」与「该产线一次一个订单」两句话都在，且**与产线订单字段同时出现**——只写前半句会让模型以为是自己没跟上
- [ ] 两个错误判别 helper 有**可运行示例**，示例里的形态与真源包定的形态逐字一致
- [ ] 文档里**明写禁止**用类型判断或真值去猜一个返回值是不是错误，并给一句为什么（那两类判断在两种返回形态下都可能给错答案）
- [ ] 「丢弃 vs 异常」对照表已按新的错误码形态重写（05 产出的码表与这张表逐条对齐）
- [ ] 快照形状的字段名与真源包定的字段名**逐字一致**——草案那行「字段名以终稿为准」的免责句在终稿里删掉
- [ ] 文档里每一个可运行示例都真能编译过（沿用 06 的配置）
- [ ] 快照面不得出现「你自己是几号」这类**要求模型反推**的表述——入口函数是唯一入口
