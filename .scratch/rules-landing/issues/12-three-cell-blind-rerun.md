# 12: 三舱盲写重跑

**What to build:** 三份**在终稿契约下**由模型独立写的脚本：爆兵压制 / 扩张运营 / 占点不采集。这一票烧的是机时与网关时间，没有代码产出，但它是「规则闭环与区分度成立」这句话唯一指向的证据——现有四份脚本是草案契约的产物，不是交付物。

隔离舱方案**直接复用现成脚本，不改动它**（已 smoke test 过）。舱内 agent 走它自己的认证，与模型 API 凭证那条线无关，所以本轮不受那一格的时序影响。

**Blocked by:** 11（终稿 prompt 基座）

**Status:** ready-for-agent

- [ ] 三舱各出一份脚本，**三舱互相看不见**（隔离舱里读不到仓库、读不到别舱）
- [ ] 可比性按已有纪律来：同一份终稿契约、同一份基座、同样的夹具配置；**跑正表之前先过夹具闸门**，与既有基线逐字一致才继续
- [ ] 舱内产出**核文件存在性**，不能只看进程退出码（隔离脚本在旧一轮踩过：进程正常退出但产出文件不存在）
- [ ] 每舱的原始产出、调错清单、完整会话存档留档，**按旧一轮的同一套清单收**
- [ ] 失败舱（零产出、反复崩）**照实留档，不重跑到成功为止**；留档不进基准目录，但要能解释为什么这舱失败
- [ ] 跑完给一份判读：每份脚本读出来是什么策略、静态校验零违规与否、卡在契约哪一句
- [ ] 与旧四舱的关系写清：这三份**不可与旧四舱的读数互比**（契约形态变了、移动层与错误处理都变了）；凡引用旧四舱结论的地方带上这条
- [ ] 机时与网关单流时间上限（实测约 15–20 分钟）是已知约束；思考膨胀导致超时的舱**按旧舱的处理方式**记录，不当成规则缺陷
