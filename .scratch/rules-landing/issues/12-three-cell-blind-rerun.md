### 结果

三舱都出了脚本，**无失败舱**：`cell-a`（A 爆兵压制 × deepseek-v4.1-flash，365 行）、
`cell-b`（B 扩张运营 × MiniMax-M3，239 行）、`cell-c`（C 占点不采集 × deepseek-v4.1-flash，194 行）。
用时 10.7 / 13.4 / 13.0 分钟，都在单流上限内；`cell-a` 第 14 轮撞过一次 `stopReason=length`
（`reasoning=31872`），自己续跑收尾，**按旧舱的处理方式只记一笔、不另立失败存档、不当规则缺陷**。

**判读出的策略**：a 是「留 2 个农民的近战全场扑敌」（压单位不压点位）；b 是三份里唯一有
「经济 → 占中立矿 → 转军事」完整链条的；c 是「零农民纯近战占点」，开局 16 资源出 2 近战后归零、
按 §4.3 经济死亡，靠占点与残兵继续。区分度成立，但 a 与 c 内核高度重合，分野只在留不留那两个农民。

**静态校验：零违规**（三份 err 0 / warn 0），反向对照跑过（一份故意写坏的脚本被判出 11 条 err），
确认检查器不是恒绿。**类型面本轮判不了**——脚本 API 声明面未回填，`tsconfig.scripts.json` 的 `types: []`
是刻意的空数组，拿 tsc 编译只会得到一屏 TS2304，量的是回填没做。

**卡在契约哪一句**：三份都卡在同一句 —— **`rules.md` §5「占领」整节是 `TODO(→ 机制契约:占领进度机。本节未排期)`**。
API 表里也确实没有占领动作函数，所以占领只能靠位置被动触发，可「什么位置」正好落在空着的那一节里。
三舱因此造出**两种互斥的机制**：a 让单位 `moveTo` 到点位格上（假设站得上去），b 与 c 停在相邻格
（假设站旁边即累积）。c 的整份策略建立在这个猜测上，它自己在 `FIXES.md` 里把这条列成「已知假设」。

### 票面之外的发现

1. **§5 占领进度机是本轮唯一的真卡点，且占位原文写着「未排期」**。票 07–10 那批散文落了经济、采集、
   生产、战斗轮转、异常披露、终局措辞，唯独漏了占领——这不是措辞问题，是缺一节机制。它归哪张票需要指派。
   （§1 初始条件 / §2 结算管线 / §9 确定性约束同样未排期，但这一轮实际影响为零到一：§2 那条
   「同 tick 只留最后一条单位级意图」在 api.md §1.3 写了、§1.1 的禁列覆盖了 §9，三份都照做。）
2. **「静态校验零违规」本轮只能回答一半**：可见面 / 形态 / 禁列 / 整数这四层判得了（全绿），
   类型面判不了（声明面未回填），每单位单意图也判不了（运行期语义）。
3. **本轮没走到过一次校验回喂**：三舱都是 v1 直接交、0 轮修改，静态校验器那张待办票还没实施，
   所以「≤5 轮回喂」至今是纸面机制、零实测。
4. **`cell-b` 没写 `FIXES.md`**：任务书写的是「后续每轮校验才记」，它没进校验轮所以没写。
   首次交付要不要记账，任务书没规定。
5. **模型对「未定值」的反应是保守化而不是放飞**：a、b 看到预算阈值未定后都主动削减 API 调用，
   而不是「反正不判罚就随便调」。rules.md §8.3 的披露分级起作用的正面读数。
6. **存档的 1336 场表头有两条指针在拷贝时失效**：抬头写「判读在 `../results.md`」，而标定环那一轮的文件名是
   `results-rerun.md`；同一段还写 `VARIANT_SLOT_REPS`「按 30% 概率整轨填墙」而代码里是 50%。两份都是
   **拷贝过来的生成物表头**，数字逐字未改，改它要连生成器一起改，所以本票只记录、不动。

### 「复制而非改动隔离舱脚本」的理由

票面第一句写的是「隔离舱方案**直接复用现成脚本，不改动它**（已 smoke test 过）」。执行下来的做法是
**复制成副本再改副本，原件 `.scratch/rules-calibration/blind/blind-run.sh` 一个字未动**——这是票面那句话的
唯一能同时成立的方式，理由有三层：

1. **原件是那一轮隔离条件的唯一凭据**。旧四舱连同 7 次零产出存档都是「跑在那份脚本之下」的证据；
   一旦改动它，「旧四舱跑在什么隔离条件下」这件事就没有可复现的出处了，而本票恰恰要拿本轮与旧四舱对照。
   改副本则两轮的隔离条件各自完整、各自可复现。
2. **改动不是可选的，是必然的**。终稿契约与草案契约有六处硬差异，副本头部逐条列了出来：
   投放文档从 `draft/` 四文件换成终稿两份、白名单与哈希去掉 `README.md`/`wording-risks.md`、
   `PROMPT.base.md` 换源、策略三行换词、`TASK.txt` 的交付名 `script.v1.js` → `script.ts`
   （终稿裁决：单文件 script-mode TypeScript）、`collect` 白名单跟着换交付名与哈希文件名。
   任何一处不改，舱内 agent 拿到的就不是终稿契约。所以「不改动原件」与「跑终稿」只能靠两份文件同时存在来调和。
3. **原件里那两个已知缺陷在副本里没有对应物可继承**。原件对 `draft/*` 整目录取哈希，于是 `no-risks` 舱
   也会泄露 `wording-risks.md` 存在；终稿舱只投放确定的两份，按投放物取哈希就是逐字钉住投放物。
   留着不改会把一个只在草案形态下成立的缺陷带进终稿轮。

副本落在 `.scratch/rules-landing/blind/blind-run.sh`，`CLAUDE`/docs 侧不引用它，家就在本票的落点里。
