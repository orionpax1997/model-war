## 2. 逐舱判读

### cell-a —— 读出来是「留 2 个农民的近战全场扑敌」

- 生产：每个自家基地先读 `producing`，空才下单；农民下限 2，其余全投 `melee`
  （自写 `costOf`/`attackRangeOf` 两张表，取值与 §10 逐项对得上：4/8/12/16，远程射程 2）。
- 单位行为：农民满载（`carrying >= 20`）回家 `transfer`，否则在**自家**资源点 `harvest`；
  战斗单位取**全场最近的敌方单位**，射程内 `attack`，射程外 `moveTo` 追。
- 每单位每 tick 一条单位级意图（`actWorker`/`actCombat` 的每条分支都 `return`），符合 api.md §1.3。
- **判读**：策略取向 A 的「尽早争夺与压制点位」在这份脚本里落成了**压制单位**而不是**压制点位**——
  它追的是人不是点。`nearestNonOwned` 那条「无敌人时压最近的非己方点位」的分支，在 1v1v1v1 里
  几乎走不到（四家开局就都有单位），是一段事实上的死代码。
- 静态校验：零违规（§3）。

### cell-b —— 读出来是「6 农 + 6 兵的扩张运营，占点靠停在相邻格」

- 生产：目标 6 农民 + 6 近战，都达标后继续出近战；同样先读 `producing` 空才下单。
- 农民：满载交付 → 有己方有储量的矿就采 → **没有可采的己方矿就去占最近的中立矿**，
  走到相邻格后本 tick 不提交任何意图（「站相邻格让进度累加」）。
- 战斗单位：射程内 `attack`，否则追最近敌方单位；全场无敌人时压最近的敌方基地。
- **判读**：三舱里唯一一份有完整「经济 → 扩张 → 转军事」链条的。它是唯一主动去找中立矿的。
  两处小的口径偏差：`meleeN < 6 && myRes >= 12` 把近战的门槛写成了远程的造价（§10 近战 8）；
  `spawnUnit` 的返回值整个没接（预检了余额，所以不构成违规，只是没走 api.md §2.3 那两步判别）。
- 静态校验：零违规（§3）。

### cell-c —— 读出来是「零农民纯近战占点」

- 生产：只造 `melee`，每个空产线一单，余额 < 8 停手；**全程不造农民、不调 `harvest`、不调 `transfer`**。
- 单位：射程内有敌人就 `attack`；否则用 `getTerrainAt` 在点位周围找一格 `plain` 落脚、
  `moveTo` 过去，进到相邻格后原地驻守「让占领进度累积」。本 tick 内用 `claimed[]` 避免多个单位抢同一点位。
- **判读**：是三份里最干净的一份退化形态——开局 16 资源出 2 个近战后归零，按 rules.md §4.3
  经济死亡且不可逆，它就靠占点与残兵继续（这恰好是契约 §4.3 写明的合法打法）。
  它自己把四条「文档未展开处、不替契约补写」列进了 `work/FIXES.md`，是三舱里唯一主动记账的。
- 静态校验：零违规（§3）。

**区分度**：三份读出来确实是三种打法（留经济底线的近战扑杀 / 有链条的扩张运营 / 零经济的纯占点），
不是同一份脚本换了个名字。但 A 与 C 的内核高度重合（都只造近战、都把战斗单位往点位方向赶），
真正的分野只在**留不留那 2 个农民**。旧四舱那轮里「两份收敛到爆兵压制」的现象在本轮重现了。

## 3. 静态校验

工具 `.scratch/rules-landing/blind/static-check.ts`（本轮留档，一次性）。它**不发明名单**：
可见面白名单取 `packages/schema/src/script-surface.ts` 的 `SANDBOX_INJECTED_API_SYMBOLS`，
禁列取同文件的 `FORBIDDEN_GLOBAL_NAMES` 与 `HOST_BRIDGE_PREFIX`，内置全局名与 `Math` 成员取
`packages/schema/src/builtin-globals.ts`，解析层用 `packages/tools/src/parse-source.ts`。

判的是「白名单反转」：脚本里每一个自由标识符，要么在注入面里，要么是标准 ECMAScript 纯函数，
否则判红。检查项与本轮结果：

| 检查项 | cell-a | cell-b | cell-c |
|---|---|---|---|
| 语法（`lang: "ts"` 解析） | 过 | 过 | 过 |
| 顶层 `function loop()`、零参数 | 过 | 过 | 过 |
| 可见面白名单反转（自由标识符全归入） | 过（69 个） | 过（53 个） | 过（54 个） |
| 禁模块语法（`import`/`export`/`require`）、禁 `eval`/`new Function` | 过 | 过 | 过 |
| 禁列（`Date`/`Math.random`/`performance`/`queueMicrotask`/`__*` 宿主桥） | 过 | 过 | 过 |
| 全整数（浮点字面量 0、除法 0、`Math` 成员 0） | 过 | 过 | 过 |
| 错误判别（`typeof` 0、真值猜返回值 0） | 过 | 过 | 过 |
| **合计 err** | **0** | **0** | **0** |

反向对照跑过：一份故意写坏的脚本（`import` + `Date` + `__bridge` + `eval` + `console` + `process`
+ 浮点字面量）被同一条命令判出 11 条 err，确认这份检查器不是恒绿。

**两条本轮判不了的口径，票面之外**：

1. **类型面判不了**。脚本 API 的类型声明面尚未回填（api.md §2.1 明说），`tsconfig.scripts.json` 的
   `types: []` 是刻意的空数组，于是 `getMyIndex` 这些名字对 tsc 就是未声明的——拿 `tsc` 编译三份脚本
   只会得到一屏 TS2304/TS2552，量的是回填没做，不是脚本写错。票 06 的 Answer 已预告过这条。
2. **每单位每 tick 单意图判不了**。它是运行期语义，静态层判不了；本轮只能靠人读（三份都过，
   理由见 §2）。

## 4. 卡在契约哪一句

三份脚本都读得通、零违规、也能直接编译成裸脚本——但**同一处空白把三份都卡住了**：

> **`rules.md` §5「占领」整节是 `TODO(→ 机制契约:占领进度机。本节未排期……)`。**

三舱的模型都在会话里逐字撞上这一句，然后各自猜：

| 舱 | 撞墙时的原话（节录） | 猜出来的占领形态 |
|---|---|---|
| a | 「§5 is TODO, so capture mechanics are not specified beyond `captureTicks`. We don't know how to initiate capture. Hmm!」 | 战斗单位 `moveTo` 到**点位格坐标**上（假设单位可以站上去） |
| b | 「§5 says capture progress machine - but that section is TODO. We have to infer from the field shape.」 | 走到**相邻格**后停手不再提交意图（假设站相邻即累积） |
| c | 「§5 is TODO — not written! So we don't know the exact capture mechanic… there's no `capture` function in the API table!」 | 同 b（站相邻），外加用 `getTerrainAt` 找相邻 `plain` 格落脚 |

**两种互斥的猜法（站上去 vs 站旁边），契约一句话都没裁定。** 雪上加霜的是 API 表里也确实没有
占领动作函数（生成块只有 `move`/`moveTo`/`attack`/`harvest`/`transfer`/`spawnUnit`），
所以占领只能靠位置被动触发——可「什么位置」正好落在空着的那一节里。`cell-c` 整份策略
（占点不采集）完全建立在这个猜测上。

另外两处空白，模型都看见了、都没被卡住，但都影响了写法：

- **预算阈值未定**（§10 的 `apiCallTickLimit` / `eventTickLimit` / `memoryTickCeiling` / `scriptSizeLimit`
  等渲染成「未定」）。cell-a 原话：「The budget limit being "未定" means we can't know… So we should
  minimize API calls」；cell-b：「The `apiCallTickLimit` is "未定" (undetermined). So I don't know the limit.」
  两份都因此主动削减了 API 调用（a 放弃逐格 `getTerrainAt` 环、b 不再对每个单位重复查快照）。
- **`exceptionTickLimit` 未定**意味着「离判负还有多远」没有数；`players[].exceptionTicks` 那一栏
  三份都没读——不是违规，是这条读数在阈值未知时给不出可执行的决策。

`rules.md` §1（初始条件与点位不变量）、§2（tick 结算管线）、§9（确定性约束）三节同样未排期。
这一轮的实际影响是零到一：§2 没写，但「同 tick 只留最后一条单位级意图」在 api.md §1.3 写了，
三份都照着做；§9 没写，但 §1.1 的禁列已经覆盖，三份都没碰非确定源。**真正咬人的只有 §5。**

## 6. 与旧四舱的关系：**不可互比**

标定环那一轮的 `cell-a..d` 跑的是**草案契约**（`.scratch/rules-calibration/draft/`，含 `wording-risks.md`），
交付名是 `script.v1.js`；本轮跑的是**终稿契约**（`docs/rules-v1/`），交付名 `script.ts`。
两者之间至少变了三处，每一处都会让读数失去可比性：

1. **契约形态变了**：草案的 §5 有正文（占领进度机、轮转方向的 TODO 标注、快照字段名待定），
   终稿把 §5 整节删成占位、把座位自认从「候选 A/B 二选一」钉成 `getMyIndex()` 单一入口、
   把动作函数返回值从「`ErrResult` 形态未披露」改成 `isError`/`errCode` 两步判别、
   把源语言从 `.js` 改成单文件 script-mode TypeScript。旧四舱那些「卡在座位自认」「卡在轮转方向
   假设」「卡在 `ErrResult` 怎么判」的结论**在新契约下已经不存在**，不能搬过来当本轮的卡点。
2. **移动层变了**：旧四舱是在标定环那一版移动层（无墙感知贪心）下取读数的，
   地图池那一轮重写过探针的移动层（墙感知移动、扩张车道、资源记账、扩张无目标即静止兜底）。
   契约里的 §3（移动与碰撞）这一轮又还没排期。读数因此跨了两层移动层。
3. **错误处理变了**：草案把七码全归「丢弃」，终稿把**超预算与调用不存在的 API** 归「异常」
   （该 tick 全部意图丢弃 + 累计 `exceptionTicks`，达 `exceptionTickLimit` 判负出局）。
   同样一份脚本在两套错误处理下的存活形态可能完全不同。

**因此**：本轮三份脚本的读数（策略收敛形态、零违规、卡点位置）与旧四舱的读数**不可互比**；
旧四舱那轮的胜负、交付量、经济死亡 tick 等一切数字，都不能拿来当本轮的基线或对照。
凡引用旧四舱结论的地方都已带上这条口径（`docs/gdd.md` §8 记录表抬头、
`docs/rules-v1/rules.md` §7.1 那两条读法）。可以互比的只有两件事：**模型档位**（本轮三舱用的
仍是 `deepseek-v4.1-flash` 与 `MiniMax-M3`）与**隔离舱脚本形态**（同一份脚本，只改了投放文档与交付名）。

## 7. 票面之外的发现

1. **§5 占领进度机是本轮唯一的真卡点，而它「未排期」**（rules.md §5 的占位原文写着「本节未排期」）。
   三舱全部撞上、全部自造机制、且造出两种互斥的版本。票 07–10 那批散文把经济、采集、生产、
   战斗轮转、异常披露、终局措辞都落了，唯独漏了占领——**这不是措辞问题，是缺一节机制**。
   它归哪张票需要指派（本票只判读，不改契约）。
2. **静态校验这一条，本轮能判的只有一半**。可见面/形态/禁列/整数这四层判得了（全绿），
   **类型面判不了**（声明面未回填，`tsconfig.scripts.json` 的 `types: []` 是刻意的空数组），
   每单位单意图也判不了（运行期语义）。票面的「静态校验零违规与否」本轮只能按可判的那一半回答。
3. **本轮没有触发任何一轮校验回喂**（三舱都是 v1 直接交，0 轮修改）。静态校验器那张待办票
   （`.scratch/script-validator/issues/08-parser-source-form-too-wide.md`）还没实施，
   所以「≤5 轮回喂」这条机制本轮根本没被走到过一次——它是纸面机制，尚无实测。
4. **`cell-b` 没写 `FIXES.md`**。任务书写的是「后续每轮校验只改 work/ 内文件并记 `work/FIXES.md`」，
   它没进校验轮所以没写。这条其实暴露了任务书的措辞问题：首次交付要不要也记账，没说。
5. **存档的 1336 场表头有两条指针在拷贝时失效**：抬头写「本文件只放数字，判读在 `../results.md`」，
   而标定环那一轮的文件名是 `results-rerun.md`；同一段还写着 `VARIANT_SLOT_REPS`「按 30% 概率整轨
   填墙」，而代码里是 50%（探索笔记已记这条口径错位）。两份都是**拷贝过来的生成物表头**，
   数字本身逐字未改，改它要连生成器一起改，所以本票只记录、不动。
6. **模型对「未定值」的反应是可预期的保守化**。两份舱（a、b）看到预算未定后都主动削减 API 调用，
   而不是「反正不判罚就随便调」——rules.md §8.3 那句「别把任何实现细节当成可依赖的边界」
   是起作用的。这算 §8.3 披露分级的一个正面读数。

## 8. 复现

```bash
# 三舱（隔离舱脚本是标定环原件的副本，改的是投放文档与交付名）
./.scratch/rules-landing/blind/blind-run.sh setup cell-a A
./.scratch/rules-landing/blind/blind-run.sh run  cell-a deepseek/deepseek-v4.1-flash
./.scratch/rules-landing/blind/blind-run.sh collect cell-a      # b/c 同理，模型分别 MiniMax-M3 / deepseek-v4.1-flash

# 静态校验（三份一起）

```
