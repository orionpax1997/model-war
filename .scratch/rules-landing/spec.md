# 规则集与契约落库

Status: ready-for-agent

## Problem Statement

M1 的另两件交付物(`rulesets/v1.json`、`docs/rules-v1/`)至今是空的,而规则侧的全部裁决已经做完、全部躺在别处。**取值真源不在它该在的房间里**,于是现在有四件同时为真的事:

1. **规则集的取值无处可读**。标定环的交接单把 13 个定稿键和 8 个预算键的取值写在一张 markdown 表里,预算键只取了占位值;真源包有 21 个键的机器可读清单和 JSON Schema,却没有任何一个文件能让别人读到键的值。真源包头注里那段「为什么是 21 不是 22」的考据,读的人得先知道交接单存在才看得懂它在解释什么。
2. **面向模型的那份契约还是草案**。`docs/rules-v1/` 该有的两份文档(`rules.md` 机制与结算、`api.md` 签名与语义)不存在;现存的是标定环的草案目录,头一句就写着 throwaway。它已按 21 条裁决裁过一遍措辞,但裁决的落点全在草案里。
3. **M1 的验收至今是用草案做的**。标定环四舱盲写跑在草案契约上,而 21 条裁决里有 6 条 P0 会改写这份契约:座位自认从「在快照里二选一猜」改成单一正式入口、错误返回有了必须显式判别的两个 helper、快照字段补进 API 面、源码形态与交付名的记法自洽。这意味着**现有四份脚本不是终稿契约的产物**,而基准脚本目录还是空的。
4. **两条交办的账还挂着**。地图池那一节点验出的等效命题、以及规则侧对其中一条的复验结果,都明确写着「要换终稿契约再验一遍」,而终稿契约还不存在。

还有一个更窄、更硬的问题,它是本 spec 真正的技术对象:**终稿 API 面与静态校验器已落地的实现形状不同源**。名单的真源在真源包里,并且已经有一条纪律说「静态校验器一个名字都不许自己存」;但那张决定「哪些 API 符号会被铺进沙箱」的表**当前是空的**,它的注释写着「等沙箱执行器产出注入面再回填」。于是那份要直接进 prompt 的契约文档,没有任何机器能保证它写的名字与校验器读的名字、沙箱铺的名字是同一批。

## Solution

让规则落库这一格同时交出**取值**、**契约**与**同源保证**三件:

- **取值落 `rulesets/v1.json`**:13 个定稿键取标定环的终值,8 个预算键取未定值占位。取值真源是这一个文件,标定环的交接单随之作废。
- **契约落 `docs/rules-v1/{rules.md,api.md}`**:散文段按 21 条裁决改草案;**表格部分(API 表、常量表、错误码表、数值表)由真源包与规则集文件生成**,因此「文档里的名字」与「校验器读的名字」不可能分叉。
- **同源保证**:回填真源包里那张沙箱注入 API 符号表(收录判据:收脚本能在运行时当值用到的名字——函数、helper、错误码字符串收,类型名与数值不收),并给生成器加一种**区块形态**,使混合的散文文档也能挂生成表格,漂移检查仍逐字节比对。
- **验收对象换成终稿契约**:三舱盲写(爆兵压制 / 扩张运营 / 占点不采集)拿终稿契约重跑,产物进基准脚本目录;标定环的桩复用(不搬)重跑等效命题的 ②。

## User Stories

1. As a **维护者**, I want 规则集的取值只在一个文件里, so that 我不需要在交接单与文档之间判断哪份是真源。
2. As a **维护者**, I want 标定环的交接单在取值落库后被标作废, so that 后来者不会拿一份自称会被作废的文件当权威。
3. As a **模型作者**, I want 我拿到一份自包含的机制与 API 契约, so that 我不必读设计文档就能写出脚本。
4. As a **模型作者**, I want 契约里只有一种写法并写明「返回类型可省略」, so that 我不会在 `function loop(): void` 与 `function loop()` 之间反复横跳。
5. As a **模型作者**, I want 我的座位有一个正式的入口函数, so that 我不必靠单位位置反推自己是谁(实测四方跑同款位置法脚本会互相误判)。
6. As a **模型作者**, I want 错误返回有必须显式判别的两个 helper 并配可运行示例, so that 我不会用 `typeof` 或真值去猜一个对象是不是错误。
7. As a **模型作者**, I want 每个错误码有名字和一句触发条件, so that 我能照着改而不是猜语义。
8. As a **模型作者**, I want 快照里玩家的资源、存活、异常计数与产线的当前订单都读得到, so that 我不必在脚本里自己记一份队列(实测拒单率 69% 的成因就是被迫自记队列)。
9. As a **模型作者**, I want 三层披露的异常语义(必知 / 建议知 / 不披露), so that 我知道写崩会发生什么,又不必去猜实现细节。
10. As a **模型作者**, I want 契约里出现的每一个预算类数值渲染成「未定」而不是 `0`, so that 我不会把占位值当成真上限去设计脚本。
11. As a **维护者**, I want 契约文档里的 API 表由真源包生成, so that 改一个名字不必记得改三处。
12. As a **维护者**, I want 改了真源包而没重跑生成器会被门禁判红, so that 「同源」不是一句注释而是一条可执行的断言。
13. As a **维护者**, I want 把文档里的某个生成区块整段删掉也会判红, so that 检查不会因为无事可做而放行。
14. As a **维护者**, I want 静态校验器与规则文档读同一份符号表, so that 「参赛脚本能用什么」只有一个答案。
15. As a **沙箱执行器作者**, I want 符号表已被填满而不是等我回填, so that 我照着实现注入面即可,不必反推契约文档写过什么。
16. As a **生成管线作者**, I want 参赛脚本的编译配置已经定好, so that 我不必自己决定沙箱里的类型环境长什么样(它决定白名单反转是否成立)。
17. As a **生成管线作者**, I want 脚本的编译配置是一份我能直接读的配置而不是散落在文档里的一句话, so that 我的编译步骤与静态校验器读的是同一份。
18. As a **静态校验器作者**, I want 脚本编译配置落地, so that 我能收紧解析层的源形态(它比入口契约宽,是一条已登记的待办票)。
19. As a **里程碑验收者**, I want 基准脚本是模型在终稿契约下写的, so that 「规则闭环与区分度成立」这句话指向的是交付物而不是草案。
20. As a **里程碑验收者**, I want 三份基准脚本覆盖三种不同取向(爆兵压制 / 扩张运营 / 占点不采集), so that 规则集的区分度有证据而不是只有一个策略跑通。
21. As a **里程碑验收者**, I want 基准脚本目录里有编译产物, so that 校验器判的与门禁跑的是同一份东西,而不是每次现编。
22. As a **里程碑验收者**, I want 基准脚本目录里没有半截的存档元数据, so that 后来者不会以为那个形状已经定稿。
23. As a **维护者**, I want 规则侧挂账的两条等效命题在终稿契约下复验一次, so that 那两条结论不是只对一份已丢弃的草案脚本成立。
24. As a **维护者**, I want 复验复用标定环那个已经跑过 1336 场的桩而不是新造一个, so that 两条结论的证据链不断成两截。
25. As a **维护者**, I want 复验时把地图池那一节点定下的两条口径随引用一起带, so that 我不会拿旧口径的数去核新口径的结论。
26. As a **维护者**, I want 400–600 那个枯竭窗口的重推定案不混进这一格, so that 规则裁决不会被顺手做掉而无人复核。
27. As a **维护者**, I want 这一格把标定环交接单标作废, so that gdd 记录里指向它的指针有明确去处。

## Implementation Decisions

### 取值落库

- **21 个键一个不少**,8 个预算键取未定值占位。预算键的「未定」由键自己身上的判别式标记,不由「值是不是 0」推断——`0` 在别的键上完全可能是真取值。
- **派生规则不是独立键**:`spawnTicks = ceil(cost × 0.5)` 与满产烧钱率由生成器/规则层按公式实现。内存软阈是 `0.8 × memoryTickCeiling` 的推导展示项,**入表不入键清单**。
- **开局资源点归属是不变量不是键**:每方开局恰好拥有家附近最近一圈资源点(数量为 4 的倍数),其余资源点中立、须先占领才有开采权。它由地图声明与地图校验器断言,不在规则集文件里。
- **标定环交接单随之作废**,其文件头已预写了作废条款与三个去处。作废动作落在这一格收口时,不是落库当时——落库后仍需一段时间用新真源复算。

### 契约文档与生成物

- **两份文档的散文段手写,表格段生成**。文档结构按 hld §6.1 定的两份(机制与结算顺序、API 签名与语义),不新增第三份文件。
- **生成物加一种区块形态**:真源产出 `{ marker, content }`;漂移检查按 marker 抽出工作树文件里对应的区块逐字节比,区块外的散文不比。**marker 被手改或整段被删都要判红**——否则「把区块删掉让检查无事可做」是一条绕过检查的路。
- **挂在规则文档上的区块至少三处**:API 表(签名 + 一句语义)、常量表(单位类型、意图种类、错误码及其触发条件)、数值表(取自规则集文件,预算键渲染成「未定」)。数值表的那处与 `rules.md` 里的数值表是同一份内容生成两次,不是两份各自维护。
- **错误码全定**。草案里只有「资源不足」那一码在来源文档被点名过,其余是按界检查职能反推的候选。终稿要么全部定名并各配一句触发条件,要么全部删掉;**半截的码表比没有码表更坏**,因为模型会当真。错误码集合与「丢弃 vs 异常」对照表逐条对齐——对照表因错误码形态变化要重写一遍。

### 符号表与收录判据

- **收录判据:收脚本能在运行时当值用到的名字。** 查询函数、动作函数、座位自认入口、两个错误判别 helper、错误码字符串,全部收。
- **类型名不收**(`UnitType` / `IntentKind` 这类):它们不占全局,是类型面上的名字,而「API 误用」那条判据本来就是读类型面。两张脸各管一件事,不重叠。
- **数值不收**:预算类与兵种类数值归规则集文件那条生成链,已经是另一张表。收在这里等于同一份事实两个家。
- **真源包里那张表的注释要改**:它现在写着「刻意为空,回填触发条件是沙箱执行器」。本决定之后那是历史陈述,留着会让后来者把它当成待办而跳过。

### 参赛脚本的编译配置

- **家是仓库根的一份配置**,与根编译基座同级;不落进包目录,不做成真源包的生成物(它的身份是编译器的输入,没有任何仓库代码 import 它),也不落进文档目录。
- **刻意不继承仓库的编译基座**。脚本跑在沙箱里,要的是最小 ECMAScript + 脚本 API 类型声明;继承了仓库基座就等于把 Node 类型带进沙箱,白名单反转当场漏。
- **归属修正**:静态校验器那一节点把「脚本编译配置归规则落库这一格」写进了它的待办票触发条件,而 hld §6.2 编译那一行写的是「归生成管线的编译步骤」。**两处对不齐,本决定取前者并改 hld**——承载它的配置形状与契约面同源,而它是下游的实现。
- **脚本 API 的类型声明不进这一格**:家已定在真源包,内容由对局内核与沙箱执行器回填。这一格只保证编译配置存在且指向那个家,不预填类型面。
- **实测约束(TypeScript 7.0.2,2026-10-04)**:本仓库的 TypeScript 7 **已移除 `outFile`**,且 `--module` 的合法取值里**没有 `none`**。单文件 script-mode 产物要走 `--outDir` + 单文件输入(探针实测 `preserve` / `esnext` / `commonjs` 三种取值对无 `import`/`export` 的源文件产出逐字相同的裸脚本,故模块取值只需选一个不自引入模块语义的)。这一格定的配置必须在这条约束内成立——它顺带把「产物里不会有 `export`/`import`」这条从 hld §2.2.2 的运行时实测发现,提前变成了配置层的可判定事实。

### 验收:三舱盲写

- **三舱,不是两舱**:爆兵压制 / 扩张运营 / 占点不采集。第三档是标定环里最反直觉的一份(它逼出了「该策略几乎不采集」这个标签修正),且里程碑对区分度的口径是「能体现不同策略」,两舱是下限而非目标。
- **可比性按已有纪律来**:共享同一份终稿契约、同一份 prompt 基座、同样的夹具配置跑正表之前先过夹具闸门。标定环那一轮的教训是「换一个移动层就够不着被标定的窗口」,可比性不是形式。
- **prompt 基座随契约重写**:21 条裁决里有 6 条 P0 会改它(座位自认改成单一入口、轮转方向不再是假设、返回类型可省略、错误判别 helper、快照字段补进 API 面、源码形态与交付名自洽)。旧基座里有「二选一自认候选」「轮转方向为假设」两处,它们在终稿里都不成立。
- **prompt 基座不进 `prompts/` 目录**:那是生成管线的数据文件,归后续那一格;本格用的是一次性盲写模板,留在本 feature 的工作目录里。
- **盲写隔离舱直接复用现成脚本,不改动它**(它已 smoke test 过)。它走的是 agent 自己的认证,与模型 API 凭证那条线无关,所以本轮不受那一格的时序影响。

### 基准脚本落库形态

- **落源码与编译产物,加一份说明表**(策略标签、模型标识、生成参数、静态校验结果、契约版本)。**不落存档元数据**——它的形状家已定在真源包、字段由生成管线那一格回填,现在写就是「半截字段比没有更坏」的真源包里明令禁止的事。
- **编译产物必须落**:收紧源形态之后校验器判的就是产物,而基准门禁要拿产物对打;库里没有产物就等于每次跑门禁多一道构建,而门禁的第一印象必须是「clone 完直接能跑」。
- **按已有先例排除**:标定环的采集探针不进基准目录(它不是参赛脚本),某模型的零产出存档也不进(它是失败记录不是基准)。

### 复验:挂账的那条 ②

- **复用标定环的桩,不搬它**。搬桩等于改一个已经产出 1336 场记录的证据源,动了那 1336 场就不可复现。本格的产品写自己的工作目录,只引用桩的代码。
- **两条口径随引用一起带**。第一条:「整局 ≈440」那个数是单矿储量 125 时代、全矩阵平均,不是「4 份基准脚本」的数——基准脚本口径实测 351,这条命题的松紧度是被储量那一刀改掉的,不是被地图改掉的。第二条:种子维度对消耗指标零方差,每臂的有效独立样本只有 4 个座位轮转,**引用时不得写成「128 场独立样本」**。
- **① 不排期**。400–600 那个枯竭窗口的重推定案是规则侧的后续工作,触发条件是「出现一个移动层不同的探针」;它与本格的「终稿契约复验」是两件事。本格只在文档里留指针。

## Testing Decisions

### 什么算好测试

只断言**外部可观察行为**。本格的外部行为有三件:规则集文件能不能被校验器收下;契约文档与真源包会不会漂移;基准脚本在终稿契约下能不能编译、过静态校验、打出正常终局。凡是能靠改内部结构而失效的断言,都是坏断言。

### 缝(三条,按高度排列)

1. **契约自证——最高的一条,也是本 spec 想立的唯一新缝**。一个脚本,拿终稿契约把基准脚本目录里的三份脚本**编译 → 过静态校验器 → 跑桩矩阵**,然后只回答外部可问的问题:
   - 三份都是**零静态违规**(证明契约没有把合规脚本判死,这是静态校验器那一节点立下的不误伤纪律的延续);
   - 三份都**打出正常终局**,不被判负出局;
   - 三份的**消耗中位数都落在总储量的四分之一以内**(这条就是挂账的 ②);
   - 三份的**取策略互不相同**(区分度的可观测代理:若三份脚本的行为指标收敛到同一形态,规则集就还没被证明有区分度)。

   这条缝选得高的理由:它不测生成器的排版、不测区块抽取的实现、不测规则表的每一行,只测「这套契约能不能让模型写出合规脚本并打出正常终局」。任何一处重构——换 marker 语法、换区块抽取方式、改错误码的呈现形态——都不该让它变红;而改一个 API 名字、改一条错误码、删一段判据,必须让它变红。
2. **漂移检查的区块判定——复用既有门禁**,不加新门禁。`check:drift` 现有三段判定逐字节比对整文件;本格给它加的是「按 marker 抽区块比对」这一段。断言全部走门禁自测那一层的先例(每道门禁的退出码与反向用例,不混进全量门禁):改了真源不重跑生成 → 判红;区块内容被手改 → 判红;**marker 被删或整段被删 → 判红**(这一条是绕过检查的那条路,没有它,整套同源保证有一个洞)。
3. **规则集文件的读入端校验——单点,刻意不接线**。真源包的 ajv 校验通路在地图那一侧已经跑通,规则集这一侧的调用点随对局执行器落地(FR-10 AC2 的「读入端强制校验」按尚未兑现记)。本格只保证这份文件能被现有校验器收下,不新增子命令、不把它接进任何子命令的装载路径。

### 明确不测

- **区块抽取器不单独测**(沿用静态校验器那一节点对遍历层的判断):它上面就是那三条缝。
- **散文段的内容不测**。契约散文的质量靠三舱盲写抓——模型读不懂就写不对,这条证据比任何断言都硬。
- **沙箱侧的注入行为不落仓库测试**,沿用既有决定:对第三方库行为的断言会被后来者误读成「沙箱这块验过了」。
- **桩本身不测、不修**。它是一次性原型,证据有效即可;搬它或修它都会让已有记录不可复现。

## Out of Scope

- **400–600 枯竭窗口的重推定案**(规则侧记录 #13 的 ① 号命题)。它的返工方向是重推窗口、触发条件是出现一个移动层不同的探针,属规则侧后续工作;本格只在文档里留指针,不排期、不造探针。
- **沙箱执行器与预算裁决**。符号表由本格填,但 runtime 怎么注入、异常怎么裁决、预算怎么判,都在后续那一格。
- **对局内核与真引擎**。本格的复验跑在桩上,真引擎上的复验归内核那一格。
- **生成管线**(模型 API 客户端、适配层、退避限流、迭代回喂、存档目录)。本格交出它要读的编译配置,不实现它。
- **存档元数据、终局结果、回放行三类形状**。形状家已定在真源包、字段未回填,本格不预填。
- **脚本 API 的类型声明面**。归对局内核与沙箱执行器回填;本格只保证编译配置指向那个家。
- **预算类 8 个键的终值**。归预算终值标定那一格;本格取未定值占位,并让文档把它渲染成「未定」。
- **把静态校验器接进生成管线**。接线归生成管线那一格;本格交出被读的那份配置。
- **命令行子命令**。本格不新增(hld §9 的子命令不动)。
- **地图坐标与点位不变量的重开**。三条真图已落库,复验不改图;记录里的回流条件(改矿路长度)本轮不触发。
- **参赛脚本的成员级白名单**(写 `Math.sqrt` 无人拦)。已落规则侧开放项,属规则裁定,不在本格。

## Further Notes

- **决策记录**:`docs/adr/0004-contract-api-surface-lands-in-rules-landing.md` 记了「表格生成 + 符号表时点」这一组决定及其取舍;本 spec 里「收录判据」「错误码全定」「编译配置不继承仓库基座」三条都是它的直接后果,不复述理由。
- **两处文档错位要一并改**:hld §6.2 编译那一行(编译配置的归属)、静态校验器那一节点规格里「把校验器接进生成管线,接线归本格」这一条(应归生成管线那一格,本格交出的是被读的那份配置)。两处都是「一个事实两个家」,改的时候按 hld > gdd > srs > fsr 的采信顺序取架构侧。
- **词汇表本轮无新增**。收录判据是一条规则不是一个概念;「脚本可见全局」在架构文档里已是既有叫法,不另造「契约面 / 注入面」——那两个候选在本轮已被裁掉。
- **一个已知的窄口**:三舱盲写烧的机时与网关单流时间上限(标定环实测约 15–20 分钟)是两个已知的现实约束。舱内产出必须核文件存在性,不能只看进程退出码——这是标定环踩过的坑,本轮直接沿用。
