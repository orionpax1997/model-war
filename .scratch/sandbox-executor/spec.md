# 沙箱执行器与预算裁决

Status: ready-for-agent

## Problem Statement

规则、引擎、地图、schema、参战凭证都已落地,`modelwar match` 也已经能把一个对局从头跑到尾——**但跑的是桩**。`apps/cli/src/match/index.ts` 往 `runMatch` 里塞四个空策略(永远不提交 intent),回放 meta 写着 `runner: "stub"`,而 `sandboxRuntimeHash` 是用 `sha256("stub-runner/" + RULESET_VERSION)` 拼出来的假值。于是有六件事同时为真:

1. **信任边界根本不存在**。FR-4 AC1 要求参赛脚本无网络、无文件系统、无宿主进程访问,而**没有任何一行脚本被执行过**——`packages/engine` 里零行 QuickJS 代码,`quickjs-wasi` 只躺在根 `package.json` 的 devDependencies 里(那是 spike 留下的)。
2. **四类预算裁决一条都没实现**。`interruptHandler` 从没装上,双计数没有,内存读数没有,`exceptionTicks` 在 `world/state.ts` 里初始化成 0 之后**永远不变**(`driver/apply.ts` 的 Change 联合里没有能加它的种类)。
3. **`modelwar verify` 是空壳**。`apps/cli/src/commands.ts` 把它登记成 engine 的 `verifyReplay`,而那个符号不存在,运行时只会打「未实现」退 1。于是 FR-2 / NFR-1 要的「重放一致性」没有任何入口,尽管 `packages/replay` 的 `stateHashOf` 与规范化早就写好了。
4. **沙箱行为的五条结论今天只是一份对未验证版本的承诺**。hld §5.0 的表全部来自 `quickjs-wasi@3.6.2` 的一次 spike,而 hld:576 自己写着复验责任挂在「实现真实沙箱执行器」这张票上(§12 #8),并且「**没有任何机器会提醒后来者它们已经过期**」——升级条款当前是空头承诺。
5. **runtime bundle 不存在**,`engine:sandbox-runtime` 只有一行规划表条目,`sandboxRuntimeHash` 因此没有真源,存档里那一栏今天写着假值。
6. **两个对抗场景没有任何夹具**。纯计算死循环与 API 轰炸——「控制流事件计数」与「API 调用计数」互为盲区这条设计,今天唯一的证据是 `.scratch` 里的一次 throwaway spike,仓库里没有可重复的夹具。

另有一处**必须由本 feature 裁掉的文档冲突**:hld:570 明写「回调内绝不能放墙钟」,而 hld:609 又要求墙钟硬超时能截停单 tick 内的失控——单 tick 是同步的,进程内没有第三个地方能插手。两条不能同时成立,而它们争的是同一件事的家。

## Solution

给引擎装上**真的执行器**,并让「预算裁决」成为它的一部分。

交付到三条缝:

1. **引擎的 `runMatch`**:它今天已经收四个执行器,只是桩。本 feature 让组装层可以递真执行器进去——四个 QuickJS VM,各跑一份受预算约束的脚本。引擎仍然不知道 VM 的存在。
2. **CLI 的 `match`**:它变成「每对局一个子进程」的那个子进程本身——纯函数式入口(读 `input.json` → 写产物),用真沙箱跑四个座位的脚本,并把真的 `sandboxRuntimeHash` 与三件套常量写进回放 meta。执行失败由**退出码表 + 一行 stderr JSON**表达。
3. **CLI 的 `verify`**:逐 tick 复算一条回放并与原始 hash 比对,退出码 0/1。它是 NFR-1 的「CI 重放一致性」入口。

同时把三件「只有承诺、没有机器」的事补成机器:

- **五条沙箱行为结论**变成仓库里可执行的探针,并新增一条**廉价的版本耦合断言**:`quickjs-wasi` 一升版,默认门禁立刻红,并提示去跑复验。之后把复验结果写回 hld §5.0 并关掉 §12 #8。
- **runtime bundle** 入库成形(TS → 单文件 IIFE),它的字节 hash 就是 `sandboxRuntimeHash` 的真源;产物有漂移门禁守着。
- **观测通道**:墙钟软限与内存压力走一个回放之外的 `observations.jsonl`,墙钟永远不进回放、更不进 `stateHash`。

做完之后,一条真实的赛季对局链是通的:存档脚本 → 真沙箱 → 可复算回放 → `verify` 一致。

## User Stories

1. 作为一个参赛模型(脚本),我想要在一个没有网络、没有文件系统、够不着宿主的 VM 里执行,这样我的代码不会意外或故意影响对局之外的东西。
2. 作为引擎,我想要把每 tick 的局面以只读快照交给每个座位的脚本,这样脚本只能通过明确的接口读局面、下指令。
3. 作为一个失控脚本,我想要被计数而不是被墙钟杀掉,这样对我的判罚在换台机器重跑时结果一致。
4. 作为引擎,我想要给每个座位独立累计「控制流事件」次数,这样纯计算死循环(有回边、有调用)到顶就被截停。
5. 作为引擎,我想要给每个座位独立累计 API 调用次数,这样 API 轰炸(每 tick 数万次 `findPath`)到顶就被截停,而不是拖垮整个对局。
6. 作为引擎,我想要在每 tick 末按该方存活堆占用读一次数,这样内存判据锚定在宿主可直接测量、不依赖 guest 异常可见性的量上。
7. 作为引擎,我想要在脚本吞掉 OOM 异常时仍然能判定这次超限,这样「try/catch 掉错误然后继续」不构成逃逸。
8. 作为一个偶发缺陷的脚本,我想要异常被累计而不是一次判负,这样单次 flake 不会直接出局;但累计到上限时我要被判负出局,点位回归中立。
9. 作为引擎,我想要 `exceptionTicks` 随 tick 写进回放并跨 VM 故障续算,这样反复失控不能靠在两个 tick 之间重置计数逃逸。
10. 作为引擎,我想要脚本抛的未捕获异常只作废该座位这一 tick 的意图(单位原地待命),这样一方失控不污染其他三方或引擎本身。
11. 作为一个想作弊的脚本,我想要调用 `__setSnapshot` / `__drainIntents`,但这两个桥在我执行之前就被从全局删掉了,这样越权只是一次普通 `ReferenceError`。
12. 作为维护者,我想要 `__` 前缀在静态校验期就是一条红线,这样删桥只是纵深防御的第二层,而不是唯一防线。
13. 作为引擎,我想要每个 VM 的 `Date` / `Math.random()` / 时区都由固定常量决定,这样同一份脚本与快照在对局内、跨 VM、跨重跑三个维度上得到同一序列。
14. 作为审计者,我想要回放 meta 里记着沙箱运行时的 hash、`quickjs-wasi` 版本与三件套常量的取值,这样我能在一年后凭存档复算出同一份回放。
15. 作为跑批的人,我想要 `modelwar match` 读一份物化的输入就产出回放,不需要我告诉它用哪个执行器,这样脚本来源与执行方式不会被两处配置弄不一致。
16. 作为跑批的人,我想要 `match` 用可区分的退出码告诉我失败原因(引擎崩溃 / 不确定超时 / 输入或校验错),这样调度器能把「重跑一次」与「记问题清单」分开处理。
17. 作为 CI(或夜间流水线),我想要 `modelwar verify <replay.jsonl>` 逐 tick 复算并比对 hash,这样任何破坏确定性的改动都会红。
18. 作为 CI,我想要 `verify` 拒绝执行方式、`quickjs-wasi` 版本或 runtime hash 与回放不符的情况,这样「用桩复算真沙箱的回放」不会静默通过。
19. 作为维护者,我想要 runtime bundle 以确切字节进版本库,并有门禁比「现算 == 入库」,这样存档里的 hash 在任意克隆上都指向同一串字节。
20. 作为维护者,我想要一条廉价的版本耦合断言挂在默认门禁上,这样升级 `quickjs-wasi` 不可能悄悄溜过——它会立刻红,并告诉我该去跑复验。
21. 作为维护者,我想要五条沙箱行为结论各自有一条可执行探针,每条探针的报错信息里带它对应 hld 的行号,这样红的时候我不用回来翻文档。
22. 作为维护者,我想要口径未定的预算键在引擎里表现为「该轨不启用」,这样在 K 标定终值之前我就能真跑对局,且不会因为「占比 0」而被瞬间判负。
23. 作为报告的使用者,我想要墙钟软限与内存压力这两类观测被记在回放之外的文件里,这样它们不会改变 `stateHash`,也不会让对局在换台机器时不可复算。
24. 作为报告的使用者,我想要观测文件每玩家每类只记首条,这样它始终是有界的几行,而不是几百行噪声。
25. 作为引擎的维护者,我想要执行器那一格仍然只有两条方法,这样「预算裁决」不会把 VM 的生命周期泄进结算管线。
26. 作为结算管线的维护者,我想要预算裁决的结果经由既有的那一次返回载荷回到引擎,由 `apply()` 唯一写入口落成状态变更,这样桩与真执行器共用同一条路径。
27. 作为测试作者,我想要桩执行器在加了观测栏之后一行测试都不用改,这样本 feature 不会把 F 已收口的十余处测试搅动一遍。
28. 作为工具与文档的读者,我想要「执行器缝」只有一个名字(`SeatRunner`)、只有一种方法论,这样我不会以为它有三个方法或按对局划分。

## Implementation Decisions

### 缝的形状(ADR 0005 的修订点)

- **`SeatRunner` 仍然只有两个方法**:`setSnapshot(snapshot)` / `drainIntents()`。不新增接口方法、不加基类、不加工厂、不加生命周期协议;建 VM 与释放(dispose)归**组装层**,引擎不持 VM。
- **`drainIntents()` 的返回载荷加栏**,由 `readonly Intent[]` 变成「intents + 观测」的结构。这不新增中间表示、也不新增桥调用——ADR 0005 的「缝就是那两次宿主桥调用」原样成立,只是回来的那一次载荷多了几栏。
- 观测条目形如:一个种类(`tripped` / `wall-clock-soft` / `memory-pressure`)、一条轨名、一个观测值、一个上限值。`tripped` 由引擎在步 0 落成状态变更;另外两类转发给观测 sink。
- **桩执行器返回空观测数组**,因此 F 已收口的桩路径测试一行不改。
- `runMatch` 的参数由「四个桩策略」泛化为「四个已构造好的 `SeatRunner`」,并把规则集、地图、种子、预算配置、回放 sink 与可选观测 sink 一并收下。引擎对执行器的认知止于那两条方法。

### 四类裁决(修订 hld §5.2)

- 四类 = **guest 未捕获异常 / 控制流事件超限 / API 调用超限 / 内存判据超线**。
- **WASM trap 移出判罚轨**:spike 实测脚本路径上不可达(深递归是 host 侧 `RangeError`,`isJSException:false`,VM 可续用)。trap 若发生按引擎故障处理,走「重跑一次、再触发则剔除」那条轨。
- **不实现防御性重建**。理由:trap 若真发生通常是引擎自身的缺陷,重建会把缺陷掩盖成「这一方运气不好」,并与重跑轨抢语义。hld §5.2 那一行据此改写。
- 前两类与第四类在超限时**作废该座位本 tick 的意图**(单位原地待命),不中断其他三方与引擎;`exceptionTicks` 累加。
- 按异常**事件**累加(不是按轨),并在变更里带上轨名以便读数。

### 双重计数与墙钟

- **两个计数互为盲区**:控制流事件计数抓纯计算死循环,API 调用计数抓 API 轰炸。两者都以宿主侧纯整数计数实现,回调内自乘计数,绝不做重活。
- 计数回调只能作为 VM 构造时的选项装上,因此**计数器状态住在宿主闭包里**;每 tick 重置本 tick 的计数,累计值由宿主侧持有。
- **墙钟按抽样读**:在同一个回调里每若干次(量级为 20)读一次时钟。软限只记观测,不参与判罚;硬超时返回中断标志,让本 tick 停下并标记为 `nondeterministic-timeout`。
  - 这是本 feature 裁掉的文档冲突:hld:570 的「回调内绝不能放墙钟」改成「不得放**每次**都做的重活;时钟按抽样读」。理由:单 tick 内失控只有这里能打断,而硬超时若只挂在 tick 边界就永远抓不到同步死循环。
- 每 tick 结束时把 VM 的待处理 job 排空到不动点(不排空会让 intent 跨 tick 残留)。

### 内存判据

- 判据读数 = 每 tick 末 `runGC()` 之后的**存活堆**(malloc 池口径),不是活对象占用口径。
- 三层:分配上限(硬)、判罚线(硬)、软阈值(`0.8 ×` 判罚线,只观测)。软阈值是推导项,不入参数键清单。
- 「tick 内瞬时借满即还」不触发判据(已接受的残余),要在契约面与文档里写明。
- `gcThreshold`(自动 GC 阈值)保留默认,**不动它**:tick 末已有手动 `runGC()`,关掉自动 GC 只会把读数推高、更容易误踩判罚线。

### 未定值与预算配置

- 预算参数键在标定完成前取**未定值**(占位 0),而「未定」与「真想设成 0」由键清单上的两态字段区分,**不是靠值判断**。
- **解析放组装层**:组装层读键清单的两态字段,把「启用的轨 + 阈值」显式传给 `runMatch`。引擎不认识「未定值」这个概念。
- 预算配置里**字段缺席即该轨不启用**;不需要第二个字段表达「开但值是 0」。
- **脚本体积上限不进这个配置**:它是编译期的事,判定点在编译/校验层(编译后产物的字节数),装载期再由 CLI 复核一次存档里的产物字节数。「迭代期只提示、冻结期才拦」用存档元数据里已有的校验字段判,不新造标记。

### runtime bundle 与 hash

- runtime bundle 是**入库产物**:TS → 单文件 IIFE,由构建脚本产出,产物与「产物字节的 sha256」常量一并进版本库。它是独立构建入口,**不进 engine 的公开导出面**。
- 门禁是**独立的漂移检查**:构建一次、与入库产物逐字节比。它进全量检查链,不进快速链。
- `sandboxRuntimeHash` 的语义从此收敛成一个:入库产物的字节 hash。CLI 里那个用字符串拼出来的假 hash 删除。
- 沙箱模式的回放 meta 记运行时 hash + `quickjs-wasi` 版本 + 三件套常量;桩模式下这几栏仍为 `null`(形状已由 schema 定死)。
- wasm 字节与 bundle 字节由组装层读盘传入引擎,引擎侧保持零磁盘 I/O(它今天只允许 `node:crypto` 一个内置模块)。

### WASI 三件套与回放 meta

- 三件套 = 冻钟(固定毫秒值)、随机字节固定填充、时区偏移固定为 0。取值是工程常量,不是对局参数。
- 回放 meta 的 `wasiClock` / `wasiRandomFill` 两栏已存在,但**时区偏移没有栏位**,而 hld 明文要求三件套都可审计。本 feature **新增一栏**表示时区偏移,三栏填法定死(十进制毫秒 / 十六进制字节不带前缀 / 十进制分钟)。

### 观测通道

- 新增一种回放之外的 JSONL 行:**每个对局一个观测文件**,与回放同级。观测**永远不进回放、更不进 `stateHash`**。
- **每玩家每类只写首条**(首触),文件因此有界。将来要计数是**加栏**,不是改形。
- 行形状进 `packages/schema`(类型 + required 键 + JSON Schema 三处),由 `packages/replay` 再导出一条,`apps/cli` 的校验器加一条行校验。
- 引擎侧新增一个**可选**观测 sink;缺席时静默丢弃,这样引擎单测不必关心它。回放线保持「就是回放」的纯度——`verify` 会逐 tick 比它。
- 命名取「观测」而不是「警告」:里面的东西不都需要处置(内存压力是披露)。

### `match` 与 `verify` 的职责

- **`match` 是「每对局一个子进程」的那个子进程本身**:纯函数式入口,读物化输入、写产物。本 feature **不做 spawn、不做进程池**(那是调度节点的账)。
- `match` 默认走真沙箱;**桩路径保留但只作测试入口**,不进 CLI 公开面。物化输入里**不加**执行方式字段——执行方式是执行方式,不是对局输入,它由回放 meta 如实记录。
- 组装层在跑之前核一遍四条存档的运行时 hash 与当前产物 hash 是否一致,不一致即拒跑。
- **`verify` 在 CLI 落 handler**(复用 `runMatch` 与回放包),engine 的导出面**保持恰好一个运行时符号**。它不起子进程;退出码 0/1。
- `verify` 的判据 = 逐 tick `stateHash` 比对 + 末行结果;并核回放 meta 的执行方式、`quickjs-wasi` 版本、运行时 hash 与本次执行是否一致,不一致即报错,不静默换。
- **退出码表**(写进 hld 的 CLI 章节):`0` 正常 / `1` 用法或校验错 / `2` 引擎崩溃 / `3` 不确定超时 / `4` 其它内部错;细节另在 stderr 给一行 JSON。调度器只认退出码。

### 依赖与构建

- 引擎新增对 `quickjs-wasi` 的运行时依赖(为了 VM 构造 API);它仍不做磁盘 I/O。
- 工具的源码形态直接由 Node 执行,探针与门禁脚本落那里;若工具侧要引 `quickjs-wasi`,必须同步声明依赖,否则声明式依赖门禁会拦。

### 文档与 ADR 的落点

- **新开一条 ADR**:入库产物 + 漂移门禁(依据是可信性要求:第三方凭存档复算,前提是版本库里那串确切字节)。
- **修订 ADR 0005**:加一节说明「组装层的泛化」与「载荷加栏」都不改变缝;缝仍是那两次桥调用。
- hld 写回:`§5.0`(五条复验的新数字与版本组合)、`§5.2`(不重建 / trap 归引擎故障 / 四类裁决)、`§5.3`(抽样时钟)、`§5.1`(三件套加栏)、CLI 章节(退出码表);并关闭 `§12 #8`。
- 术语与文档漂移的小票**已完成**:srs 的「指令」改成「控制流事件」;hld 三处 `Runner` 改成 `SeatRunner`,并把 `§5.1` 里那句写成 `init/tick/dispose` 三方法的执行器缝改成实际的两方法形状(它此前与 ADR 0005 和已交付代码直接冲突);`CONTEXT.md` 补 `SeatRunner` 词条;`.scratch/sandbox-budget/` 两处断言加总错(7/4/1 → 6/4/1)修正。
- 标定代桩的兼容层**保留但改身份**:在它的头注里写明「只为标定代桩服务,桩一行未改是 gdd §8 记录 #7–#13 可复现的前提;真引擎上的基准复验是另一个节点的账」。

### 已知的两处反直觉但刻意如此

- `maxStackSize` **不启用**:启用会把栈溢出变成 guest 可捕获的异常(可被吞掉);不启用(默认)则溢出是 host 必见的 `RangeError`。这是「判据锚定宿主可直接测量的量」那条纪律的又一个落点。
- 越权调用**不做特殊处置**:删桥之后它只是普通 `ReferenceError`,被脚本吞掉时宿主零痕迹。真正的防线是静态期的 `__*` 禁令,删桥是第二层。

## Testing Decisions

好的测试只断言**外部行为**:对局产出的回放行、回放复算的一致性、退出码、观测文件的内容。不断言内部回调次数、不断言私有函数、不并列内部张量的形状。

三个测试面,按由高到低:

1. **引擎的 `runMatch`(最高缝,首选)**
   - 桩路径的既有测试是**不回归的基线**:执行器缝、导出面、十次重跑、三张夹具,全部必须保持绿。
   - 真沙箱路径新增一组集成测试:用真 VM 跑夹具脚本,断言回放可复算、`exceptionTicks` 按轨累加、到限出局时点位回归中立、未启用轨不判负。
   - 四个对抗场景各一条夹具:未捕获异常 / 控制流事件死循环 / API 轰炸 / 内存超线(含「guest 吞掉 OOM 仍被判」这一条)。
   - 先例:`packages/engine/src/determinism.test.ts`(十次重跑 + 回放复算 + 反向自证)、`packages/engine/src/fixtures/`(只钉不变量不钉结论)。
   - 注意:引擎的边界门禁只管**运行时代码**;测试文件可以自由读盘,所以真 VM 集成测试可以直接读 wasm 与入库产物。

2. **工具侧的五条复验探针与门禁**
   - 每条探针断言 hld §5.0 对应那一行的行为,数值类断言已冻结的常量、计时类断言区间;每条报错信息带对应的 hld 行号。
   - 一个冻结常量模块记录核对时的 `quickjs-wasi` 版本与 Node 大版本。
   - 先例:`.scratch/sandbox-budget/spike/`(可复现的一次性验证)与 `packages/tools/src/selfproof/run-selfproof-gate.ts`(命名门禁脚本的形态:多问、可开关反例)。
   - 另有一组端到端:真脚本 → `match` → `verify` 一致。

3. **CLI 的 `match` / `verify`**
   - 断言退出码与观测文件,不读回放内部结构以外的实现细节。
   - 先例:`apps/cli/src/cli.test.ts`(未实现子命令清单与退出码)、`apps/cli/src/match/` 的既有测试。

## Out of Scope

- **对局子进程池与并发调度**:本 feature 只把 `match` 做成子进程入口,不做 spawn、不做池、不做重跑编排。
- **跨进程的确定性门禁**(F 已交出同进程的十次重跑;跨进程那一层归质量与流水线节点)。
- **C 舱(占点不采集)在真引擎上的行为复验**:那份脚本按「站相邻」的猜测写成,在真规则下不累积进度,它的复验归占领契约补齐那个节点。
- **八个预算键的终值标定**:本 feature 只实现机制与「未定即不启用」的语义,终值归预算标定节点。
- **赛季报告、排名与叙事战报**。
- **两个对抗探针作为标定口径的用法**:本 feature 只把它们作为夹具交付,标定判据归预算标定节点。
- **变异测试、夜间流水线。**
