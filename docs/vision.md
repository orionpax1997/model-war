# vision:model-war 为什么做

| 项 | 值 |
|---|---|
| 状态 | 有效 |
| 本文拥有 | 定位、服务对象、核心差异、非目标与产品取舍、长期风险 |
| 本文不写 | 玩法规则与设计意图(→ [gdd.md](./gdd.md))、架构与工程约束(→ [hld.md](./hld.md))、参数取值(→ `rulesets/*.json`)、面向模型的契约(→ [docs/rules-v2/](./rules-v2/)) |

## 1. 定位

model-war 是一个私有、防污染的 LLM 对战项目,**娱乐优先、兼作 benchmark**:各参赛大模型在赛前一次性写定版 TypeScript 策略脚本;脚本在确定性引擎里自动进行 **1v1v1v1 四方领土争夺 RTS** 混战,人类只观战。

**首要产出是好看的对局**:多方混战、偷点、翻盘构成的对局就是主产品;模型排名是副产品。

## 2. 服务谁、测什么

两类读者:

- **做横向对比的人**(自媒体、评测作者):新模型发布后重跑一轮,就能拿到同一题目下的横向结果。
- **写模型的人**:题目固定、可复算,策略失败能定位到契约或引擎,而不是「说不清为什么输」。

项目同时测两种能力:

1. **读文档写代码** —— 模型能否仅凭契约一次性写出能通过校验、可运行的策略;
2. **策略质量** —— 写出的策略在对弈中是否真的会赢。

## 3. 核心差异

**规则文档私有、带版本、可演化**。题目本身不公开定版,厂商无法对固定题目做专项训练;新模型发布后重跑一轮即可得到横向对比,这是本项目对自媒体场景的价值。

竞品与先例分析见 [docs/competitors/](./competitors/);结论只有一条:有近似先例(LLM Skirmish)验证了「模型能写出可运行 RTS 策略」,但没有先例同时做**防污染**与**赛前定版**。

## 4. 非目标与产品取舍

| 不做 | 为什么 |
|---|---|
| Web UI 与观战渲染 | v0 交付 CLI + ASCII 回放查看器;回放自第一天按「可渲染」设计,渲染器后置 |
| 视频内容生产管线 | 叙事战报已能产出可用的文案素材,渲染不在本项目范围 |
| 开放式练习赛与持续策略优化 | 默认协议是赛前定版;事实优化与候选选拔是**显式开启**的固定协议,不是持续陪练 |
| 模型自动接入平台化 | 接一个新模型 = 改一份配置再重跑,不改代码 |
| 战争迷雾、多资源种类、部件拼装、技能 | 规则面最小。每加一种机制,都要重跑对称性与区分度验收,收益却不线性 |
| 跨赛季规则版本演化 | v0 只做版本隔离:不同 ruleset 版本的结果不进同一份排名 |

## 5. 长期风险

只列会让**项目定位失败**的风险;工程风险(沙箱逃逸、确定性破损)由 [hld.md](./hld.md) 的设计手段承接。

| # | 风险 | 影响 | 处置 |
|---|---|---|---|
| R1 | **防污染失效**:规则一旦离开私有仓库即可能被训练。泄漏路径不止「公开网站」——生成管线本身就要把契约全文送进各厂商 API,厂商是否用 API 流量训练无法验证 | 高 | 契约版本化演化,每赛季更换或微调;核心价值在「新模型发布后第一时间横向对比」,时间差内被污染的收益有限。**接受为残余风险** |
| R2 | **规则无区分度**:规则太简单则最优策略平凡(如无脑爆兵必胜),排名退化为编程功底排名 | 高 | [gdd.md](./gdd.md) 的设计约束是验收命题;约束在数值下不成立,必须是有意的设计决定并留记录 |
| R3 | **地图池偏差**:少量地图可能被特定策略(如出生点 rush)主导 | 中 | ≥3 张风格迥异的地图 + 座位均摊 + 矿路红线;由 `map-lint` 与基准脚本对局验证 |
| R4 | **脚本整体质量低**:弱模型全灭、对局单调 | 中 | 已证明强模型能写出高胜率策略;若整体偏低,放宽协议即可(迭代轮数是配置项),不必改代码 |

## 6. 已完成论证的去向

可行性论证、成本与时间估算、里程碑计划是一次性结论:它们已被代码与本仓现状承接,不再随文档维护。仍需追溯时看 git 历史(`git log -- docs/fsr.md`)。
