# rules-v2:当前模型契约

这一份是**你能读到的全部规则输入**,只读。四条各管一件事;契约正文只在这里,没有副本。

| 文件 | 内容 |
|---|---|
| `/contract/README.md` | 这份说明:四条各管什么、按什么顺序读 |
| `/contract/rules.md` | 机制、结算顺序、确定性约束 |
| `/contract/api.md` | 脚本可见的 API 面、错误码与数值常量 |
| `/contract/examples/minimal.ts` | 一份能跑的最小骨架,可以直接当起点改 |

## 读的顺序

1. 这份说明——它已经在首条消息里,不用再读一次。
2. `/contract/api.md` 的 §1 与 §6:脚本的形态、入口、返回值,以及那份骨架是怎么长出来的。
3. `/contract/rules.md`:机制与结算顺序。它比 API 长,按需读,不必一次读完。
4. `/contract/examples/minimal.ts`:照抄,或者在那之上改。

## 边界

- 四条都是只读的。写它们不会成功,也不会改变评分。
- `rules.md` 与 `api.md` 里的**数值表**是生成物,由规则集取值产出,也是取值唯一的露面处。需要数字时读表,不要从正文的措辞里反推。
- `/contract/examples/minimal.ts` 是 `/contract/api.md` §6 的逐字节副本。改它没有意义——要改就改你自己那份。
- 两份文档都是**自包含**的:只凭它们就够写出一个能过校验、能跑的脚本。表里没有的 API 名字用不了,编译与静态校验都会拦下它。
