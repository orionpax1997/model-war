## 1. 设计支柱(按优先级)

1. **戏剧性优先** —— 四方制衡、落后翻盘空间、多线冲突。任何让对局单调化的机制(必胜套路、无解滚雪球、垃圾时间)视为设计缺陷。
2. **领土即一切** —— 经济、产能、胜负全部挂在"点位控制权"上,博弈密度集中在抢点上。
3. **确定性可复算** —— 规则本身不含对局内随机过程;同种子 + 同四份脚本逐 tick 状态一致。
4. **对称公平** —— 地图四重旋转对称,四方初始条件严格对等,先后手不固定。
5. **规则面最小** —— 固定兵种、无部件拼装、无技能、无战争迷雾。

## 2. 核心循环

```
每 tick(四方基于同一份快照各自决策;调用顺序是引擎实现细节,见 hld《engine 概要设计》):
  1. 引擎向每方脚本喂一次只读状态快照(全图可见,无迷雾)
  2. 各方 loop() 执行,提交一组 intents(move / moveTo / attack / harvest / transfer / spawnUnit)
  3. 引擎统一结算:解析 intents → 移动碰撞裁决 → 对象 tick(伤害、占领、采集、生产)→ 写入状态
  4. 判定:点位全归一方 → 胜利;满足淘汰条件 → 出局(见 §3.1)
  5. tick 达上限 → 按领土分定名次
```

结算顺序、移动裁决细则、状态的持久化形态见 hld《engine 概要设计》;此处只定义"会发生什么",不定义实现顺序以外的细节。

**设计时间轴(随 `tickLimit` 缩放)**

| 阶段 | 预期内容 |
|---|---|
| tick 0 | 4 家各 1 主基地 + 起始农民 + 起始资金(见 §5) |
| 0 ~ 1/15 | 开矿、占家门口中立点、出第一批兵 |
| 1/15 ~ 4/15 | 中路点位争夺,第一次多方接触、偷点与反偷点 |
| 4/15 ~ 2/3 | 滚雪球与反滚雪球:多基地产线 vs 游击骚扰 |
| 2/3 ~ 上限 | 资源枯竭压力 + 领土分压力 → 决战 |

> 该时间轴是**设计预期,也是调参目标**:若对局在 2/3 处已经分出胜负,说明滚雪球过快;若到上限仍无人领先,说明终局压力不足(见 §8)。

## 3. 对局规则

### 3.1 胜利与淘汰

- **主胜利条件:单一玩家控制地图上全部点位(含敌方主基地)的瞬间获胜**,无需持续时间。
- **捷径条款:其余三方全部被淘汰时,仅剩玩家立即获胜**(避免清场垃圾时间)。
- **淘汰条件:玩家同时无任何单位且无任何基地**。部队尚存就仍有翻盘可能——被夺家后靠残兵反夺基地是刻意保留的戏剧空间。
- 被淘汰玩家名下残余点位全部**回归中立**。
- **结算顺序(判定即规范)**:每 tick 先判淘汰 → 被淘汰者点位回归中立 → 再判全点位归属 → 最后判捷径条款(兜底)。回归中立可能破坏"全点位"条件时,由捷径条款接住。
- **超时**(tick 达 `tickLimit`)与**淘汰并存时的名次排序**:

```
1) 获胜者(胜利或捷径条款)为第 1 名
2) 其余参赛者按存活状态分层:存活者排在已淘汰者之前
3) 层内:存活者按领土分降序;已淘汰者按淘汰时间倒序(后出局者名次更前)
4) 仍完全相同 → 并列同名次(赛季记分处理见 hld《排名》)
```

```
领土分 = baseScore × 控制基地数 + resourceScore × 控制资源点数
       + ⌊Σ存活单位造价 / unitCostDivisor⌋
```

### 3.2 占领机制(全兵种一致)

每个可占领点位(基地、资源点)持有 `owner`(可为中立)、`progressOwner`、`progress`。

- 点位为**单格**,同一时刻最多一个驱动者 D(站在点位格上的单位所属方),单格单单位。
- 单位**站在点位格上**即驱动占领;累积达 `captureTicks` 后所有权易主,进度清零。
- **全兵种占领速度一致**:农民不加速,它的价值只在经济与堵点。
- D 与 `owner` 同阵营:进度冻结保留。
- D 与 `owner` 不同:若 `progressOwner ≠ D`,则 `progressOwner = D、progress = 1`(转轨重计,无侵蚀);否则 `progress + 1`。
- **无人站立:进度冻结保留,不衰减。**
- **堵点战术**:己方单位站在自家点位上可直接物理阻止敌方踩点;对方需先消灭该单位(单位可被攻击,基地不可)。
- **占领不需要资源**,因此经济死亡 ≠ 出局(见 §5)。

> 设计张力(调参时须实测):占领速度全兵种一致 + 农民是最便宜的兵种 ⇒ 农民也是"最便宜的占领/堵点单位"。这与"农民专职经济"的意图相抵,必须靠基准脚本验证"农民海抢点"不是无脑最优。

### 3.3 公平性

- 地图**四重旋转对称**(绕中心 90° 旋转自洽),四方初始条件严格对等。
- 移动冲突按 `(tick + playerIndex) mod 4` 轮转优先。它保证单场内首发顺序逐 tick 轮转,但**不消除头对头偏置**:下标差 d 的两人,低下标在 `(4-d)/4` 的 tick 中先手。
- 因此**座位必须在赛季内轮换**:同一组参赛者在不同场次中轮流占据每个 seat(playerIndex),使偏置在赛季尺度上被摊平。**M×K 为 4 的倍数时,每位参赛者各座位的场次数严格相等;否则最多差 1 场,且差额落在同一相对位次**(要求与实现见 hld《场次与座位》)。
- 对象处理顺序按对象数值 id 升序(定序语义见 hld)。

### 3.4 异常与出局

- 脚本单 tick 抛异常(含超预算、越权调用):该 tick 指令集为空(单位原地待命),不影响其他三方与引擎;VM 与跨 tick 记忆保留。
- 累计异常达 `exceptionTickLimit`:该方判负出局(按淘汰规则处理,点位回归中立;判定顺序见 §3.1)。
- 累计计数随对局状态持久化,VM 中断或重建后**续算不清零**。
- 仅引擎级故障(WASM trap)会重建该方 VM,重建后模块级记忆清零;异常计数由持久化值续算,不受重建影响。
- 内存判据:每 tick 末按该方存活堆占用判定,达 `memoryTickCeiling` 视同该 tick 异常;tick 内瞬时触顶后自行释放的分配不判罚(分配上限 `memoryLimit` 本身不可突破)。
- 墙钟只用于观测,不参与判罚(见 hld《计算预算》)。

## 4. 地图与点位

- **网格**:边长由地图 JSON 声明(地图池内统一),Chebyshev 距离(八向移动,对角与直行等价)。
- **地形只有两种**:平原(可通行)与墙(不可通行)。无沼泽、无疲劳——机动价值靠地图形状与速度差体现,不靠地形税。
- **地图池**:≥3 张风格各异(开阔对攻图 / 廊道分割图 / 中心要塞图),均四重旋转对称。地图坐标是规则侧开放项(§8)。
- **点位布局(单张图基准)**:

| 点位 | 不变量(地图必须满足) | 说明 |
|---|---|---|
| 主基地 | 每方恰好 1 个,四象限对称 | 开局归属各家;具体坐标由地图声明 |
| 中立基地 | 数量为 4 的倍数,对称分布于中路/边路 | 可占领,占领后获得产线 |
| 资源点 | 数量为 4 的倍数,内圈(高危高收益)+ 外圈(家门口安全矿) | 有限储量 |

**具体数量与坐标由地图 JSON 声明**(hld《地图 JSON》),规则只声明上表的不变量并由 map-lint 断言;引擎按地图数据的点位数判定胜利,不硬编码数量。

### 4.1 种子变体

- 规则集本身无对局内随机过程,故种子驱动**地图变体**:地图声明成组四重对称的变体槽位,引擎以种子做确定性填充(墙体)。
- 变体只做**装饰性微扰**:保持四重对称与点位布局不变,不增加风格多样性(风格多样性仍由 ≥3 张地图承担),也不改变点位数量。
- 派生与生成实现见 hld《种子的用途》。

## 5. 经济与生产

**经济模型:主动采集,无任何被动收入**(刻意不做死锁保护)。
```
农民在己方资源点采集: +harvestRate 资源/tick(射程 1,站在矿相邻格)
携带上限:              carryLimit
交付:                  移动到己方控制基地相邻格,transfer(射程 1,一次交全部携带量)
资源归属:              玩家全局共享池(无上限,不按基地分池)
资源点:                必须先占领才有开采权;有限储量,采空后点位仍计入胜利条件
```

推论(设计意图):

- **无死锁保护是刻意取舍**:农民全灭 + 存款不足 = **经济死亡**,形式定义:玩家无任何农民单位且 `resources` < 农民造价。此时仍可用军事单位抢点续命(占领不需要钱),或抢回带农民的点翻盘——经济死亡 ≠ 出局,但压力拉满。
- **护矿是常态**:农民是全图最脆弱的高价值目标,骑兵袭扰农群是最廉经济的打击手段。
- **交付目标必须唯一确定**:单位同时相邻多个己方基地时,交付给 **id 最小的那个**(与全局定序语义一致)。
- 初始条件:`initialResources` 起始资金 + 起始农民,保证开局即可补经济或补兵。

**基地与生产**

- **不可摧毁,只能被占领**;无攻击能力、无维修。基地格可通行、单格单单位。
- **任何己方控制的基地都是产线**:生产排队互相独立(每基地一条队列,一次一个),多基地 = 并行产能——扩张直接转化为兵力优势,这是滚雪球的引擎,也是翻盘战的核心争夺物。
- 生产耗时由造价按固定比例派生(`spawnTicks`),下单即扣款;**资金不足时下单无效**(`ERR_NOT_ENOUGH_RESOURCES`),不占队列也不扣款。
- 出兵格被任意单位占据时,该队列挂起等待,格子空出后自动续出。
- 基地易主时,该基地队列取消并**全额退款**给原主;**原主已淘汰(基地回归中立)时不退款**——已出局者的资源池不再有意义,已投入资源销毁。

**扩张的两端约束(调参目标)**:单基地满产的资金消耗速度远高于单农收入,因此经济必须靠"多占矿 + 多农民"扩张;同时全图总储量必须在 `tickLimit` 内**可被采空**,否则 §2 的"资源枯竭压力"只是文案(§8)。

## 6. 单位与战斗

四种固定兵种,不可拼装;单一血池(无部件损伤),伤害整数。数值取值见 `rulesets/*.json`,本节只定义定位与必须成立的关系。

### 6.1 兵种定位与设计约束

| 兵种 | 定位 | 关键参数 |
|---|---|---|
| 农民 | 经济与堵点:采集、携带、交付;无攻击能力 | `worker{cost,hp,speed,spawnTicks,harvestRate,carryLimit}` |
| 近战 | 正面战力与抗线,性价比标杆 | 射程 1(仅相邻格);`melee{cost,hp,damage,speed,spawnTicks}` |
| 远程 | 阵地输出,无距离衰减;靠纵深与保护发挥 | 射程 > 1(取值须同时满足 C2 与 C6);`ranged{cost,hp,damage,speed,spawnTicks}` |
| 骑兵 | 高机动:袭扰、抢点、抓农、无视主力直插后方 | 射程 1、速度 = 2 × 其他兵种(C5);`cavalry{cost,hp,damage,spawnTicks}` |

**必须成立的约束(等成本、站桩对拼,由基准脚本对局验证)**:

| # | 约束 | 意图 |
|---|---|---|
| C1 | 近战 > 远程(等成本对拼近战胜) | 近战是抗线与换血基准 |
| C2 | 远程 > 骑兵(等成本对拼远程胜) | 骑兵不能靠正面换取战果 |
| C3 | 近战 > 骑兵,且优势明显 | 骑兵的价值全部来自速度,不来自战斗面 |
| C4 | 近战的 HP/造价与伤害/造价均为全兵种最高 | 使"数量 × 抗线"成为正面主策略,把战术差异推给机动与射程 |
| C5 | 骑兵速度 = 2 × 其他兵种速度(其余兵种速度为 1),且其造价 ≥ 2 × 近战造价 | 骑兵是"战略面的选择权",必须贵到不能当主力 |
| C6 | 远程在近战贴身 2 个 tick 内被击杀 | 防止远程成为通用兵种;它的输出必须靠保护换来 |
| C7 | 单基地满产的资金消耗 > 单农收入,且差距使"只开矿不扩产"与"只扩产不开矿"都不能赢 | 经济与产能必须互相牵引 |

> 若某条约束在数值下不成立,R2 风险(无区分度)即被触发:最强的兵种会退化成唯一解。约束本身可协商,但不成立必须是有意的设计决定,并在 §8 留记录。

### 6.2 战斗结算

- 同 tick 所有攻击**同时结算**(批处理,无先手秒杀);攻击者本 tick 死亡不影响其攻击生效。
- 伤害单一血池扣减,归零死亡;无护甲、无技能、无冷却。
- 目标不可为基地(基地不可摧毁)。
- `attack` 目标须为敌方单位,任意兵种均可被攻击(含农民);无攻击能力的单位的 `attack` 无效。

## 7. 参数清单

取值真源:`rulesets/v1.json`(由 `schema` 校验);面向模型的数值表由它生成到 `docs/rules-vN`。本表只定义参数的含义与设计意图。

| 参数 | 含义 | 设计意图 |
|---|---|---|
| 点位数量不变量 | 每方主基地数;其余点位的数量与对称性由地图声明、map-lint 断言 | 中立基地是滚雪球引擎;资源点分内外圈制造抢占动机 |
| `tickLimit` | 对局上限 | 决定终局压力出现的位置,须与采集能力匹配(§5) |
| `captureTicks` | 占领所需累积 tick | 抢点必须"站得住":数值越大越需要先清场 |
| `exceptionTickLimit` | 累计异常判负阈值 | 容忍偶发缺陷,不给失控脚本长期占用算力 |
| `initialResources` | 起始资金 | 保证开局即可在"补经济/补兵"之间做选择 |
| `harvestRate` / `carryLimit` | 采集速率与携带上限 | 与基地距离共同决定单农收入,是经济扩张的节拍器 |
| `resourcePerSite` | 单矿储量 | 与 `tickLimit` 共同决定枯竭压力是否真实存在 |
| `worker` / `melee` / `ranged` / `cavalry` | 四兵种的造价、HP、伤害、射程、速度、生产耗时 | 满足 §6.1 的七条约束 |
| `baseScore` / `resourceScore` / `unitCostDivisor` | 领土分权重 | 超时名次必须由"领土 + 存活兵力"共同决定,不能只看地盘 |
| `variantSlots` | 地图变体槽位 | 让种子有实际作用(§4.1) |

## 8. 开放项(规则侧)

工程侧开放项见 hld《开放项》,此处不重复。

| # | 项 | 备注 |
|---|---|---|
| 1 | §7 全部参数的取值终值 | 用 ≥2 个人类基准脚本标定;验收命题 = §6.1 的七条约束 + §2 的时间轴 |
| 2 | 3 张地图的具体坐标与 `variantSlots` 设计 | 四重对称由 map-lint 校验;需覆盖三种风格 |
| 3 | 资源枯竭压力与 `tickLimit` 的自洽核算 | 当前量级下"采空全图"在 `tickLimit` 内不成立,须重算储量或采集能力 |
| 4 | 农民担任占领/堵点单位的性价比是否过高 | §3.2 的设计张力;由基准脚本对局统计 |
| 5 | 单农收入 vs 单基地满产资金消耗的差距 | §6.1-C7;差距过小则"爆兵无穷",过大则对局停滞 |
| 6 | 种子变体的有效性 | 变体目前是纯装饰性微扰,对结果方差贡献极小,则 K 增大只是重复对局;需决定变体是否参与策略决策,或把 K 压到统计所需的最小值(fsr R3 现取 ≥5) |

## 9. 娱乐产出设计

- **回放数据自第一天起按"可渲染"设计**:每 tick 记录足以绘制完整画面的状态(点位归属、占领进度、单位位置与血量、玩家资源)。数据格式见 hld《回放 JSONL》。
- **叙事素材来自事件流**(首次接触、点位易手、单位阵亡、玩家淘汰、经济死亡、终局),战报生成器只消费事件,不重新解析状态。
- v0 交付 CLI + ASCII 回放查看器;Web 渲染器的交付时点见 srs §1.3。
