## 1. 定位与设计支柱

**一句话定位**:各参赛大模型赛前一次性编写 TypeScript 策略脚本,脚本在确定性引擎中打 **1v1v1v1 四方领土争夺 RTS**;人类仅观战。

本项目的首要产出是**好看的对局**:多方博弈、翻盘、偷袭、夹击。benchmark 排名是副产品,不是第一目标。

### 设计支柱(按优先级)

1. **戏剧性优先**——规则要制造"节目效果":四方制衡、落后翻盘空间、多线冲突。任何机制如果让对局单调化(必胜套路、无解滚雪球、垃圾时间),视为设计缺陷。
2. **领土即一切**——经济、产能、胜负全部挂在"点位控制权"上,博弈密度集中在抢点上。
3. **确定性可复算**——同种子 + 同四份脚本,逐 tick 状态一致;回放是纯数据。
4. **对称公平**——地图四重旋转对称,四方初始条件严格对等。
5. **规则面最小**——固定兵种、无部件拼装、无技能、无迷雾。LLM 可驾驭、观众可理解、失败可归因。

### 与 LLM Skirmish 的关键差异

| 维度 | LLM Skirmish | model-war |
|---|---|---|
| 玩家数 | 1v1 | **1v1v1v1**(远期 N 方) |
| 胜利条件 | 摧毁对方 Spawn(歼灭战) | **占领全部基地与资源点**(领土战) |
| 单位构造 | body-part 自由拼装 | **固定兵种,各明码标价** |
| 经济 | 矿脉采集 | 采集 + **占领解锁开采权** |
| 首要目标 | benchmark 评测 | **娱乐内容**;排名降级为副产品 |
| 排名 | Elo | 名次积分制(Elo 可选) |

## 2. 核心循环

```
每 tick(四方脚本同时执行):
  1. 引擎向每方脚本喂一次只读状态快照(全图可见,无战争迷雾)
  2. 各方 loop() 执行,提交一组 intents(move / attack / harvest / transfer / spawnUnit)
  3. 引擎统一结算:
       a) 解析 intents
       b) 移动碰撞裁决(单格单单位;冲突时按 (tick + playerIndex) mod 4 轮转优先)
       c) 对象 tick(伤害落地、占领进度累积/衰减、采集、生产倒计时)
       d) 写入状态,清空 intents,tick++
  4. 判定:全点位归属单一玩家 → 胜利;玩家无单位且无基地 → 淘汰
  5. tick 达上限 → 按领土分定名次
```

局内时间轴(设计预期):

```
tick 0       4 家各自:1 主基地 + 3 农民 + 2 近战 + 初始资金
tick 0-100   开矿、占家门口中立点、生产第一批兵
tick 100-400 中路点位争夺,第一次多方接触,偷点与反偷点
tick 400-1000  滚雪球与反滚雪球:多基地产线 vs 游击骚扰
tick 1000+   资源枯竭压力 + 领土分压力 → 决战
最迟 1500    领土分结算
```

## 3. 对局规则

### 3.1 胜利条件

- **主胜利条件:单一玩家控制地图上全部基地与资源点(含敌方主基地)的瞬间获胜**。无需持续时间。
- **捷径条款:其余三方全部被淘汰时,仅剩玩家立即获胜**(避免无观众的清场垃圾时间)。
- **淘汰条件:玩家同时无任何单位且无任何基地**。部队尚存就仍有翻盘可能——被夺家后靠残兵反夺基地是设计上刻意保留的戏剧空间。
- 被淘汰玩家名下残余点位全部**回归中立**。
- **超时(tick 上限 1500 ⚙)按领土分定名次**,同分同名次(允许并列):

```
领土分 = 3 × 控制基地数 + 1 × 控制资源点数 + ⌊Σ存活单位造价 / 2⌋
```

### 3.2 占领机制(全兵种一致)

每个可占领点位(基地、资源点)持有:`owner`(可为中立)、`progressOwner`、`progress`。

- 单位**站在点位格上**即驱动占领:**累积 30 tick ⚙ 进度**后所有权易主,进度清零。
- **全兵种占领速度一致**(已确认:农民不加速,专职经济)。
- 站立者与 `progressOwner` 同阵营:维持进度(若 `progressOwner` 为他人则无事发生)。
- 站立者与 `progressOwner` 不同:先以 1/tick **侵蚀**对方已有进度,清零后转为己方累积。
- 无人站立:进度以 **1/5 tick ⚙ 缓慢衰减**(中断保留、缓慢蒸发)。
- **堵点战术**:点位为单格,己方单位站在自家点位上可直接物理阻止敌方踩点;对方需先消灭该单位(单位可被攻击,基地不可)。

### 3.3 多方公平性

- 地图**四重旋转对称**(绕中心 90° 旋转自洽),四方初始条件严格对等(FR-1 AC2)。
- 移动冲突裁决按 `(tick + playerIndex) mod 4` 轮转优先,消除固定先后手。
- 对象处理顺序按对象 id 字典序,保证确定性。

### 3.4 异常与出局

- 脚本单 tick 抛异常:该 tick 指令集为空(单位原地待命),不影响其他三方与引擎(FR-4 AC3)。
- 累计异常达 100 tick ⚙:该方判负出局(按淘汰规则处理,点位回归中立)。

## 4. 地图与点位

### 4.1 网格与地形

- **50×50 ⚙ 网格**,Chebyshev 距离(八向移动,对角与直行等价)。
- 地形仅两种:**平原**(可通行)与**墙**(不可通行)。无沼泽、无疲劳系统——骑兵的机动价值靠地图形状与速度差体现,不靠地形税。
- 地图池 **3 张 ⚙**,风格各异(开阔对攻图 / 廊道分割图 / 中心要塞图),均四重旋转对称。

### 4.2 点位布局(单张图基准)

| 点位 | 数量 ⚙ | 说明 |
|---|---|---|
| 主基地 | 4 | 四象限对称分布(如 (10,10) 旋转组),开局归属各家 |
| 中立基地 | 4 ⚙ | 对称分布于中路/边路,可占领,占领后获得产线 |
| 资源点 | 8 ⚙ | 对称分布,内圈(高危高收益)+ 外圈(家门口安全矿) |
| 合计 | 16 | 全部计入胜利条件 |

> 参考:主基地 (10,10)/(39,10)/(10,39)/(39,39);中立基地于四边中点;资源点 4 个内圈近心 + 4 个外圈近主基地。具体坐标由地图 JSON 定,引擎不硬编码。

### 4.3 基地

- **不可摧毁,只能被占领**。无攻击能力、无维修。
- **任何己方控制的基地都是产线**:生产排队互相独立,多基地 = 并行产能——扩张直接转化为兵力优势,是本作滚雪球的引擎,也是翻盘战的核心争夺物。
- 基地格可通行、单格单单位(站上去即占领/堵点,见 §3.2)。

### 4.4 资源点

- **必须先占领才能开采**(己方点位的矿,己方农民才可采集)——占领即开采权,经济与领土强耦合。
- **有限储量,单矿 5000 ⚙**(约为典型对局总消耗的 1/2~1/3,全图总储量设为消耗的 2~3 倍),采空后点位仍计入胜利条件。
- 资源枯竭是天然的终局压力:无法再爆兵,逼僵局走向决战。

## 5. 经济

**经济模型:主动采集(Screeps 式),无任何被动收入**(已确认:不做死锁保护)。

```
农民在己方资源点采集:  +2 资源/tick ⚙(射程 1,即站在矿相邻格)
携带上限:              50 ⚙
交付:                  移动到任意己方控制基地相邻格,transfer(射程 1)
资源归属:              玩家全局共享池(无上限,不按基地分池)
```

推论(设计意图):

- **无死锁保护是刻意取舍**:农民全灭 + 存款不足 50 = 经济死亡。此时玩家仍可用军事单位抢点续命(占领不需要钱),或抢回带农民的点翻盘——经济死亡 ≠ 出局,但压力拉满,这是娱乐性来源之一。
- **护矿是常态**:农民是全图最脆弱的高价值目标,骑兵袭扰农群是最廉经济的打击手段。
- 初始资金 300 ⚙ + 起始 3 农民,保证开局即可补经济或补兵。

## 6. 单位(固定兵种)

**四种固定兵种,各明码标价,不可拼装**(已确认)。单一血池(无部件损伤),伤害整数。

| 兵种 | 造价 ⚙ | HP ⚙ | 伤害/tick ⚙ | 射程 | 速度(格/tick) ⚙ | 生产耗时 ⚙ | 特性 |
|---|---|---|---|---|---|---|---|
| 农民 | 50 | 100 | —(无攻击) | — | 1 | 5t | 采集 2/tick、携带 50;占领速度与其他兵种一致 |
| 近战 | 100 | 400 | 30 | 1 | 1 | 10t | 正面战力性价比之王 |
| 远程 | 150 | 150 | 20 | 3 | 1 | 15t | 射程 3,无距离衰减 |
| 骑兵 | 300 | 250 | 40 | 1 | **2** | 30t | 高机动:袭扰、抢点、抓农 |

- 生产耗时 = 造价 / 10 tick;每基地一条队列,一次一个;下单即扣款。
- 无治疗单位、无第 5 兵种——v0 锁死四兵种,v1 再扩。

### 6.1 克制关系(设计意图)

成本效率链(**站桩对拼**):**近战 > 远程 > 骑兵**。

- 近战 vs 远程:近战 400 HP 抗线,2 tick 贴身后近战 30 dmg 对远程 150 HP 是碾压;等价远程方需要拉扯与纵深才有得打。
- 远程 vs 骑兵:等价成本下(2 远程 vs 1 骑兵)集火可换掉骑兵,且骑兵接近途中白吃 1~2 轮射击;远程方阵型纵深是关键。
- 近战 vs 骑兵:站桩对拼近战大优(3 近战 3 tick 击杀 1 骑兵)。

**骑兵的价值不在正面**:速度 2 使其可以打得起选择权——绕后屠农、长途抢点、追杀溃兵、无视近战主力直插后方基地。**骑兵克近战克的是"战略面"而非"战斗面"**。

### 6.2 战斗结算

- 同 tick 所有攻击**同时结算**(批处理,无先手秒杀)。
- 伤害单一血池扣减,归零死亡;无护甲、无技能、无冷却。
- 目标不可为基地(基地不可摧毁)。

## 7. 脚本契约

与 LLM Skirmish 的 Screeps 系 API 保持同构,降低模型学习成本;完整签名与语义由 `docs/rules-vN` 定稿(FR-3 / FR-10)。此处为设计基准:

- **入口**:`loop()`,每 tick 一次;模块级状态跨 tick 保留(记忆能力)。
- **感知**:只读快照,全图可见(无迷雾,四方信息对称——背刺与结盟博弈全部摊在明面上,这是娱乐性来源)。
- **动作(intent)**:`moveTo` / `move`、`attack`、`harvest`、`transfer`、`spawnUnit(baseId, type)`。占领无需指令,站立自动驱动。
- **查询**:`getObjectsByType` / `getObjectById` / `getTick` / `getRange` / `findPath`(A* + CostMatrix)/ `getTerrainAt`。
- **沙箱**:worker 隔离,无网络/FS/宿主访问;预算形态(指令计数/计时)与超限细则是 **v0 设计待定项**(受 FR-2 确定性约束,见 §11)。
- **协议不变**:规则文档 + API 文档 → 生成 → 静态校验 → 仅回喂编译/校验错误 → ≤5 轮 → 冻结(FR-5)。无对战反馈。

## 8. 多方赛制与排名

### 8.1 对局组成

- 每场对局 = **4 个不同模型各一份冻结脚本**,同图同 tick 跑满。
- 循环赛:N 个模型取全部 4 人组合 × M 地图 × K 种子(5 模型 → 5 组合 × 3 图 × 5 种子 = 75 场)。场次选取对全体参赛者一致(FR-7 AC1)。

### 8.2 排名:名次积分制(已确认放弃 Elo 为主输出)

- 每场按最终名次记分:**第 1 名 3 分 / 第 2 名 2 分 / 第 3 名 1 分 / 第 4 名 0 分**;超时按领土分定名次,同分并列。
- 赛季总分 = Σ 各场名次分,场均分排名。
- Elo 可作为可选副产品输出(FR-8 AC1 的双轨仍满足),不进主报告标题。

### 8.3 娱乐产出(主输出)

- **叙事化战报**:每场对局自动生成事件时间线(首次接触、点位易手、玩家淘汰、经济死亡、终局数据),直接可作自媒体文案素材。
- **JSONL 回放自第一天起按"可渲染"设计**:每 tick 记录足以绘制完整画面的状态(点位归属、进度条、单位、血量、资源)。
- v0 交付 CLI + ASCII 回放查看器(FR-9);**Web 渲染器列为 v0.5**(范围变更,见 §12)。

## 9. 可观测性

- JSONL 状态流 + 人类可读战报双轨(FR-8 / FR-9),回放纯数据、不依赖引擎运行时。
- 每场对局的输入完整物化:四方脚本存档引用(含元数据,FR-6)+ 地图 + 种子,可复算、可重放。
- 报告标注规则版本 `ruleset vN`;不同版本结果不入同一排名。
