# GDD:model-war 玩法设计意图

| 项 | 值 |
|---|---|
| 状态 | 有效 |
| 本文拥有 | 玩法目标、设计支柱、设计取舍、不可从代码推导的约束、规则侧决策记录 |

**本文只解释「为什么这样设计」。** 规则本身(机制、结算顺序、确定性约束)在面向模型的契约 [docs/rules-v2/](./rules-v2/);参数取值在 `rulesets/*.json`;工程实现见 [hld.md](./hld.md)。凡是能从前三者读出来的事实,本文不复制。

## 1. 设计支柱(按优先级)

1. **戏剧性优先** —— 四方制衡、落后翻盘空间、多线冲突。任何让对局单调化的机制(必胜套路、无解滚雪球、垃圾时间)视为设计缺陷。
2. **领土即一切** —— 经济、产能、胜负全部挂在「点位控制权」上,博弈密度集中在抢点上。
3. **确定性可复算** —— 规则本身不含对局内随机过程;同种子 + 同四份脚本逐 tick 状态一致。
4. **对称公平** —— 地图四重旋转对称,四方初始条件严格对等,先后手不固定。
5. **规则面最小** —— 固定兵种、无部件拼装、无技能、无战争迷雾。

## 2. 核心循环与目标形态

每 tick:引擎向每方喂一次只读状态快照 → 各方提交一组 intents → 引擎统一结算(移动裁决 → 同时攻击 → 对象 tick → 胜负判定)→ 写出一帧可渲染状态。结算顺序的规范表述在 `docs/rules-v2/rules.md`。

**目标形态**(调参目标,不是规则):

| 阶段 | 预期 |
|---|---|
| 开局 | 四家各 1 主基地 + 起始农民 + 起始资金,开局即可采矿或出兵 |
| 前段 | 中路点位争夺,第一次多方接触、偷点与反偷点 |
| 中段 | 滚雪球与反滚雪球:多基地产线 vs 游击骚扰 |
| 收束 | 决战:领先格局定型后的收束;压力主要来自淘汰与领土分结算 |

对局在收束段之前就分出胜负,说明滚雪球过快;到上限仍无人领先,说明终局压力不足。**墙钟与资源枯竭不是终局压力的来源**:典型终局压力来自淘汰与领土分,资源枯竭只在极端经济下出现(见 §8 记录 #7)。

**首触判据吃的是接近度,不是路径**:绕路成本落在路径上,而首触看的是两军相向而行的接近程度,所以网格尺寸不因墙调整(实测复核见 §8 记录 #13 与 `packages/engine/src/fixtures/` 下的夹具)。

## 3. 关键取舍

### 3.1 胜负与经济死亡

- 主胜利条件是**单一玩家控制全部点位(含敌方主基地)的瞬间**;其余三方全灭时仅剩玩家立即获胜(避免清场垃圾时间)。
- 淘汰条件是**玩家同时无任何单位且无任何基地**。部队尚存就仍有翻盘可能——被夺家后靠残兵反夺基地是刻意保留的戏剧空间。
- **为什么接受经济死亡**:经济模型是主动采集、无任何被动收入(刻意不做死锁保护)。农民全灭且存款不足就是经济死亡,形式定义为「无任何农民单位且资源不足以购买农民」。经济死亡后经济不可逆,但**经济死亡 ≠ 出局**:占领不需要资源,玩家仍可用军事单位抢点续命。这是「压力拉满但保留翻盘」的关键取舍——若给被动收入,资源就永远不会成为死局,抢点动机随之消失。
- 被淘汰玩家名下残余点位回归中立。

### 3.2 占领机制的设计张力

- 点位为单格,单格单单位;**全兵种占领速度一致**,农民不加速,它的价值只在经济与堵点。
- 占领进度**无人站立时保留不动、不衰减**;驱动者换阵营即转轨重计,不侵蚀。
- **堵点战术**:己方单位站在自家点位上可直接物理阻止敌方踩点,对方需先消灭该单位(单位可被攻击,基地不可)。
- **未解的张力**:占领速度全兵种一致 + 农民是最便宜的兵种 ⇒ 农民也是最便宜的占领/堵点单位。这与「农民专职经济」的意图相抵,必须靠基准脚本验证「农民海抢点」不是无脑最优(证据见 §8 记录 #10 与规则侧开放项的裁决)。

### 3.3 公平性

- 地图**四重旋转对称**,四方初始条件严格对等;对象处理顺序按数值 id 升序。
- 移动冲突按 `(tick + playerIndex) mod 4` 轮转优先,方向定死为「值大者胜」。它保证一个对局内首发顺序逐 tick 轮转,但**不消除头对头偏置**(下标差 d 的两人,高下标在部分 tick 中先手)。
- 因此**座位必须在赛季内轮换**,使偏置在赛季尺度上摊平;精确均摊要求 `M × K ≡ 0 (mod 4)`,不满足直接报错。
- **策略优化机会相同**:显式启用事实优化的参赛模型遵循同一机会分配原则,不因无得分来源、已有行动或表现优劣获得额外或更少机会;诊断修复只恢复候选有效性,不替代优化机会。
- **优化与选拔共用一张评测网格**:同一轮生成里,每个有效候选在整张评测网格上跑一次,那份读数既是它的成绩,也是下一轮事实回喂的原料。**选拔独立于生成的执行,而不独立于测量**:它在独立进程里对**同一张计划**全量复算校验,排序直接用生成阶段的网格分数,不另起一次实验。正式评测仍是在对全体一致的条件下单独比较定版策略,其种子与生成阶段隔离;选拔与正式结果均不回喂。网格的形状、计划身份与两代存档的读取边界见 [ADR-0024](./adr/0024-single-evaluation-grid-and-selection-as-recompute.md),对手池见 [ADR-0023](./adr/0023-sparring-scripts-replace-benchmarks-as-opponents.md)。
- **选拔决胜规则**:只比较本轮完成全部优化机会的有效候选,采用整张网格的平均名次积分,分母恒等于计划声明的场次(缺场、异常与不确定终局不缩分母、不补零、不剔除);同分时先定义最高均分候选集合,仅在该集合内优先较晚阶段,再按协议轮号、编译产物 hash 确定决胜。历史归档保留原决胜语义(见 [ADR-0020](./adr/0020-selection-tiebreak-compatibility.md))。

### 3.4 异常与出局

- 脚本单 tick 抛异常(含超预算、越权调用):该 tick 指令集为空,不影响其他三方与引擎;VM 与跨 tick 记忆保留。
- 累计异常达阈值:该方判负出局(按淘汰规则处理)。
- **异常不清记忆、不重建 VM**:反复失控的脚本若能靠重建绕过计数,就等于没有上限。
- **墙钟只用于观测,不参与判罚**:墙钟受机器负载影响,任何参与判罚的墙钟都会破坏确定性。

## 4. 地图与点位

- 网格,Chebyshev 距离(八向移动,对角与直行等价);地形只有平原与墙两种。无沼泽、无疲劳——机动价值靠地图形状与速度差体现,不靠地形税。
- **三图共用一套点位布局**(4 主 + 8 中立 + 16 资源),**风格差异 100% 由墙承载**。「开阔对攻 / 廊道分割 / 中心要塞」只是描述性标签,不是需要枚举的分类表。
- **种子驱动地图变体**:变体是纯装饰性微调,只扰动墙体,保持四重对称与点位布局不变,**不参与策略决策**;种子数 K 的取值裁决见 §8 记录 #12。
- **两条只有人能守的地图设计约束**(机器判不出来,校验器只判红线):

  1. **地图正中的争夺目标三图都不放墙**:中心那 4 个中立基地与它们围出的空地,三张图上都是平原。要塞语义完全由墙给出。
  2. **家门到自家矿的那一小片必须留空,这是硬规则不是风格偏好**:墙把它拉长会拉长采集往返、压低吞吐,把枯竭时点推后。校验器有对应断言,但「为什么不能为了风格让一步」只有人记得。

- **两把尺并存是有意的**:点位归属用 Chebyshev 理论距离(与墙正交),矿路红线用八向最短路(量得到墙把路拉长)。矿摆得远不一定是错的,矿走不到才一定是。

## 5. 经济与生产

**经济模型:主动采集,无任何被动收入**(取舍理由见 §3.1)。

- 农民在己方资源点采集,携带上限封顶,交付到相邻的己方控制基地;资源是玩家全局共享池,不按基地分池。
- **护矿是常态**:农民是全图最脆弱的高价值目标,骑兵袭扰农群是最廉经济的打击手段。
- **交付目标必须唯一确定**:单位同时相邻多个己方基地时,交付给 id 最小的那个(与全局定序语义一致)。
- **基地不可摧毁,只能被占领**;**任何己方控制的基地都是产线**,多基地 = 并行产能——扩张直接转化为兵力优势,这是滚雪球的引擎,也是翻盘战的核心争夺物。
- 下单即扣款,资金不足时无效(不占队列也不扣款);基地格被单位占据时产线挂起等待——**自家单位堵自家基地会阻塞自己的产线**,这是堵点战术的自限成本。
- 基地易主时该队列取消并全额退款给原主;**原主已淘汰时不退款**——已出局者的资源池不再有意义。

**扩张的两端约束**:单基地满产的资金消耗速度远高于单农收入,因此经济必须靠「多占矿 + 多农民」扩张;同时全图总储量必须在终局前**可被采空**,否则「资源枯竭压力」只是文案。

## 6. 单位与战斗

四种固定兵种,不可拼装;单一血池,伤害整数,同 tick 全部攻击**同时结算**(批处理,无先手秒杀),攻击者本 tick 死亡不影响其攻击生效。

**必须成立的约束**(等成本、站桩对拼,由基准脚本对局验证;取值在 `rulesets/*.json`):

| # | 约束 | 意图 |
|---|---|---|
| C1 | 近战 > 远程 | 近战是抗线与换血基准 |
| C2 | 远程 > 骑兵 | 骑兵不能靠正面换取战果 |
| C3 | 近战 > 骑兵,且优势明显 | 骑兵的价值全部来自速度,不来自战斗面 |
| C4 | 近战的 HP/造价与伤害/造价均为全兵种最高 | 使「数量 × 抗线」成为正面主策略,把战术差异推给机动与射程 |
| C5 | 骑兵速度 = 2 × 其他兵种,其造价 ≥ 2 × 近战造价 | 骑兵是战略面的选择权,必须贵到不能当主力 |
| C6 | 远程在近战贴身 2 个 tick 内被击杀 | 防止远程成为通用兵种 |
| C7 | 单基地满产的资金消耗 > 单农收入,且差距使「只开矿不扩产」与「只扩产不开矿」都不能赢 | 经济与产能必须互相牵引 |

若某条约束在数值下不成立,R2 风险(无区分度)即被触发:**最强的兵种退化成唯一解**。约束本身可协商,但不成立必须是有意的设计决定,并在 §8 留记录。

## 7. 参数的含义与意图

参数的**取值**真源是 `rulesets/*.json`(键名、类型、量纲与含义的真源是 `packages/schema` 的键清单);面向模型的数值表由它生成到 `docs/rules-v2/`。本文不复制取值。

最容易误读的三处:

| 参数 | 含义 | 意图 |
|---|---|---|
| `tickLimit` | 对局上限 | 决定终局压力出现的位置,须与采集能力匹配 |
| `captureTicks` | 占领所需累积 tick | 抢点必须「站得住」:数值越大越需要先清场 |
| `resourcePerSite` | 单矿储量 | 与 `tickLimit` 共同决定枯竭压力是否真实存在 |
| `variantSlots` | 地图变体槽位(静态候选轨道清单) | 种子唯一的实际作用;变体纯装饰、不参与策略决策 |

## 9. 娱乐产出设计

- **回放数据自第一天起按「可渲染」设计**:每 tick 记录足以绘制完整画面的状态。
- **叙事素材来自事件流**:叙事战报生成器只消费事件,不重新解析状态。
- v0 交付 CLI + ASCII 回放查看器;Web 渲染器不在范围内(见 [vision.md](./vision.md) 的非目标)。
