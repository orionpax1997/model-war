# agent 形态的档案形状：过程记录、候选序与形状版本

## 问题

现有档案的形状是**为「逐轮」设计的**：`prompts` 每条存一轮的完整 prompt、下标即轮次；装载期断言「协议轮数等于 `prompts` 条数」；候选恰好三个，`stage` 是阶段下标；生成日志每轮一行。

分步形态把这些前提一起拆掉：一次会话有 N 步，每步对应的对话是**递增长度的完整历史**；「阶段」不再是 harness 施加的时序，而是三次评测配额的自然结果——模型可以第一步就用光，也可能只用到第二次就收工。

同时出现一个新问题：`evaluate` 就是提交（ADR-0030），所以档案必须记住「评的是哪一版」；而现有档案只记定版结果，不记**过程**。定版结果本来也不需要过程——one-shot 的产出即定版。

要裁决的是三件事：过程记录住在哪、候选怎么编号、形状变更怎么表达。这个过程记录还有一个决定性用途：**一次评测都没做的会话记为整次失败**，那时档案里唯一能回答「为什么失败」的东西就是过程记录。

## Considered Options

- **`prompts` 装每步的完整对话（落选）**：体积按 O(步²) 膨胀，且它已经不是「prompt」这个语义——装进老名字里会让读者按老语义读，而这个坑会随着引用次数固化。
- **复用生成日志承载全部历史（落选）**：日志是给人看的、可截断的、无结构保证的字符串行。把唯一的事实来源放进「有没有这个键」里，等于让日志格式决定数据完整性。
- **保持三个候选，缺的补空或重复末位（落选）**：空候选会被下游当成「这个阶段产出的东西」读，那是伪造。
- **保留 one-shot 生成路径，把分步表达为步数为 1 的退化（落选）**：两条生成路径意味着每个新字段、每条新断言都要维护两遍，而退化路径不产生任何新信息——它只是用更慢的方式跑一遍 one-shot。
- **档案形状进 harness 身份清单（落选）**：清单描述的是**模型面对的世界**（动作语法、可见二进制、挂载、配额、服务、观测出口、deadline、工具链）；档案是那个世界留下的**记录**，是消费侧格式。混进去之后，任何纯序列化的重构都会让身份哈希改变、让榜断代，把「换了 harness」稀释成「改了 JSON 排版」；而真正的读兼容问题它又解决不了——装载器没法靠一个叙事哈希判断「这份档案能不能读」。
- **快照新建独立目录（落选）**：档案目录的发布不变量是「目录存在即三件套完整」，往里塞东西会让这条变形；而逐候选产物已有命名族与引用字段，不需要第二套。
- **把派生的观测视图也搬进档案（落选）**：派生视图落盘等于给同一事实两个家；要复核「模型当时看到什么」，该进身份清单的是渲染规则，不是渲染结果。

## Consequences

### 过程记录是顶层一份，与协议轮数同义

档案顶层新增一个**可选**的过程记录字段，与 `prompts` / 生成日志平级，不进优化段——优化段装的是产物，过程记录装的是经过，层级错了会让「候选三个」的读者以为步数也归优化。

它是一份结构化条目数组，条目最小键集合固定为「步号、动作、标准输出、标准错误、退出码」，另带一个可选的模型原文键（ADR-0032：原文落盘，与发回去的字节同源；键集合与截断上限不变，所以形状版本不因它升）。条目键集合必须现在定死：装载器要靠它判完整性。

**每步 payload 的上限是上下文决策，不是存档决策。** 线性历史每一步都要重新发送，所以某一步的输出会被后续每一步重复付费；这才是上限存在的理由。因此截断发生在**生成侧**：模型看到的字节就是落盘的字节。档案大小于是被同一个上限封住（步数 × 上限量级），属磁盘账、不属正确性账。具体哪几条键有上限、保留多少比例，另由 loop 侧给定（ADR-0032）；其中模型原文键**不设上限**，因为它上一轮已经是响应 token，回传不增加新信息成本，而截断它会让模型看到自己刚写的代码被砍断。这条也是「观测外置」的同一条逻辑——摘要进上下文、全文在盘上、要不要看细节是模型的策略决策；上限对模型自己整读大文件同样生效，逼的是定向读，不是致残。

### 断言合并成一个公式

分步形态下 `prompts` 恢复原始语义：它装「这个会话是拿哪份 prompt 起的」，即一条。协议轮数在两种形态下本来就是同一个意思——**一次模型调用 = 一轮**，所以分步形态下它就等于步数。

于是装载期不再需要按形态分派两套规则，只需要一个公式加一个条件：协议轮数等于过程记录条数；起始 prompt 的条数在零步会话时为零、否则为一。传输重试耗尽的那次调用不进过程记录、也不进协议轮数，只在生成日志留一条传输末行——与既有语义一致。

### 发送侧证据与结果侧证据分家

生成日志保持「一次模型调用一行」，但它只装**发送侧**证据（轮号、模型、参数、用量、耗时、收敛与停止细节）。「这一轮被什么驱动」「编译错误码」属于结果侧，真源在过程记录的条目里；日志不再复写一份。一个事实一个家，复写的代价是迟早有一份是陈的。

唯一保留的行内判别符是**行类型**：传输失败行与收敛行形状本就不同，它需要一个说明「这一行是什么」的标记。判别行类型不是复写结果——结果讲的是「这一轮怎么回事」，行类型讲的是「这一行按哪种形状读」。传输重试耗尽的那一次调用因此仍能被单独识别，不必靠猜某个字段是否缺席。

### 候选不再按阶段编号

候选条数从「恰好三个」改为「一到三」：三次评测是**配额上限**，不是下限。候选的数组下标就是「第几次评测」，`stage` 这个概念连同它的字段一起消失；候选条目记录自己的步号，从而与快照、试跑观测一一对上。

这条改动不是把某个数字从三改成三的区间：**「恰好三个」散落在结构校验、装载关系校验与报告的上限计算里**，每一处都是一条独立判据。留下任何一处，「一到三」的档案就会在某条路径上被当成损坏。放开条数与登记档案形状版本必须是同一次变更。

把「必须满三次」写死会造出一个荒谬的激励：模型必须把配额用光才算数，而后两次评测可能只是重复提交。同理，`stage` 这个字段留下来就是「名字比内容活得久」——它对应的机制已经不在了，读者却仍会以为有阶段。

阶段概念的其余下游全部随之作废：反馈轮数、跨阶段复用标记、网格计划与陪练身份。分步形态的对局计划由配额与候选自身的分数、场数承担，不需要第二份计划结构。选拔仍然存在，但它的「胜者」指向候选序里的某一位，而不是某个阶段。

### 三个版本号各管一件事

- 档案形状版本：档案级的**读兼容契约**，必填，装载器与报告按它分派，不认识的版本**拒读**而不是猜。它是唯一能覆盖「失败档没有优化段」的版本号。既有的「精确键集」落盘断言随之按版本分派：每个版本的键集断言属于该版本的契约，不能用一个数字代表所有档案。
- 优化段版本：优化段内部的形状变体号，继续按现有方式分派。
- harness 身份（叙事版本 + 行为清单哈希）：只描述模型面对的世界。

三者同进同出会漂移，所以关系写死为一条断言：档案形状版本为分步形态时，优化段版本必须是对应值或优化段缺席。档案形状的变更**只**靠升档案形状版本表达，与身份哈希正交。

### 快照沿用既有命名族

评测时的快照落在既有逐候选产物的命名族里（观测旁挂 + 候选源码/产物后缀），由候选条目既有的文件字段引用，步号即那一族的序号。不新建目录，不改发布不变量。

派生的观测视图与检查全文**不搬进档案**：它们由落盘的观测数据与渲染规则确定性生成，落盘等于造第二个家；且「模型当时看到什么」这件事由身份清单里的观测出口形状承担。

### 失败档与成功档同形

失败记录是一份单文件，过程记录进同一个文件，与成功档**同键集合、同一条 payload 上限**。特殊化「失败档存少点」会让装载器、报告、复核工具各长一个分支，长期成本远高于那点体积；而失败档恰恰是校准 harness 的主要证据——读契约读了几步、命令全挂在编译上、动作没解析出来，这些是调步数上限与时序的唯一依据。

零步会话（一次模型调用都没成功）的合法形状是：过程记录为空、起始 prompt 为空、协议轮数为零、无优化段，落成失败档。

### 删生成侧，留读侧

阶段外循环被替换后，one-shot 生成路径没有调用者，删掉；**读侧保留**，既有的成功档与失败档仍要能被报告、复跑与回放读出。删掉生成路径后，那些只由存量档案覆盖的读侧分支靠**从现有档案抽取的测试 fixture** 保活（档案目录不在版本控制里，fixture 要复制进测试资产）。保留一条表现为「步数为一」的生成路径不是选项：它没有消费者，只有维护成本。

### 旧契约快照的读者是档案复核

`docs/rules-v1/` 的保留理由此前只写在它自己的目录说明里（「审计旧的生成记录与旧脚本」），ADR 里一句都没有。它其实是本册的直接推论：档案要能被复核，就必须留着当时那份契约，而且档案得能定位到**具体字节**——版本号定位不到文字（ADR-0008），所以定位只能靠契约包的内容哈希（ADR-0037）。

于是保留期不是「哪天想起来清理」，而是**跟着档案保留期走**。旧版本的散文冻结，生成区块仍归漂移检查管：那份快照不是归档的死文件，是「不许再改、但必须仍与真源自洽」。

## 残余风险

1. **过程记录让档案体积随步数线性增长**（每份兆字节量级），而档案目录是无保留策略的本地目录。这是磁盘账，不改变「模型看到的字节即落盘的字节」这条原则；若第一季后成为问题，解法在存储层（压缩或把过程记录移到旁挂文件），后者是升档案形状版本的变更。
2. **报告侧要靠「轮号等于步号」的左连接才能给出「这一步失败在哪」**。它成立的前提是「一次模型调用 = 一步」；一旦出现一步多调用的动作形态，这个连接立刻失效。
3. **读侧的分派从「两版优化段」变成「三版优化段 + 一个没有优化段的失败形态」**，报告的分支数会继续增长。这是为「删生成侧留读侧」付的账。

## 重评条件

- **出现一步多调用的动作形态**（一次模型输出触发多条命令、或 harness 替模型补发调用）：捕获侧证据与结果侧证据的连接键要重定，本 ADR 的证据分家结论随之作废。
- **对外公开发布 benchmark 结果、需要「同一张榜必须同一种档案形状」的强校验**：那时档案形状版本才进身份清单——它那时是对外承诺的一部分，而不是内部格式。
- **档案目录体积成为实际问题**：走存储层压缩或旁挂分卷，不修改「截断在生成侧」这条原则；任何改变档案形状的解法都要升档案形状版本。
- **loop 侧决定过程记录不保存模型原始输出**：该条已裁决——原文落盘（ADR-0031 与 ADR-0032），于是「复核模型当时被喂了什么」在分步形态下可复原；代价是 ADR-0029 里「档案不含模型原始输出」这句话只适用于既有 one-shot 档案，「语料只能自造」那条重评条件需要重新评估。
- **`CONTEXT.md` 里 one-shot 时代的词汇（优化轮、诊断修复、初次候选）在分步形态下失去所指**：已随 ADR-0032 同批收口——四条旧词条删除，「会话、动作块、过程记录、候选序、配额、工具档、上下文守卫」立为新词条，其余带阶段语义的措辞改述成会话与候选序。
