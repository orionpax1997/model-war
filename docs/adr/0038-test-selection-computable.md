# 测试选择：判据靠计算与观测，不靠声明；agent 不留决策点

「这次改动该跑哪些测试」这件事，判据必须由机器算出来并打印依据，而不是由人（或 agent）读一份表去判断。由此跟着两条硬约束：**少选必须能被证明**，**agent 面前不留档位选择**。

## 问题

三个事实把这件事撑开，前两个是实测。

1. **依赖图看不见最贵的那批用例。** 改 `packages/engine/src/runner/quickjs.ts`，`vitest related` 只选出 7 个 engine 测试；`cli-match` / `cli-verify` / `cli-season` / `selection` / `trial` 一个都不在——它们 spawn 打好的单文件产物，与被测代码在图上**没有边**。而缺的正好是工作量最大的那一块。少选的输出是**全绿**，没有任何信号。
2. **手写映射会腐烂，而腐烂无声。** 本仓曾用一张「改动半径 → 命名脚本」的前缀表替代选择器。它是人的拐杖：目录级、要人维护、新包新目录靠门禁提醒。更根本的问题是，读到它的人**无法判断它是否过期**——一张 40 行的表，正确与过期的样子完全一样。
3. **agent 没有独立真值。** 人忘了跑测试，后果会在 CI 上显形，人下次会记住；agent 少跑了测试，拿到的是绿，然后基于这个绿继续推理、写报告说「done」。所以「静默跳过」对人类是疏忽，对 agent 是**污染整条推理链**。这个仓的一等用户是 agent（AGENTS.md 的定位），所以这条是设计约束，不是体验优化。

再叠一条行为事实：agent 不会累，但**会批量化**。反馈回路一长，它就开始「攒着一次跑」，而那恰好是本仓最想避免的失败模式（写完一起跑 = 反馈回路断掉，与 `gate:types` 不进 `verify` 同源）。

## 决策

### 一、让被测对象的边界在依赖图上可见

入口拆成两半：可 import 的 `main(argv): Promise<number>`，加一层只负责进程边界的薄壳。

```ts
export const main = async (argv: readonly string[]): Promise<number> => { ... };
if (process.argv[1] === fileURLToPath(import.meta.url)) {
  process.exitCode = await main(process.argv.slice(2));
}
```

测试文件（经共用夹具传递）import `main`，于是「测试 → 命令面 → 各包 → 引擎」在图上连成一条真实的边；进程级断言仍然保留**少量**真 `spawn` 打 bundle 的用例，证「进程边界成立」（退出码、stdout 契约、bundle 打得出来）。

这不是为了选择器才做的重构。它独立成立：同一条链路现在能在同进程里跑，agent 调一次 `main([...])` 就能拿返回值做断言，不必为每个用例付一次 esbuild。

### 二、图看不见的输入靠观测，不靠声明

图看不见的有两类：**数据文件**（`rulesets/`、`maps/`、`prompts/`、`models.yaml`）与**产物字节**（被打进 bundle 的源码、wasm、入库 rootfs）。共同点是它们被读、被执行，不被 import。对这两类别猜——**记**。

一个 recorder 经 `NODE_OPTIONS=--import` 注入测试进程，并**随 spawn 传进每一个子进程**（子进程也是 `process.execPath`，环境在手里），记录每一次 open（**含失败的 open**，这样 `skipIf(!exists(...))` 的分支也留得下痕迹）与每一次 spawn（argv + 解析后的脚本路径）。产物按测试 id 落到 `test-inputs/`，**入库**。

选择 = `changed ∩ (计算闭包 ∪ 观测)`。这条设计的关键性质是：**它把「我没想到的第四类输入」变成可枚举的**。任何被真正读到、真正执行到的东西都会留下记录，不需要谁去列举。esbuild 的 `metafile` 作为第二真源并行存在（静态闭包），两者取并，不互相替代。

### 三、一条命令，没有档位

agent 面前只有 `check`（改完就跑）与 `check --full`（收口，与 CI 同一条定义）。人可以用 flag 取子集，agent 不做「这次算哪一档」的判断。

输出必须是**证据行**，不是结论：

```
packages/engine/src/runner/quickjs.ts
  → test:vm   (computed: 6 个测试 import 它)
rulesets/basic.json
  → test:vm   (observed: sandbox.test.ts 第 2 次 open 命中)
docs/hld.md
  → 无测试依赖 (gate:static 覆盖)
```

agent 不需要「理解」这张表，它只需要看到每一行都有依据。

### 四、少选必须打印证据；无证据即红

未登记的路径、无法解释的观测输入、声明与计算不一致、spawn 出去的子进程没带 recorder——全部红。这类红的方向是本 ADR 的核心：**错的方向要红，不能沉默**。

### 五、改动无人观测即红

改完之后没有任何测试观测到（computed 为空、observed 为空）→ 红，并给出两条出路：补用例，或在 `coverage-debt.txt` 里登记一行写清「为什么现在不测」。

这条把「未覆盖的改动」从夜间变异测试（12 小时后、片级、要人解释）搬到编辑循环里的即时信号。agent 的最大盲区正是「我改的东西没人测」——而现在的系统在它改完之后什么都不说。债务可见优先于债务为零：后者做不到，前者能持续驱赶。

## Considered Options

- **手写「改动半径 → 脚本」表当判据（落选）**：目录级、要人维护、过期无声。降级保留为**文档**——解释「为什么有这个测试族」有价值，参与选择没有。
- **`vitest --changed` 单独用（落选）**：它对闭合世界是准确的，对本仓最贵的那批用例是静默跳过。上面第一条决策之后它对**代码类**变得可靠，但仍看不见数据文件与产物字节，所以只能作为半个真源。
- **生成一个「bundle 输入清单」模块，让 `--changed` 的图覆盖它们（落选）**：这是把隐式边变真边的最省事写法，但它生成的是**又一张会腐烂的表**——一份手不用写、却必须与 metafile 保持一致的 import 清单。既然 metafile 能算，就用算的；既然图能连，就连真的。
- **按目录或测试标签过滤（落选）**：标签知道「一个测试是什么」，不知道「你改了什么」。两者之间没有映射，硬做出来就是上一条那种表。
- **靠 CI 全量兜底、本地只管快（落选）**：这正是当前的形态，也正是 agent 拿到假绿的形态。CI 那一次全量是收口，不是发现问题的位置——发现问题的位置必须在编辑循环里。
- **给用例标记「慢 / 需要真 VM」，让 agent 自己决定跳不跳（落选）**：把判断塞给 agent 就是留幻觉入口。跳与不跳必须由半径决定，不由人（或模型）的猜测决定。
- **观测靠「上一次记录」，接受它可能过期（部分采纳）**：过期的方向是少选，所以配一条自维护机制——**每次全量都重录并与入库 map 比对，差异即红**。输入集合变了，说明某段代码的副作用面变了，那本身就值得被看见，不该悄悄过去。

## 长期约束

1. **入口必须可 import 且 import 无副作用**：顶层只做 `argv[1] === fileURLToPath(import.meta.url)` 守卫。不用 `import.meta.main`（Node 22 上它是 `undefined`，CI 用的是 22）。
2. **recorder 必须传进子进程**，否则观测是片面的——这条自己有判据：spawn 出去的子进程没带 recorder 即红。
3. **`test-inputs/` 入库**，判据随仓库走。理由与 ADR-0027（变异基线随仓库走、不靠 14 天过期的 CI 产物）同源。
4. **每次全量重录并比对**，差异即红；map 永远从最近一次全量长出来。
5. **分层按「谁负责跑、能不能跳」**，不按耗时。四层：每次编辑（agent 每轮）、任务收口（agent 每任务一次）、合并前（CI，与收口同一条定义）、夜间（变异棘轮 / 自证 / kernel / 跨进程）。
6. **文档不承载判据**。`AGENTS.md` 只写「改完跑 `check`，收口跑 `check --full`」；「跑什么」不得出现在文档里。
7. **跳过必须有证据行**。任何「这次不跑 X」都要打印出为什么；打印不出来的就不许跳。

## 重评条件

- 观测漏选若在三个月内出现至少一次（由 `check` 与 `check --full` 的测试 id 差集暴露，且差集里出现了会红的用例），重评「观测」是否是合格真源，考虑回退到按半径的保守全跑。
- 若 vitest 或 Node 提供官方的「测试外部输入」机制（可外部声明依赖、或内建 open 观测），重评 recorder 与自带 map 的必要性。
- 若真进程特有的行为占比上升（跨进程断言无法在同进程复现），重评「少量真 spawn」的占比，以及 `check` 是否必须常带进程级那一族。
- 若 `coverage-debt.txt` 的行数持续增长而没有下降趋势，说明判据（红线）比团队产能更严，重评红线的形态——但不得改成「静默通过」。
