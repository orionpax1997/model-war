# 测试选择:判据靠计算与观测,不靠声明;agent 面前不留决策点

**约束**:「这次改动该跑哪些测试」由机器算出来并**打印依据**,不由人(或 agent)读一份表去判断。

## 问题

- **依赖图看不见最贵的那批用例。** 跨包的边指向产物(包解析走 `exports` → `dist/`),而 `git diff` 给的是 `src/`。改 `engine/src/runner/quickjs.ts`,`vitest related` 只选出 7 个包内测试;把同一改动翻译成 `dist/`,选出 11 个,含全部 `cli-*`。少选的输出是**全绿**,没有任何信号。
- **手写映射会腐烂,而腐烂无声。** 本仓曾用一张「改动半径 → 命名脚本」的前缀表。更根本的问题在读者:一张 40 行的表,**正确与过期的样子完全一样**,读到它的人无法判断它是否过期。
- **agent 没有独立真值。** 人忘跑测试,后果会在 CI 上显形,下次会记住;agent 少跑了拿到的是绿,然后基于这个绿继续推理、写报告说「done」。对人是疏忽,对 agent 是**污染整条推理链**。本仓一等用户是 agent,所以这是设计约束,不是体验优化。

再叠一条行为事实:agent 不会累,但**会批量化**——反馈回路一长就开始「攒着一次跑」,那恰好是最想避免的失败模式。

## 落了什么

1. **先修改动的表述:源码展开成产物。** 按每个包 `tsconfig` 的 `rootDir` / `outDir` 把源码映到产物,源码与产物**都**交给图取并集。映射不靠约定靠读;缺 `rootDir` / `outDir` 直接红(映射不出来就是图看不见它,而图看不见它会静默少选);`emitDeclarationOnly` 的包只映 `.d.ts`——映出不存在的 `.js` 会让「产物在不在盘上」永远答「不在」,于是一个几秒的改动每次退回全量。**产物不在盘上时退回全量**,不照旧少选:空边与「这个改动确实没影响任何测试」长得一模一样。
2. **让被测对象的边界在图上可见。** 入口拆成可 import 的 `main(argv)` 加一层只管进程边界的壳;测试 import `main`,于是「测试 → 命令面 → 各包 → 引擎」在图上连成真实的边;进程级断言仍留**少量**真 `spawn` 打 bundle 的用例,证「进程边界成立」。**它补的是包内那一跳,不是全部**(跨包的边在 `dist` 上),所以它不是第 1 条的替代。独立成立就要独立验收:同进程调用与真进程产物的表面输出必须**逐字节一致**,否则「同进程那一批」验的东西与「真跑一遍」验的东西会悄悄不是一回事。
3. **图看不见的输入靠观测,不靠声明。** 数据文件(`rulesets/`、`maps/`、`prompts/`、`models.yaml`)与产物字节被读、被执行,但不被 import;对这两类别猜——**记**。recorder 经 `--import` 注入测试进程并随 spawn 传进每个子进程,记录每次 open(**含失败的 open**,让 `skipIf(!exists(...))` 的分支也留痕)与每次 spawn;按测试 id 落到 `test-inputs/` 并**入库**。选择 = `changed ∩ (计算闭包 ∪ 观测)`,于是「我没想到的第四类输入」变成可枚举的。esbuild 的 `metafile` 作第二真源并行存在,两者取并,不互相替代。
4. **一条命令,没有档位。** agent 面前只有 `check`(改完就跑)与 `check --full`(收口,与 CI 同一条定义);人可以用 flag 取子集,agent 不做「这次算哪一档」的判断。输出是**证据行**不是结论:

```
quickjs.ts      → test:vm   (computed: 6 个测试 import 它)
rulesets/basic  → test:vm   (observed: sandbox.test.ts 第 2 次 open 命中)
docs/hld.md     → 无测试依赖 (gate:static 覆盖)
```

5. **少选必须打印证据;无证据即红。** 未登记的路径、无法解释的观测、声明与计算不一致、spawn 出去没带 recorder——全红。这条约束的核心是**方向**:错的方向要红,不能沉默。
6. **改动无人观测即红。** 改完没有任何测试观测到(computed 空且 observed 空)→ 红,两条出路:补用例,或在 `coverage-debt.txt` 登记一行写清「为什么现在不测」。这把「未覆盖的改动」从夜间变异(12 小时后、片级、要人解释)搬到编辑循环里的即时信号。债务可见优先于债务为零:后者做不到,前者能持续驱赶。

## 落选方案

- **手写「半径 → 脚本」表当判据**:目录级、要人维护、过期无声。降级保留为**文档**——解释「为什么有这个测试族」有价值,参与选择没有。
- **`vitest --changed` 单独用**:对闭合世界准确,对本仓最贵的那批静默跳过。产物展开之后它对**代码类**可靠了,但仍看不见数据文件与产物字节,只能算半个真源。
- **生成一个「bundle 输入清单」让图覆盖它们**:那还是**一张会腐烂的表**——手不用写,却必须与 `metafile` 保持一致。既然能算就用算的,既然图能连就连真的。
- **按目录或测试标签过滤**:标签知道「一个测试是什么」,不知道「你改了什么」;硬做出来就是上面那张表。
- **靠 CI 全量兜底、本地只管快**:那正是 agent 拿到假绿的形态。CI 那次全量是收口,不是发现问题的位置——发现问题的位置必须在编辑循环里。
- **给用例标「慢 / 需要真 VM」让 agent 自己决定跳不跳**:把判断塞给 agent 就是留幻觉入口;跳与不跳由半径决定。
- **观测只认「上一次记录」(部分采纳)**:过期的方向是少选,所以配一条自维护机制——**每次全量都重录并与入库 map 比对,差异即红**。输入集合变了说明某段代码的副作用面变了,那本身就值得被看见。

## 长期约束

1. **入口必须可 import 且 import 无副作用**:顶层只有 `argv[1] === fileURLToPath(import.meta.url)` 守卫;不用 `import.meta.main`(Node 22 上是 `undefined`)。
2. **recorder 必须传进子进程**,否则观测是片面的——这条自己有判据:spawn 出去的子进程没带 recorder 即红。
3. **`test-inputs/` 入库**:判据随仓库走,不靠会过期的 CI 产物(与变异基线同源)。
4. **map 永远从最近一次全量长出来**:重录即比对,差异即红。
5. **分层按「谁负责跑、能不能跳」,不按耗时**:每次编辑、任务收口、合并前(与收口同一条定义)、夜间。
6. **文档不承载判据**:「跑什么」不得出现在文档里,`AGENTS.md` 只写两条命令。
7. **跳过必须有证据行**:任何「这次不跑 X」都要打印为什么;打印不出来的就不许跳。

## 重评条件

- 观测漏选若三个月内出现至少一次(由 `check` 与 `check --full` 的测试 id 差集暴露,且差集里出现了会红的用例):重评「观测」是否合格真源,考虑回退到按半径的保守全跑。
- vitest 或 Node 提供官方的「测试外部输入」机制:重评 recorder 与自带 map 的必要性。
- 真进程特有行为占比上升(跨进程断言无法在同进程复现):重评「少量真 spawn」的占比,以及 `check` 是否必须常带进程族。
- `coverage-debt.txt` 行数持续增长而没有下降趋势:说明红线比产能更严,重评红线的形态——但不得改成「静默通过」。
