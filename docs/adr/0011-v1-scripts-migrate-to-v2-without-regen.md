# v1 冻结脚本直迁 v2:只改版本标签,不重新生成

v2 相对 v1 只改了两个预算终值(`eventTickLimit` 10000→50000、`apiCallTickLimit` 300→800),
机制、散文、快照面一字未动。11 条 v1 冻结脚本不再重新走 `modelwar gen`(省 11 次模型调用),
只把各存档 `meta.json` 的 `ruleset` 字段 v1→v2(每档 1 行 diff,脚本字节、prompts、哈希全不动),
直接跑 v2 赛季。本 ADR 记这条迁移合法的依据、边界与审计链。

## 依据:脚本在运行时看不见预算

- 预算在运行时**没有读口**:`api.md` 只把两数写成文字,引擎不向脚本暴露任何 getter。
  脚本能做的只是每 tick 发意图;限额只决定引擎何时拔线。v1→v2 是**纯放松**(两线都上调),
  同一份字节码在 v2 下的行为与 v1 下逐 tick 一致,直到 v1 会拔线而 v2 不拔的那个 tick——
  而那正是 v2 要纠正的误杀(测试季 77% 对局有人异常出局)。
- 冻结期校验(tsc + 确定性静态检查 + 体积)与取值无关,同一份字节码在两版下同过同不过;
  `validation.passed` 的印章继续有效,不重验。
- 模型写码时读到的是 v1 数字(v1 文字的 prompts/ 原样保留,不改写历史)。实测证明模型
  根本不按这些数字做优化(旧 sol 单 tick 5.5 万事件,顶着 10000 的线照写),故「读 v1 数字
  写出来的码」与「读 v2 数字写出来的码」在竞技上无实质差异;差异若存在,方向也是 v1 更保守。

## 边界

- 本决议**仅适用于纯预算量级变更**。v3 若动机制、散文判据或快照面,本 ADR 自动失效,
  回到「换契约即全重冻」(benchmarks/README §3 的重跑规则不受本 ADR 豁免,见该文件 v2 豁免记)。
- 旧 sol(单 tick 5.5 万)在 v2 线(5 万)下照死:直迁名单用的是已冻好的新 sol
  (`2026-10-10T23-08-53-678Z`,零 `findPath`,真峰 events 2 万/apis 172),不是复活旧脚本。
  旧 sol 存档留在库里,不参赛季。

## 审计链(机器可验)

- 11 档 diff 每档恰 1 行:`-  "ruleset": "v1",` → `+  "ruleset": "v2",`(本提交内)。
- `scriptSha256` 自洽、`sandboxRuntimeHash` 对常量、`prompts.length == rounds` 三判据不受影响:
  赛季装配期的存档校验会逐一重验,过不了就拒跑,不静默。
- prompts/ 里 v1 文字的契约是**真历史**(模型当时看到的就是 v1 数字),保留不动;
  若将来有人把 prompts 改写成 v2 数字,那才是伪造冻结记录。

## Consequences

- S1(首个 v2 赛季)的 11 条参赛脚本零新调用、零新字节,只有 11 行标签迁移。
- `season.yaml` 的参赛名单里 sol 一项换为新 runId,其余 10 条 runId 不变(同目录)。
- 若 v2 赛季出现与预算有关的异议,先查本 ADR 的「依据」节是否还成立,再决定是否重冻。
