# 优化与选拔的对手换成能力阶梯,基准脚本退回契约回归

优化与选拔都靠「跟谁打」这个词回答「这份候选强不强」,而同一个问题,不同的对手给出的答案是不同的问题。此前两处对局都用版本库内的三份**基准脚本**当对手。基准脚本的职责不是当强敌:它们由参赛模型**仅凭契约文档**盲写,存在的意义是证明「契约足够写出一份跑得通的策略」,行为互异是它们的判据,强弱不是。

后果是三重的。第一,**反馈里没有失败样本**:基准脚本对任何像样的候选都是被清场的对象,第一版候选就完胜,模型收到的反馈是三次「我赢了」,没有一处需要修。第二,**最能暴露问题的维度不在读数里**:同一份候选在四个座位上的表现差异极大(0 号位第一、1 号位掉到第三且超时),而对局只测过一个座位,失败从未进入提示。第三,**基准脚本会被契约变更整批重跑**:它们的身份不是钉死的,拿它们当尺子,尺子自己会换。

决定把对手换成来自**冻结存档**的**能力阶梯**:榜首、中位、末位,加上**在位脚本**(正在被优化的那个模型自己最近一次冻结存档)。这几份身份是**数据**,连同模型、存档运行标识与脚本内容摘要一起钉死,不随榜单滚动重算。一场对局只有四个座位、候选占一个,所以对手集合按「轮空一份」枚举,每份陪练在各组合里出场次数平衡——组合作为网格的一个维度归 [ADR-0024](./0024-single-evaluation-grid-and-selection-as-recompute.md),本文只定「谁是对手」。

在位那份有两处必须诚实。**没有存档时**:模型首次生成,它还没有任何冻结存档,在位由钉死的次弱档顶替,计划来源带上代位标注,反馈里写明「本阶段以 X 代位」——代位是**来源**,不是另一个角色,读计划的人看来源就知道这一份不是该模型自己的脚本。**字节相同时**:候选的编译产物与某份陪练逐字节相同,那一场照跑,并在反馈里标注「本场对手与你字节相同」。确定性镜像不携带独立信息,但回避它等于让读者以为那是一场比试;照跑并标注,是唯一既不重复计算也不掩盖事实的做法。

基准脚本**不被淘汰**,它们退回原本的职责:契约回归与产物逐字节门禁。那是另一类问题(契约能不能读懂、产物有没有漂移),与「对手够不够强」不是同一件事。两者不可互称,理由与用法见 [CONTEXT](../../CONTEXT.md) 的两个词条。

被否的方案:

- **继续用基准脚本当对手**:反馈里没有失败样本,优化轮没有可修的东西;要让它们变强就得放弃「互异」这条判据,而那条判据正是它们存在的理由。这是用优化效果换契约判据,两头都拿不到。
- **两者并用(同一场里既有基准又有陪练)**:口径混杂。同一份分数里既有「能不能跑通」又有「打不打得过」,分母、对手集合与结论都说不清属于哪一个;更要紧的是基准脚本会随契约变更整批重跑,混进去之后历史分数立刻不可比。
- **按榜单滚动重算(每次生成取当时的最新榜单)**:两次生成的分数不可比。模型名次一换,尺子就换;而与候选无关的事件(别人的比赛)也会改变这次的分数。要换池子就改钉死的那张表、重算计划身份并留下记录——那是一次显式决策,不是自动漂移。

长期约束:陪练身份是数据(角色 + 模型 + 存档运行标识 + 内容摘要),计划摘要覆盖内容摘要,装载时现算盘上字节的摘要并逐字比对,不符即拒并指名是哪一份;`scriptSha256` 认**编译产物**的字节,不认记录里的自述。代位只改来源、不改角色,来源标注与反馈里的「以 X 代位」不得省略。字节相同的对手照跑并标注,这条不因「看着像浪费一场」而删。基准脚本不承担优化与选拔的对手角色,它们的判据不为配合网格而放宽或收紧。反馈与存档只写事实(代位、字节相同),不给「该学谁、该躲谁」的因果结论。

重新评估的条件:扩容后三阶段仍然不改脚本(说明池子没有梯度)——那时该调**池子构成**(例如补一份与候选同档的对手),而不是继续加场次或加图;榜首陪练导致候选全线大败、反馈只剩事实没有可修项;榜单出现无档可用的模型荒(在位与代位都取不到可靠存档);或基准脚本与陪练的读数开始被人互相引用(有人拿基准分数当强弱证据),那时要把两者的边界写得更硬。
