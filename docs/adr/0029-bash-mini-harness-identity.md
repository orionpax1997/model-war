# 自建 bash-only harness，且它的身份由行为清单而非源码定义

## 问题

策略生成此前是「一次调用产出一整份脚本」。改成分步形态（模型自己写文件、自己跑检查、自己试跑）之前，要回答三个问题：**为什么现在要改**、**用谁的实现**、**换 harness 之后成绩还能不能比**。

第一个问题的答案在这轮实测里变了。改主意原本的理由是「一次产出会撞超时闸门，某些模型结构性不可用」。但渠道迁移后那个闸门不存在了（见 ADR-0028），同一个模型用 one-shot 跑通了全部阶段并拿到与快模型相同的分数。所以「不可用」这条论据已经作废，现在的理由是实测出来的另外两条：

- **代价**：那个模型花了 9 倍输出 token、17 倍墙钟去拿同一个分数，其中 96% 的 token 是 thinking。分步的意义是让每次产出小，而不是让原本跑不通的东西跑通。
- **反馈**：one-shot 形态下，模型对「自己写的脚本能不能编译、跑起来会不会飞、在评测网格上排第几」一无所知。这三件事在真实工程里是最基本的回路，砍掉它们之后，生成质量的瓶颈就不再是模型能力。

## Considered Options

- **用 mini-swe-agent 官方实现（落选）**：唯一优势是「我们用了公开的 v2.4.6」这句外部可信度。但逐项核查后这个优势归零——执行前配额拦截要写 `Environment` 子类，自定义动作语法要写 `Model` 子类（`action_regex` 只能换正则，返回形状固定是 `{"command": ...}`），四族原始 usage 也要自写 `Model` 类（走 litellm 会丢原始 provider body，cache 字段形状失真）。这三样写完，从 mini 借来的只剩 `agents/default.py` 里那 70 行循环，而**实际行为——什么命令能跑、什么动作算提交、看到什么 usage——全部由我们的子类决定**。对外说「用了 mini」，指的那 70 行恰好是全部行为里最不重要的部分。附加一条：`cmd &` 起的后台进程 mini 不管（`start_new_session=True` 让它脱离 `killpg` 清理路径），而那正是「模型自己起进程偷偷跑对局」的通道。
- **继续 one-shot，把分步当未来选项（落选）**：它确实能跑通，所以这不是「做不了」的落选。落选理由是上面的两条——代价与反馈。尤其是反馈：一次都没试跑过的脚本，与试跑三次后改过的脚本，是两类不同的产出，把它们放进同一张榜等于假装这个差别不存在。
- **自建 `packages/gen/src/agent/`（采纳）**：同栈、留在现有类型与测试覆盖内、复用既有的四族端点与证据链（`generation-policy.ts` / `requestEvidence`）、沙箱内容物可裁剪（禁自跑的唯一实现点）。

## Consequences

- **harness 身份是双轨：人写的叙事版本 + 门禁自动算的清单哈希**。`harnessVersion` 是人维护的（如 `bash-mini/0.1`），只用于叙事；`harnessDigest` 是对一份**显式行为清单**取的 sha256，进档案。两者不一致即门禁报错。
- **digest 的输入是清单，不是源码哈希**。源码哈希会因为重构就变，那是噪音；清单只在其行为真的改了时变，而那正是「换 harness」的定义。清单的内容是动作语法、可见二进制、挂载点、网络、配额、服务形状、可观测性形状、deadline、工具链。
- **换 harness 即不跨榜比较**，键是四维（见 ADR-0028 的 `channelId`）。`tscVersion` 不进键——决定 `check` 用哪版编译器的是 harness，它已经被 `harnessVersion` 吸收。
- **会话是单条，阶段是配额的副作用**。不切会话；三次 `evaluate` 把会话自然切成三段。阶段不再是 harness 施加的时序。
- **配额总量固定、自由分配**。强制均匀分配等于替模型决定「先广撒网还是先深挖」，而那正是分步形态的价值所在。
- **配额强制在宿主侧，不在沙箱内**。沙箱内的计数器不安全（模型能删、能重写）。真正的拦截点是 harness 自己：每条命令都是它派生的独立子进程，它在执行**之前**解析命令、命中受限工具就查自己的内存计数器，超限直接返回伪造的 stderr 而不执行。模型永远碰不到那个计数器。这条成立的前提是「harness 是唯一执行者」。
- **deadline 是两项硬约束加一项防挂起**。步数上限与总墙钟是 deadline；单步墙钟**不是** deadline，它只用于杀 `sleep 999` 这类挂起，与公平性无关，任何取值都不该影响成绩判读。服务调用不受单步约束，只受总墙钟约束。总墙钟取三十分钟而非一小时：单会话三段各数十步、每步平均十几秒才会用满，慢模型几步就能吃满，一小时会让这条变成空条款。
- **one-shot 表达为步数为 1 的特例，不建第二条流水线**。同一套外循环，`maxSteps=1` 时逐字节等价于现状。这不是为了兼容——它给了一个零成本的对照开关和一条回归基线：任何 harness 改动都应当能在 `maxSteps=1` 下重放旧档并得到相同字节。
- **不做 effort / thinking 分档控制**。推理控制的映射在各渠道上未验证，且这不是分步形态的必要条件。推论：分步省钱的路径只有「让每步输出小」一条，成本模型不得假设「探索步低 effort、定稿步高 effort」可用。

## 残余风险

这三条写在 ADR 里而不是留在对话里，因为它们会在 M1 之后才被回答：

1. **步数上限是估的**。无状态 shell 意味着模型会重复读契约、重复 `ls`，有效步数会被「重新读文件」吃掉一部分。实测后回填，回填即 digest 变更即断代——这是诚实的，不是缺陷。
2. **配额宿主侧拦截的凭证是「harness 是唯一执行者」**。一旦某个执行器引入持久会话或模型可触达的控制面，这条不成立，必须重测。
3. **某个带 `:free` 后缀的席位带着未验证前提进入赛季**。免费档在当前观测下无限流，但那是观测不是保证（见 ADR-0028）。

## 重评条件

- **决定对外公开发布 benchmark 结果时**，被否的 mini-swe-agent 重新进入考虑。届时的路径不是重做实验，而是把这份 ADR 的清单移植到它的 `Environment` / `Model` 子类上——契约已经定义清楚，移植是机械活。**在此之前不重开**，包括「借公开实现的名头让文档好看」这种理由。
- **步数上限实测后显著偏离估计**（无论偏高还是偏低）：回填即 digest 变更，旧档不跨该点比较。
- **执行器引入持久会话、容器 `exec` 或任何模型可触达的控制面**：配额强制的位置要重测，这是单会话方案的前提。
- **发现某条禁令无法靠沙箱内容物实现**：那意味着「bash 一开、白名单失效」这个前提有了例外，禁令的实现方式要整段重写。
