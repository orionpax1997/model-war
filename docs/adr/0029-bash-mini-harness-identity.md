# 自建 bash-only harness，且它的身份由行为清单而非源码定义

## 问题

策略生成此前是「一次调用产出一整份脚本」。改成分步形态（模型自己写文件、自己跑检查、自己试跑）之前，要回答三个问题：**为什么现在要改**、**用谁的实现**、**换 harness 之后成绩还能不能比**。

第一个问题的答案在这轮实测里变了。改主意原本的理由是「一次产出会撞超时闸门，某些模型结构性不可用」。但渠道迁移后那个闸门不存在了（见 ADR-0028），同一个模型用 one-shot 跑通了全部阶段并拿到与快模型相同的分数。所以「不可用」这条论据已经作废，现在的理由是实测出来的另外两条：

- **代价**：那个模型花了 9 倍输出 token、17 倍墙钟去拿同一个分数，其中 96% 的 token 是 thinking。分步的意义是让每次产出小，而不是让原本跑不通的东西跑通。
- **反馈**：one-shot 形态下，模型对「自己写的脚本能不能编译、跑起来会不会飞、在评测网格上排第几」一无所知。这三件事在真实工程里是最基本的回路，砍掉它们之后，生成质量的瓶颈就不再是模型能力。

## Considered Options

- **用 mini-swe-agent 官方实现（落选）**：唯一优势是「我们用了公开的 v2.4.6」这句外部可信度。但逐项核查后这个优势归零——执行前配额拦截要写 `Environment` 子类，自定义动作语法要写 `Model` 子类（`action_regex` 只能换正则，返回形状固定是 `{"command": ...}`），四族原始 usage 也要自写 `Model` 类（走 litellm 会丢原始 provider body，cache 字段形状失真）。这三样写完，从 mini 借来的只剩 `agents/default.py` 里那 70 行循环，而**实际行为——什么命令能跑、什么动作算提交、看到什么 usage——全部由我们的子类决定**。对外说「用了 mini」，指的那 70 行恰好是全部行为里最不重要的部分。附加一条：`cmd &` 起的后台进程 mini 不管（`start_new_session=True` 让它脱离 `killpg` 清理路径），而那正是「模型自己起进程偷偷跑对局」的通道。
- **继续 one-shot，把分步当未来选项（落选）**：它确实能跑通，所以这不是「做不了」的落选。落选理由是上面的两条——代价与反馈。尤其是反馈：一次都没试跑过的脚本，与试跑三次后改过的脚本，是两类不同的产出，把它们放进同一张榜等于假装这个差别不存在。
- **自建 `packages/gen/src/agent/`（采纳）**：同栈、留在现有类型与测试覆盖内、复用既有的四族端点与证据链（`generation-policy.ts` / `requestEvidence`）、沙箱内容物可裁剪（禁自跑的唯一实现点）。

## Consequences

- **harness 身份是双轨：人写的叙事版本 + 门禁自动算的清单哈希**。`harnessVersion` 是人维护的（如 `bash-mini/0.1`），只用于叙事；`harnessDigest` 是对一份**显式行为清单**取的 sha256，进档案。两者不一致即门禁报错。**这是设计，当前代码里两者都还不存在**，实现随里程碑落地。
- **digest 的输入是清单，不是源码哈希**。源码哈希会因为重构就变，那是噪音；清单只在其行为真的改了时变，而那正是「换 harness」的定义。清单的内容是动作语法、可见二进制、挂载点、网络、配额、服务形状、工具的参数面（收不收参数）、可观测性形状、deadline、工具链；**不含档案形状**——档案形状由 `archiveSchemaVersion` 表达（ADR-0031）。
- **换 harness 即不跨榜比较**，键是四维（见 ADR-0028 的 `channelId`）。`tscVersion` 不进键——决定 `check` 用哪版编译器的是 harness，它已经被 `harnessVersion` 吸收。档案形状变更同样不构成断代：它走 `archiveSchemaVersion`，与身份哈希正交（ADR-0031）。
- **会话是单条**。不切会话；三次 `evaluate` 是**配额上限**而不是时序，用几次由模型自己决定。「阶段」这个概念连同档案里的阶段字段一并废除（ADR-0031）——它原本是配额被用满几次的分段外观，不是 harness 施加的时序。
- **配额总量固定、自由分配**。强制均匀分配等于替模型决定「先广撒网还是先深挖」，而那正是分步形态的价值所在。
- **配额强制在宿主侧，不在沙箱内**。沙箱内的计数器不安全（模型能删、能重写）。真正的拦截点是 harness 自己：每条命令都是它派生的独立子进程，它在执行**之前**解析命令、命中受限工具就查自己的内存计数器，超限直接返回伪造的 stderr 而不执行。模型永远碰不到那个计数器。这条成立的前提是「harness 是唯一执行者」。
  > **修订（2026-11-20）：前提没变，保住它的**方式**变了。** 以前靠「沙箱里只放薄壳 + 一条只通向宿主的 fd 3 通道」：`check` / `evaluate` / `finish` 在沙箱里是真实存在的名字，只是不干实事。协议换成原生工具调用之后（ADR-0032 修订），这四个名字**不在沙箱里了**——受限工具根本不是沙箱里的东西，rootfs 的 `bin/` 里没有它们，模型唯一够得着它们的方式是一次工具调用，而工具调用由宿主分派。于是「阻止绕过」从「敲不到别的路径」升级成「**没有那个路径**」：`host/dispatcher.ts` 不再需要解析任何人写的字节来判配额，入参是结构化的。上面那段里「伪造 stderr」的具体载体也跟着换了：拒绝现在是一条 `isError: true` 的工具结果。
- **deadline 是两项硬约束加一项防挂起**。步数上限与总墙钟是 deadline；单步墙钟**不是** deadline，它只用于杀 `sleep 999` 这类挂起，与公平性无关，任何取值都不该影响成绩判读。服务调用不受单步约束，只受总墙钟约束。总墙钟取三十分钟而非一小时：单会话的步数上限内、每步平均十几秒才会用满，慢模型几步就能吃满，一小时会让这条变成空条款。
- **只有一条生成路径**。这是一条**结构约束**，不是一条行为承诺：它由「`generateOneModel` 是唯一生成入口、`sendOneRound` 只有一个调用点」保证，并由一条调用计数测试钉住（步数为 N 时 `check` 被调用 N 次）。**不保留表现为「步数为一」的 one-shot 生成路径**：它没有消费者，只有维护成本（ADR-0031）；既有档案改由读侧的版本分派承接。
- **不承诺跨版本的产出字节等价**。既有 one-shot 档案里没有模型原始输出（元数据只含起始 prompt 与生成日志，日志每行是发送侧证据，不含正文），所以「重放旧档」没有输入；这条适用范围只到既有档案为止：分步形态的过程记录带模型原文（ADR-0032），再往后的档案能重放「模型当时写了什么」，但那仍然不等于行为等价——且换 harness 即不跨榜比较（四键见 ADR-0028），「与旧版本比字节」没有消费者。本 ADR 初稿曾把「任何 harness 改动都应当能在 `maxSteps=1` 下重放旧档并得到相同字节」写成一条 Consequences，该承诺已撤回：它在技术上不可执行，而它想保护的东西（不建第二条流水线）由上面的结构约束承担。
- **等价这件事的能力边界写在测试里，不写在文档口号里**。任何离线测试都验不了模型行为是否改变——那是渠道与模型的属性，不是管线的属性。这句话现在有了具体住所：生成管线的落盘断言（元数据键集精确、候选源码哈希对得上冻结产物、冻结产物字节等于胜者字节）是「档案形状没漂移」的机器证明；它是回归测试，不是等价基线。这些断言的预期值由 `archiveSchemaVersion` 分派——一个数字代表不了所有档案（ADR-0031）。
- **不做 effort / thinking 分档控制**。推理控制的映射在各渠道上未验证，且这不是分步形态的必要条件。推论：分步省钱的路径只有「让每步输出小」一条，成本模型不得假设「探索步低 effort、定稿步高 effort」可用。

## 残余风险

这三条写在 ADR 里而不是留在对话里，因为它们会在 `A1` 之后才被回答：

1. **步数上限是估的**。无状态 shell 意味着模型会重复读契约、重复 `ls`，有效步数会被「重新读文件」吃掉一部分。实测后回填，回填即 digest 变更即断代——这是诚实的，不是缺陷。这只是身份哈希的变更；档案形状的变更不断代（ADR-0031）。回填之前，每步 payload 上限与上下文守卫已被 ADR-0032 定成硬约束，它们同样进清单、同样是断代项。
2. **配额宿主侧拦截的凭证是「harness 是唯一执行者」**。一旦某个执行器引入持久会话或模型可触达的控制面，这条不成立，必须重测。
   > **修订（2026-11-20）：这条风险的形状变了。** 它的原始关切是「薄壳通道」：一条继承的 fd 3 既可能是配额判据的传送带，也可能是逃逸路径。通道与薄壳都已删除（ADR-0032 修订），所以这条重评条件的对象要换成新的那一条：**受限工具不是沙箱里的东西，模型触达宿主的唯一路面是工具调用**。于是需要重测的情形变成「工具调用不再由宿主分派」——例如执行器自己实现了工具环、或渠道侧代发了调用。
3. **某个带 `:free` 后缀的席位带着未验证前提进入赛季**。免费档在当前观测下无限流，但那是观测不是保证（见 ADR-0028）。

## 重评条件

- **出现跨版本或跨 harness 比较产出的实际需求时**，重新评估「等价基线」的必要性——首个这样的场景是对外公开发布 benchmark 结果。届时语料不能取自 `archive/`：它不在版本控制里（`.gitignore`），且不含模型原始输出，只能按路径特征自造，从旧提交打金标。在此之前不重开，包括「想确认一下重构没改坏」这种理由——那件事由既有单测、code review 与一次真生成共同承担。
- **决定对外公开发布 benchmark 结果时**，被否的 mini-swe-agent 重新进入考虑。届时的路径不是重做实验，而是把这份 ADR 的清单移植到它的 `Environment` / `Model` 子类上——契约已经定义清楚，移植是机械活。**在此之前不重开**，包括「借公开实现的名头让文档好看」这种理由。
- **步数上限实测后显著偏离估计**（无论偏高还是偏低）：回填即 digest 变更，旧档不跨该点比较。
- **执行器引入持久会话、容器 `exec` 或任何模型可触达的控制面**：配额强制的位置要重测，这是单会话方案的前提。
  > ⚠️ **更新（2026-11-20）：这条的指向已变。** 它当初针对的是「薄壳通道」那套分派形状——一条模型能触达的常驻通道。通道没了，「模型可触达的控制面」在新世界里具体指「工具调用不再由宿主分派」（例如执行器自带工具环、或渠道代发调用），而不指「沙箱里又多了个东西」。旧世界那半条前提随 ADR-0032 修订作废；「持久会话」那半条仍然有效（它关系的是进程树回收与工作区生命周期，ADR-0033）。
- **发现某条禁令无法靠沙箱内容物实现**：那意味着「bash 一开、白名单失效」这个前提有了例外，禁令的实现方式要整段重写。
