# agent 形态下的度量与报告：证据归属、步级计时与上下文口径

## 问题

前五册把世界、记录、loop 与执行器都定了（ADR-0029/0030/0031/0032/0033），**没有一册回答「怎么量」**。而现有的度量层是**为「轮」设计的**：`AttemptEvidence` 挂在轮上，报告按轮渲染，`sendMs` 是「这一轮一次调用耗了多久」。M0.5 刚把用量口径补齐（`usage_semantic` / `usage_source`、缓存 TTL 分档、命中率），补的也是按轮的那一套。

agent 形态下这个单位**改名不消失**。一个会话最多 120 步、每步一次模型调用，而一次模型调用本来就是协议意义上的一轮——`meta.protocolRounds` 数的一直是它。所以按轮挂的度量恰好就是按步挂，**不需要重裁粒度**。

要重排的是四件事，每件都有一处「以为有、其实没有」的塌陷：

**证据挂在哪。** ADR-0031 把生成日志收窄成只装发送侧证据，结果侧（驱动来源、编译错误码）搬到过程记录，报告靠「轮号等于步号」左连接取回。那条左连接今天**一行都读不出来**：报告全文没有「步」的概念，档案里也还没有 `steps`。

**时间怎么量。** 整个档案**没有任何步级时间戳**。`stepWallClockMs` 是防挂起的闸门，不是度量值（ADR-0029）；沙箱执行耗时被 ADR-0033 显式排除出墙钟口径。所以「一步有多贵」在今天无从算起，而 agent 形态下「模型慢还是沙箱慢」是比 one-shot 重要得多的诊断。

**成本记什么。** `map.md` 说等第一轮真实数据。但**先要知道采集什么才能等数据**——而调查发现报告里**根本没有**「中位耗时」「总 token」「`wallClock`」「`tokens-per-solved`」这四列：今天只有 `sendMs` 逐轮加求和合计、token 各分量求和合计、以及现算不落盘的命中率。所以这件事不是改口径，是**新增列的清单**。

**上下文增长谁来兜。** one-shot 形态下上下文只增一次，agent 形态下它随步数增长。`maxSteps: 120` 与 `glyph-cluster` 的 256k 窗口放一起，可能步数上限根本达不到。更麻烦的是**命中率会因此失去信息量**：每步重发完整历史，分子分母同步增长，命中率是步数的函数而不是缓存效率的函数。

## Considered Options

- **两条报告各管一种形态（落选）**：one-shot 榜封存、agent 榜重开。不必——harness 身份双轨（ADR-0029）已经把「形态」变成身份维度，第二套表只是第一次跨形态比较时多出一份口径。而它还会掩护一个坏结果：两套表意味着我们可以不说清「一步」到底是什么。
- **把 `sendMs` 拓宽成整步耗时（落选）**：合一之后就再也分不清「模型慢」与「沙箱慢」。这个区分在 agent 下才真正值钱——一步里有 `check`、有 `tsc`。
- **步级计时用会话起止的绝对时间戳，其余靠推（落选）**：绝对时钟破坏档案的**确定性**。同一输入重跑产出不同字节，档案 diff 失去意义，这与「档案形状不进身份哈希」背后的那条立场相反。
- **把沙箱耗时排除在度量之外，`stepMs` 就等于 `sendMs`（落选）**：等于承认沙箱不可观测。而沙箱现在是 bubblewrap 起进程、跑 tsc，它的开销不是噪声。
- **结果侧证据扁平挂在步上（落选）**：`steps[i].kind` 与 `action.kind` 同层撞名——后者是 `bash` / `evaluate` / `smoke` / `done`，前者是驱动来源 `tsc` / `contract`，两个正交概念共用一层字段名，读侧迟早读错。
- **结果侧证据不落步，只留指针指向已外置的观测产物（落选）**：推翻 ADR-0031 已裁的「结果侧真源在过程记录」需要重开那一册，而收益只是省几个字节——观测产物记的是观测内容，不是「这一步是谁驱动的」。
- **截断重试算新的一步（落选）**：会产出没有动作、没有观测的空步，污染步数统计，并把「步数上限」偷偷变成「调用次数上限」——那与「一步 = 一次模型调用、整会话计」的口径打架。更要紧的是它让「轮号等于步号」从结构性保证退化成巧合。
- **左连接缺失时静默通过（落选）**：会把「证据缺失」渲染成「这一步没有失败原因」。这与报告已有的立场直接冲突——「没记录和真实零命中是两件事」，缺数据渲染 `null` 而不是 `0%`。
- **把「每步未命中 token」也单列一列（落选）**：它与保留下来的命中率是同一个信号的两种画法。一列够用，两列会让读数的人以为它们是两个独立现象。
- **加一个 `historyPolicy` 字段表达「目前不压缩」（落选）**：身份清单里多一栏，等于承认压缩是一个开放选项。而 ADR-0032 已把历史裁剪判为落选，`CONTEXT.md` 把上下文压缩列进了 _Avoid_。留一栏空位就是在邀请它回来。
- **现在就把 `tokens-per-solved` 定成判据，或落一个 `solved` 布尔（落选）**：前者把一个还没观测过的量锁成判据；后者是往档案里塞派生量。而分母（候选条数、步数、token、是否产出候选）本来就全在档案里——**采集侧零新增**，只等读侧口径。
- **把落点断言提前写进 `docs/hld.md` §11（落选）**：§11 的门禁逐行验落点存在性，一行里认不出任何落点即红。本册不写代码，写进去的只能是未来的测试名——那不是验收，是让门禁绿在一个空断言上。

## Consequences

### 一套列，形态是身份维度

报告只有一套列。「轮」一律读作「步」，one-shot 档就是步数为 1 的退化形态。跨形态比较靠 `modelVersion + harnessDigest` 分组，不靠换表。

这条约束的用处不在省事，在**逼着只给「步」写一个定义**。两套表会让「一步是什么」永远可以有两份答案。

### 步级计时必须新造落点，且不许用绝对时钟

过程记录条目加两个键：`atMs`（步起点相对会话起点的毫秒偏移）与 `harnessMs`（沙箱执行加观测回填的耗时）。

`atMs` 用**相对偏移**，因为它是唯一既能让档案自足、又不破坏确定性的形式；会话总墙钟由 `max(atMs + sendMs + harnessMs)` 跨步聚合得出，不往档案顶层另放一份。

`harnessMs` 是 `sendMs` 的**补集**，两者相加就是整步。这里刻意不复制 `sendMs` 进步记录：它已经在生成日志里，按「轮号等于步号」能关联到同一步。一个事实一个家。

顺带结清一笔：`AttemptEvidence` **不加任何时间字段**。尝试是证据单位，不是计时单位；重试窗口由步级的 `sendMs` 覆盖。M0.5 留下「重试等待只能看轮级耗时」那条 P2 项，就此正式回绝而不是挂账。

### 结果侧证据包一层

过程记录条目带 `result?: {kind: "tsc" | "contract", errorCodes: string[]}`。

包一层而不是扁平的第二个理由比避免撞名更重要：**「结果」可以整体缺失**。步超时、进程被杀、配额在动作执行前就切断，这些情况下那一步没有结果，而 `result` 缺席比 `errorCodes: []` 空数组忠实得多——空数组说的是「跑过了，没有错误」。

这与报告侧「缺数据渲染 `null`、不渲染零」是同一条纪律，落在两个不同的层。

### 截断重试并入同一步的尝试，左连接才是结构性的

传输重试已经有裁决：耗尽的那次调用不进过程记录、不进协议轮数（ADR-0031）。ADR-0032 的**截断重试一次**（`finishReason=length`）是另一次模型调用，本册裁定它也**不占步**——它作为同一步的第二个尝试，生成日志仍一行、`attempts` 两条、`sendMs` 覆盖两次调用。

判据是把「步」钉在**一个动作加一个观测**上，而不是「一次 HTTP 调用」。这样「轮号等于步号」是一一对应的结构性保证，ADR-0031 那条左连接才不是靠运气成立。

反过来说，一旦实现时把某种重试做成独立的步，「轮号等于步号」就会静默退化成一对我不知道多少。所以报告必须显式数不匹配的次数（见下），那是这条裁决的体检指标。

### 上下文不压缩，但要量出「离窗口多近」

历史不压缩这条继续照 ADR-0032 与 `CONTEXT.md` 的词条走：不裁剪、不摘要、不引入额外调用。本册不重开它，只承认它并把待决项**收缩成一个可测量的数**——`maxSteps` 在真实分布下是不是根本达不到，由报告回答，不由裁决回答。

代价是命中率不再能当效率指标读。所以报告保留命中率，但**降级成回归哨兵**：它一旦低于该步的理论值，说明前缀被打断了（时间戳注入、序列化不确定、中途改 `system`），那是别处看不见的真 bug 信号。报告必须写明这层口径，否则半年后必然有人拿它当效率排名。

真正有信息量的是每步的 `prompt` 大小（它同时是撞窗口的预测器）与每步的增长量。增长量取 `input[i] − input[i−1]`，首步渲染 `null`：这个数稳定而命中率骤降，就是前缀被断；两者同涨同落时，它们说的是同一件事，不必各画一列。

判「离窗口多近」需要窗口大小，而窗口今天只在 `models.yaml` 里。所以 `contextLength` **进档案的 `meta`**，档案自足优先——否则历史报告等于用今天的配置解释昨天的行为。它**不进身份哈希**：窗口是模型席位的属性，塞进 digest 会让同一个 harness 在两个窗口不同的模型上算出两个身份，榜单上就再也比不了 harness。窗口参与守卫行为这件事，由身份清单里的守卫参数间接表达，不重复记。

### 成本列全是诊断列，采集新增为零

资源不平权、只记录（ADR-0029）否掉的是「门槛」，没否掉「主指标」——本册把后者也否掉：所有成本列都是诊断列，不设排名主指标。

`tokens-per-solved` 暂不加。理由不是它不重要，是它的分母在 agent 形态下可争议（失败步算不算），而争议要在真实分布上裁，不能在空数据上裁。它的分母所需数据**全部已经在档案里**，所以采集侧新增为零——这一条写进清单比写一张字段表更有信息量。

命名上避开已有的对局预算字段：`wallClockSoftLimit` / `wallClockHardTimeout` 说的是对局，所以生成侧的墙钟叫 `modelWallClock` 与 `harnessWallClock`。

### 断言不能提前写进落点表

本册产出决策与落地断言，不写代码。而 `docs/hld.md` §11 是「已经能跑的东西」的家——它的门禁逐行验落点存在性。所以断言分两处住：本册写口径与重评条件，票的完成判据写断言本身作为交接物，由实现票在**落点已存在的同一次提交**里补进 §11。

这条不是流程洁癖。提前写进去会让门禁绿在一个空断言上，而那正是「能改判据的开关不能出现在判据自己的正常路径上」要防的形状。

## 残余风险

1. **`maxSteps` 与窗口的关系未实测**。本册只保证报告能量出步级 `prompt` 的 p95/max 与窗口的比例，让这个数由数据决定。若实测证明 120 步在 256k 窗口下根本达不到，要动的是步数上限，不是压缩历史——后者会让本册与 ADR-0032 同时作废。
2. **左连接成立依赖「截断重试不占步」被 loop 实现遵守**。这是本册与 ADR-0032 之间的一个交接面，没有测试能替它担保；靠报告的不匹配计数暴露。
3. **过程记录加键的 schema 解释未确认**。若条目的 `additionalProperties` 被判为精确键集而非可选键，加键要改 schema；按 ADR-0031「可选原文键不升形状版本」的先例，改 schema 也不 bump。这条要在实现时结账。
4. **`contextLength` 进 `meta` 需要一次形状版本 bump**。老读者读到新档按版本分派而不是靠猜——但这也意味着 `A1` 首档就必须带它，否则第一批数据没有窗口可比。ADR-0034 已把「身份从第一份 agent 档起就写」定成纪律，本册把窗口并入同一条纪律。
5. **步级分位的分组会随榜键演化**。分组维度用 `modelVersion + harnessDigest` 与榜键一致，榜键一变（ADR-0028 的渠道维度是最近一次变动），分位的可比性也变——那是分榜问题，不是度量问题。
6. **`harnessMs` 的边界依赖沙箱执行器的分派形状**。「沙箱执行加观测回填」这个划分只有在薄壳—宿主通道成立时才有意义；若执行器引入持久会话，一步之内的时间分界要重划。

## 重评条件

- **出现「一步多调用」的动作形态**（一次模型输出触发多条 harness 调用，或 harness 替模型补发调用）：本册的截断重试归并口径与 ADR-0031 的左连接同时失效，步的定义要重裁。
- **实测显示 `maxSteps` 在 256k 窗口下明显达不到，或实测显示高得离谱**：步数上限要回填（身份清单变更、断代）；若同时证明必须压缩历史，则本册的「不压缩」与 ADR-0032 的历史裁剪落选项一起重开。
- **第一季数据显示 `tokens-per-solved` 的分母在失败步上产生歧义**：那时才需要定分母口径，且只动读侧，不动采集。
- **命中率长期无法区分「前缀被打断」与「模型确实重读了大段历史」**：需要引入一个独立的缓存诊断量（例如按步的前缀哈希），而不是把命中率重新解释回效率指标。
- **`docs/hld.md` §11 的门禁放宽到允许悬空落点**：本册「断言不提前写」的约束随之失去理由，需要重新论证。
- **`CONTEXT.md` 里「步」的词条演化出「调用」这层含义**：本册把步钉在「一个动作加一个观测」上的前提失效，左连接与步数上限都要跟着改。
