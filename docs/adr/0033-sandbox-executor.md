# 生成期沙箱的执行器:bubblewrap,内容物以入库 rootfs 钉死

## 问题

ADR-0029 把禁令的落点定成**沙箱内容物**(不放引擎、不放试跑入口、无网络),ADR-0030 把它写成「工具白名单不存在,模型不能做什么由沙箱里放了什么决定」,ADR-0032 把三个受限工具(`check` / `evaluate` / 收工那一条;第四个候选工具 `smoke` 已在 ADR-0030 里落选)从二进制改成**薄壳 + 一条只通向宿主的通道**。收工那条在 ADR-0032 修订里叫 `finish`(`done` 是 bash 保留字,整块会被解析阶段拒掉)。**没有任何一册回答执行器是什么**,而它决定实现的第一行代码。

> **修订（2026-11-20）：本节里的「薄壳 + 一条只通向宿主的通道」已删除，那半句作废。** 协议换成原生工具调用之后（ADR-0032 修订④），`check` / `probe` / `evaluate` / `finish` **不在沙箱里**：rootfs 的 `bin/` 里只有静态 ELF，它们的家在请求体的 `tools` 声明，由宿主分派。所以执行器少了两件事：不必带薄壳副本，也不必架那条 fd 3 通道。本册下面凡提到「薄壳」「fd 3」的段落都按此读——它们是历史，不是当前形状。

三个问题捆在一起:谁提供隔离(`PID`/mount/网络命名空间)、内容物从哪来(从宿主借还是自带)、以及「一步」在进程意义上是什么。

第一条已被排除:宿主进程 + 目录裁剪。mini-swe-agent 用 `start_new_session=True` 让子进程脱离 `killpg` 清理路径,所以 `cmd &` 起的后台进程**活得过一步**。这一条洞不是洁癖问题——步数、配额、观测、提交四件事全部建立在「一步 = harness 派生的一次 `bash -c`」上,后台进程不产生步也不经过 harness:它白拿并行算力(步数上限与实际工作量脱钩)、让步与步之间的磁盘状态失去因果(过程记录记下的观测与 `/workspace` 现状不符)、并且能在 `evaluate` 之后继续持有写句柄,让「成绩取最后一次 `evaluate` 评的版本」这条失效。

另外两条事实决定了候选集:**仓库里 OS 级隔离零实现**(`bwrap`/`unshare`/`docker` 在代码里零命中),以及 `docs/hld.md` §2.2.11 早已把「Docker(主路径)」列入明确不做。第二件事在投票前要摆明:采纳容器化不是新增一条裁决,是推翻一条既有裁决。

## Considered Options

- **宿主进程 + 目录裁剪(落选)**:最快、零依赖,但没有 PID 命名空间,`cmd &` 活过一步;补法只有「独立 mount namespace」(已经是容器)或 cgroup 清理(要 root 或可靠的 cgroup 委托,而 runner 上没有用户 systemd 会话)。
- **Docker,每步一个容器(落选)**:它的隔离强度确实更高(容器销毁即清理,连内核态残留一起),但那份强度落在**威胁模型之外**——要防的是内核漏洞利用,而这里的对手是一个在写 shell 命令的语言模型。成本却落在预算之内:每步 200 ms–1 s 的启动往返、一个必须常驻的 daemon、以及通道从「继承的额外 fd」降级成「和 `bash` 抢 stdio」。**并且它与 §2.2.11 已有裁决冲突**。要区分两种容器形状:`docker run` 每步一次性,不构成持久会话;**`docker exec` 是持久会话**,正是 ADR-0029 重评条件点名的那种,不在候选之列。
- **gVisor / Firecracker microVM(落选)**:同上的错配,再叠加外部依赖——`/dev/kvm` 在托管 runner 上存在但未被文档化、官方声明嵌套虚拟化不受支持,把地基放在一项不承诺的能力上;启动形态也从每次 10 ms 级变成需要快照池才划算,通道还得从 fd 改成 vsock 重写。
- **nsjail / firejail(落选)**:前者不在 Ubuntu 源里、要编译;后者是 setuid 加桌面应用取向,有 CVE 史,不适合作为跑不可信代码的长期边界。
- **proot(落选)**:ptrace 语义,**不是安全边界**。
- **Landlock + seccomp,不建命名空间(落选)**:能封文件系统与网络,但没有 PID 命名空间,第一条洞照旧;它适合「限制一个可信程序的权限」,不适合「回收一棵不可信进程树」。
- **cgroup 清理作为兜底(落选)**:PID 命名空间已经覆盖,且它在托管 runner 上不可靠,多一套机制等于多一处会悄悄失效的判据。
- **内容物从宿主借:白名单二进制 + `ldd` 闭包(落选)**:零构建成本,但 `bash`、`grep`、coreutils、glibc 的版本随机器漂移,后果直接打在等价基线上——同一模型在两台机器上跑出不同成绩时,你先得排除「bash 版本不同」。缓解办法是记版本加一条 `ldd` 漂移门禁,而那是把不确定性记下来,不是消掉它。
- **内容物:busybox-static 顶三个命令 + 宿主 `bash`(落选)**:只解掉了三个 `.so`,`bash` 仍耦合,而且 `cat`/`cp`/`ls`/`grep` 换成 busybox 语义后 flag 差异会变成「模型失败原因不可归类」——最难修的一类噪声。

## Consequences

### 隔离机制是 bubblewrap,只用它

每一步是一次 `bwrap` 调用,不是「进一个沙箱」。形态是:**根文件系统从空开始**(`--tmpfs /`),宿主根目录一个 inode 都不出现;只 `--ro-bind` 进入库 rootfs、受限工具的薄壳与只读契约,`--bind` 进 `/workspace`;`--unshare-user --unshare-pid --unshare-ipc --unshare-uts --unshare-net --unshare-cgroup-try`、`--cap-drop ALL`、`--new-session`、`--die-with-parent`、`--clearenv`。

四条互不替代的性质:

1. **进程树回收靠内核语义,不靠 cgroup、不靠容器销毁。** 命名空间的 init 退出时,内核会杀掉该命名空间内全部残留进程。所以 `cmd &` 只能在**同一步内**活着(模型写 `cmd & sleep 1; wait` 是合法的),步一结束即全灭。
2. **可见面是「从空根里长出白名单」,不是「把宿主的 `/bin` 裁掉」。** 所以「绝对路径能绕过 PATH 白名单」这个问题结构上不存在:清单外的路径没有 inode 可指向。这是「隔离靠不给」纪律在进程侧的复述。
3. **无网络仍然是对的，但它的第二个理由没了（指针：见上节修订）。** `--unshare-net` 连 loopback 都不给，沙箱里的代码出不了网——这条不变，它把一条安全要求写成了结构性事实。原文还有半句「所以薄壳只能走继承的 fd」：薄壳与那条 fd 都已删除，这半句作废，剩下的「禁止出网」一个用途已经足够。
4. **两个生命周期是分开的,别混。** 沙箱实例 per-invocation(一步一次,没有可复用的旧实例);工作区 `/workspace` per-session(持久、由宿主持有、bind 进每一步的新实例)。连续性由工作区提供,不由沙箱进程提供。**「每步新实例」因此在 bwrap 下不是一条需要维护的不变量,而是定义使然**;只有在容器方案里它才变成一个需要设计并付启动开销的决定。

单步启动开销在 10 ms 量级,整场 120 步合计 1–2 s 量级。这个量不进墙钟口径的裁决:它小到不值得为它改判据。`totalWallClockMs` 的起止点仍归会话级 deadline 那一册,不在本 ADR 内。

### 薄壳通道已删:宿主的分派面在请求体里

> **修订（2026-11-20）：本节原文（「薄壳走 fd」那两段）已作废，只留指针。** 薄壳与 fd 3 通道整条删除（ADR-0032 修订④），细节见 `packages/gen/src/agent/host/dispatcher.ts` 的头注。

原文里有一条仍然成立、而且现在更强的性质：**信任方向由位置而不是由协议保住**。旧世界的说法是「模型能构造伪造**请求**，构造不出伪造**响应**」；新世界里模型连请求都不构造——宿主拿到的入参是结构化的（一次工具调用），不是一段要从 fd 上读回来再逐字节校验的文本。于是宿主侧那三件判定（工具名在声明里、配额按调用次数计、总墙钟未超）不再需要解析任何人写的字节。

本册只需记住一条：**执行器不再为宿主服务提供任何传输**。它只负责「一步一个新进程树」，宿主服务的接线在 loop 与 dispatcher 之间。

### 内容物是入库 rootfs,不从宿主借

沙箱里的全部内容物是一个十来 MB 的 rootfs 产物:静态 `bash` 加一组钉死的 coreutils,再加只读契约。它**入版本库、以字节为准**,并配一条「现算 == 入库」的漂移门禁——与 ADR-0007 对 runtime bundle 的处理同款。**清单本身不在这册里枚举**:它的家是 `packages/schema/src/sandbox-rootfs.ts`,每个二进制的版本、来源、sha256 与构建命令的家是 `packages/gen/sandbox-rootfs/PROVENANCE.md`(生成物),在 ADR 里抄一份只会过期。

这条选择的实质是把「容器」唯一真实的优势搬了过来:**镜像的价值是「内容物可钉」,不是「隔离更强」**。钉住内容物之后,等价基线的可比性不再依赖「两台机器的发行版恰好一样」,`ldd` 闭包门禁整条消失。

> **修订（2026-11-20）：本节原稿的「再加三个薄壳」已删，只留指针。** 薄壳副本不存在了（ADR-0032 修订④），`bin/` 里只剩静态 ELF；「不是 ELF 的内容物」这条分类随之消失（`gate:rootfs` 因此只剩一条判据）。

顺带缩小了沙箱的职责:因为 `check`/`evaluate` 全在宿主侧执行,沙箱里**不需要** `node`、`tsc`、`node_modules`、`rulesets/`、测试框架。它只需要 `bash` 加那几个 coreutils——其中 `cp` 是首条消息写明的起手式(`cp /contract/examples/minimal.ts /workspace/script.ts`),缺它那一步就是一次 `exit 127`。

### 资源上限靠 `ulimit`,不靠 cgroup——而且要承认它不完整

bubblewrap **没有**资源限制:没有 cgroup,也没有 rlimit 选项(上游「Use cgroups」请求至今未实现,「limit memory」的结论是「用 `prlimit`」)。而 **PID 命名空间只限制进程的可见性,不限制进程数量**:一个 fork bomb 在沙箱里照样能把宿主的 CPU 与内存吃光。

所以每步的 shell 外面必须包一层 `ulimit`(进程数、地址空间、CPU 秒),由 `bash` 内置承担,零依赖。这是必须项,不是加固项。

它的边界要说清:rlimit 是**逐进程**额度,不是聚合额度,`N` 个子进程各有一份额度。所以它是把「一次炸穿」降级成「炸得慢一点」,不是根除。彻底的办法是 cgroup v2 委托,它在托管 runner 上不可靠,所以本 ADR 选择不做,并把它记进残余风险。

### 不可用就失败,不降级

执行器启动时先自证:跑一条最小 `bwrap` 调用并断言成功,同时断言版本不低于所需的那个下限。失败即 fail-closed,任务直接失败,**不回落**到宿主进程执行。

理由与「降级并打标」的取舍:降级路径正是 `cmd &` 那条洞所在的路径,允许它存在会让威胁模型变成两套,于是逐条核对失去意义;而「标注降级」在实践中会退化成降级样本悄悄进了对比表。

报错必须写出已知成因,否则不可诊断——bwrap 从内核只拿到 `EPERM`,这是上游明说的限制,不是 bug:

- Ubuntu 24.04 默认开 `kernel.apparmor_restrict_unprivileged_userns`,一步 `sysctl` 可解;
- Ubuntu 26.04 起 `bwrap-userns-restrict` profile 默认已加载,光改 `sysctl` 不够,还要卸载该 profile,且 bwrap 的子进程会跑在一个拒掉全部 capability 的 profile 下;
- 在容器里跑 harness 需要四个 override(seccomp、apparmor、systempaths、`SYS_ADMIN`),少一个就是另一种 `EPERM`。

**Ubuntu 收紧非特权用户命名空间是政策而非缺陷**(发行版明确拒绝为 `bwrap` 提供通用 profile,选择给每个使用者单独配),所以「每个大版本重验一次」是长期成本,不是一次性成本。

**CI 上必须让它真跑起来,不许 skip。** 一条 `sysctl`(条件执行)、一次显式探针,让环境变化失败在**它自己那一行**,而不是变成一串莫名的测试失败或一整排静默跳过的用例。「不可用就跳过」是这一条的反面,门禁纪律不允许。

### 与「Docker 主路径明确不做」是同向的

本 ADR 不推翻 §2.2.11,而是给那条裁决补上生成期这一半的理由:容器化换来的强度不在威胁模型内,代价在预算内。Docker 不进入任何里程碑,也不作为「终态」保留——留一个「终态」等于给实现者一条迟早会走的捷径。

### 里程碑绑定

- **`A1`** 就要完整的执行器:rootfs、命名空间、fd 通道、受限工具的薄壳。理由是 `A1` 的验收里已经有 `check` 与 `evaluate`，而它们的前提就是那条通道——通道不能推迟到 `A2`（ADR-0034）。
- **`A2`** 同 `A1`，不换实现。
- **隔离收口**（preflight 门禁进主流水线 + 威胁模型逐条落成断言 + 四维榜键分榜）不单列成一段，压在 `A2` 末尾：它不改变模型看到的世界，拿不到新反馈。验收落点在实现落地时补进 `docs/hld.md` §11（此刻不写，写了就是指向不存在的文件）。

### 调试面必须结构隔离

沙箱内没有 `ps`、`strace`,也没有「进容器看一眼」这回事。所以会需要一个本地的诊断 profile(把宿主根 bind 进去、附送常规工具)。它必须是**独立代码路径 + 只认显式环境变量**,结构上不可能在生产路径生效。否则「调试开关」就是自己留的洞。

## 残余风险

1. **资源上限是逐进程 rlimit,不是聚合 cgroup。** fork bomb 能把宿主吃穿。缓解只有 `ulimit` 与宿主侧墙钟到点后杀整棵 bwrap 进程树;后果是可用性(DoS),不涉及读泄漏或逃逸。
2. **AppArmor 政策会一直变。** 每个 Ubuntu 大版本都要重验 preflight,26.04 已在迁移窗口内。这不是一次性适配。
3. **在容器里跑会缺能力。** 谁把 harness 塞进 devcontainer 或容器化 CI,就会撞上四个 override 标志;本 ADR 不提供兼容层。
4. **不设 seccomp。** 系统调用面全开,内核 bug 不在防线内。这不是疏忽,是威胁模型划界:对手是模型不是漏洞利用者。
5. **Linux-only。** macOS 与 Windows 开发机跑不了这条路径,要靠 VM 或容器(而容器又撞上第 3 条)。
6. **rootfs 产物是新的入库件。** 谁来更新它、怎么验它,实现时才定;它比代码产物更容易被「顺手升级一下」而无人察觉。
7. **首次在陌生环境上 triage 的成本是真实的。** bwrap 的报错只有 `EPERM` 这一档信息量,preflight 的成因清单是唯一的缓解。

## 重评条件

- **需要防内核漏洞的隔离**(对外公开发布 benchmark、或跑第三方交付的脚本):那时容器、gVisor、microVM 重新上场,本 ADR 的「威胁模型划界」这条理由失效。
- **目标环境里 bwrap 不可用且政策步骤解不掉**(例如强制容器化的执行环境):退回每步一容器,但薄壳通道与「宿主是唯一执行者」要重测(ADR-0029 同一条)。
- **执行器引入持久会话或模型可触达的控制面**:ADR-0032 的薄壳分派形状前提失效,与那册同一条重评条件合并处理。
  > **修订（2026-11-20）：这条的前半句已结账，后半句换了所指。**「薄壳分派形状」不存在了（通道已删，ADR-0032 修订④），所以旧世界那半条前提失效。「持久会话」那半条仍然有效（它关系的是进程树回收与工作区生命周期）；「模型可触达的控制面」现在指**「工具调用不再由宿主分派」**（执行器自带工具环、或渠道代发调用），不再指「沙箱里又多了个东西」（ADR-0029 同一条重评条件的更新）。
- **模型确实需要网络**(例如要装依赖才能跑 `check`):`--unshare-net` 要拆,通道协议与信任方向要重新设计,而不仅是加一个开关。
- **要把 `check` 从宿主侧搬进沙箱**(把 `node`/`tsc` 塞进 rootfs):rootfs 体积与漂移口径要重估,并且它与「宿主是唯一执行者」直接冲突,优先级高于本条本身。
