# 变异分数是棘轮:不许比上次低,基线的抬升必须显式为之

ADR-0010 把 `mutate` 定为夜间链上的观测项、不设红线,理由是「尚无基线就设红线只会得到一条天天红的流水线」。这条理由排除掉的是**绝对阈值**,并没有排除**相对退化**——同一套配置下,这一次的分数与上一次的分数是可比的,退化了就是退化了。而一个只落盘、不阻断的观测项,会在组织认知里变成「变异测试已经接入了」:它对交付没有任何约束力,低分片可以长期无人处置。故把变异分数做成**棘轮**:不设绝对红线,只设「不许比上次低」,并且基线的抬升只能由显式命令完成。

## Considered Options

- **保持只观测不设红线(落选)**:即 ADR-0010 的现状。落选理由不是它的推理错,而是它的结论停在半路——观测项一旦被当成「已完成」,就不再有人读它。设施的规模不变,约束从零变成一条,代价只是一份入库基线。
- **设绝对阈值(例如 80%)(落选)**:ADR-0010 已裁否,原因仍然成立。绝对阈值会同时产生两个坏结果:低于阈值的分片永远红(于是被忽略),高于阈值的分片永远绿(于是即使退化了也不报警)。它把一条连续信号压成一个二值开关,而二值开关的两种失效都不可见。
- **文件级棘轮(落选)**:一次合理的拆文件或并文件就会变成「必须批量抬降一批数字」,成本远超收益。分片的语义比文件稳定得多。
- **自动写回基线(落选)**:抬基线的成本一旦低于修测试,棘轮就会退化成另一种刷分——与刷覆盖率是同一条路径。约束的设计必须让「放弃约束」比「满足约束」更贵。
- **全局单一加权分(落选)**:分片之间本来就不可横向比较(跨包覆盖会被静默记成 Survived/NoCoverage,见 `stryker/base.mjs` 的头注)。把它们加权成一个数,等于制造一个不存在的可比性,再让人据此做决定。
- **棘轮(采纳)**:每个分片各自带一个入库基线,跑完即比;任何分片低于基线且未被显式接受,门禁红。

## Consequences

- **比较粒度必须与分片边界一致**。分片不是审美选择,它对应 Stryker「一次进程只有一份 mutate scope 与一份 testFiles」的物理边界;跨分片的分数不可比,因此也不能汇总成一个数。
- **基线入版本库,是棘轮的组成部分,不是产物**。产物(`reports/mutation/`)可以过期,基线不能——不入库的棘轮不是棘轮。
- **抬基线只能显式为之**。执行抬升的命令不得出现在任何流水线、任何默认链、任何常跑入口上;门禁自测须断言「跑完 `mutate` 后基线文件字节不变」,这条与「观测项不进任何常跑入口」是同一种反例。
- **agent 不得运行抬基线的命令**。这条与 `check:selfproof` 的 `--probe` 只准用于反例是同一个形状:**能改判据的开关,不能出现在判据自己的正常路径上**。
- **ADR-0010「只落盘观测」的条款在 `mutate` 上被本 ADR 取代,`scan` 上仍然成立**(本 ADR 只管有可比基线的分数,不管复杂度扫描的行数)。

## 重评条件

- **出现自定义 mutator 使分片间可比时**:重新考虑是否合并为全局棘轮。当前不可比的根因是跨包覆盖被静默记为存活,不是分片本身。
- **每变异体成本结构改变时**:若全量变异从「占一整夜」降到可 nightly 跑完,重新考虑棘轮粒度是否该更细。
- **某个分片的基线长期靠「接受」维持而非靠补测试时**:这是该分片变异体无解释力的信号(而非测试太弱的信号),应重新考虑它的 operator 范围,或删掉该分片——保留一个只靠接受维持的数字,比没有这个数字更坏。
