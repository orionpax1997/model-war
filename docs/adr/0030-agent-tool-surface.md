# agent 的工具面：两档、无提交动作、观测外置

## 问题

分步形态一旦给模型 bash，工具白名单就不存在了——`bash` 能调用的东西不经过我们的枚举。所以「模型不能做什么」这件事只能靠**沙箱里放了什么**来实现：不放引擎、不放试跑入口、不放对局存档、不放网络。

在这个前提下，要裁决的是「模型能做什么」的形状。两件事绑在一起：分几档、以及**模型能观测到什么**——最后一件是公平性问题，因为「观测到自己脚本的表现」是一种信息机会，而信息机会与资源不同，它不能靠多花钱买到。

「试跑」这一档的存废是本 ADR 的核心取舍：直觉上它该是一个廉价的先看一眼，但它的执行前提（缩小的网格、更紧的 tick 上限）与既有评测网格是同一个身份对象，见下方落选条目。

题面上有一个错需要更正：不是「完全没有示例」。规则文档里有完整可编译的最小骨架，且已有测试保证它与文档一致。缺的是**它没被拆成一个可以直接 `cp` 的文件**，所以模型得把骨架正文写进 completion 才能开始。

## Considered Options

- **`smoke`：一场对局、只回自己脚本的运行时状态（落选）**：它想解决的是「模型能否廉价地确认自己的代码没跑飞」。落选理由全部落在执行侧，不在价值侧——(1) **网格不能缩**：场数由常量派生，计划摘要是网格的身份对象，装载期会重建比对，手写一份小计划在生产路径直接判「与可重建结果不符」；(2) **tick 上限不是执行参数**：它是规则集键，取值真源只在 `rulesets/*.json`，为一场冒烟另造一份规则集等于给参数造第二个真源；(3) 于是它只能是一条**新的一小步执行路径**，而另一档 `evaluate` 的入口、观测、回喂、选拔全是现成的；(4) 它换来的信息严格少于一次完整 `evaluate`——不回胜负、不回对手身份、不回最差几场。代价账也不支持它：单场对整张网格的耗时差在一步的量级，而步数是硬约束但总墙钟留得很宽。
- **每轮恰好一次试跑（落选）**：单会话形态下没有「修复轮」也没有阶段边界，只有步——一步就是一次模型调用，所以「每轮恰好一次」无处可挂。它原本要解决的是「修复轮里大量失败发生在试跑阶段」，那个问题现在由「总量固定、自由分配」承接，而不是由 harness 掐点触发。
- **两步 `submit` + `evaluate`（落选）**：`submit` 会让模型「多存几版再挑」，那是评估配额之外的**新信息机会**——候选数从一到三次变成一到三次乘版本数。档案格式也要跟着改。而它换来的能力，`evaluate` 在快照语义下已经具备。
- **把契约正文注入首条消息（落选）**：全文体量与 one-shot 时代的 prompt 同量级，分步形态会名存实亡——模型还是面对同一个超人任务，只是多了一个能改文件的循环。分步的意义是让模型**自己去查**它需要的那一小块。
- **压缩观测而不外置（落选）**：增量渲染（「同上」）拿确定性换体量。模型需要回溯时，压缩过的历史会逼它重跑一遍；而步数是硬约束。
- **两档加信息外置（采纳）**：`check` 计步不占配额，`evaluate` 是唯一的信息机会。见下。

## Consequences

### 两档的性质不同，待遇也不同

| 档 | 内容 | 谁跑 | 配额 | 性质 |
|---|---|---|---|---|
| `check` | 类型检查（锁定版本）+ 静态校验 | 模型 | **计步**，无独立配额 | 资源 |
| `evaluate` | 完整评测网格，回聚合对差表、逐场一行与最差几场展开 | 仓库 | 总量三次，自由分配 | 信息机会 |

`evaluate` 的「三次」是**上限**：用几次是模型自己的策略决策，所以档案里的候选是一到三个，不是恰好三个（ADR-0031）。

`check` 计步而不是免费：否则会造出「所有命令都算一步，除了这个」这条没有解释成本的例外；而且检查本身要几秒到十几秒，真放开会让总墙钟被检查吃掉，结果是模型想检查却检查不到。

资源与信息机会的区别是这条 ADR 的核心：`check` 消耗的是墙钟与步数（资源），`evaluate` 消耗的是**信息**（机会）。前者可以花钱换，后者不能——所以后者的配额固定，全模型相同。**两档不是一档的合并，是这一区别的唯一落点**：只剩一档信息机会，就没有「哪一档算机会、哪一档算资源」的边界问题。

### 没有提交动作，`evaluate` 就是提交

模型写文件，叫 `evaluate` 就把**当前文件**送去跑完整网格。**成绩取最后一次 `evaluate` 评的那个版本**，不是会话结束时的文件内容。

这要求 `evaluate` 时必须把当前文件快照下来，落点沿用既有的逐候选产物命名族，不新建目录（ADR-0031）。one-shot 形态没有这个问题（产出即定版），分步形态必须有——否则模型在最后一次评估之后改坏文件，成绩就丢了，而它可能只是想清理一下。

一次 `evaluate` 都没做的会话记为整次失败，无成绩；失败档的形状与成功档同形，唯一差别是没有候选（ADR-0031）。收工工具只用于提前收工，不消耗 `evaluate` 配额，成绩仍取最后一次 `evaluate` 的版本。（这条命令在 ADR-0032 修订里定名为 `finish`：`done` 是 bash 保留字，当不了命令名；档案侧的 `termination: "done"` 这个名字不变。）

### 契约挂载是四条,首条消息只给目录

只读挂载目录里放规则文档、API 文档、一个目录说明，以及那份最小骨架的独立副本。四条都来自契约目录本身，挂载源与真源是同一批字节（ADR-0037）。骨架不新增第三份真源——它从 API 文档 §6 那个块**逐字节抽出**，一致性由构造保证；收益是「复制骨架开始改」成为零输出 token 的起手式。

首条消息**不注入任何契约正文**，只内联目录说明（哪几个文件、各管什么）、任务说明与三条硬约束（清单在 ADR-0032）。「内联目录说明」指**全量内联**那份文件：它只有二十来行，省下那几百 token 的代价是引入一条「内联的这段 == 文件的那一节」的同源判据，不划算；全量内联让「重复但不一致」在物理上不可能。读契约要花几步，这是设计的一部分：把「先读什么」变成模型的策略决策。具体步数是估的，实测后回填：每步 `stdout` 上限定为 16 KiB 之后，规则文档与 API 文档各两次读完，所以「一到三步」重新成立（ADR-0032）。

本节原稿在骨架那一句上写错过：「由已有的编译测试保证与文档中的示例一致」——那道测试验的是文档里每个可运行块零诊断，它不知道独立副本存在，而「能编译」是两份**各自**的性质。一致性现在由抽取保证（ADR-0037）。

### 观测外置，而不是压缩

`evaluate` 的 stdout 只给聚合对差表加一行指向完整观测文件的路径；逐场明细与最差几场的展开落文件，模型按需读。同一条逻辑用于检查诊断：stdout 给前若干条加总数，全文落文件。

这些派生视图留在工作目录，**不进档案**：它们由落盘的观测数据与渲染规则确定性生成，搬进档案等于给同一事实第二个家。要复核「模型当时看到什么」，进身份清单的是**观测出口的形状与渲染规则**，不是渲染结果（ADR-0031）。

收益是把常驻观测从「每次几 k」降到「每次不到一 k」，且**一分信息没丢**。外置与压缩的差别在谁承担风险：压缩让模型在回溯时付出步数，外置让模型自己决定要不要看细节。

## 残余风险

这三条接受并写死，因为下轮 review 会把它们当漏洞打：

1. **信息机会平权与资源不平权在跑速这一格相交**。配额相同，但每次 `evaluate` 都要跑满整张网格，慢席位一次就是分钟级；跑得慢的席位可能主动放弃第二次评测，于是「用得起几次」间接取决于跑速。接受这一格，是因为替代方案（按跑速发配额、或按钱买评测）直接推翻平权本身。
2. **观测外置依赖模型主动去读文件**。常驻上下文省下来了，代价是它可能不看细节就改，尤其在步数紧的时候。这里没有机制性保证，只有上限与告警文案。
3. **执行器不可用时模型只看到一条非零退出码**，而不是「沙箱坏了」的解释——它会被当成自己的错误去修。接受这条，因为把环境故障解释给模型等于把归因工作从人挪给模型；真正的处置在会话之前：执行器启动即自证、失败即任务失败（ADR-0033）。

## 重评条件

- **实测读契约定型所需的步数显著超过预期**：要调的是步数上限，不是把契约塞回 prompt。把正文塞回去等于取消分步。
- **某个席位的推理是加密不透明块**：这会影响多轮对话能否稳定延续，需要在 harness 侧确认回传语义后再决定该席位的去留。处置形式已定（ADR-0032：加密块按端点族原样回传，不走档案），剩下的是端点是否接受——一次三族三步的探针就能结账，结论回填 ADR-0032。
- **配额形状被证明不足以区分「广撒网」与「深挖」两种策略**：那么「总量固定、自由分配」这条要重估，而不是简单地加减次数。
- **实测显示慢席位把三次上限用成一次、且原因就是单次网格的耗时**：要动的是网格场数或场数上限，不是把信息机会按跑速发；把「一次评测太贵」翻译成「多给几次配额」等于把资源差换成信息差。
- **实测显示模型普遍不读外置的观测文件**：那么「外置而非压缩」这条要重估——但重估的对象是常驻观测与逐步渲染的粒度，不是把全文塞回 stdout。
- **出现不通过 bash 就能触达试跑或存档的路径**：那么「禁令靠沙箱内容物实现」这个前提不成立，整节要重写。
