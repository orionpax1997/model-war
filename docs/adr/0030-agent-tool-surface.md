# agent 的工具面：三档、无提交动作、观测外置

## 问题

分步形态一旦给模型 bash，工具白名单就不存在了——`bash` 能调用的东西不经过我们的枚举。所以「模型不能做什么」这件事只能靠**沙箱里放了什么**来实现：不放引擎、不放试跑入口、不放对局存档、不放网络。

在这个前提下，要裁决的是「模型能做什么」的形状。三件事绑在一起：分几档、试跑频率、以及**模型能观测到什么**——最后一件是公平性问题，因为「观测到自己脚本的运行状态」是一种信息机会，而信息机会与资源不同，它不能靠多花钱买到。

题面上有一个错需要更正：不是「完全没有示例」。规则文档里有完整可编译的最小骨架，且已有测试保证它与文档一致。缺的是**它没被拆成一个可以直接 `cp` 的文件**，所以模型得把骨架正文写进 completion 才能开始。

## Considered Options

- **每轮恰好一次冒烟（落选）**：单会话形态下没有「轮」这个概念，这个选项已经失去所指。它原本要解决的是「修复轮里大量失败发生在试跑阶段」，那个问题现在由「总量固定、自由分配」承接，而不是由 harness 掐点触发。
- **两步 `submit` + `evaluate`（落选）**：`submit` 会让模型「多存几版再挑」，那是评估配额之外的**新信息机会**——候选数从三次变成三次乘版本数。档案格式也要跟着改。而它换来的能力，`evaluate` 在快照语义下已经具备。
- **把契约正文注入首条消息（落选）**：全文体量与 one-shot 时代的 prompt 同量级，分步形态会名存实亡——模型还是面对同一个超人任务，只是多了一个能改文件的循环。分步的意义是让模型**自己去查**它需要的那一小块。
- **压缩观测而不外置（落选）**：增量渲染（「同上」）拿确定性换体量。模型需要回溯时，压缩过的历史会逼它重跑一遍；而步数是硬约束。
- **三档加信息外置（采纳）**：见下。

## Consequences

### 三档的性质不同，待遇也不同

| 档 | 内容 | 谁跑 | 配额 | 性质 |
|---|---|---|---|---|
| `check` | 类型检查（锁定版本）+ 静态校验 | 模型 | **计步**，无独立配额 | 资源 |
| `smoke` | 一场对局，带 tick 上限 | 仓库 | 总量三次，自由分配 | 信息机会 |
| `evaluate` | 完整评测网格 | 仓库 | 总量三次，自由分配 | 信息机会 |

`check` 计步而不是免费：否则会造出「所有命令都算一步，除了这个」这条没有解释成本的例外；而且检查本身要几秒到十几秒，真放开会让总墙钟被检查吃掉，结果是模型想检查却检查不到。

资源与信息机会的区别是这条 ADR 的核心：`check` 消耗的是墙钟与步数（资源），`smoke` 与 `evaluate` 消耗的是**信息**（机会）。前者可以花钱换，后者不能——所以后者的配额是固定的，全模型相同。

### 没有提交动作，`evaluate` 就是提交

模型写文件，叫 `evaluate` 就把**当前文件**送去跑完整网格。**成绩取最后一次 `evaluate` 评的那个版本**，不是会话结束时的文件内容。

这要求 `evaluate` 时必须把当前文件快照下来。one-shot 形态没有这个问题（产出即定版），分步形态必须有——否则模型在最后一次评估之后改坏文件，成绩就丢了，而它可能只是想清理一下。

一次 `evaluate` 都没做的会话记为整次失败，无成绩。`done` 只用于提前收工，不消耗配额，成绩仍取最后一次 `evaluate` 的版本。

### 契约挂载是四条，首条消息只给目录

只读挂载目录里放规则文档、API 文档、一个目录说明，以及那份最小骨架的独立副本。骨架不新增第三份真源——它由已有的编译测试保证与文档中的示例一致；收益是「复制骨架开始改」成为零输出 token 的起手式。

首条消息**不注入任何契约正文**，只内联目录说明（哪几个文件、各管什么）、任务说明与三条硬约束。读契约要花一到三步，这是设计的一部分：把「先读什么」变成模型的策略决策。

### 观测外置，而不是压缩

`evaluate` 的 stdout 只给聚合对差表加一行指向完整观测文件的路径；逐场明细与最差几场的展开落文件，模型按需读。同一条逻辑用于检查诊断：stdout 给前若干条加总数，全文落文件。

收益是把常驻观测从「每次几 k」降到「每次不到一 k」，且**一分信息没丢**。外置与压缩的差别在谁承担风险：压缩让模型在回溯时付出步数，外置让模型自己决定要不要看细节。

## 残余风险

这三条接受并写死，因为下轮 review 会把它们当漏洞打：

1. **冒烟只回自己脚本的运行时状态**——跑完了、撞了 tick 上限、或者撞了预算的哪一项。不回对手局面，不回胜负。
2. **撞了哪一档预算不构成泄露**。预算项本身是面向模型的公开契约，模型本来就能读到；这里泄露的只是「我的脚本在第几步撞了哪一档」，那是它自己的行为。
3. **三次冒烟对所有模型相同，不可用钱购买**。这是信息机会平权的落点。

砍掉冒烟不是选项：那等于承认模型不能观测自己写的代码有没有跑飞，而这是真实工程里最基本的反馈回路。砍掉它会让生成质量下降，且下降原因与模型能力无关——是 harness 人为致残。

## 重评条件

- **实测读契约定型所需的步数显著超过预期**：要调的是步数上限，不是把契约塞回 prompt。把正文塞回去等于取消分步。
- **某个席位的推理是加密不透明块**：这会影响多轮对话能否稳定延续，需要在 harness 侧确认回传语义后再决定该席位的去留。
- **配额形状被证明不足以区分「广撒网」与「深挖」两种策略**：那么「总量固定、自由分配」这条要重估，而不是简单地加减次数。
- **出现不通过 bash 就能触达试跑或存档的路径**：那么「禁令靠沙箱内容物实现」这个前提不成立，整节要重写。
