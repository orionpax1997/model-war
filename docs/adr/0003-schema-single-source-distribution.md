# schema 真源:形状归属与跨包分发

`schema` 包拥有全部五类数据形状的 TypeScript 类型与 JSON Schema(规则集、地图、存档 meta、result、回放行),`replay` 包收窄为纯编解码层;TypeScript 类型是上游,JSON Schema 手工对齐并由测试断言一致性。ajv 校验器只存在于 `apps/cli` 一处,`schema` 交付数据不交付校验器。生成器代码在 `packages/tools`,与真源之间**混合传输**:生成器 import `schema`,而 `tools` 的规则层读生成出来的源文件,以保住快门禁「零构建」的性质。

## Considered Options

- **生成器放 `packages/gen`**:落选。它要进 PR 主流水线,而 `gen` 是唯一联网包,将来按 hld §2.2.6 要装 HTTP 客户端与厂商适配层——一条只读写仓库内文件的仓库门禁,不该让依赖面随别的节点扩张。它同时要推翻 hld §3.1 写下的「工具包之所以独立存在,就是为了不把门禁挂在唯一联网包下」。
- **生成器放 `packages/schema` 或新增第 8 个包**:落选。`schema` 被包依赖规则限定为「无运行时代码」;新增一个包要让 hld §3.1 的拓扑图与职责矩阵一起改,代价与收益不成比例。
- **`tools` 规则层直接 import `schema`**(不分层传输):落选。实测 `tsc -b` 增量 0.32s,会让 `check:quick` 由 1.04s 涨到约 1.36s,更关键的是让快门禁从「零构建」变成「需先构建」——新克隆跑第一条命令就要先编译。`tools` 以源码形态由 Node 的类型擦除执行、不产 JS,这个性质不是偶然,是 hld §2.2.1 里 Node 下限取 22.18 的成因之一。
- **JSON Schema 以独立 `.json` 文件存在**:落选。ajv 接受 JS 对象,不需要文件;`.json` 的唯一好处是「标准可外读」,而 v0 没有任何外部工具读它(契约面向模型,由生成器渲染成 Markdown)。代价是 `resolveJsonModule` 与仓库现有编译配置组合的风险面。
- **反向生成(从 JSON Schema 产出类型)或代码生成**:落落选。回放行与终局原因枚举靠判别联合让结算管线穷尽分支,反向生成会把它压成索引签名,直接伤到 NFR-1;而代码生成要么新增运行时依赖,要么依赖 TypeScript 的编程 API——ADR-0002 已实测记录 TypeScript 7 没有 JS 编程 API。

## Consequences

- **`tools` 里会躺着一个生成出来的 `.ts` 文件,而不是直接 import 真源包**。这是整件事里最反直觉的一处,后来者很可能想「简化」掉它——简化会让快门禁依赖构建,代价见上。
- **`tools` 正式声明对 `schema` 的依赖**,而这条边**不在依赖门的巡航范围内**(`tools` 以源码形态执行,`dist` 里没有 `.js`)。它指向依赖图的根,方向合法,但没有机器守护:hld §3.2 那句「工具包不 import 任何 `@model-war/*`」因此改写为「只允许 import `schema` 这一个根包」,由规范而非门禁承担。
- **校验器只有一份,但只在一个入口。** 调度包不独立校验形状,FR-10 AC2 的「读入端强制校验」由 CLI 一个入口兑现。真正的风险不是校验点少,而是日后有人为了让调度包也能校验而手写一份形状判断——那才是第二真源。
- **形状的唯一性靠测试断言维持,不是靠结构强制。** 判别联合、额外属性禁令、一致性断言三者都可能被后来者放宽,所以它们各自都要有能被弄红的反例。
