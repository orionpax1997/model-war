# 预算终值可失效,但不可就地修改

八个预算参数键的终值由标定节点产出并写入 `rulesets/v1.json`(把键的标定状态从未定值改为已定稿),**就地写、不新开版本**:未定值只是「终值归后续图」的占位,把它换成终值不是 ADR 0008 意义上的「取值变更」,契约散文对此一个字都不动(面向模型的数值表是生成物,状态一改就渲染成数字,`check:drift` 盯着)。但**终值一旦落库就不可就地修改**:契约散文修订、快照结构变更、沙箱 runtime 版本或中断粒度变更触发专用预算复核;复核判红才确认终值失效,开一个新的收尾节点重标,而不是把数改掉。

## Considered Options

- **终值 = 永久冻结,要改就开新版本规则集**:落选——「永久」是假的。中断粒度这类东西是宿主对沙箱运行时行为的镜像、不在规则集里,runtime 一升级就可能变,规则集哈希却不变;承诺冻结只会让下一次「不得不同步改数」变成一次偷偷的改。
- **终值 = 随便改的当前值**:落选——那「终值」这个词就是空的,而且改一次就要重生成面向模型的数值表、复核 selfproof 的地板值与静态校验下限,代价远不止改一个数。没有「什么情况下必须重标」的明文,这些代价会在某次改动里被漏掉。
- **分层:值就地写、失效条件与重标路径写进 hld(采纳)**:末落选择。理由是三类失效事件的**触发点都在别的地方**(gdd 散文、快照结构、runtime 构建),把它们钉在一处比钉在八个键上有效。
- **按赛季定时自动重标**:落选——终值失效由工程变更触发,时间流逝不构成失效理由。定时复核可以作为常驻守卫,自动重标却会在没有失效事件时制造终值变更,破坏「终值不可就地修改」的约束。
- **按路径或文件名的 git diff 自动判定复核触发**:落选——同一路径既有影响预算的语义变更,也有无关措辞修订,路径命中不能替代语义判断。触发判断由修改者负责,机器负责运行复核并判红;具体触发范围与处置动作统一归 [HLD §5.3](../hld.md)。

## Consequences

- **改引擎/契约的人要连带回答「终值是否失效」**。默认门禁不能判断这些变更后的预算终值是否仍自洽:中断粒度改的是宿主镜像常量、ruleset 哈希不变;runtime 升级有版本耦合门禁但不会判预算阈值是否失配;契约散文修订按 ADR 0008 连版本号都不升。所以这条纪律靠 `check:budget-recheck` 的失配断言（终值下预算探针仍被截停、基准脚本仍不被截停且推导仍自洽)执行,修改者须按 HLD §5.3 显式触发复核。
- **「终值」与「未定值」是一对可逆的状态**,不是一个方向的一次性开关:一个键可以在失效后回到未定值、再重标。这正是词条「终值」与「未定值」都不能写成「最终」/「占位」的原因。
- **内存两个键的终值对引擎缺陷敏感**:判罚线标的是「tick 末存活堆」,而存活堆会因引擎泄漏而自己增长。所以「先修泄漏、再标内存」是标定的顺序约束,不是并行项——同一个道理适用于任何「读数由引擎行为决定」的键。
