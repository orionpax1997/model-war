# 编译前剥模型输出的围栏包装:管线改,不动提示词

`modelwar gen` 全量重跑 v2 契约时,10 家一次冻结,唯 `claude-opus-5-5`(yomiapi 中转) 10 轮连挂:
9 轮 `script.ts(1,1) TS2349: This expression is not callable. Type 'String' has no call
signatures`,1 轮围栏残留 TS1127 系列。原文证据见 `.scratch/opus-probe/run2-r{1,2,3,4}-assistant.txt`:
r1–r3 首行 ```` ```typescript ````、r4 首行中文引导语 + 空行 + 围栏,尾行都是 ```` ``` ````。
管线按裸文本直接进 `tsc`,与模板 `prompts/base.md` 的禁围栏令正面对撞。本 ADR 记"在编译调用处剥包装"的决定。

## 为什么是管线改而非提示词改

- 提示词侧已打满:禁围栏/解释文字是模板硬约束,tsc 诊断逐字回喂也已在协议里;同一签名连挂 10 轮
  证明这两层对该模型实证无效,再改措辞只是第三次烧 token。
- 围栏不是内容分歧,是传输包装:有效 TS 里不存在以 `` ``` `` 起首的行,剥它不可能误伤代码本体;
  剥后诊断行号自第一行代码起算,与编译文本天然对齐,回喂口径不变(transcript 留原文,只编译吃剥后文本)。

## 语义(家在 `packages/gen/src/extract.ts`)

- 无围栏行 → 原样返回同一字符串值:已守约的输出逐字节不变(10 份 v2 冻结脚本逐字节核对过)。
- 首尾各一道围栏 → 取首道之后、末道之前的那段原字节(内部不 trim,末行换行保留);开围栏前的引导语、
  闭围栏后的尾随语同去。单道围栏取较长一侧,正中单道不猜、原样返回。
- 落盘与校验都吃剥后文本;`meta.prompts` 的 transcript 仍记原文,失败链可解释。

## Consequences

- opus 连挂 10 轮证明的系统性不守约被管线兜底吸收,不再为"包装问题"烧协议轮数。
- 后续若出现无围栏的纯散文包裹(未观测到),本函数原样返回、照旧走 tsc 失败回喂,不静默吞掉。
