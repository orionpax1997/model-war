# 执行器的缝就是那两次宿主桥调用,中间不设任何表示

`engine:runner` 那个缝**照 hld §4.5 已经写好的两次桥调用原样交付**:`__setSnapshot(snapshot)` 进、`__drainIntents()` 出。`StubRunner` 与 `QuickJsRunner` 是这个缝的两个适配器,都不在缝与适配器之间加中间表示。测试侧的参赛策略写成**普通 TS 函数**,不经字符串、不经 VM。

hld §5 已经把这条缝的动机写死了:「§5.0 的 `Runner` 缝**只为可测性**存在」,而 §5 的边界说明写着「不为『未来换 VM』保留抽象层(那是投机抽象)」。本决定是那两句在类型层面的落地。

## Considered Options

- **缝 = `runTurn(snapshot, seat) → intents[]`,一个纯参数一个纯返回值**:落选。它比桥协议更干净、更好测,但会与 hld §4.5 的两条桥调用构成**两套平行的表示**。G 落地时要么绕过它(那它就是死代码),要么逐 tick 翻译一次(那是一次漂移源,而 intent 恰恰是最不容漂移的东西——六个变体每一个都要翻)。选它等于让「跑一个对局」这件事有两个可写的写法。
- **缝 = 一个 session 对象,持有一整个对局的 VM 生命周期(`load` / `runTurn` / `dispose`)**:落选。它把 VM 的生命周期泄进 F,而 F 的 `StubRunner` 没有 VM 可持——它只有一整个对局的一堆纯函数调用。那条缝会逼着 `StubRunner` 造一个空壳 VM 对象来满足形状,而那个空壳的每个方法都是「什么都不做」,它测不到任何东西,只把类型对齐的成本付了两遍。
- **缝取两次桥调用,但 `StubRunner` 收字符串(把测试策略当脚本源码跑)**:落选。那样 StubRunner 要自己实现一次编译或解析,而它存在的全部理由就是**不引入编译与沙箱**。要测结算管线的时候让测试夹具承担一份 TS 文件的编译,等于把 D 那一格刚钉死的「校验器跑在编译产物上」的同一道门复制到测试夹具上。
- **不给 StubRunner 单独一条缝,测试直接调 `processor` 的内部函数**:落选。那样结算管线在测试里跑得和在生产里跑的不是同一条路(生产要经过快照拷贝与 intent 收集,测试不经过),而「`Object.freeze` 是不是真挡住了 seat 间的脏写」这类问题只有生产那条路能验。

## Consequences

- **`packages/engine` 的对外接口面积不因执行器而增加**。适配器要满足的那个接口就是两个桥函数调用的形状,没有 `Runner` 基类、没有工厂、没有生命周期协议。后来者想加一层,得先说明那层挡住了什么。
- **`StubRunner` 有一个**硬约束**:它必须同样做「拷一份快照、拿到 intent 数组」这两件事,不能抄近路直接读引擎状态**。它一旦读真状态,测试就在验一条生产不走的路,而 FR-3 AC1(脚本读到的每个 state 对象都是只读封存/复制副本)会变得无法证伪。
- **测试策略的形状被定为普通 TS 函数**,这一条是后续所有结算管线测试夹具的写法约束,值得在 `processTick` 的私有内部缝落地时一并写进头注。
- **`__setSnapshot` / `__drainIntents` 这两个名字从此有两处必须一致**:`packages/schema` 的宿主桥前缀常量,和 hld §4.5 的协议描述。G 落地时新增任何宿主桥都要过同一道核对——这与静态校验器那条「`__*` 前缀全禁」是同一条纪律的两端。
- **G 拿到的不是「一个待填的适配器槽」,而是一条已跑通的缝**。它的第一条验收(hld 开放项 #8 的五条复验)因此可以专注于沙箱行为本身,不必先证明两个适配器之间等价。
