# 生成侧的交付切法：两段，按模型第一次拿到什么反馈切

## 问题

生成侧从「一次 prompt 写出一份定版脚本」改成分步 harness 这件事，被排过一条顺序记号：`M0.5 → M1 → M2 → M3 → M4`。它只在一次会话的笔记里出现过，不是定义，而且已经不是现在的链：

- `M0.5` 有完整定义（用量采集与 messages 族缓存）且已完成；
- `M1` 的定义是「等价基线」，已被裁掉不做——既有档案不含模型原始输出，重放没有输入；换 harness 即不跨榜比较，字节等价没有消费者（ADR-0029）；
- `M2` 与 `M4` 从未定义过。

后果不是文档缺口：每次讨论都要现场推断切法，而推断会漂。上一轮的实例是先说「`M2` = 沙箱加 `check`」，随即自我推翻，因为那只到「模型能编译」为止，模型对策略好坏一无所知，与盲写没有区别。

还存在一个记号冲突：`docs/diagrams/v0-milestone-dag.md` 里 `M1`–`M4` 已经用来表示 v0 交付边界（规则与契约 / 对局执行与回放 / 脚本生成与冻结 / 赛季调度与报告），ADR-0010 的正文引用过它们。

要裁决的是：这件事切成几段、每段的判据是什么、记号怎么取。

## Considered Options

- **按代码分层切（沙箱 → loop → 档案 → 配额 → 观测）（落选）**：分层顺序在实现上不存在——loop 要沙箱，沙箱要通道，通道要配额，档案要有 loop 才有内容。强行分层得到的每段都是「一半的路径加两倍的维护」，而每段都拿不到新反馈。
- **把「等价基线」单列成一段（落选）**：它已随等价基线本身取消而作废（ADR-0029）。这条单列的实质是拿一个阶段去换一句「重构没改坏」的安心，而那句话由既有单测、code review 与一次真会话共同承担。
- **一条分支做到底，不分段（落选）**：全程可以做到绿，但唯一一次要花钱的十人真跑就没有准入门槛——它前面整条链路没被任何一次真会话走过。那种失败会以「十个人一起失败」的形式出现，而不告诉你断点在哪一段。
- **三段，把身份与隔离收口单列（落选）**：收口那批（preflight 进主流水线、威胁模型逐条落成断言、四维榜键分榜）不改变模型看到的世界，拿不到新反馈；它防的是退化，不是新的信息机会。单列会让「分步形态是不是更好」这条主线凭空多等一段。
- **沿用 `M2`/`M3` 记号（落选）**：同一个 `docs/` 里会出现两个 `M2`——一个是对局执行与回放，一个是生成侧的第一段，而 ADR-0010 引用的是前者。
- **两段，按「谁第一次拿到什么反馈」切（采纳）**：见下。

## Consequences

### 判据是反馈的新增，不是代码的完成度

每一段的判据都是「这一段结束后，**谁**第一次拿到了**哪一种**反馈」。按代码完成度切会造出脚手架段：能编译、能跑、门禁绿，但模型对策略好坏仍然一无所知——那不是中间态，那是把一次盲写换成多次盲写。

### `A1`：单会话回路闭合

判据：**模型第一次看到自己写的脚本排第几，并据此改过它。** 这是分步形态相对 one-shot 的全部意义（ADR-0029 的两条理由：代价与反馈）。

内容（都在 `A1` 内，不推迟）：

- agent loop 替换 `packages/gen/src/pipeline.ts` 的阶段外循环。它是 `A1` 的第一个提交；不保留「步数为一」的退化路径（ADR-0032）。
- 契约挂载：只读四条、首条消息不注入正文（ADR-0030）。
- 生成期沙箱：执行器、入库 rootfs、薄壳与宿主侧通道（ADR-0033）。`check` 与 `evaluate` 的前提就是那条通道，所以它不能等。rootfs 的「现算 == 入库」漂移门禁与 CI 上的 bwrap 探针同批落地——它们是内容物被钉住这件事的判据，不是加固项。
- 工具面两档与配额（ADR-0030）：`check` 计步，`evaluate` 是唯一的信息机会。
- 档案新形状（ADR-0031）：过程记录、候选一到三、档案形状版本必填且不认识的版本拒读。
- harness 身份双轨（ADR-0029）：叙事版本与清单哈希**从第一份 agent 档起就写**，不等收尾。理由不是「早写便宜」，而是 `A1`/`A2` 期间产出的档正是用来校准 harness 的证据（调步数上限、调每步上限），没有身份就只能靠时间戳推断「这份档是哪个世界产的」。

验收分两半：

- 机器可判的进落点清单（形状见本节末）；
- 人工的那一条在本 ADR 里定死形状：**一个 chat 族席位、一次真会话**，证据是档案本身，必须能读出「至少一次 `evaluate` → 之后至少一步改了同一份脚本 → 再 `evaluate`」这个序。它验的是回路真的闭上，不验行为等价——离线测试验不了模型行为，那是渠道与模型的属性（ADR-0029）。

### `A2`：十人分布与可比性

判据：**我们第一次拿到十个席位可比的分布。** `A1` 的样本量是一，一不构成分布，也回答不了「分步形态是否比 one-shot 好」。

内容：

- 名册各跑一次完整会话；
- 报告与度量口径落地：token、步数、墙钟、钱进报告列，**不设可比性门槛**，资源只记录（ADR-0029/0030）；
- 与既有 one-shot 档案同口径对比：同一个分数定义、同一个分母（ADR-0024）；
- 收口清单：preflight 进主流水线、威胁模型逐条落成断言、四维榜键分榜（ADR-0028/0029）。

验收：十份成功档，加一份同口径的分布对比结论；机器可判的部分同上。

### 依赖

`A1` 的前置是五册 ADR 已裁（0029–0033 全部 accepted），不留待定项；`A2` 的前置是 `A1` 落地且那次真会话跑通。`A2` 不换执行器、不换 loop、不改档案形状——它换的是跑多少个席位、看多少数据。

### 验收落点先写在 ADR 里，实现落地时才搬进 §11

`docs/hld.md` §11 由 `check:landings` 逐行验存在性（文件必须存在且被版本库跟踪、命名脚本必须在脚本清单里），所以**给还不存在的文件加行会让门禁立刻变红**。因此落点的家暂时是本 ADR，实现落地时再搬。这一点是门禁的约束，不是窗口期安排。

机器可判的清单（每项都对应一条能在无模型、无网络下跑的命令或测试）：

- 生成入口唯一：`generateOneModel` 是唯一入口、发送只有一个调用点，步数为 N 时 `check` 被调用 N 次；
- 配额在宿主侧按**调用次数**拦截，超限返回伪造的错误输出且命令不执行；
- 沙箱 fail-closed：执行器不可用即任务失败，不降级到宿主进程；
- rootfs 内容物「现算 == 入库」；
- 档案形状：未知的档案形状版本拒读、失败档与成功档同键集合、候选一到三、`protocolRounds` 与过程记录条数同源；
- 身份双轨一致：叙事版本与行为清单哈希不符即报错。

### 记号对账

`M0.5` 是已完成的那一段（用量采集与 messages 族缓存），保留原名不复用；`M1` 已取消，也不复用；`M2` 起改称 `A1`/`A2`。`docs/diagrams/v0-milestone-dag.md` 里的 `M1`–`M4` 是 v0 交付边界，与本 ADR 的记号无关。

## 残余风险

1. **`A1` 的人工验收只有一次会话。** 它只能证明「回路能闭上」，不能证明「闭上之后更好」——后者要等 `A2`。别把一次成功的会话当成质量证据。
2. **`A2` 十人各一次仍可能不足以区分「广撒网」与「深挖」两种策略。** 那时要动的是重复实验次数，不是把结论写得含糊（ADR-0030 的重评条件正等着这条）。
3. **收口压在 `A2` 末尾。** 若 `A1` 期间有人拿 `A1` 产出的档做跨版本比较，会得到没有身份、没有分榜的读数。这是已知的、被接受的窗口，不是漏洞——但它要求 `A1` 的数据不被当成结论。

## 重评条件

- **`A1` 的第一次真会话跑不通**（不是分数低，是过程记录里读不出那个序）：说明 `A1` 装的东西还撑不起一个完整回路，要么补内容，要么拆段。不许把「跑不通」解释成「模型不会用分步」。
- **出现跨版本或跨 harness 比较产出的实际需求**：收口前移，档案形状版本是否进身份清单重估（ADR-0031 同一条重评条件）。
- **十人一次回答不了「分步是否更好」**：`A2` 扩成重复实验，而不是把段数改多。
