# 一次生成只定义一张评测网格,选拔是排序加独立复算

优化与选拔原先是两次独立实验:一轮试跑(几场对局、单张地图、候选恒坐同一个座位)驱动改写,选拔再另跑一批对局定版。「选拔必须独立于优化」的理由本身没错——用被回喂过的信息挑胜者,等于让候选在自己看过的尺子上被评判。但把它落成「另一次实验」,代价是重复测量、两把尺子,以及一个更根本的问题:在确定性引擎里,**重复测量买不到任何新信息**。

引擎的对局内不消费随机数,种子只改地图墙的装饰性微扰,所以「多个种子」只是同一场对局的多份逐字相同的读数;同一份候选的同一批对局被两处各算一遍,而其中一部分是逐位重算。与此同时,另一次实验给出的分数与试跑分数不同源,两者一旦相反,没有人能判断该信哪个——它们测的其实是同一个东西。

决定一次生成只定义**一张评测网格**:对手组合 × 座位 × 地图,每格恰好一场。**种子不是维度**,每格一个固定值——地图变体是纯装饰性微扰,多种子不产生新信息,这条裁决归 [gdd §8](../gdd.md) 记录 #12。同一张网格同时产出候选的成绩与下一轮回喂的原料:候选一旦产出就在整张网格上跑一遍,那份读数既是它的分数,也是它下一轮被改写的依据。

由此得到本文要写清的那条论断:**在确定性引擎下,同脚本 + 同计划 ⇒ 同数字**。能独立的是**执行**(另一个进程、全量重跑、逐场逐字比对),不能独立的是**测量**。所以选拔从「另一次实验」降级为「排序 + 独立复算」:排序直接用生成阶段那张网格的分数,复算在独立子进程里把**同一份计划**重跑一遍,逐场比对观测行与分数三元组,任一不一致即整次生成失败。这不是放松校验,而是把校验挪到它真正能成立的地方——「选拔会不会跑出和试跑不一样的结论」这类只能在事后发现的漂移,变成当场失败;只比总分不够,总分相同而某一场不同,同样说明这份存档再也无法声称「这些场次是它跑出来的」。

决胜顺序不因换尺子而改:平均分 → 较晚阶段 → 更早协议轮 → 编译产物摘要,规则真源是 [gdd §3.3](../gdd.md);`earlier-stage` 仍只属于历史档。**分母恒等计划声明的场数**:缺场、异常与不确定终局不缩分母、不补零、不用已有候选替补,也不复用赛季的异常剔除口径。均分是「按计划场数记账」的结果,不是「跑了几场算几场」的算术副产物——后者会让少跑几场变成刷分手段。

计划是**纯数据身份**:陪练身份(含内容摘要)、组合、座位、地图摘要、种子、规则集与运行时摘要全部被计划摘要覆盖,并随存档落档。读入端不是「信这份文件」,而是由现场事实重建一份计划再比对,不符即指到具体哪一处(哪一场的种子、哪张图的摘要)。于是「跟谁打、坐哪、哪张图、什么种子、按哪版规则」在任何一次生成之后都能复现,而不是靠当次的日志。

**同字节候选复用**已算出的网格结果,但复用只省「跑」不省「查」:来源摘要、计划同源、观测完整性与逐场逐字一致四关都过才允许复用,复用来源落档。字节相同被当成跳过校验的借口,等于让一份网格结果记到别人的候选名下。

**版本只增不改**:计划与存档升到 v2,历史 v1 档按原形状读取,不迁移、不回填。读入端按版本分派,而不是把旧档改写成新形状。

与既有 ADR 的关系:本文局部取代 [ADR-0018](./0018-generation-policy-and-candidate-selection.md) 里「选拔是预定相同条件下的另一次实验」那层独立性表述(它的「相同编译产物复用同一计划的完整结果」一条被继承,并扩成同字节复用网格);局部取代 [ADR-0019](./0019-terminal-match-facts-feedback.md) 里「独立选拔按预定独立计划」的语义,但**不改写 0019 正文**——该决定自己写明旧 ADR 保留各自决策时的历史表述。本文也不改 [ADR-0017](./0017-uniform-two-fact-feedback.md) 的机会分配与计量边界。**ADR-0020 的意图在 v2 下仍成立**:历史档要可审计,所以 v1 档继续按原决胜语义与原算法读完,`earlier-stage` 只属 v1;v2 档的选拔计划与生成阶段同源,不再产生这个历史理由。两版由读入端按版本分流,而不是迁移。

被否的方案:

- **继续两次独立实验(选拔另跑一批对局)**:重复测量。在一个确定性引擎上它买不到独立性,只是花两遍时间算同一批数字,并顺手制造「试跑说 A、选拔说 B」这种无从判断的漂移。要独立的是执行,不是测量。
- **网格只用于反馈,选拔仍另跑**:两把尺子。选拔结论与反馈对不上,而且要维护两套计划、两套分母、两套版本;最终一定会有人问「为什么同一份候选有两个分数」。
- **只加座位不加地图(或只加图不加组合)**:座位偏置是实测里最大的差异来源,而地图差异只在地形被真正读懂的脚本之间才显出来;只有把两者同时纳入,才谈得上「同尺同分母」。只加一侧会把网格规模花在信息量更低的那一维上。地图数也不再往赛季层的要求上靠——生成阶段的网格只用地图池的一部分,不违背赛季层的地图池要求(见 [vision §5](../vision.md) 的 R3)。

长期约束:一次生成只有一张网格计划,候选的成绩只有一个定义(该网格的平均名次积分),不同来源的数字不混用、不互相换算。分母恒等计划声明的场数;不缩分母、不补零、不剔除异常局。计划是纯数据,摘要覆盖全部身份字段;选拔与生成阶段必须是同一份计划(摘要相等),不同源即整次生成失败。同字节复用必须逐场一致且落档来源。三类分数彼此不替代:生成阶段分数(网格均分)、选拔复算分数(只作校验,应与前者逐位相同)、赛季分数(另一套口径,不进反馈)。版本只增不改,历史档按原形状读取。决胜顺序不因尺子换代而改。

重新评估的条件:引擎开始消费随机数(那时种子重新成为维度,同一格多个种子才携带信息);网格的对局时长把生成等待推到不可接受(那时先减维度,而不是缩分母);陪练或地图数量变化导致计划形状必须变(升版本,不就地改);或有人需要跨赛季比较生成阶段的分数——那时要先有陪练版本化的对外口径,本轮明确不做。
